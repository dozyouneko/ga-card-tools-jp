## 4. ⚠️ ⭐ 前工程（#117）との関係 — **`readScan` は通さない。理由は実測した**

#117 は今日、**UI規約検査①②③の走査の入口を `readScan(rel, who)` に一本化**し、
**`SCAN_READERS = ["①","②③"]` と「実際に `readScan` を呼んだ経路名」の双方向照合**を入れた。

### 4-1. ⭐ `readScan` は #97 のブロックからは呼べない（**構造の事実**）

`readScan` / `scanned` / `SCAN` は **①②③のブロック（`{ … }`）の中のローカル**で、
`preferredArtIndex is single-sourced` のブロックは**そのあとに別のブロックとして**書かれている。
⭐ **だから「通す」には、まずモジュールスコープへ引き上げる必要がある。**

### 4-2. ⚠️ ⭐ 引き上げるだけでは足りない — **G2 の検証が「全経路より前」に走る**（実測）

**測った**: `SCAN_READERS` に `"④"` を足し、**G2 被覆センチネルの検証ブロックより後ろ**で `readScan(…, "④")` を呼ぶ。

```text
EXIT=1

  - SCAN_READERS にあるのに readScan を呼んでいない経路: ④ — その検査が走査の入口（readScan）を迂回していませんか（#117）
```

## 5. 変更内容（`scripts/validate.mjs` の1ブロック）

### 5-1. D-1: 条件取り出しフィクスチャ **4組**（穴A）

#### (1) サンドボックスに合成セットを入れる

いまの (b)(c) 用サンドボックスは `sb.GA_I18N = { meta: { sets: [] }, … }` で、**`SETS` が空**。
⚠️ **`artCondOf()` の `set` 側は `setPrefixes()` → `SETS[添字]` を通るので、空のままでは `set` キーを測れない。**

```js
// ⭐ 条件取り出しフィクスチャ用の合成セット。els.set.value は SETS の添字（本物と同じ）。
// ⚠ 実データを読まない（validate はオフライン前提）。2件あれば「添字1 → BBB」で判別できる。
const ART_ELS_SETS = [{ label: "合成セットA", prefixes: ["AAA"] }, { label: "合成セットB", prefixes: ["BBB"] }];
```

→ サンドボックスを `sb.GA_I18N = { meta: { sets: ART_ELS_SETS }, terms: {}, cards: {} };` にする。

- ⭐ **既存6組（`ART_FIXTURES_*`）の結果は変わらない**（`preferredArtIndex()` は `SETS` を読まない。§2-4 で実測）

#### (2) フィクスチャ（⭐ キーごと2組 ＋ 共通2組 ＝ **4組**）

⭐ **`els` は本物の絞り込みUIと同じ形にする**: エキスパンションは `<select>`（`value` は `SETS` の添字）、
レアリティは**チップ群**（`getValues()` を持つ）。⭐ **`valuesOf()` が `getValues()` を優先する経路を通すため**。

| # | 目的 | `els` | `imgs` | 期待 |
|---|---|---|---|---|
| **E1** | ⭐ `set` の els を読める | `{ set:{value:"1"}, rarity:{getValues:()=>[]} }` | `[{AAA,1},{BBB,1}]` | **1** |
| **E2** | ⭐ `rarity` の els を読める | `{ set:{value:""}, rarity:{getValues:()=>["8"]} }` | `[{AAA,1},{AAA,8}]` | **1** |
