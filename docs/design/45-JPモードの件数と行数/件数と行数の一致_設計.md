## 1. 問題

**JPモードで「全 N 件」が実際の行数より多く、最後までめくっても N 件に届かない。**

本番実測（2026-08-02・**#43 の前後どちらでも同じ**）:

```
効果欄「グオ・ジアボーナス」 → 30 件を表示 / 全 34 件   ← 4件足りない（1ページで終わり）
効果欄「追放」（名前順）      → 575 件を表示 / 全 577 件
効果欄「追放」（コスト順▼）   → 207 件を表示 / 全 208 件
```

⚠️ **「概算です」の注記は出ない。** `jpApprox` は**索引に未収録のslugが混じるときだけ**立つが、
後述のフリップ面22件は**索引に入っている**。→ **サイトは注記なしで確信をもって間違った件数を出す。**

### 1.1 原因 — 候補は「裏面のslug」、表示は「表面のslug」

| 段階 | 何を数えるか |
|---|---|
| `localJpSlugs()` | `I18N.cards` の全slug。⚠️ **裏面（フリップ面）のslugも入っている** |
| `total = jpCand.length` | **候補slug数**（裏表を別に数える） |
| `fetchCard(slug)` | ⚠️ **常に表面カードを返す**（#27 からの仕様） |
| `app.js` の `shownSlugs` | 同じslugを**重複として弾く** → 行が1つ減る |

＝ **総件数は取得前・行数は取得後**で数えており、間に「表面への置換＋重複除去」が挟まっている。

### 1.2 ⭐ 表示は既に正しい（直すのは件数だけ）

サイトは**両面カードを1枚のタイルで表現済み**である:

- 検索結果のタイルに **`🔄 両面` バッジ**（クリックで裏面画像に切替・`app.js:218,273`）
- 詳細モーダルに **「🔄 裏面」セクション**（`shared/js/card-detail.js:421-423`）

→ **表面1枚に畳むのがUI上も正しい。** 裏面を別行として出すべきではない。

## 3. 方針

> **フリップ面のslugを、候補列を作る段階で表面slugに置き換えて重複を除く。**
> 対応表はメタ索引に `f` として持つ。
> あわせて、**取得後に落ちた件数を数えて画面に出す**（畳み漏れ・索引の腐り・取得失敗が黙って消えないように）。

### 3.1 却下した案

| 案 | 却下理由 |
|---|---|
| **B: 総件数を「表示できた行数」に合わせる** | 最後までめくるまで総件数が確定しない。⚠️ 「全 N 件」を先に出せなくなり、**絞り込みの手応えが失われる**（現状よりUXが悪化する） |
| **C: JPモードの検索対象から裏面slugを外す** | ⚠️⚠️ **裏面の日本語テキストで検索できなくなる**（「朱雀」「青龍」で引けなくなる）＝**機能後退**。裏面は独自の name/effect を持つので、検索対象から外すのは損失が大きい |
| 表示側で「裏面も別行として出す」 | §1.2 のとおり**両面は1タイルで表現済み**。2行にすると同じ物理カードが2枚あるように見える |

## 4. 索引フォーマットの変更（`scripts/gen-card-meta-index.mjs`）

### 4.1 形式

```
現在: { d: […], m: { slug: [ …8要素… ] } }
変更: { d: […], m: { slug: [ …8要素… ] }, f: { "<裏面slug>": "<表面slug>", … } }
```

⚠️ **`m` のエントリ形状は変えない。** #43 の `sortKeyOf()` が `entry.length < 8` で
旧形式を判定しているため、**9要素目を足すとその判定に干渉する**。トップレベルに別キーを置く。

### 4.2 生成

個別取得のループは**すでに表面slugを受け取っている**（`log(\`  ${slug} → ${c.slug}\`)`）。
これを記録するだけでよい:

```js
const flip = {};   // 裏面slug → 表面slug（#45）
…
for (const slug of missing) {
  try {
    const c = await fetchJson(`${API}/cards/${encodeURIComponent(slug)}`);
    meta[slug] = metaOf(c);
    // #45: 返ってきたのが別のslug＝この slug はフリップ面（裏面）。
    // 消費側は候補列でこれを表面slugへ畳み、総件数と行数を一致させる
    if (c.slug && c.slug !== slug) flip[slug] = c.slug;
    log(`  ${slug} → ${c.slug}`);
  } catch (e) { /* 既存のまま（除外して続行） */ }
}
```

出力:

```js
const f = {};
Object.keys(flip).sort().forEach((k) => { f[k] = flip[k]; });   // ⚠ キー順を固定（決定性）
const json = JSON.stringify({ d, m, f });
```

⚠️ **キーは必ずソートしてから書く**（#29 の決定性要件。`missing` は `translated` 由来で
実際には既にソート済みだが、**依存せず明示する**）。

### 4.3 完走サマリに1行足す

```
生成: 2262slug / 辞書233トークン / 182.1KB → data/card-meta-index.json
並び替えキー: level 124 / power 910 / life 768 / cost_memory 478 / rarity 2262
フリップ面: 22件を表面slugへ対応づけ                                    ← 追加
```

⚠️ ここでも **exit 1 にはしない**（cronの後段に到達しないとその日の大会データの取り込みごと失われる）。

## 5. 候補列を畳む（`shared/js/card-search.js`）

### 5.1 `foldFlip()`

```js
// フリップ面（裏面）のslugを表面slugへ畳んで重複を除く（#45）。
// 裏面は独自の name/effect を持つので検索の対象には残すが、表示は表面カード1枚に集約される
// （fetchCard は常に表面を返し、タイルの 🔄 両面 バッジで裏面を見られる）。
// ⚠ 索引に f が無い（旧形式）ときは畳まない＝現状の挙動に劣化する（fail-open）。
//   その場合の重複は §6 の取得後カウントが拾う
function foldFlip(idx, list) {
  const f = idx && idx.f;
  if (!f) return list;
  const out = [];
  const seen = new Set();
  for (const slug of list) {
    const front = f[slug] || slug;
    if (seen.has(front)) continue;
    seen.add(front);
    out.push(front);
  }
  return out;
}
```

⚠️ **畳んだ直後の並びは slug昇順ではない**（裏面の位置に表面slugが入るため）。
⭐ ただし **#43 の `sortJpCand()` が必ず並べ替える**ので問題にならない
（索引が使えないときも `unknown.sort()` で slug昇順になる）。**この依存関係を消さないこと。**

### 5.2 `run()` への組み込み

```js
if (jpCand === null) {
  const idx = await metaIndex();
  if (mySeq !== seq) return;
  const folded = foldFlip(idx, jpSlugs);          // ← #45。取得前フィルタより前で畳む（§2.2）
  let base;
  if (idx) {
    base = folded.filter((s) => metaMatches(idx, s));
    jpApprox = hasJpFilters() && folded.some((s) => !idx.m[s]);   // ⚠ jpSlugs → folded
  } else {
    base = folded;
    jpApprox = hasJpFilters();
  }
  const s = sortJpCand(idx, base);                // #43（変更なし）
  jpCand = s.list;
  jpSortUnknown = s.unknown;
  jpSortDropped = base.length > 0 && s.unknown === base.length && sortField() !== "name";
}
```

⚠️ `jpApprox` の判定対象を `jpSlugs` から `folded` に変える（**実際の候補集合**で見るため）。
実データでは差は出ないが、表面が未翻訳で索引に無いフリップ面が現れたときに正しく概算になる。

## 6. 取得後に落ちた件数を数える（✅ ユーザー判断で範囲に含める）

### 6.1 なぜ要るか

**総件数と行数がズレる経路は、フリップ面のほかに2つある。** どちらも**今は発生していない**が、
⚠️ **発生しても画面には何も出ない**（総件数だけが多いまま）。

| 経路 | いつ起きるか | 今の可視性 |
|---|---|---|
| **① フリップ面**（本issue） | **常に**（22件・決定的） | ❌ 何も出ない |
| **② 索引の腐りによる過剰包含** | 禁止改定・再録から**最大24時間**（cronが直すまで）。`metaMatches` が候補に残したカードを `matchesActiveFilters` が落とす | ❌ 何も出ない |
| **③ `fetchCard` の失敗** | ネットワーク断・APIの一時エラー | ❌ 何も出ない |
| （④ 畳み漏れ） | `f` に載らなかったフリップ面（個別取得に失敗したslug等） | ❌ 何も出ない |

⭐ **①を直すだけでは②③④が残る。** しかも**①を直したあとは「ズレたら異常」**になるので、
数えて出す価値が上がる（今は常時ズレていて異常が埋もれる）。

### 6.2 実装

```js
let jpDropped = 0;    // 取得後に落ちた件数（reset ごとに0へ）
let jpSeen = null;    // 取得できた表面slug（reset ごとに new Set()）
…
const batch = jpCand.slice(from, from + JP_PAGE_SIZE);
const fetched = await Promise.all(batch.map((s) => fetchCard(s)));
if (mySeq !== seq) return;
cards = [];
for (const c of fetched) {
  if (!c) { jpDropped++; continue; }                        // ③ 取得失敗
  if (jpSeen.has(c.slug)) { jpDropped++; continue; }         // ④ 畳み漏れ（表面が重複）
  if (!matchesActiveFilters(c)) { jpDropped++; continue; }   // ② 索引が腐って過剰包含
  jpSeen.add(c.slug);
  cards.push(c);
}
total = jpCand.length;
hasMore = from + JP_PAGE_SIZE < jpCand.length;
```

⚠️ **`total` は減らさない。** `jpDropped` は「めくったページまで」の累計でしかないので、
総件数を引くと**スクロールするたびに総数が減る**という、より分かりにくい表示になる。
→ **総件数はそのまま出し、注記で差を説明する。**

⚠️ `app.js` の `shownSlugs` は**そのまま残す**（非JPモードも守っているため）。
JPモードでは `jpSeen` が先に弾くので二重には効かない。

### 6.3 注記

```js
// 取得後に落ちた件数の注記（#45）。①を直したあとは「出たら異常」の信号になる
function jpDropNote(info) {
  if (!info || !info.jpMode || !info.jpDropped) return "";
  return `（うち${info.jpDropped}件は取得後の判定で除いたため表示されていません）`;
}
```

`app.js` / `tools/deck-builder/app.js` の両方で、`jpSortNote` の直後に足す:

```js
suffix += GA_CARD_SEARCH.jpSortNote?.(info) || "";
suffix += GA_CARD_SEARCH.jpDropNote?.(info) || "";   // ← 追加
```

⚠️ **`?.` は必須**（push直後の伝播ラグ対策。#39 §7.2・#43 §7.2 と同じ理由。
⭐ **#43 の本番検証で実際に「新 `app.js` ＋ 旧 `card-search.js`」の窓を踏んでいる**）。

`onResults` に `jpDropped: jpSlugs ? jpDropped : 0` を追加する。

## 7. 静かに劣化しないための検査（`scripts/validate.mjs` に追加）

`f` は cron が毎日作り直すため、**黙って壊れる経路**ができる。#43 で足した索引検査の隣に置く:

| # | 検査 | 壊れると何が起きるか |
|---|---|---|
| 1 | `f` がオブジェクトとして存在する | 畳まれず件数が元のズレに戻る |
| 2 | **`f[k] !== k`**（自分自身を指さない） | 無意味なエントリ（生成バグの兆候） |
| 3 | ⚠️ **`f[f[k]]` が存在しない**（連鎖が無い） | **1回の置換では収束しない**。`foldFlip` は1回しか引かないので**畳み残る** |
| 4 | `f` のキーがすべて `m` にある | 索引と対応表が食い違っている |
| 5 | **件数が1件以上**（実測22件） | 生成デグレで対応表が空になっても気づけない |

⚠️ 5 は**固定値（22）で照合しない**（フリップ面カードが増減すると誤検知する）。「全滅」だけを見る。
⚠️ **cron は `validate` を実行しない**ので、人を止めるのはここ・痕跡を残すのは §4.3 のサマリ、という
#40/#43 と同じ二段構え。
