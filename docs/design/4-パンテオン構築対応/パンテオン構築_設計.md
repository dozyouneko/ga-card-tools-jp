## 1. 背景と目的

統計タブ（#12 第6版）でパンテオンの**判定**はできるが、パンテオンデッキを**構築**するための対応が無い。
現状の問題:

- デッキに「どのフォーマットで作っているか」の情報が無い。メーター（メイン60/マテリアル12/サイド15pt）も
  警告バナーも**スタンダード固定**で、パンテオンデッキを作ると常に誤った基準で表示される
- Boon（Lesser/Greater 各1枚）は「本ツールでは管理対象外」と注記しているだけで、置き場所が無い
- **Boonカードをメインデッキに入れられてしまう**（Boonの `types` は `GREATER BOON` / `LESSER BOON` で、
  現在の `isMaterialCard()` に該当しないため `zoneDisallowed()` を素通りする）
- デッキ一覧でパンテオンデッキを見分けられず、絞り込みもできない

## 2. 公式ルールの確認（2026-08-10 再確認）

出典: [Grand Archive Comprehensive Rules — Format Conventions](https://rules.gatcg.com/general-rules/general-rules-format-conventions)

| | スタンダード | パンテオン |
|---|---|---|
| メインデッキ | 最低60枚・**同名4枚**まで | 最低60枚・**同名1枚**（シングルトン） |
| マテリアルデッキ | **最大**12枚・同名1枚・Lv0チャンピオン必須 | **ちょうど**12枚・同名1枚・Lv0チャンピオン必須 |
| サイドボード | 最大15枚（通常1pt・チャンピオン/レガリア3pt、最大15pt） | **存在しない** |
| パンテオン（Boon） | 無し | **Lesser Boon 1枚・Greater Boon 1枚**を対戦開始時に裏向きで提示 |

- パンテオンは3〜4人のフリーフォーオール（多人数戦）フォーマット。2026-04-03 の Radiant Origins で開始
- ⚠️ **「マテリアルちょうど12枚」以外は現行の統計タブの判定と一致している**（#12 第6版の調査どおり）

### 公式APIの調査結果（2026-08-10 実測）

| 調べたこと | 結果 |
|---|---|
| Boonカードの収録 | **47枚**（`type=LESSER BOON` 34枚／`type=GREATER BOON` 13枚） |
| Boonの `types` | `["LESSER BOON"]` / `["GREATER BOON"]`（`subtypes` はクラス＋SPELL等） |
| Boonの `legality` | `{"DRAFT":{"limit":0},"STANDARD":{"limit":0}}` ＝ **パンテオン専用**。既存の `exclusiveFormat()` が 🏛 を出す |
| パンテオンの禁止カード | `legality_format=PANTHEON&legality_state=RESTRICTED` で **44枚**（スタンダードは122枚）。既存の `bannedFormats()` で判定済み |
| Boonの和訳 | `data/tl/rdop.js`・`data/tl/rdopd.js` に**全47枚収録済み**（「〜の大いなる恩恵」「〜の小さな恩恵」） |
| `data/translations.js` の `meta.types` | ⚠️ **`GREATER BOON` / `LESSER BOON` が未登録**。タイプ絞り込みのチップに出ず、ラベルが素の英語のまま |
| `deck_cards.board` | **自由入力（TEXT）**。`'pantheon'` を足すのに**マイグレーションもAPI改修も不要**（`functions/api/decks/[deckId]/cards/index.js` は board を検証していない） |
| Omnidexのデッキリスト構造 | `main` / `material` / `sideboard` の3つのみ。**pantheon / boons セクションは無い**（[API docs](https://api-docs.gatcg.com/endpoints/omnidex)）→ §7-C の未決事項 |

## 3. 決定済み要件（2026-08-10 ユーザー決定）

1. **Boonは専用ゾーンで管理する**（5つ目のゾーン `pantheon`）。統計の「本ツールでは管理対象外」注記は撤去する
2. **フォーマットは新規作成モーダルで選び、後から変更もできる**（現行の `prompt()` を置き換える）
3. **パンテオンではサイドボードのゾーンを出さない**。統計の「フォーマット適合」は**デッキのフォーマット1行だけ**にする
4. **逸脱の警告はタブ帯の直上**に出す（デッキ／統計どちらのタブでも見える）。統計タブ内の既存バナーは撤去する

## 4. データモデル

### 4-1. マイグレーション `migrations/0004_deck_format.sql`（新規）

```sql
-- デッキの構築フォーマット。'STANDARD' | 'PANTHEON' の2値。
-- 既存デッキはすべて 'STANDARD' として扱う（作成時にフォーマットの概念が無かったため）。
ALTER TABLE decks ADD COLUMN format TEXT NOT NULL DEFAULT 'STANDARD';
```

- ⚠️ `CHECK` 制約は付けない（D1/SQLite の `ALTER TABLE ADD COLUMN` で制約を足すとテーブル再作成が要り、
  ロールバックが重くなるため）。**値の検証はAPI側で行う**
- 本番反映は `npm run db:migrate:local` のリモート版（ユーザーがpush時に実行）。**dev担当はローカルまで**

### 4-2. `deck_cards.board` の値

| board | 用途 | 追加作業 |
|---|---|---|
| `material` / `main` / `side` / `maybe` | 既存 | — |
| **`pantheon`** | Boon（Lesser 1・Greater 1） | **スキーマ変更不要**（boardは自由入力・§2の調査済み） |

### 4-3. API（`functions/api/decks/`）

| ファイル | 変更 |
|---|---|
| `index.js` (GET) | `SELECT` に `d.format` を追加 |
| `index.js` (POST) | `body.format` を受理。`"STANDARD"`/`"PANTHEON"` 以外（未指定を除く）は `400 invalid_format`。未指定は `'STANDARD'` |
| `[deckId]/index.js` (GET) | 返す deck に `format` を含める（共有閲覧でも使うため） |
| `[deckId]/index.js` (PATCH) | `"format" in body` のとき検証して更新。不正値は `400 invalid_format` |

- ⚠️ **`getDeck()`（`functions/_lib/decks.js`）が `SELECT *` でないなら `format` を追加すること**。
  実装前に必ず現物を確認する
- 複製（`copyDeckToMine`）は**元デッキのフォーマットを引き継ぐ**（POSTに `format` を渡す）

### 5-1. 新規作成モーダル `#new-deck-modal`（新規・`prompt()` を置き換え）

デッキ一覧の `＋ 新しいデッキ` で開く。既存の `openModal()` / `.modal-body` 基盤に載せる。

```
＋ 新しいデッキ                                    [×]
デッキ名
[ 新しいデッキ                                        ]
フォーマット
┌────────────────────┐ ┌────────────────────┐
│ ◉ ⭐ スタンダード     │ │ ○ 🏛 パンテオン      │
│ メイン60枚以上・同名4枚 │ │ メイン60枚以上・同名1枚│
│ まで／サイドボードあり  │ │ ／サイドボードなし・   │
│                    │ │ Boon 各1枚           │
└────────────────────┘ └────────────────────┘
                              [ キャンセル ] [ 作成する ]
```

- 既定は **スタンダード**。ラジオ（`name="new-deck-format"`）で、カード全体がクリック領域
- デッキ名が空のまま「作成する」→ 入力欄の下に `デッキ名を入力してください`（`.form-error`）。モーダルは閉じない
- 入力欄で **Enter でも作成**する
- 375px幅では2枚のカードを**縦並び**にする（`flex-wrap: wrap`）
- 作成に成功したら `location.hash = "#edit/<id>"`（現行と同じ）。失敗時は `.form-error` にAPIのメッセージ

### 5-2. 編集画面

#### (a) editor-bar のフォーマットバッジ（変更可能）

`#ed-pub`（公開/非公開）の**直後**に `<button id="ed-format" class="badge-fmt">` を置く。
クリックで `confirm()` を出してから切り替える（PATCH `{format}` → 再描画）。

- スタンダード → パンテオン（サイドボードにN枚ある場合）:

  ```
  このデッキをパンテオンに変更します。
  パンテオンにサイドボードはないため、サイドボードの15枚は集計対象外になります（カードは残ります）。
  よろしいですか？
  ```

  サイドボードが空なら2行目を省く。
- パンテオン → スタンダード（パンテオンゾーンにN枚ある場合）:

  ```
  このデッキをスタンダードに変更します。
  スタンダードにパンテオン（Boon）はないため、パンテオンの2枚は集計対象外になります（カードは残ります）。
  よろしいですか？
  ```

- ⚠️ **カードは絶対に削除しない**（非アクティブゾーンとして残す。§5-2(c)）

#### (b) 警告バナー `#deck-warn`（タブ帯の直上）

`.deck-tabs` の**直前**に置く。デッキタブ・統計タブのどちらを表示していても見える。

```
⚠️ パンテオンで使用できない構成です（禁止カード 2枚・メイン同名1枚制限の超過 3種）
（詳細は「📊 統計」タブのフォーマット適合へ）
```

- 表示条件: **デッキのフォーマット**の適合判定に issue（禁止カード／シーズン禁止(active)／
  メイン同名制限の超過／マテリアル同名1枚超過／**Boonの枚数超過**）が1つ以上あるとき。無ければ `hidden`
- 理由の並びは固定: `禁止カード N枚` → `シーズン禁止カード N枚` → `枚数制限の超過 N種` → `Boonの重複 N種`
- ⚠️ **「不足」は出さない**（メイン60枚未満・マテリアル12枚未満・Boon未設定）。構築途中に常時点灯して
  ノイズになるため。既存の「デッキ最低枚数は判定せずメーターに委ねる」方針を踏襲し、ゾーンのカウンタに任せる
- **既存の統計パネル最上部のバナー（`.warn-banner`）は撤去する**（重複するため）。
  `statsHtml()` の「0. ⚠️警告バナー」ブロックごと削除
- 共有閲覧画面（`#view-deck`）にも**同じものを出す**（`#v-tabs` の直前）。実装は同じ関数を共有する

#### (c) ゾーンの構成

| デッキのフォーマット | 表示するゾーン（上から） |
|---|---|
| スタンダード | マテリアル → メイン → **サイドボード** → 検討中 |
| パンテオン | マテリアル → メイン → **パンテオン** → 検討中 |

- **非アクティブなゾーンにカードが残っている場合だけ、検討中の下に出す**。
  見出しは `サイドボード（このフォーマットでは使いません）`、`.zone-note` に
  `⚠️ パンテオンにサイドボードはありません。統計・適合判定の対象外です（スタンダードに戻すと元通りに数えます）。`
  - タイルは **`＋` を出さず `−` と `⋯`（削除・移動）だけ**残す（掃除できるように）
  - メーターは出さない。カウンタは `15枚`（`ok`/`over` を付けない）
- 検索結果の `＋マテリアル/＋メイン/…` ボタンと枚数ステッパーは**アクティブなゾーンだけ**を出す
  （`ZONES` をそのまま回さず、`activeZones(format)` を使う）

#### (d) パンテオンゾーンの仕様

```
PANTHEON                                  Lesser 1/1・Greater 0/1
[■■■■■■■■■■□□□□□□□□□□]
対戦開始時に裏向きで提示する Lesser Boon 1枚・Greater Boon 1枚。メインデッキには含めません。
```

| 項目 | 仕様 |
|---|---|
| `ZONE_LABEL.pantheon` | `パンテオン` |
| `ZONE_SHORT.pantheon` | `パンテオン` |
| カウンタ | `Lesser {L} / 1・Greater {G} / 1`（**ASCII表記。375px幅で `.zone h3` を折り返さないため**） |
| `.cnt.ok` | `L === 1 && G === 1` |
| `.cnt.over` | `L > 1 \|\| G > 1` |
| メーター | 幅 = `(min(L,1) + min(G,1)) / 2`。`ok` は上と同条件、`over` も同条件 |
| 空のとき | `.zone-empty` は既存文言のまま（`カードがありません。上の検索から追加できます。`） |

#### (e) ゾーン投入制限 `zoneDisallowed()` の拡張

`isBoonCard(card)` = `types` に `GREATER BOON` または `LESSER BOON` を含む、を新設する。

| ゾーン | 入れられないカード |
|---|---|
| `material` | Boon、マテリアル系以外（＝既存の条件に Boon を追加） |
| `main` | **Boon**（追加）、マテリアル系（既存） |
| `side` | 変更なし（両方可） |
| `pantheon` | **Boon以外すべて**（新規） |
| `maybe` | 変更なし（メモ用なので何でも可） |

- 禁止ゾーンの `＋` ボタンは `disabled` ＋ `title="このカードは◯◯に入れられません"`（既存の仕組みのまま）

### 5-3. 統計タブ

#### (a) 集計対象ゾーン（`STAT_ZONES` をフォーマット依存にする）

| フォーマット | 統計・合計の対象 |
|---|---|
| スタンダード | material / main / side |
| パンテオン | material / main / **pantheon** |

- 合計の内訳行:
  - スタンダード: `72枚 ＝ マテリアル12＋メイン55＋サイド5（「検討中」は含みません）`（現行のまま）
  - パンテオン: `74枚 ＝ マテリアル12＋メイン60＋パンテオン2（「検討中」は含みません）`

    `（サイドボード15枚はパンテオンでは集計対象外）`
- ゾーン別の統計カードも上表に従う（パンテオンでは「サイドボード」の統計カードを出さない）

#### (b) フォーマット適合カード

**デッキのフォーマット1行だけ**を出す。見出しの注記も切り替える。

| フォーマット | 見出しの注記 | 末尾の注記 |
|---|---|---|
| スタンダード | `メイン＋マテリアル＋サイドで判定` | （無し。現行のBoon注記は撤去） |
| パンテオン | `メイン＋マテリアル＋パンテオンで判定` | `※パンテオンにサイドボードはありません。Boonは対戦開始時に Lesser・Greater 各1枚を裏向きで提示します。` |

判定ロジック（`FORMAT_RULES`）:

```js
const FORMAT_RULES = {
  STANDARD: { zones: ["material", "main", "side"],     mainCopyLimit: 4, boons: false },
  PANTHEON: { zones: ["material", "main", "pantheon"], mainCopyLimit: 1, boons: true  },
};
```

- 既存の `banned` / `seasonalActive` / `seasonalSoon` / `overMain` / `overMaterial` はそのまま
- **追加**: `overBoon`（パンテオンのみ）— `pantheon` ゾーンで Lesser または Greater が2枚以上ある場合。
  表示は `⚠️ Boonは Lesser・Greater 各1枚までです — Lesser Boon of Artemis（アルテミスの小さな恩恵） ×2`
- **追加**: `boonInDeck`（パンテオンのみ）— マテリアル/メインにBoonが入っている場合（過去データ救済）。
  表示は `⚠️ Boonはパンテオンゾーンに置いてください — <カード名> ×N`
- ⚠️ **「Boonが足りない（0枚）」は適合カードにも出さない**（§5-2(b)と同じ理由。ゾーンのカウンタで示す）
- ⚠️ 恒久禁止とシーズン禁止は**合算しない**（既存方針・#34）

### 5-8. タイプ辞書への Boon 追加（`data/translations.js`）

`meta.types` に2件追加する（アルファベット順に挿入）:

```js
"GREATER BOON": "大いなる恩恵", "LESSER BOON": "小さき恩恵",
```

- ⚠️ 訳語は**既存のカード名の訳に合わせる**（`data/tl/rdop.js`: 「アストラエウスの**大いなる恩恵**」
  「アルテミスの**小さな恩恵**」）。タイプ名としては `LESSER BOON` = **「小さな恩恵」**とする
  （カード名の訳と完全一致させる。「小さき」等に揺らさない）
- これでトップ／デッキ構築の**タイプ絞り込みチップに Boon が出る**（チップは `meta.types` から作られる）
- ⚠️ **`npm run build:cards` を実行し、生成物（`cards/` `sets/`）もコミットすること**。
  Boon 47枚のカードページとセットページ（RDOP/RDOPD）のタイプ表記が変わる。
  忘れると**翌朝のcronが同じ差分を無関係な自動コミットとしてpushする**（CLAUDE.md の既知の落とし穴）
- ✅ `data/card-meta-index.json` の**再生成は不要**（索引はタイプの**生値**（`GREATER BOON`）を
  トークン化しており、和訳を持たない。実測で確認済み）

## 8. やらないこと（今回のスコープ外）

- **Lv0チャンピオン必須の判定**（両フォーマット共通の要件だが、現状も未判定。別issue候補）

  現行の `ok`（=12）/`over`（>12）の色分けで足りる）

  ⚠️ 公式ルール上スタンダードのメインも**最低60枚（上限なし）**だが、現行の実装は61枚以上を

  Boonは検索結果に 🏛 バッジが出るので識別できる）
- **公開デッキ検索（#5）へのフォーマット絞り込み**（#5 は凍結中）
