**個数ではなくキー名が条件**です。→ ⚠️ **検査は「1つまで」ではなく
「版レベル項目の集合が `{rarity}` と一致」で書く**ことにしました。

## 3. 対象範囲（**2ファイルだけ**）

1. **`shared/js/card-search.js`** — 返却オブジェクトに1行足すだけ:

   ```js
   INDEX_BLIND_KEYS: MULTI.filter(isIndexBlind).map(([k]) => k),
   ```

   ⚠️ ⭐ **必ず `MULTI` から導くこと。配列リテラルを書き写さない**——二重定義になり、
   **本件が塞ごうとしている「片方だけ直すと静かにずれる」型そのもの**になります。
   ⚠️ **`matchesMulti()` / `rarityMatchesIn()` / `matchesActiveFilters()` / `matchesAndFilters()` /
   `metaMatches()` / `MULTI` の本体には一切触らない**（J4）。

2. **`scripts/validate.mjs`** — 検査を1本追加（UI規約3本の直後・版順序の検査の直前）:
   - **(a)** `vm` で `shared/js/card-search.js` を読み込む（⚠️ **`fetch` はスタブで塞ぐ。ネットワークを使わない**）
   - **(b)** `INDEX_BLIND_KEYS` と `INDEX_BLIND_ALLOW = ["rarity"]` を**双方向**に照合（⚠️ 片方向にしない）
   - **(c)** 許可リストの各キーについて**実際に絞れること**を本物の `create()`/`run()` で確かめる
     （⚠️ **フィクスチャが無いキーは exit 1**＝将来2つ目を足す人が必ず止まる）

⚠️ **`CLAUDE.md` は触らないでください**（設計担当の担当パス。承認時または締め作業で私が足します）。
