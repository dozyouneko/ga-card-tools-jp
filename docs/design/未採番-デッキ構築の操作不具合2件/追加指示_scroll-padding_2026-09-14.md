## 2. Q1 の判断の理由

- ⭐ **報告の原因分析は正しい**。チップのフォーカスは中の `<input>`（`position: absolute; width/height: 0`・縦中央）に当たるので、ブラウザは**その点**だけを画面内に入れる。
  旧 `#search-top` の `scroll-padding-bottom: 5rem` は、**ボタン行の重なりだけでなくこの切れも救っていた**。**D5（0.2）はこの2つ目の役割を見落としていた**＝設計の誤り
- ⭐ **値は `2rem`**（`5rem` にしない）。ボタン行はもう重ならないので、残る役割は**チップの高さの半分＋フォーカスリング**ぶんの余白だけ。
  1行のチップ（34px）で最大約 20px、2行に折り返したチップ（約 58px）で約 32px。**`5rem` だと Tab のたびに 80px 余分に送る**。報告の CSSOM 試行でも **`2rem` で 0件**
- ⚠️ **V39 の期待値を「一部なら可」に緩める案は採らない**——**キーボードで辿ったときにフォーカス中の要素が欠けて見えるのは、左ペイン化で守ってきた性質の後退**で、直すコストが1宣言だから
- 見た目の仕様ではなくキーボード操作時のスクロール量の話なので、**ユーザー判断は取らない**

## 3. やること（開発担当）

### 3-1. 実装

`tools/deck-builder/style.css` の `@media (min-width: 1200px)` 内、`#search-top > .pane-scroll { … }` の末尾に1宣言を足す。**コメントは設計書 §4-7 (2-b) のコードのとおり**:

```css
  /* ⚠️ 0.3 で追加（D5 を覆した）。チップのフォーカスは中の 0×0 の <input> に当たるので、
     ブラウザは「その点」だけを画面内に入れ、チップの下半分がこの箱の下端で切れる
     （実測: 157種を Tab で辿ると ANIMAL の下 9px が切れた）。下端から 2rem を「見えていない」扱いにして
     チップ全体が入るまで送らせる。⭐ 値の根拠: <input> はチップの縦中央にあるので、切れる量は最大で
     チップの高さの半分＋フォーカスリング（1行のチップ 34px なら約 20px）。2rem=32px は2行に折り返した
     チップ（約 58px）まで覆う。 */
  scroll-padding-bottom: 2rem;
```

- ⚠️ **実装報告 §B-5 で `.pane-scroll` のコメントに書いた「scroll-padding-bottom は要らない」理由は、この宣言と矛盾するので消す**（上のコメントに置き換える）

- ⚠️ **コメントに `<file>.js:<行番号>` 形式を書かない**
