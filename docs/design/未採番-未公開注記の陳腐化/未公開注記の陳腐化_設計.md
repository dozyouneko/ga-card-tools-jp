## 4. A3 の仕様

### 4-1. 10箇所の落とし方

⭐ **括弧内の該当句だけを消し、各注記の本文（仕組みの説明）には一切触れない。**

```
【前】- ⚠️ ⭐ **UI規約の自動検査が3本ある**(2026-09-08〜。⚠️ **未pushなので本番にはまだ出ていない**)。
【後】- ⚠️ ⭐ **UI規約の自動検査が3本ある**(2026-09-08〜)。
```

- ⚠️ **10箇所は文脈が少しずつ違う**（`(2026-09-06〜。⚠️ …)` / `(2026-08-30。⚠️ …)` /
  `⚠️ **どれも未pushなので本番にはまだ出ていない**):` / `(2026-08-21実装・2026-08-26承認。⚠️ …)` など）。
  ⚠️ ⭐ **一括 `sed` で機械的に消すと、句読点・括弧・コロンが壊れる**。**1箇所ずつ見て直すこと**
- ⚠️ **日付や経緯（`2026-09-08〜`・`2026-08-26判明 → 2026-08-30実装`）は残す**。
  消すのは**現在形の公開状態の主張だけ**
- ⚠️ **行750 は `):` で終わる**（表が続く）。**コロンを落とさない**

### 4-2. 測り方の案内（1箇所だけ）

⭐ **「git運用」節の中、`docs/` 例外の直前**に置く（公開の可否を判断する文脈がそこにあるため）。

⚠️ ⭐ **マーカーで囲う**（B2 がこのブロックだけを除外するため）:

⭐ **`CRON-ADD` と同じ置き方にする**——**`START` は先頭行の末尾／`END` は最終行の末尾**:

```markdown
- ⚠️ ⭐ **ある変更が本番に出ているかを、このファイルに書かない。** <!-- PUBSTATE-NOTE:START -->
  本番公開の経路は2つあり(push と `wrangler pages deploy`)、gitのブランチ状態から公開状態は導けない。
  ⭐ **測り方は `docs/design/待ち行列/待ち行列と復旧手順.md` §3**(本番位置 `P` を測り、
  `git merge-base --is-ancestor <実装のコミット> $P` で祖先判定する)。
  ⚠️ **ここに書いた状態は、次の公開で黙って誤りに変わる**(2026-08-31〜09-20 に10箇所が実際にそうなった)。<!-- PUBSTATE-NOTE:END -->
```

- ⚠️ ⭐ **マーカーを行頭に置かない。** CommonMark の HTMLブロック(type 2)に入り、**その行のMarkdownが死ぬ**
  （#70 で実際に踏んだ）。

  （**2026-09-20 に GitHub の `/markdown` API で実測**。`**強調**` が生のまま・`` `code` `` が `<code>` にならない）。
  ⭐ **だから本文を先に書き、マーカーはその行の末尾に置く**
  - ⚠️ ⭐ **1.0 の snippet はこれを破っていた**（`START` が行頭にあった）。実装 `195adc71` が正しい
- ⚠️ **文面に「未push」という語を使わない。** 使うと**自分の検査に引っかかる**

## 5. B2 の仕様

⭐ **`scripts/validate.mjs` の `LINEREF` 検査と同じ形**（真偽を検証せず、書き方そのものを禁止する）。
⭐ **マーカーの扱いは `CRON-ADD` 検査と同じ流儀**（出現数を数え、1組だけを許す）。

### 5-1. 判定

対象は **`CLAUDE.md` の1ファイルだけ**。`<!-- PUBSTATE-NOTE:START -->` 〜 `END` の**内側を除いた**各行について:

> **「未push」を含み、かつ次のいずれかを含む行**があれば **exit 1**
> — `本番にはまだ出ていない` / `本番にまだ出ていない` / `未公開` / `公開されていない` / `出ていません`

- ⭐ **「未push」を含まない行は見ない**（裁定①）
- ⭐ **否定語が無い行は見ない**——`push待ち` の目的説明
  （「**未pushの本番配信物が、issueを見ただけで分かる**」）は**正当な記述なので落としてはいけない**

### 5-2. fail-closed の条件（⚠️ **すべて exit 1**）

| 条件 | 理由 |
|---|---|
| `CLAUDE.md` が読めない | 走査対象の指定が陳腐化している（`LINEREF` と同じ） |
| マーカーが **0組** | 案内ごと消された＝受け皿が無いのに禁止だけ残る |
| マーカーが **2組以上** | 2組目に古い案内を残すと黙って通る（`CRON-ADD` の S1 と同型） |
| `END` が `START` より前 | 除外範囲が壊れている |
| マーカーが**行頭にある** | ⭐ Markdown が死ぬ（#70 の実測）。**見た目では気づけないので機械で止める**。⚠️ ⭐ **1.1 で定義を拡張**: 前置きから**空白とリスト/引用の記号（`-` `*` `+` `1.` `>`）を除いて何も残らなければ行頭とみなす**（`- <!-- START -->本文` も死ぬことを 09-20 に実測したため） |
| マーカー間が**空** | 案内の中身が消された |

### 5-3. 出力

```
成功: no publication-state claims in CLAUDE.md — 0件（注記ブロック1組）
失敗: PUBLICATION STATE CLAIMS (CLAUDE.md):
        - CLAUDE.md:640 — 未pushなので本番にはまだ出ていない
        → 公開状態はここに書かず、待ち行列 §3 の手順で測ってください（文言は下記の3点を含める）
```

失敗時のメッセージは次の3点を必ず含める:

1. **行番号つきで該当箇所を出す**（20件を超えたら先頭20件＋「…ほか N件」＝`LINEREF` と同じ）
2. `→ 公開状態は CLAUDE.md に書かないでください。経路②があるので、pushの状態から公開状態は導けません`
3. `  測り方は docs/design/待ち行列/待ち行列と復旧手順.md §3（本番位置 P を測って祖先判定）`

## 7. ⚠️ この設計が引き受けていない穴

- ⚠️ **ブラックリストなので言い換えれば抜けられる**（`LINEREF` と同じ性質）。
  ⭐ **狙いは「無意識に同じ形を書くこと」を止めること**で、意図的な回避は止められない
- ⚠️ **`docs/` は対象外**。設計書・工程記録は「その時点の実測」を書く文書なので、
  古くなっても誤りではない（⭐ `LINEREF` が `docs/` を除外しているのと同じ理屈）
- ⚠️ ⭐ **「公開済み」と書くことは禁止できていない。** 裁定①は「未push」を含む行だけを見るため、
  **`✅ 本番公開済み` とだけ書けば通る**。これも現在形の状態なので同じ型で腐りうる
  → ⭐ **A3 の案内（§4-2）で「書かない」と規約化するところまでが本設計の守備範囲**。
  機械で止めたくなったら別タスクにする（⚠️ **誤検出が跳ね上がるので安易に広げないこと**）
