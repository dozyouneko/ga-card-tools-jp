# issueの起票案 — マーカー間の除外にブロック長の上限が無く、`END` を動かすと検査が無言で緑になる

- ⭐ **起票時**: タイトル「マーカー間の除外にブロック長の上限が無い（`PUBSTATE-NOTE` / `CRON-ADD`）」／ラベル `bug` `小タスク` `検討中`
- 出所: 「未公開注記の陳腐化」のレビュー判定 `b4a892d0` の推奨指摘 **S-2**

## 1. 症状（2026-09-20 実測）

`scripts/validate.mjs` の `PUBSTATE-NOTE` 検査は、マーカーの**内側を除外**して各行を判定する。
⚠️ ⭐ **`END` マーカーをファイル末尾へ移すと、全行が「内側」になり、
禁止文言が10箇所に復活しても `npm run validate` が緑のまま通る。**

⚠️ **マーカーの個数検査（1組だけ）は通ってしまう**——個数は変わらないため。

## 2. ⚠️ これは新規の後退ではない

⭐ **既存の `CRON-ADD` 検査（#70）も同じ性質**（マーカー間から列挙を取るので、
`END` を動かせば取る範囲が変わる）。⚠️ **つまり2箇所に同じ穴がある。**

⭐ **だから「新しく入れた検査の欠陥」として直すのではなく、
マーカー方式そのものの扱いとして2つまとめて直すのが筋**。

## 3. ⚠️ 起こりやすさ

- ⭐ **偶然ではまず起きない**（`END` を意図的に遠くへ動かす必要がある）
- ⚠️ **ただしこのリポジトリが最も嫌う「無言で緑」の型**である。
  過去に同型（検査が空回りしたまま緑）を**複数回**踏んでいる
  （ハイライト検査の無言緑 / スマホ帯の素朴な集合検査 / 索引の転記ドリフト）

## 4. 選択肢

| 案 | 内容 | ⚠️ 損 |
|---|---|---|
| D1 | ブロックの**行数に上限**を設ける（例: 20行を超えたら exit 1） | 上限値の根拠が弱い。案内を長く書けなくなる |
| D2 | ⭐ **`START` と `END` が同じ節（直近の見出しまで）にあることを要求** | 実装がやや複雑 |
| D3 | 除外をやめ、**案内の文面が禁止語を含まないことを前提にする**（親タスクの裁定③を覆す） | ⚠️ 受け皿が消える。裁定③の理由3点を再検討する必要 |
| D4 | 何もしない（意図的な改変でしか起きないため） | ⚠️ 「無言で緑」が2箇所に残る |
