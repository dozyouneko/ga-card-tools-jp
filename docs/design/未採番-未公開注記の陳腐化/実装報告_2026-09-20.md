## 4. 設計書の想定との食い違い・逸脱

### 逸脱1（⚠️ **実測にもとづく・要確認**）: 案内マーカーの置き方を `CRON-ADD` 方式にした

設計書 §4-2 の字面は **`<!-- PUBSTATE-NOTE:START -->⚠️ ⭐ **ある変更が…**`**（START が本文の直前、行の先頭寄り）。
⚠️ **この形は GitHub の描画で Markdown が死ぬ**——`/markdown` API で実測した:

```text
入力: - <!-- M:START -->⚠️ **太字** と `コード` の行<!-- M:END -->
出力: <li>⚠️ **太字** と `コード` の行</li>    ← ⚠️ 強調もコードも生のまま
入力: - ⚠️ **太字** と `コード` の行 <!-- M2:START -->
出力: <li>⚠️ <strong>太字</strong> と <code>コード</code> の行 …   ← ✅ 生きている
```

⭐ **リスト記号 `- ` だけが前にある場合も、行頭と同じく HTMLブロック(type 2)に入る**（#70 の症状そのもの）。
→ **`CLAUDE.md` 内で実績のある `CRON-ADD` と同じ置き方**（START は先頭行の**末尾**・END は本文の末尾）に変えた。
⭐ **設計書 §4-2 の警告（「マーカーを行頭に置かない／Markdown が死ぬ」）の趣旨はこちらが満たす**と判断した。文面は変えていない。

### 逸脱2: 行頭判定を「リスト/引用の記号だけが前にある場合」まで広げた

上の実測どおり `- <!-- … -->` も死ぬため、検査の「行頭」を
**「前置きから空白と `- * + > 1.` を除いて何も残らない」**と定義した（V5 の追加1通り）。
⚠️ **禁止語の増減ではなくマーカー配置の検査**なので実装側で決めたが、**§5-2 の表より厳しい**ので §6 に挙げる。

### 逸脱3（体裁）: 案内の丸括弧を半角にした

設計書 §4-2 の snippet は全角 `（）`。置いた「git運用」節の周囲は半角 `()` で統一されているため**半角に合わせた**。語句は変えていない。

### 食い違いなし

- **10箇所という件数**・行番号（629/640/649/750/765/803/869/1229/1234/1285）とも設計書 §1-1 の実測と**一致**

- 禁止語は §5-1 の5語のまま。**追加も削除もしていない**
