## 3. 申し送りへの回答（リードからの2点）

### 3-1. 不変条件 (c)（辞書側の無言の緑）の追加はスコープとして妥当か → ⭕ **妥当**

- **手続き上**: (c) は**設計担当が設計書に明記して決めた**もの（D3・§2-4）で、実装はそれに従っている。
  ⭐ **開発担当が仕様を足したのではない**ので、M7（設計書に無い変更）には当たらない
- **中身**: 起票案が扱うのは①生成物側の無言の緑だが、**この検査の入力は①生成物と②辞書の2つ**あり、
  ②が壊れても**同じ症状（全ページ走査したのに hits が常に空 → exit 0）**になる。
  ⭐ V6′ で実測したとおり、**辞書の `jp` キーが変わっただけで検査が空回りし、それを捕まえる検査はほかに存在しない**
- **コスト**: `cores.length === 0` の比較1つ。閾値のハードコードなし（D7 を守っている）、実行時間への影響なし
- → **「同じ検査ブロックの、同じ型の穴を、同時に塞ぐ」もの**であり、設計意図の範囲内と判断する

### 3-2. V10 の外れ値（2664ms）を「誤差」とした判断 → ⭕ **妥当**

- ⭐ **自分で測り直して追認した**: 実装前後を同一条件で各5回並べた結果、**系統的な増加は無い**（§2 V10）
- ⭐ **構造的にもそうなる**: 追加処理は**すでにメモリ上にある同じHTML文字列に対する正規表現走査1本**で、
  **I/O は1バイトも増えていない**（ファイル読みは既存の1回のまま）。ページ数に比例する定数倍の増加しか起こり得ない
- 開発担当が挙げた原因（直前に2,498ファイルを `tar` 展開したためページキャッシュが冷えていた）も、
  1回目だけが高いという観測の形と整合する
- → **「1回だけ外れた値を、原因を切り分けて誤差と判断した」手続き自体が適切**（測り直しの記録も報告に残っている）
