## 1. 問題

**検索結果のタイルを 🔄 で裏面に切り替えてから ＋🖨️ を押すと、印刷リストには表面が入る。**

⚠️ **#46 の実装前から再現する既存バグ。** ただし **#46 が入ると目立つようになる** ——
いまは自分で 🔄 を押した人だけが踏むが、#46 後は日本語検索で裏面が一致したタイルが
**最初から裏面表示**になるため、そのまま ＋🖨️ を押した人が踏む。

### 1.1 原因

`app.js` の ＋🖨️ ハンドラは `cardEl.dataset.artUrl`（＝**表面の版**）しか見ていない。
🔄 のハンドラは `showingBack` を切り替えて `syncImg()` を呼ぶだけで `dataset.artUrl` を触らない。
＝ **表示中の「面」が追加処理に伝わっていない。**

### 1.2 ⭐ #42 の原則の漏れ

#42 で **「表示中のものがそのまま入る」** という原則を立て、**🎨（版）** については直した。
**🔄（面）についてだけ同じ漏れが残っている。** 本件はその穴埋めであって、新しい概念は増えない。

---

## 2. 器はすでにある（新しいデータ構造は要らない）

| 事実 | 場所 |
|---|---|
| 印刷リストの**同一性キーは画像URL** | `addToPrintItem`（`app.js:334-336`） |
| → **表面と裏面は別行として共存できる**（slugキーではないため合算されない） | 同上・#42 の設計 |
| 詳細モーダルには既に「🖨️ 裏面を印刷リストに追加」があり、`back.slug` で入れている | `app.js:648-656` |
| その版に裏面画像が無ければ**既定版の裏面に倒し、そのとき版ラベルは付けない**（実物と食い違うため） | 同上 |

→ **タイル側から呼び分けるだけ。** 保存形式（localStorage）の変更もマイグレーションも**不要**。

## 3. 影響範囲

- **`app.js` のみ。**
- ⚠️ **デッキ構築ツールとカード個別ページには印刷リストが無い**（実測で確認済み）。触らない
- ⚠️ **デッキ構築のゾーン追加（＋メイン等）は対象外**（ユーザー判断・2026-08-03）。
  `renderAddRow` は `card.slug` で入れており、両面カードは物理的に1枚なのでこれが正しい

## 4. 実装

### 4.1 状態変数を ＋🖨️ ハンドラより前へ出す

現状の `app.js` は次の順で書かれている:

```
1. cardEl.innerHTML = …                       （＋🖨️ ボタンを含む）
2. addBtn のイベント登録                       ← ここで面を知りたい
3. const artBadge / flipBadge / imgEl
4. if (imgEl && (artBadge || flipBadge)) {
     let ai = initialAi;
     let showingBack = false;                  ← 宣言がここ（2 から見えない）
     …
   }
```

**`ai` と `showingBack` の宣言を 2 より前へ移す**（ブロック内の `let` は消す）。

```js
// 表示中の「版」と「面」。⚠ ＋🖨️ も参照するため、ブロックの外で宣言する（#47）
let ai = initialAi;
let showingBack = startBack;   // startBack は #46 で導入。#46 未実装なら false
```

⚠️ **`if` ブロックの中に `let showingBack = false;` を残さないこと。**
残すと**内側が外側を隠し（シャドーイング）**、画像は裏返るのに ＋🖨️ は表面のまま —— という
**元の症状と見分けがつかない状態**になる。しかも例外は出ないので気づけない（検証 V9 がこの検査）。

### 4.2 ＋🖨️ ハンドラに面の分岐を足す

```js
addBtn.addEventListener("click", (e) => {
  e.stopPropagation();
  const artUrl = cardEl.dataset.artUrl || null;
  const cur = artUrl ? imgs.find((im) => im.url === artUrl) : null;
  // 表示中の「面」も反映する（#47）。規則は詳細モーダルの backAction と同一（app.js:653-656）:
  // その版に裏面画像が無ければ既定版の裏面に倒し、そのときは版ラベルを付けない（実物と食い違うため）
  if (showingBack && back) {
    const useSel = !!(cur && cur.back);
    addToPrintItem(back.slug, jpName(back), useSel ? cur.back : back.image, useSel ? cur.label : null);
    return;
  }
  addToPrint(card, artUrl, cur && cur.label);   // 従来どおり（表面）
});
```

- ⚠️ **`dataset.artUrl` は今までどおり「表面の版」を指したままにする。** これは 🎨 と ＋🖨️ の間の
  既存の伝達路で、裏面URLを入れると `imgs.find()` が引けなくなる（`imgs[].url` は表面のURLのため）
- ⚠️ **`backFace(card)` の `back` は既に上（`app.js:198`）で宣言済み。** 二重に取らない
- 裏面の行の名前は **`jpName(back)`**、idは **`back.slug`** —— モーダル経由で入る行と**同じ形**にする。
  ここを揃えないと、同じ裏面がモーダル経由とタイル経由で別行になる（画像URLが同じなら合算されるが、
  名前・idが食い違うと表示が不安定になる）

## 5. fail-open / 退行しないこと

| 経路 | 期待 |
|---|---|
| 両面でないカード | `back` が `null` → 従来どおり表面が入る |
| 画像が1版しかない両面カード | `artBadge` が無くても `flipBadge` はある → 分岐は効く |
| その版に裏面画像が無い | 既定版の裏面が入り、**版ラベルなし**（モーダルと同じ規則） |
| #46 未実装の状態で先にこれを入れた場合 | `startBack` が無いので `showingBack = false` 始まり ＝ **自分で🔄を押したときだけ効く**。単独でも成立する |
