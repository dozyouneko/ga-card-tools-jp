## 2. ⚠️ 起票案との食い違い（2026-09-24 に実測）

⭐ **起票案は「確定した事実」ではなく投函前の下書き**なので、主張を1つずつ実測した。**4点が実態と違っていた。**

### 2-1. ⚠️ 「いまは2つとも正しい（規則が一致している）」 — **半分だけ正しい**

⭐ **規則の本体（`findIndex` の5行）はバイト一致**している。`diff` で確認済み（`app.js` と `tools/deck-builder/app.js` の該当5行は完全一致）。
⚠️ **だがシグネチャと「条件の取り方」は既にずれている**:

| ファイル | シグネチャ | 条件の出どころ |
|---|---|---|
| `app.js`（トップ） | `preferredArtIndex(imgs)` | ⚠️ **関数の中で生DOMを読む**（`el.fSet.value` / `el.gRarity.getValues()`） |
| `tools/deck-builder/app.js` | `preferredArtIndex(imgs, artCond)` | ⭐ **引数で受ける**（`artCondOf(tab.cond)` が作る「そのタブの条件」） |

- ⭐ **ずれた原因は「検索結果のタブ化」（#85）**。左ペインの「いま」ではなく**タブごとに凍結した条件**で絵柄を選ぶ必要が生じたため、デッキ構築側だけが引数化された
- ⚠️ ⭐ **起票案の「コメントだけが同期を主張している」はもう当たらない。** 現在のデッキ構築側のコメントは
  **「この関数はトップと二重定義」「二重定義の解消は別タスク——トップ側は引数化していない」**と正直に書いてある
- ⭐ **つまり本タスクは「そろっているものを1本にする」のではなく、「半分だけ引数化された状態を最後まで進める」作業**

### 2-2. ⚠️ 「`init()` に1つ渡すだけで済む」 — **不正確**

デッキ構築の `openDetail()` の呼び出し元は **3種類**ある（起票案の影響範囲表には**検索結果タイルしか載っていない**）:

| 呼び出し元 | セレクタ | 版の絞り込み条件 |
|---|---|---|
| **A** デッキゾーンのタイル | `.gtile` | ⭐ **無い**（デッキに入っているカード） |
| **B** 検索結果タイル | `.result` の `.cardph` / `.rname` | ⭐ **そのタブの条件**（＝今回直す対象） |
| **C** 共有画面のタイル | `#v-zones .cardph` | ⭐ **無い**（読み取り専用の閲覧画面） |

⚠️ ⭐ **`init()` に「いまの絞り込みを読む関数」を1つ渡すと、A と C のモーダルまで検索条件に従ってしまう**——
**デッキに入っているカードの詳細が、左ペインの検索条件で別の絵柄になる**という**新しい不具合**になる。
→ **呼び出し元ごとに条件を渡し分ける**（§5 の D-3）。

### 2-3. ⭐ 起票案に無い発見 — **デッキゾーンのタイルは、もともとモーダルと絵柄が食い違っている**

デッキ行は選んだ版を `art_image` として**保存している**（`rowImageUrl()` がそれを表示する）。ところがモーダルは常に先頭の版で開く。
**2026-09-24 実測**（`art_image` に idx2 の版を保存した行）:

```text
gtile  idx=2   https://api.gatcg.com/cards/images/zRYKP4YYfx.jpg
modal  idx=0   https://api.gatcg.com/cards/images/ggliackmst.jpg   → 食い違う
```

- ⚠️ ⭐ **これは「版の絞り込みに追従しない」とは別の原因**（デッキが覚えている版を見ていない）。
  **#97 の範囲外**として扱い、§11 に派生候補として残す
- ⭐ **だからこそ A・C の挙動を変えてはいけない。** 変えるなら「絞り込み」ではなく「保存した版」に合わせるべきで、それは別の設計判断

### 2-4. ⭐ 起票案に無い発見 — 既存の UI規約検査① が `app.js` の **276行を見ていない**

`scripts/validate.mjs` の `stripJs`（コメント除去）は、**`app.js` の 60〜335行（276行 / 全917行の約30%）を丸ごと消している**。
原因は **60行目の行コメントに `data/tl/*.js` という文字列があり、その `/*` が 335行目のブロックコメントの `*/` と対になる**こと:

```text
次の /*     : 行60   「// 訳データ(#22 フェーズ2)。data/tl/*.js 38本の <script> をやめ、…」
対応する */ : 行335  「… } catch { /* 保存不可でも継続 */ }」
→ 誤って消える範囲: 60〜335 ＝ 276行
```

- ⭐ **今日は誤判定していない**（`onRemoveOne:` はその範囲に無い）が、⚠️ **その範囲に書けば検査をすり抜ける**
- ⚠️ ⭐ **本タスクに直接効く**: §6 の新しい検査で `stripJs` を再利用すると、**`app.js` の再定義を見落とす穴が最初から開く**
  → **§6 の検査はコメントを剥がさず生テキストで判定する**（根拠は §6-4）
- ⭐ **`scripts/validate.mjs` 側の是正は #97 の範囲外**。§11 に派生候補として残す

## 4. 設計判断

### 4-1. 共有先は **`shared/js/card-search.js`**（`card-i18n.js` ではない）

| 根拠 | 内容 |
|---|---|
| **① 依存の向き** | 条件の取り出しに **`setPrefixes()`** が要る。これは `card-search.js` にあり、⚠️ **`card-i18n.js` は先に読み込まれるので参照できない** |
| **② 「版レベルの絞り込み」の定義がある** | `MULTI` / `isIndexBlind` / `INDEX_BLIND_KEYS`（#93）が `card-search.js` にある。§6 の検査はここと突き合わせる |
| **③ 消費側の集合が一致する** | ⭐ **絞り込みUIを持つページ＝`card-search.js` を読むページ**（トップ・デッキ構築）。大会デッキページは読まないし要らない（§3-4） |

⚠️ **`card-i18n.js` に置くと ① で詰まり、`setPrefixes` を二重に持つことになる**（＝別の二重定義を作る）。

### 4-2. 引数の形 — **`cond` オブジェクトを受ける**（`els` を直接受けない）

```js
GA_CARD_SEARCH.artCondOf(els)            // → { prefixes: [...], rarities: [...] }
GA_CARD_SEARCH.preferredArtIndex(imgs, cond)   // → 番号
```

⭐ **2本に分けるのが必須**。理由:

- デッキ構築は**条件を凍結して持ち回る**（タブごと・`makeSearchCtl` の作成時に固定）。⚠️ **生の `els` を渡す形にすると凍結できず、
  「もっと見る」や裏のタブの絵柄が左ペインの「いま」で決まる**＝ V22 の不具合が戻る
- トップは凍結が要らないので、モーダルへ渡すときに `artCondOf(...)` をその場で呼ぶ

⭐ **`artCondOf(els)` は現在の両実装と完全に同じ値を返す**（実測で確認）:

| 呼び出し側 | 現在の書き方 | `artCondOf(els)` に渡すもの |
|---|---|---|
| トップ | `setPrefixes(el.fSet.value)` / `el.gRarity.getValues().map(String)` | `{ set: el.fSet, rarity: el.gRarity }` |
| デッキ構築 | `setPrefixes(setIndexOf(p.get("set")))` / `p.getAll("rarity").map(String)` | `condEls(tab.cond)`（**既存の関数がそのまま使える**） |

### 4-3. 規則は **項目表（`ART_COND`）のループ**にする

⚠️ **単に「今の5行をコピーして移す」だけにしない。** ⭐ **「版レベルの絞り込みが増えたときに1か所だけ直せばよい形」にする**のが本タスクの目的なので、
**`cond` のキー ↔ `imgs[]` の属性名**の対応表を1つ持ち、規則はそれをループする:

```js
// 版レベルの絞り込み＝「版(editions[])の属性で絞る条件」の唯一の定義。
// ⚠ 項目を足すときはここだけを直す。npm run validate が許可リストと突き合わせる(#97)
const ART_COND = [
  // [cond のキー, imgs[] の属性名, els のキー, els からの読み方]
  ["prefixes", "prefix", "set",    (els) => setPrefixes(val(els.set))],
  ["rarities", "rarity", "rarity", (els) => vals(els.rarity).map(String)],
];
```

⭐ **一般化しても選ばれる版は1つも変わらない**ことを、オフラインで全数確認済み（→ V1）:

```text
画像を持つカード            : 2,495 枚
突き合わせた (カード×条件)   : 18,911 組（条件なし／prefix単独／rarity単独／prefix∧rarity）
うち結果が 0 以外            : 5,648 組
旧実装と一般化案の不一致     : 0 件
```

⚠️ **等価になる根拠**（実装時に壊さないこと）: `cardImages()` は `prefix` に必ず文字列を入れる（無ければ `"?"`）ので `!= null` の判定を足しても挙動が変わらない。
`rarity` は `null` がありうるので **`!= null` の判定は必須**。

### 4-4. モーダルの条件は **呼び出し元から渡す**

`shared/js/card-detail.js` の `opts.preferredArtIndex(imgs)` は**引数1つ**なので、ページ側がクロージャを渡す。
デッキ構築は §2-2 の A/B/C を区別するため、**`openDetail()` の引数で条件を受け取り、A・C は渡さない**。

⚠️ **`shared/js/card-detail.js` は変更しない**（インターフェースは今のままで足りる）。

## 5. 変更内容

### D-1 / D-2: `shared/js/card-search.js` に2本追加して公開する

1. `ART_COND` 表（§4-3）と、それをループする **`preferredArtIndex(imgs, cond)`**
2. **`artCondOf(els)`** — `els` から `{prefixes, rarities}` を作る
3. `return {...}` に **`artCondOf` / `preferredArtIndex` / `ART_COND_KEYS`** を足す
   - `ART_COND_KEYS` は ⚠️ **配列リテラルを書き写さず `ART_COND` から導く**（`ART_COND.map(([,,elsKey]) => elsKey)`）。
     ⭐ **導出しないと §6 の検査が空回りする**（`INDEX_BLIND_KEYS` と同じ流儀）
4. コメントに**残すこと**: 「両方が有効なときは AND」「一致が無ければ先頭へフォールバック」「根拠は `editions`（`cardImages` 経由）だけ・`result_editions` を見ない（#44）」

### D-1b: `app.js`（トップ）から定義を消す

- `function preferredArtIndex(imgs) { … }` を**削除**
- タイル描画（`appendGrid`）: `preferredArtIndex(imgs)` → `GA_CARD_SEARCH.preferredArtIndex(imgs, GA_CARD_SEARCH.artCondOf(artEls()))`
  - ⭐ `artEls()` は `{ set: el.fSet, rarity: el.gRarity }` を返すだけの薄いもの（⚠️ **ページに残るのは「どの要素から取るか」だけ**）
- `GA_CARD_DETAIL.init({ preferredArtIndex, … })` → `preferredArtIndex: (imgs) => GA_CARD_SEARCH.preferredArtIndex(imgs, GA_CARD_SEARCH.artCondOf(artEls()))`
  - ⚠️ **トップはこれまでどおり「いまの絞り込み」を読む**（`#card/<slug>` のハッシュ直リンクでも同じ。既存挙動を変えない）

### D-1c: `tools/deck-builder/app.js` から定義とローカル `artCondOf` を消す

- `function preferredArtIndex(imgs, artCond) { … }` を**削除** → `GA_CARD_SEARCH.preferredArtIndex(imgs, artCond)` を呼ぶ
- ローカルの `function artCondOf(cond) { … }` を**削除** → `GA_CARD_SEARCH.artCondOf(condEls(cond))` を呼ぶ
  - ⭐ `makeSearchCtl()` は既に `condEls(tab.cond)` を作っているので、**1つの `els` を `create()` と `artCondOf()` の両方に使う**
  - ⚠️ **コメント「左ペイン（`#s-set` / `#s-g-rarity`）を読まない」は必ず残す**（この制約が消えると V22 が再発する）

### D-3: デッキ構築の詳細モーダルを、開いたタイルと同じ版で開く

1. `makeSearchCtl()` で作った `artCond` を **そのタブに持たせる**（`tab.artCond = artCond`）
   - ⭐ 成り立つ理由: `tab.cond` が変わる経路は `updateActiveSearchTab()` だけで、そこは **`tab.ctl` を作り直し `el.resultGrid` を空にして再検索する**。
     タブを切り替えても `restoreTiles()` が戻すのは**そのタブが自分の条件で描いたタイル**なので、`activeSearchTab.artCond` と常に一致する
2. `openDetail()` に条件を渡せるようにする:

   ```js
   // 詳細モーダルを開いたときの「版の絞り込み条件」。
   // ⚠ 検索結果タイルから開いたときだけ入る。デッキゾーン・共有画面は null（§2-2 の A・C）
   let detailArtCond = null;
   function openDetail(slug, artCond) {
     detailArtCond = artCond || null;
     GA_CARD_DETAIL.openBySlug(slug);
   }
   ```

3. 呼び出し元3種の書き分け:

   | 呼び出し元 | 書き方 |
   |---|---|
   | **A** `.gtile`（デッキゾーン） | `openDetail(slug)` — ⚠️ **変更しない** |
   | **B** `.result` の `.cardph` / `.rname` | `openDetail(slug, activeSearchTab && activeSearchTab.artCond)` |
   | **C** `#v-zones .cardph`（共有画面・クリックとキー操作の2か所） | `openDetail(tile.dataset.slug)` — ⚠️ **変更しない** |

4. `GA_CARD_DETAIL.init({ … })` に1行足す:

   ```js
   preferredArtIndex: (imgs) => GA_CARD_SEARCH.preferredArtIndex(imgs, detailArtCond),
   ```

## 6. 自動検査（`npm run validate` に1本足す）

### 6-1. ⚠️ #101 の字面検査はそのまま使えない

#101（0件文言）は **文言**の二重定義だったので「マーカーで囲んだブロックの静的断片が呼び出し側に現れないこと」で足りた。
