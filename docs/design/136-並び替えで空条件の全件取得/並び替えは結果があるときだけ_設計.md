## 1. 要件（⚠️ ユーザー決定。再検討しない）

> そもそも検索のソートは検索結果が表示された後に必要な機能なはず。検索する際は並び順は無視してよく、検索結果があるときのみ並び順が初めて有効となるのが望ましい。

| | 決定 |
|---|---|
| **原則1** | **🔍検索（と Enter）は並び順を無視する**＝新しいタブの条件に `sort` / `order` を含めない |
| **原則2** | **並び順が効くのは結果があるときだけ**＝結果が無いときは検索しない |
| **Q2** | ⭐ **結果が無い間は並び替え欄を使えない状態にし（a）、理由を文言で出す（c）** |
| **受け入れた代償** | ⚠️ ⭐ **R1**: 結果があって並び順が既定でない状態で 🔍 を押すと、**その並び順は捨てられる**（§7-1） |

### 1-1. ⭐ 「結果がある」の定義

⭐ **`activeSearchTab`（結果パネルの持ち主）が `null` でないこと。**
⚠️ ⭐ **「タブがある」でも「帯で選ばれている」でもない**（実測）:

| 場面 | タブ | 帯で選択 | `activeSearchTab` | ⭐ 結果があるか |
|---|---|---|---|---|
| デッキを開いた直後 | ⭐ **ある** | ない | **null** | ⭐ **無い** |
| 検索した後に 🃏デッキへ戻る | ある | ⭐ **ない** | ⭐ **非null** | ⭐ **ある**（⚠️ **ここを止めてはいけない**） |
| 持ち主のタブだけ × で閉じる | ⭐ **ある** | ない | **null** | ⭐ **無い** |

## 3. 変更内容（**3点 ＋ CSS 1点 ＋ HTML 1点**）

⚠️ **対象は `tools/deck-builder/` の3ファイルだけ。** ⭐ **`shared/js/card-search.js` は1行も触らない。**

### 3-1. 原則2 — `updateActiveSearchTab()` の冒頭

```js
function updateActiveSearchTab() {
  const tab = activeSearchTab;
  if (!tab) { return; }   // ← runNewSearchTab() をやめる
```

### 3-2. 原則1 — `runNewSearchTab()`

```js
function runNewSearchTab() {
  const p = new URLSearchParams(condFromForm());
  p.delete("sort"); p.delete("order");   // ⭐ 原則1: 検索は並び順を無視する
  const tab = addSearchTab(p.toString());
  selectSearchTab(tab);
}
```

⭐ **副産物（実測）**: `selectSearchTab()` → `applyCondToForm()` → **先頭の `resetSearchForm()`** が走るので、
⭐ **🔍 を押した瞬間に並び替え欄が「名前順 ▲昇順」へ戻る**＝ **無視されたことが表示で見える**（無言にならない）。

### 3-3. ⭐ UI — `syncSortControls()` を**1か所**に置き、**状態から毎回決める**

```js
function syncSortControls() {
  const on = !!activeSearchTab;          // ⭐ 出所はこれだけ（他の変数を見ない）
  el.sSort.disabled = !on;
  el.sOrder.disabled = !on;
  el.sortHint.hidden = on;
}
```

⚠️ ⭐ **呼ぶのは `syncSearchTabSelection()` の中の1箇所だけ。**
⭐ **理由**: `activeSearchTab` への代入は**5箇所**（宣言・タブ追い出し・`selectSearchTab`・`closeSearchTab`・`clearSearchTabs`）あるが、
⭐ **そのすべてが `syncSearchTabSelection()` を通る**（直接、または `renderSearchTabs()` 経由）。

- ⚠️ ⭐ **個々のハンドラに `disabled = …` を書かないこと。** 設計担当自身が挙げた懸念
  「**4つの null 経路と同期漏れで永久に押せない**（より悪い壊れ方で、検査は無い）」はこの形でだけ防げる。
  ⭐ **`syncSearchTabSelection()` が「aria-selected と見た目を1か所で書く」と同じ流儀**（既存コメント参照）。
- ⚠️ ⭐ **`disabled` は見せ方であって、挙動の保証ではない。** **§3-1 のガードは必ず残す**
  （実測: `disabled` を実行時に外して `change` を起こしても **リクエスト0・タブ0**＝ガードが効いている）。

### 3-4. CSS — `tools/deck-builder/style.css` の末尾に2本

```css
/* #136: 結果が無い間の並び替え欄。⚠️ .btn:disabled の cursor:progress（読み込み中）を打ち消す */
.result-sort select:disabled, .result-sort button:disabled { cursor: not-allowed; opacity: .55; }
#sort-hint { margin: -4px 0 8px; font-size: .72rem; color: var(--muted); }
```

⚠️ ⭐ **この2本を書かないと、昇降順ボタンのカーソルが `progress`（読み込み中）になる**（既存の `.btn:disabled`）。
⭐ **同ファイルに先例あり**（`.result .addrow button:disabled { … cursor: not-allowed }`）。
⚠️ ⭐ **`:root` を足さないこと**（`npm run validate` の検査(ii) が exit 1 にする）。⭐ **直値の色も書かない**（検査(iii)）。

### 3-5. ⏳ HTML — `tools/deck-builder/index.html` の `.result-sort` の直後

```html
<p id="sort-hint" hidden>検索後に使えます</p>
```

⚠️ ⭐ **文言はモックの確認（M1）待ち。** ⭐ **W5「検索後に使えます」を既定案にしている**が、
**W1（文言なし）／W2・W3（ラベルに付ける）／W4（別行・長い）**も選べる（→ モック説明 §3）。
⚠️ ⭐ **W2 / W3 を選んだ場合は `<p id="sort-hint">` を足さず、ラベルの文言を差し替える形になる**（変更箇所が変わる）。

## 7. 残る問題と裁定（⭐ **設計担当が裁定した3件**）

### 7-1. ⚠️ R1 — **仕様として受ける**（ユーザーが Q1 で承知のうえ選択）

⭐ **無言ではない**（条件の箱もコントロールも「名前順」に変わる）。⭐ **取り戻すのは1操作**（もう一度選ぶ＝2req で効く）。

### 7-2. ⭐ R2 — **保存タブ経由の50ページは仕様として明記する**

⭐ **実測: 保存タブの条件が `sort=level`（絞り込みなし）だと、押したときに13req（50ページ）**＝ **HEAD と同じ。**

- ⭐ **変更後もこのタブは作れる**: 条件なしで 🔍（1req・24枚）→ 並び替えをレベルに（**結果があるので効く**＝全件取得）→ 保存される。
- ⭐ **これは「全カードをレベル順で見たい」とユーザーが明示的に頼んだ場合のコスト**＝ **#44 の想定どおり**で、**トップページと同じ**。
- ⭐ **#135 のおかげで、復元されたタブは押すまでリクエストを投げない**（開いた瞬間には走らない）。
- ⚠️ ⭐ **「0件になった」と書かないこと。**

### 7-3. ⭐ R3 — **検査は足さない**（#94 §5-7 と同じ裁定）

- ⚠️ **字面の検査は迂回できる**（実測済み: `runNewSearchTab` の中身をインライン展開すると**関数内の出現0のまま挙動が戻る**）。
- ⚠️ **`p.delete("sort")` を消すのも1行**で、**`npm run validate` は緑・生成物の差分も出ない**。
- ⚠️ **行動で測るには `tools/deck-builder/app.js` 用の DOM ハーネスが要る**（`app.js` はトップレベルで DOM を触るので `vm` に載らない）＝ **別の設計**。
- ⭐ **ただし #94 と違い、戻すと「🔍 が 1req → 十数req」に戻る＝ユーザーが体感する**（#136 はそうやって見つかった）。
- ➡️ ⭐ **裁定: 検査は足さない。`CLAUDE.md` の「外すと静かに壊れる対策」に1項目足す**（§3-3 の「1か所に集約」と §3-4 の CSS 2本）。
