## 4. 差分が設計書の想定と食い違った点（内訳と根拠）

### 4-1. `build:cards` の差分に**公式API側のドリフトが80ファイル**混ざった → **分離して除外した**

`build:cards` の初回実行で **202ファイル + 新規1枚**の差分が出た。設計書の想定（サブタイプ94枚＋カウンター語のカード）より大幅に多い。
⭐ **原因はアカウント停止で日次cronが2日以上止まっており、その間の公式APIの更新（主に `rule`＝公式裁定の追加）が
生成物に一気に載ったため**（#71 と同型。ただし #71 は `editions` の並び替え、今回は**裁定の追加**が主）。

**切り分け方法**（実行時ドリフトを構造的に排除するため、**同じスナップショットで2回ビルドして比較**した）:

1. 現在の変更込みでビルド（**B**）→ 全生成物のSHA1を記録
2. `data/` の変更だけを `git checkout` で HEAD に戻し、**`GA_SNAPSHOT_MAX_AGE_MIN=0`** で再ビルド（**A**）→ SHA1を記録
3. 変更を戻して再ビルド → **Bと1バイト差なく再現することを確認**（＝ビルドは決定的）
4. **A≠B のファイル＝本タスクに起因**（123件） / **HEAD≠A のファイル＝APIドリフト**（81件）

| 区分 | 件数 | 扱い |
|---|---:|---|
| **本タスク起因** | **123** = 新サブタイプを持つカード **94** ＋ カウンター語15種を使うカード **29** | ✅ **コミットした**（設計書の想定と一致） |
| **APIドリフトのみ** | **80**（カードページ70 + `cards/index.html` + セットページ8 + `sitemap.xml`） | ⚠️ **`git checkout` で戻した**（コミットに含めない） |
| **新規カード** | **1**（`cards/jinzhuo-bands-of-virtue/` — API に新規追加された未訳カード） | ⚠️ **削除した**（未追跡のまま残さない） |
| **分離不能（混在）** | **1**（`cards/radiant-origin-of-warrior/index.html`） | ⚠️ **コミットに含まれる**（下記） |

⚠️ **`cards/radiant-origin-of-warrior/index.html` だけは1ファイル内で混在**しており分離できなかった。
混ざった無関係な差分は **公式裁定1件（2026-08-16 `attacks using -> wields`）と、それに伴う `description` メタの
「収録セット」→「収録セット・裁定」の変化**のみ。⭐ **cronが復旧すれば同じ内容を自動で入れる差分**であり、
先に入っても不整合は起きない。

⭐ **123件の内訳がV0の実測（サブタイプ94枚 / カウンター語を使うカード29枚 = 9+4+3+2+1×11）と完全一致**しており、
「本タスク起因」の切り分けが正しいことの裏づけになっている。
