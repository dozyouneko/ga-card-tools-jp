## 1. 症状

`npm run validate` の検査 **`card term highlights up to date — 2495 ページ`** は、
**効果節のマークアップが変わると1つも節を走査しないまま緑を出す**。

- **該当**: `scripts/validate.mjs:437`

  ```js
  const SECTION = /<h2>効果（日本語）<\/h2><p class="cp-effect">([\s\S]*?)<\/p>/g;
  ```

- **失敗シナリオ（レビュー担当が実測）**: あるページの `<p class="cp-effect">` を
  `<p class="cp-effect" data-x="1">` に変え、**同時に `term-hl` を1つ剥がしても**
  → `card term highlights up to date — 2495 ページ` / **exit 0**
- **原因**: `pages++` は**ファイルを読めた時点**で加算され、`scan()` が節を1つも取れなくても
  `hits` が空になるだけなので `missed` が空のまま success 分岐に入る
  （`scripts/validate.mjs:466` 付近）

## 2. なぜ直す価値があるか

⚠️ ⭐ **この検査は「静かな劣化を止める」ために入れたものなのに、検査自身が静かに無効化される。**

- 検査が本来止めたい事象は3つ（設計書 §5-1）: ① `matchedTerms()` の回帰
  ② **用語や訳を足したのに `build:cards` を回していない** ③ ハイライト実装のデグレ。
  **①〜③のどれが起きていても、テンプレートが変わった瞬間に全部が緑になる**
- ⚠️ **テンプレート変更は「いつか起きる」ではなく「起きる予定がある」**。
  `docs/design/未採番-UI刷新の検討/` がカードページの見た目に手を入れる可能性を持っており、
  そのとき**効果節の `<p>` に属性やクラスが1つ増えるのはごく自然な変更**である
- ⭐ **`meta.subtypes` 検査（#40型）や `data/tl-*.json` の陳腐化検査と違い、
  この検査だけが「生成済みHTMLの字面」を入力にしている**＝入力が壊れやすい

## 3. 直し方（設計方針・**実測値つき**）

⭐ **不変条件を2つ足す。どちらも「数えて比べる」だけでハードコードした期待値を持たない。**

| # | 不変条件 | 今日の実測値 | 何を捕まえるか |
|:--:|---|---|---|
| **(a)** | **各ページで節が1つ以上取れること**（0のページは slug を名指しで報告して `problems++`） | 節が0のページ **0 / 2,495** | 見出し文言の変更・`<p>` の属性追加など**全面的な破れ** |
| **(b)** | **走査できた節の数が、`<h2>効果（日本語）</h2>` の出現数と一致すること** | **2,517 = 2,517**（ページ 2,495 ＋ 裏面 22） | ⭐ **裏面だけ／一部ページだけ**の破れ（(a) では通ってしまう） |

- ⭐ **成功メッセージに節の数も出す**: `card term highlights up to date — 2495 ページ / 2517 節`
  （次に誰かがテンプレートを変えたとき、**赤くならなくても数字で気づける**）
- ⚠️ **`2517` や `2495` を定数で書かない。** 裏面の枚数は公式APIに両面カードが増えれば動く
  （現在22件）。**(b) は同じHTMLから2通りに数えて突き合わせる**ので、増減に自動追従する

### 3-1. ⭐ (a) が成り立つ構造上の根拠（＝false red にならない理由）

`scripts/build-card-pages.mjs:411` の `effectSections()` は、**日本語の節を無条件に出す**
（英語原文の節だけが `face.effect ? … : ""` で条件付き）。呼び出しは
表面 `:534`・裏面 `:496` の2箇所。**訳が空のカードでも節そのものは必ず出る**ため、
「1ページに最低1節」は現在の生成器の構造から保証されている。

⚠️ **逆に言えば、日本語の節を条件付きにする変更が入ると (a) が赤くなる。それが狙いである**
（意図した変更なら、**同じコミットで検査も直す**のが正しい）。

## 4. 検証項目（案）

⚠️ **「無傷で緑」だけでは足りない。壊して赤くなることを見る**（＝破壊試験）。

| # | 壊し方 | 期待 |
|:--:|---|---|
| V1 | 無傷 | **緑**・`… — 2495 ページ / 2517 節`・exit 0 |
| V2 | 1ページの `<p class="cp-effect">` に属性を足す（＋`term-hl` を1つ剥がす） | ⭐ **exit 1**。⚠️ **現状はここが緑になる**（本issueの主症状） |
| V3 | `<h2>効果（日本語）</h2>` の文言を全ページで変える | **exit 1**（(a) が 2,495ページを名指し） |
| V4 | **裏面の節だけ**を壊す（`lu-bu-indomitable-titan` 等の2つ目の節） | **exit 1**（(b) が 2516 ≠ 2517 を検出） |
| V5 | 既存の3通りの壊し方（レビュー判定 §2 の M5 表）が**引き続き赤い** | 変更前生成物=139ページ / `term-hl` 1つ剥がす=1ページ / 辞書に用語追加＋未再生成=750ページ |
| V6 | 実行時間 | 現状 **1.78秒** から目立って伸びないこと（節・見出しの計数は読み込み済み文字列への `matchAll` のみ） |

## 6. ⚠️ 申し送り（順序）

⭐ **カードページのテンプレート（効果節のマークアップ）を変えるタスクより前に、この対応を入れる。**
順序が逆になると、テンプレート変更のレビューで `validate` が緑を返し、
**「回帰していない」根拠として使われてしまう**。
