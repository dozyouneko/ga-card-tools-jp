## 6. ⚠️ 開発担当への申し送り（実装上の落とし穴・**H1〜H9 の9点**）

⭐ **すべて設計中に実測して踏んだもの。**「知っていれば避けられる」種類の失敗なので、着手前に読むこと。

| # | 落とし穴 | 正しいやり方 |
|---|---|---|
| **H1** | ⭐ **候補の絞り込みで「採用済みを先に全部占有」と実装しない** | **採用済みと候補を混ぜて中核語の長い順**に占有する。先に全部占有すると `shadowstrike` で「プレパレーション」（採用済み・8文字）が「プレパレーションカウンター」（候補・13文字）を**食う**（実測 154件/139枚＝**1枚落ちる**） |
| **H2** | ⭐ **占有判定そのものを省かない** | 省くと対象が **140枚 → 255枚**（288件）に膨らむ。「フローティングメモリー」に覆われた「メモリー」まで用語解説に並ぶ |
| **H3** | ⭐ **カード名（`CI.jpName`）の出現を潰してから照合する** | 潰さないと **140枚 → 157枚**（172件）。「雪のフラクタル」→ `fractal` のような**名前由来の誤検出**が入る（`highlightCardName()` が先に保護する領域なので、**ハイライトは出ないのに用語解説だけ増える**） |
| **H4** | ⭐ **検出経路の実装で `grep 'term-hl">核'` の形で書かない** | **型⑤で0件になる**（`subtype-hl` が内側に入って文字列を割るため）。**タグを走査して `term-hl` の内側かどうかを判定する** |
| **H5** | ⭐ **カード名（`card-name-hl`）の内側も除外する** | しないと「雪のフラクタル」「魂の装填」「メモライト・オベリス」などが誤検出される（`bifurcating-fractal` の罠） |
| **H6** | ⚠️ ⭐ **`n += await readFile(...)` と書かない** | `+=` は await の**前**に左辺を読むため、並列実行すると集計が壊れる。**設計中に実際に踏み、読み取りバイト数が 16.2MB → 2.0MB に化けた**。`const s = await readFile(...); n += s.length;` と2行に分ける |

### その他の実装上の注意

- ⚠️ **`scripts/validate.mjs` は現在すべて同期処理**。新検査は非同期（並列読み込み）で書くため、
  **ESMのトップレベル `await`** を使い、既存の `problems++` / 末尾の `if (problems > 0) process.exit(1)`
  の枠組みに乗せること
- ⚠️ **効果（日本語）の節は1ページに複数ある**（両面カードは裏面にも同じ節が出る）。**全部走査する**
- ⚠️ **`applyOutsideSpans()` の正規表現は `.*?</span>` の非貪欲一致**なので、**入れ子の無い span にしか使えない**。
  `card-name-hl` と `term-hl` はこの時点でどちらも入れ子を含まないため安全。**関数の呼び出し順を入れ替えないこと**
- ⚠️ **1回目の `applyOutsideSpans`（`highlightTerms` を掛ける側）は変更しない**（その時点で `term-hl` は存在しない）
- ⚠️ **`grep -c` を使わない**（行数を数える）。`grep -o … | wc -l` で数える
- ⚠️ **用語解説の括弧は全角**（`ヒット時（On Hit）`）
- ⚠️ **コミットは担当パスを明示する**（`git add -A` 禁止）。設計担当が `docs/` を触っているので、
  `git status --short` で自分の担当外の変更を巻き込んでいないか確認する
- デッキ構築ツール（V13）の検証は CLAUDE.md の標準手順を使う（`#view-editor` の `hidden` を外し、
  ⚠️ **空のデッキ状態を用意してから**ページ本来の `searchCtl` を動かす。用意しないと
  `deckData.cards` が null で落ちる）
