## §E. ⚠️ push（**ユーザー判断**）— ⭐ **cron再開より前に**

### E-1. なぜ順番が重要か

⚠️ **未pushのまま日次cron（03:00 JST）が先に走ると、cronが `origin/main` の
「フレーバー修正が入っていないコード」で `cards/**` を再生成してコミットする。**
その後に `git pull --rebase origin main` すると、**`a7125896` の `cards/**` 495ファイルと
cronのコミットが同じファイルで衝突する**（実際、`a7125896` に混ざった14ファイルはその重なりの実例）。

→ ⭐ **復旧した日のうちに push の可否を判断すると衝突を避けられる。**

### E-2. 現況（2026-08-26 時点）

| 項目 | 値 |
|---|---|
| 未pushコミット | **33件** |
| `docs/` 配下の変更ファイル | 15 |
| ⚠️ **`docs/` 以外（＝本番配信物）** | **772ファイル** |

⚠️ **`docs/` だけを送る例外は使えない**（`git diff --stat origin/main..HEAD -- . ':(exclude)docs/*'` が
772ファイルを出す）。⚠️ **`CLAUDE.md` もルート直下＝配信物**なので例外に含まれない。

### E-3. 手順


## 新規: フレーバーテキストが `editions[].flavor` にあるカード473枚で、原文が一切表示されない

- **ラベル**: `bug` / `着手可`（規模は要見積り）
- **⚠️ #73 のスコープ外**（和訳ではなく**表示経路**の問題）。PRD以外の既存カードにも及ぶ

### 症状（2026-08-19 実測）

カードページ（`scripts/build-card-pages.mjs:368`）も詳細モーダル（`shared/js/card-detail.js:237`）も
**`(t && t.flavor) || card.flavor`** で、**`editions[].flavor` を一切見ていない**。

| 状態 | 枚数 |
|---|---:|
| 正常に表示 | 726 |
| ⚠️ **原文フレーバーが存在するのに一切表示されない** | **473** |
| ⚠️ **空の `<p class="cp-flavor"> </p>` が描画される** | **2**（`zinn-volnia-abbess` / `virgil-altered-future`） |

- ⭐ **同じ「未訳」でも表示が割れる**: フレーバーがトップレベルにあれば英語原文が出るのに、
  `editions[]` 側にしか無いと**何も出ない**
- ⚠️ **和訳を入れると出るようになる**ため露見しにくい。#73 バッチ2で96枚のフレーバーが
  表示されるようになったのは**訳を入れたからで、経路が直ったわけではない**
- 実例: `zinn-volnia-abbess` は `card.flavor` が `" "`（空白）で `editions[0].flavor` に
  `“If the price of brilliance is to burn, then so be it.”` があるが、**空の枠だけが出ている**

### 直し方（両方の消費側を同じ形に）

```js
const pick = v => (typeof v === "string" && v.trim()) ? v : "";
const flavor = pick(t && t.flavor) || pick(card.flavor)
  || (card.editions || []).map(e => pick(e.flavor)).find(Boolean) || "";
```

⚠️ **空白のみを falsy として扱う**こと（`||` だけでは `" "` を拾って空の枠が出る）。
⚠️ **消費側は2箇所**（`build-card-pages.mjs` / `card-detail.js`）。**両方直さないと画面で食い違う**。

### ⚠️ 影響の見積りが要る

修正すると**473枚のカードページに英語フレーバーが新たに出る**（＝生成物の差分が473ファイル）。
**日本語サイトに英語原文を出すことの是非**を先に決める必要がある（出さない選択もあり得る）。
⭐ その場合でも **空の `<p>` 2枚は直すべき**。
