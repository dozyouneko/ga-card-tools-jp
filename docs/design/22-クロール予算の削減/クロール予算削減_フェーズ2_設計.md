## 実測(2026-07-26・本番実物)

### ⚠️ フェーズ1の「1.28 MB」は非圧縮値。gzip転送は 299.7 KB

トップページが読む `<script>` **45本**を1本ずつ取得して実測:

| 区分 | 本数 | 非圧縮 | **gzip転送** | 全体比(gzip) |
|---|---|---|---|---|
| **`data/tl/*.js`** | **38本** | 1,162.1 KB | **257.0 KB** | **85.8%** |
| `shared/js` | 5本 | 62.1 KB | 22.6 KB | 7.5% |
| `data/translations.js` | 1本 | 32.8 KB | 10.2 KB | 3.4% |
| `app.js` | 1本 | 28.2 KB | 9.9 KB | 3.3% |
| **合計** | **45本** | **1,285.2 KB** | **299.7 KB** | 100% |

gzip後でも **`data/tl` が86%**を占める。**削減対象の特定はフェーズ1の見立てどおりで正しい。**

gzip転送量の大きい順: `rdo.js` 52.0 KB / `hvn.js` 15.8 KB / `alc.js` 14.2 KB / `dtr.js` 14.2 KB / `amb.js` 13.4 KB …

### 深いページは軽い(だから入口を通せば連鎖する)

| ページ | HTMLサイズ | `<script>` | 内部リンク |
|---|---|---|---|
| `/` | 9.8 KB | **46本** | → `/cards/` `/tournaments/` `/tools/*` |

⚠️ **生成物(`cards/` `sets/` `tournaments/`)は `data/tl` を実行時に読んでいない**
(ビルド時に `loadPageI18n` で埋め込み済み)。**本フェーズの影響を受けるのは実行時に読む2ページだけ**:

- `index.html`(38本)
- `tools/deck-builder/index.html`(38本)

### 分割候補のサイズ(実データ2,262エントリで実測)

| 候補 | 生 | **gzip** |
|---|---|---|
| **現状** `data/tl/*.js` 38本(EN原文コメント込み) | 1,162.7 KB | **259.4 KB** |
| 候補1: 全部を1つのJSONに(name+effect・コメント除去) | 861.8 KB | **144.4 KB**(−44%) |
| **候補2a: 名前だけ** | 96.2 KB | **41.2 KB**(**−84%**) |
| 候補2b: 効果だけ | 786.8 KB | **120.5 KB** |
| 候補3: 効果を検索用の正規化テキストのみに | 776.9 KB | 119.3 KB |

- 候補3(正規化テキスト)は候補2bとほぼ同サイズ(119.3 vs 120.5 KB)で**表示用テキストを失う**だけなので**却下**

## 初期表示に何が必要かの確定(コードで確認)

`GA_I18N.cards` へのアクセスは **`card-i18n.js` の `tr(card)` 1箇所に集約**されている
([card-i18n.js:37](../../../shared/js/card-i18n.js#L37))。用途別に整理すると:

| 用途 | 必要なもの | タイミング |
|---|---|---|
| **グリッド描画**(`appendGrid`) | **名前のみ**。`jpName()` / `isTranslated()` / `label()`(= `I18N.meta`) | **初期表示** |
| カード詳細ダイアログ(`card-detail.js:94,196`) | **効果** | **クリック時** |
| 日本語**名前**検索(`localJpSlugs` の name 側) | 名前のみ | 検索時 |
| 日本語**効果**検索(`localJpSlugs` の effect 側) | **効果** | 効果欄に日本語を入れたときだけ |

✅ **グリッドに効果テキストは1文字も描いていない**([app.js:189-197](../../../app.js#L189))。
描いているのは `jpName` / 英語名 / タイプ・レベル・エレメントのチップ(`I18N.meta` 由来)のみ。

→ **効果テキスト(gzip 120.5 KB = 全体の40%)は初期表示に不要**であり、遅延できる。

## 設計

### 変更1: `data/tl/*.js` 38本を2つのJSONに分割する

| 生成物 | 内容 | 読み込み方 | gzip |
|---|---|---|---|
| **`data/tl-names.json`** | `{ slug: 名前 }`(訳が存在する全slug。名前が空欄なら `""`) | **初期表示前に1回 `fetch`** | **41.2 KB** |
| **`data/tl-effects.json`** | `{ slug: 効果 }` | **遅延 `fetch`**(下記の2契機のみ) | 120.5 KB |

- `data/translations.js`(`terms` / `meta`・gzip 10.2 KB)は**そのまま `<script>` で残す**。
  小さく、`label()` が同期的に必要で、分割の費用対効果が無い
- **`data/tl/*.js` は人間が訳を書く原本として残す**(削除しない)。JSONは**そこから生成する**
- ⚠️ **生成物には `generated_at` のようなタイムスタンプを入れない**(決定的な出力にする)。
  [#29](https://github.com/dozyouneko/ga-card-tools-jp/issues/29) で `card-meta-index.json` の
  `generated_at` が cron 化の障害になっている。同じ轍を踏まない

**生成スクリプト**: `scripts/gen-tl-json.mjs`(新規)。既存の
[`scripts/lib/page-i18n.mjs`](../../../scripts/lib/page-i18n.mjs) の `loadPageI18n()` を使う
(`index.html` の `<script src="data/…">` の並びを読むため、**ブラウザと同じマージ順・同じ集合**になる。
#27 の索引生成と同じ手法)。

- 出力対象は **`name` か `effect` のどちらかが埋まっているslugのみ**
  (空欄スキャフォルドは「未訳」として除外。現在は空欄0件だが将来のために明示する)
- 名前が空欄で効果だけあるエントリも **`tl-names.json` に `""` として載せる**(理由は変更3)

### 変更2: 読み込みを `<script>` から `fetch` に変える

`index.html` / `tools/deck-builder/index.html` から **`data/tl/*.js` の 38行を削除**し、
`GA_I18N.cards` を JavaScript から埋める。

```js
// shared/js/card-i18n.js(または新規の小さなローダ)
// 名前: 初期描画の前に必ず解決させる。効果: 必要になった最初の1回だけ取得してメモ化する
let namesPromise = null, effectsPromise = null;

function loadNames(url) {
  if (!namesPromise) {
    namesPromise = fetch(url).then((r) => (r.ok ? r.json() : null)).catch(() => null)
      .then((map) => {
        if (!map) return null;
        I18N.cards = I18N.cards || {};
        for (const slug in map) {
          (I18N.cards[slug] = I18N.cards[slug] || {}).name = map[slug];
        }
        return map;
      });
  }
  return namesPromise;
}

function loadEffects(url) { /* 同型。既存エントリに .effect をマージする */ }
```

- **`I18N.cards` の形は変えない**(`{ slug: { name, effect } }`)。`tr()` も `jpName()` も
  `card-detail.js` も**そのまま動く**。差分を小さく保つのが要点
- **効果の遅延取得の契機は2つだけ**:
  1. `GA_CARD_DETAIL.open(card)` の先頭で `await loadEffects()`
  2. `card-search.js` の `localJpSlugs()` — **効果欄に日本語が入っているときのみ**
     (`jpEffectQuery() !== ""`)。名前だけの日本語検索では取得しない
- ⚠️ **`localJpSlugs()` は同期関数**。効果を待つ必要があるため `run()` 側で await する。
  **#27 で `metaIndex()` を `run()` 内で await する形を既に導入済みなので、同じ場所・同じ流儀で足せる**
- URLは呼び出し側から渡す(トップは `data/…`、デッキ構築は `../../data/…`)。
  **#27 の `metaIndexUrl` と同じ方式に揃える**
- `_headers` は変更不要(`/*` の `connect-src 'self'` で同一オリジンfetchは許可済み)

### 変更3: `isTranslated()` を「エントリの存在」で判定する

現在: `!!(t && (t.name || t.effect))`([card-i18n.js:43](../../../shared/js/card-i18n.js#L43))。

名前だけ読み込んだ状態では、**名前が空欄で効果だけ訳されているカードが「未翻訳」と誤表示される**。
生成側で「name か effect のどちらかが埋まっているslugのみ」を出力するので、
**エントリの存在＝訳が存在する**が成り立つ:

```js
function isTranslated(card) { return !!tr(card); }
```

⚠️ **実データでの現状は名前が空欄のエントリ0件**(2,262件すべてに名前あり)なので**今すぐの表示差は無い**。
将来の破綻を防ぐための変更。

### 変更4: 残る `<script>` に `defer` を付ける

分割後に残るのは **7本**(`data/translations.js` / `shared/js` 5本 / `app.js`)。
現在は全部が同期読み込みで、`<main id="grid">` は空配信のため**全部読み終わるまで何も出ない**。

- `defer` は**HTMLパースをブロックしない**うえ**記述順の実行順を保つ**ため、
  `GA_CARD_I18N` → `GA_CARD_SEARCH` → `app.js` の依存順は維持される
- ⚠️ ただし `app.js` が **`DOMContentLoaded` を待たずにDOMを触っていないか**を確認する必要がある
  (`defer` は DOMContentLoaded 前に実行されるので通常は問題ないが、実装を見て確認する)

### 変更5: 生成物の陳腐化を `npm run validate` で検出する

**JSONは `data/tl/*.js` から生成するため、訳を追記して再生成を忘れると新しい訳が反映されない。**
[#29](https://github.com/dozyouneko/ga-card-tools-jp/issues/29) と同じ問題を持ち込むことになる。

→ **`scripts/validate.mjs` に「`data/tl-*.json` が `data/tl/*.js` と一致するか」の検査を追加する。**

- 不一致なら**エラーで落とし**、`node scripts/gen-tl-json.mjs` の実行を促すメッセージを出す
- 検査は `loadPageI18n()` で組み立てた結果と JSON を突き合わせるだけで、**オフラインで完結**する
  (ネットワーク不要。#27 の索引生成と違い公式APIを叩かない)
- ⚠️ **こちらは #29 と違い「気づけない」問題にならない**。訳の追記者は必ず `validate` を通る運用にできる

## 期待効果

| 項目 | 現状 | フェーズ2後 | 差 |
|---|---|---|---|
| トップの `<script>` 本数 | **45本** | **7本** | −38本 |
| 初期表示の**gzip転送量**(JS+JSON) | **299.7 KB** | **約 83.9 KB** | **−72.0%** |
| 初期表示の非圧縮量 | 1,285.2 KB | 約 219 KB | −83% |
| 効果テキスト(gzip 120.5 KB) | 常に読む | **必要時のみ** | — |

**クロール予算への意味**: #22 の当初調査で Google の10日間の総ダウンロード量は **1.88 MB**。
入口のコストが 299.7 KB → 83.9 KB になれば、**同じ予算で 3.5〜3.6倍のページを取得できる**。
`/cards/`(→ 56セット → 2,240カード)へ進む余地を作ることが本フェーズの目的。

⚠️ **これはクロール予算が本当にボトルネックである場合の効果**で、予算配分は観測できない。
効果測定は **GSCのクロール統計(検出%・合計DL量)** を push 後に継続観察する。
