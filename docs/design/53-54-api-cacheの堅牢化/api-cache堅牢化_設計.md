# #53・#54 `tmp/api-cache/` の堅牢化 — 設計

⚠️ **本設計書は #53 と #54 の両方を対象とする。** 直すのは同じ2ファイルで、
片方だけ直すと同じ場所をもう一度触ることになるため、**1回の実装でまとめて閉じる**。

## 改版履歴

| 版 | 日付 | 内容 | 状態 |
| --- | --- | --- | --- |
| 1.0 | 2026-08-08 | 初版。共通化の範囲を「原子性と安全な読み込み」に限定する方針を確定 | 実装待ち |

## 1. 背景

`tmp/api-cache/` には**キャッシュが2つ**あり、#52 で直したのは片方だけだった。

| ファイル | 大きさ | 管理場所 | 有効期限 | 原子的書き込み | 壊れたときの読み込み |
| --- | --- | --- | --- | --- | --- |
| `cards-snapshot.json` | 約17MB | `scripts/lib/cards-snapshot.mjs` | ✅ #52で追加 | ❌ 無し | ⚠️ `fetched_at` のみfail-safe。**JSON全体が壊れると例外** |
| `featured-sets.json` | 約8KB | `scripts/build-card-pages.mjs`（インライン） | ❌ **無し**（#53） | ❌ 無し | ❌ 例外 |

- **#53**: `build-card-pages.mjs:59` の `if (!REFRESH && existsSync(FEATURED))` は
  **存在するかどうかしか見ない**。#52 で直したのと**まったく同じ形**が同じディレクトリに残っている
- **#54**: 書き込みが `writeFileSync` 1発で**原子的でない**。中断すると壊れたJSONが残り、
  `loadCards()` を使う**4スクリプトすべてが `SyntaxError` で起動不能**になる
  （#52 の検証中に開発担当・レビュー担当の**両方が実際に踏んだ**）

## 2. 2つを一緒に直す理由

- 直す場所が同じ（`cards-snapshot.mjs` と `build-card-pages.mjs` の2ファイル）
- **#54 の対処は #53 の対処の前提になる**。featured-sets に有効期限を持たせるには
  ファイルに取得時刻を持たせる必要があり、**形を変える＝旧形式を安全に読み飛ばす仕組み（#54側）が要る**
- 片方ずつ直すと、同じ関数を2回書き換えて2回レビューすることになる

## 3. #53 が実害になる場面（優先度の根拠）

`featured-sets` は**エキスパンションのグループ分けと公式ロゴ**の出所。腐ると:

- 新しい製品ラインがグループに入らず `cards/index.html` で**「その他」に落ちる**
- セットページの**ロゴと `og:image` が付かない**

⭐ **実例が控えている**: #51 の PRDEVP は現在どのグループにも属さず「その他」にいる。
親セット `.asphodel/paradise`（PRD）が公式に featured-sets へ入った日、
**手元のキャッシュが古いままだとローカルのビルドではグループ化されない**。
その生成物をコミットすると、cronが作った正しいグループ分けを巻き戻す。

⚠️ ただし #52 より**気づきにくい**。製品ラインの追加は数か月に1度なので、
腐っても差分に現れる機会がほとんど無い。

## 4. 設計方針 — 共通化の範囲を絞る

### 4-1. 採用する形

**共通モジュール `scripts/lib/api-cache.mjs` を新設**し、**「原子的な書き込み」と「安全な読み込み」だけ**を担わせる。
⚠️ **キャッシュの中身の形（スキーマ）と有効期限の判断は、各呼び出し元に残す。**

```text
scripts/lib/api-cache.mjs   ← 新設
  writeJsonAtomic(file, obj)  … 同じディレクトリに一時ファイルを書いて rename
  readJsonSafe(file)          … 読めない/壊れている/無い → null を返す。★例外を投げない
```

### 4-2. なぜ「全部を共通化」しないのか

| 案 | 却下/採用 | 理由 |
| --- | --- | --- |
| **A. 原子性と安全な読み込みだけ共通化（採用）** | ⭐ 採用 | **`cards-snapshot.json` の中身の形を変えずに済む**。#52 で通したV1〜V13がそのまま有効で、17MBの再取得も発生しない |
| B. キャッシュ層を完全に共通化（形も統一） | 却下 | `cards-snapshot.json` の形が変わり、**既存の全スナップショットが無効化**して再取得（75リクエスト）が走る。#52 の検証項目も作り直しになる。**得るものに対して壊す範囲が大きい** |
| C. #53 と #54 を別々に直す | 却下 | §2のとおり同じ関数を2回書き換えることになる |

⭐ **判断の軸**: #52 は**通ったばかりの変更**。その土台（オンディスクの形）を揺らさずに、
**足りない性質だけを足す**のが最も安全。

### 4-3. 有効期限は既存の環境変数を流用する

`GA_SNAPSHOT_MAX_AGE_MIN`（#52で新設・既定60分／`0`=無期限）を
**`featured-sets` にもそのまま効かせる**。

- ⚠️ 名前が `SNAPSHOT` なのに2つのキャッシュを支配するのは**名前のズレ**だが、
  **改名はしない**（#52で文書化・周知したつまみを増やす/変えるほうが混乱する）
- CLAUDE.md に「`tmp/api-cache/` 全体の有効期限」と説明を書き直す（設計担当が実施）

## 5. 変更内容

### 5-1. `scripts/lib/api-cache.mjs`（新設）

```text
writeJsonAtomic(file, obj)
  1. mkdir -p (dirname)
  2. 同じディレクトリに一時ファイル(例: <name>.tmp-<pid>-<乱数>)を書く
  3. renameSync(一時ファイル, file)          ← 同一FS内の rename は原子的
  ⚠ 失敗したら一時ファイルを消してから例外を投げる(ゴミを残さない)

readJsonSafe(file)
  ファイルが無い / 読めない / JSON.parse に失敗 → null を返す
  ⚠ 例外を投げない。呼び出し元が「取り直す」判断をする
```

### 5-2. `scripts/lib/cards-snapshot.mjs`

- 書き込みを `writeJsonAtomic()` に置き換え
- 読み込みを `readJsonSafe()` に置き換え、**`null` なら取り直す**（＝#54の本丸）
- ⚠️ **オンディスクの形は変更しない**（`{ fetched_at, total, cards }` のまま）

追加する stderr（1行）:

| 場面 | 出力 |
| --- | --- |
| JSONが壊れている・読めない | `スナップショットを読めないため取り直します` |

### 5-3. `scripts/build-card-pages.mjs` の `loadFeaturedSets()`

**tmpキャッシュに取得時刻を持たせ、有効期限を効かせる。**

```text
形: { "fetched_at": "<ISO>", "data": [ …groups… ]  }     ← tmpキャッシュのみ
```

判定の順序:

```text
REFRESH                                   → 取得
readJsonSafe(FEATURED) が null            → 取得   （無い/壊れている・#54）
fetched_at が無い or 配列そのもの(旧形式)   → 取得   （自動で新形式に移行する）
fetched_at が壊れている                    → 取得
有効期限 0（無期限）                        → 再利用
経過 > 有効期限                            → 取得   （★#53の本丸）
それ以外                                   → 再利用
```

stderr（1行）:

| 場面 | 出力 |
| --- | --- |
| 期限内で再利用 | `featured-sets キャッシュ使用: {N}件 (取得: {ISO} / {相対})` |
| 無期限指定で再利用 | `featured-sets キャッシュ使用: {N}件 (取得: {ISO} / {相対} / 有効期限なし)` |
| 期限切れ | `featured-sets キャッシュが古いため取り直します ({相対} / 有効期限{M}分)` |
| 旧形式・取得時刻が壊れている | `featured-sets キャッシュが旧形式のため取り直します` |
| 無い・JSONが壊れている | *（何も出さない。従来どおり取得に進む）* |

`{相対}` は `relativeAge()` を流用（`{n}分前` / `{n}時間前` / `{n}日前`）。

- 取得成功時の `エキスパンショングループ取得: {N}件(公式ロゴ付き)` は**現状のまま**
- 取得失敗時のフォールバック（`data/featured-sets.json`）も**現状のまま**

⚠️ **取得に失敗したとき、期限切れのtmpキャッシュへ戻さないこと。**
コミット済みの `data/featured-sets.json` は**cronが毎日更新している**ため、
**期限切れのローカルキャッシュより新しい可能性が高い**。現行のフォールバック順序を変えない。

### 5-4. ⚠️ 変えてはいけないもの

| 対象 | 理由 |
| --- | --- |
| **`data/featured-sets.json` の形（インデント付きの素の配列＋末尾改行）** | ⚠️ **コミットされるファイル**。形が変わると cron が全量差分の自動コミットを作る。**素の配列のまま**にすること（`{fetched_at, data}` で包まない） |
| `cards-snapshot.json` の形 | §4-2。#52 の検証項目を無効化しないため |
| `.github/workflows/build-tournaments.yml` | 変更不要 |
| 環境変数名 `GA_SNAPSHOT_MAX_AGE_MIN` | §4-3 |
| 生成物（`cards/**` `sets/**` `index.html` `sitemap.xml` `data/**`） | 本修正で出力は変わらない |
| `CLAUDE.md` | **設計担当が行う** |

## 6. 期待される差分

| ファイル | 変化 |
| --- | --- |
| `scripts/lib/api-cache.mjs` | **新規** |
| `scripts/lib/cards-snapshot.mjs` | 読み書きを共通関数へ・壊れたJSONのfail-safe |

**コミットせずに報告すること**（§5-4の最重要項目）。

## 7. 検証項目

⚠️ **`tmp/` 配下の他セッションの作業物は消さないこと。** キャッシュは直接書き換えて検証してよいが、
**現物を退避してから行い、終わったら戻すこと。**
