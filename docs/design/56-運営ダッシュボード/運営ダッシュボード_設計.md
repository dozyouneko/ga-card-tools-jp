## 1. 背景と目的

このサイトには「運営状況を見る場所」が無い。Cloudflare のダッシュボードで閲覧数の概要は見られるが、
**D1（登録者・デッキ）とは別画面**で、両者を突き合わせた全体像を1枚で見る手段が存在しない。

目的は**運営判断のための1枚**を用意すること。具体的には次の3問に即答できる状態にする。

1. 人は増えているか（登録者・アクティブ）
2. 作った機能は使われているか（デッキ構築・版指定・印刷・大会ページ…）
3. どこから来て、何を見ているか（流入元・パス別閲覧）

### 3.2 Web Analytics の識別子（実測値）

### 3.3 トークン権限が足りない（着手前にユーザーの手作業が必要）

現行の `~/.cloudflare-token` で RUM を引くと **`not authorized for that account`** が返る（実測）。

- 必要な権限: **Account → Account Analytics → Read**
- 現行トークンの権限（`docs/dev-setup.md` 記載）: Account/D1:Edit、Account/Cloudflare Pages:Edit、
  Account/Account Settings:Read、User/User Details:Read → **Analytics が無い**
- 追加手順: Cloudflare ダッシュボード > My Profile > API Tokens > 該当トークン > **Edit** >
  Permissions に `Account` `Account Analytics` `Read` を1行追加して保存 → `~/.cloudflare-token` は**変更不要**
- ⚠️ **`Edit` と `Roll` を取り違えないこと。** 同じメニューに並んでいるが役割が逆:

  | 操作 | 権限 | トークンの値 | 結果 |
  | --- | --- | --- | --- |
  | **Edit** | 変えられる | **変わらない** | ⭕ これを使う。`~/.cloudflare-token` はそのまま |
  | Roll | 変わらない | **再発行される** | ❌ 権限は増えず、**既存の値が無効化**され wrangler も RUM も全部落ちる |

  誤って Roll した場合は、表示された新しい値で `~/.cloudflare-token` を上書きし
  （`chmod 600` を維持）、`docs/dev-setup.md` のバックアップ手順で取り直す
- トークンは**ユーザー所有**（My Profile 配下）。Account 配下の "Account API Tokens" ではない
- 権限行を足すとき、**Account リソースの指定は既存行と同じアカウント**にする
  （別アカウントを選ぶと権限が増えたのに `not authorized` のままになる）
- ⚠️ **`docs/dev-setup.md` の権限一覧も同時に更新すること**（消費側が増えたケース。§9-3）

なお **GraphQL のイントロスペクションはこの権限が無くても通る**（実測）。スキーマ確認だけなら先行できる。

### 3.4 RUM のデータ仕様（イントロスペクションで確定）

`rumPageloadEventsAdaptiveGroups` で使える語彙（実測）:

- **dimensions**: `bot` `countryName` `date` `datetimeHour` `deviceType` `navigationType`
  `refererHost` `refererPath` `refererScheme` `requestHost` `requestPath` `requestScheme`
  `siteTag` `userAgentBrowser` `userAgentOS` ほか
- **metrics**: `count` / `sum { visits }` / `avg { sampleInterval }`

保持期間（Cloudflare公式ドキュメント）: **生データは7日**、以降は**約10%に集約**、遡れるのは**約6か月**。
→ ⭐ **長期推移は手元に日次スナップショットを溜めないと永久に失われる**（§6）。

## 4. 全体構成

```text
npm run dashboard                  取得 → HTML生成 → ローカルサーバー起動(3200)
npm run dashboard -- --no-fetch    取得せず、最新スナップショットから再生成（オフライン可）
npm run dashboard -- --no-serve    生成のみ（サーバーを立てない）
```

```text
scripts/dashboard/
├─ index.mjs          エントリ。引数処理・実行順の制御・サーバー起動
├─ collect-d1.mjs     D1（本番）から集計。SELECT のみ
├─ collect-rum.mjs    Web Analytics GraphQL から集計
├─ collect-health.mjs 運用ヘルス。ローカルファイルと git のみ（ネットワーク不要）
└─ render.mjs         スナップショット → 自己完結HTML

tmp/dashboard/                     ⚠️ 出力先はここだけ
├─ index.html                      生成物
└─ snapshots/YYYY-MM-DD.json       日次スナップショット（UTC日付・同日は上書き）
```

### 4.1 ⚠️ 出力先とコミット禁止（最重要）

**このリポジトリは公開されている。** 登録者数・閲覧数・人気カードは運営情報であり、
`docs/` に置くと（本番配信されなくても）**GitHub上で誰でも読める**。

- 数値の入った成果物は **`tmp/dashboard/` 配下にのみ**書き出す（`tmp/` は `.gitignore` 済み）
- **`data/` `docs/` に数値を書き出してはいけない**
- コミットしてよいのは `scripts/dashboard/` のコード・`package.json` のスクリプト定義・本設計書だけ

### 4.2 ポート

| 役割 | 静的プレビュー | Pages Functions | **ダッシュボード** |
| --- | --- | --- | --- |
| 開発担当 | 3000 | 8788 | — |
| レビュー担当 | 3100 | 8888 | — |
| **本ツール** | — | — | **3200** |

既存の役割別ポート割り当てと衝突しない値を選んだ。`PORT` 環境変数で上書き可能にする。

### 4.3 失敗時の方針 — **fail-open（1つ欠けても全体を落とさない）**

3つの収集元（D1・RUM・ヘルス）は**独立して失敗し得る**。1つの失敗で全体を落とすと、
権限追加前は**何も見られない**ことになる。

- 各セクションは `{ ok: true, data }` または `{ ok: false, reason }` を返す
- 失敗したセクションだけ画面に**理由と対処手順**を出し、他は通常表示する
- プロセスは **exit 0** で完走する（`--strict` 指定時のみ、1つでも失敗したら exit 1）

## 5. データ取得の仕様

### 5.1 D1（本番）

```bash
CLOUDFLARE_API_TOKEN=$(cat ~/.cloudflare-token) \
CLOUDFLARE_ACCOUNT_ID=53dcf4e7f02ea5e504977816a68865f5 \
npx wrangler d1 execute DB --remote --json --command "<SQL>"
```

- ⚠️ **`--remote` は本番DBを見る。SELECT 以外を書いてはいけない。**
  実装には INSERT/UPDATE/DELETE/DROP/ALTER を**一切含めない**（検証項目 V14 で機械的に確認する）
- **1クエリ = 1実行**とする。1ファイルに複数ステートメントをまとめて `--file` で流すほうが速いが、
  `--json` の結果配列とクエリの対応付けが崩れたときに**静かに取り違える**。11本×往復数百msは許容範囲なので確実さを取る
- ⚠️ `wrangler d1 execute --remote --json` の**出力の形**は未確認（調査時に実行がブロックされたため）。
  開発担当は**最初に Q1 を1本だけ流し、応答JSONの構造を issue に貼ってから**残りを実装すること

| # | 指標 | SQL |
| --- | --- | --- |
| Q1 | 登録者総数 | `SELECT COUNT(*) AS c FROM users;` |
| Q2 | 新規登録の日次推移（60日） | `SELECT date(created_at) AS d, COUNT(*) AS c FROM users WHERE created_at >= datetime('now','-60 days') GROUP BY d ORDER BY d;` |
| Q3 | アクティブ利用者 | `SELECT (SELECT COUNT(DISTINCT user_id) FROM sessions WHERE last_seen_at >= datetime('now','-7 days')) AS a7, (SELECT COUNT(DISTINCT user_id) FROM sessions WHERE last_seen_at >= datetime('now','-30 days')) AS a30, (SELECT COUNT(*) FROM sessions) AS live_sessions;` |
| Q4 | デッキ全体 | `SELECT COUNT(*) AS decks, SUM(CASE WHEN is_public=1 THEN 1 ELSE 0 END) AS public_decks, SUM(CASE WHEN thumb_image IS NOT NULL THEN 1 ELSE 0 END) AS with_thumb, COUNT(DISTINCT user_id) AS owners FROM decks;` |
| Q5 | デッキ作成の日次推移（60日） | `SELECT date(created_at) AS d, COUNT(*) AS c FROM decks WHERE created_at >= datetime('now','-60 days') GROUP BY d ORDER BY d;` |
| Q6 | 直近の更新 | `SELECT SUM(CASE WHEN updated_at >= datetime('now','-7 days') THEN 1 ELSE 0 END) AS u7, SUM(CASE WHEN updated_at >= datetime('now','-30 days') THEN 1 ELSE 0 END) AS u30 FROM decks;` |
| Q7 | 1人あたりデッキ数の分布 | `SELECT n, COUNT(*) AS users FROM (SELECT user_id, COUNT(*) AS n FROM decks GROUP BY user_id) GROUP BY n ORDER BY n;` |
| Q8 | board別の枚数 | `SELECT board, SUM(qty) AS qty, COUNT(*) AS rows_ FROM deck_cards GROUP BY board ORDER BY qty DESC;` |
| Q9 | 版指定（イラスト選択）の利用率 | `SELECT COUNT(*) AS rows_, SUM(CASE WHEN art_image IS NOT NULL THEN 1 ELSE 0 END) AS with_art, COUNT(DISTINCT CASE WHEN art_image IS NOT NULL THEN deck_id END) AS decks_with_art FROM deck_cards;` |
| Q10 | 人気チャンピオン top10 | `SELECT champion_slug AS slug, COUNT(*) AS c FROM decks WHERE champion_slug IS NOT NULL GROUP BY slug ORDER BY c DESC LIMIT 10;` |
| Q11 | 人気カード top20 | `SELECT card_slug AS slug, SUM(qty) AS qty, COUNT(DISTINCT deck_id) AS decks FROM deck_cards GROUP BY slug ORDER BY qty DESC LIMIT 20;` |

**slug → 日本語名**は `data/tl-names.json`（既存の生成物）で解決する。
未収録の slug は **slug をそのまま表示し、末尾に `(未訳)` を付ける**（黙って空欄にしない）。

#### ⚠️ Q3 の限界を画面に明記する

`sessions` は TTL 30日で、しかも**ログインのたびに期限切れ行を全ユーザー分まとめて削除する**
（`functions/_lib/session.js` の `createSession`）。したがって:

- `a30` は「直近30日に来た人」の**下限**でしかない
- **31日以上前の活動履歴は D1 から復元できない** — これが §6 のスナップショットを必須にする理由

画面には `アクティブ（30日）19人 ⓘ` と出し、ⓘ に上記の注記を付ける。

### 5.2 Web Analytics（GraphQL）

エンドポイント `https://api.cloudflare.com/client/v4/graphql`、
`filter` に `siteTag: "27d8cfee93a54d88932ee8790fe4f9a9"` と期間、そして **`bot: 0`** を必ず含める。

| # | 取得内容 | dimensions | 期間 | limit |
| --- | --- | --- | --- | --- |
| R1 | 日次の閲覧数・訪問数 | `date` | 30日 | 100 |
| R2 | パス別 | `requestPath` | 30日 | 500 |
| R3 | 参照元 | `refererHost` | 30日 | 20 |
| R4 | 端末種別 | `deviceType` | 30日 | 10 |
| R5 | 国別 | `countryName` | 30日 | 20 |

- **閲覧数（PV）= `count × avg(sampleInterval)`**、**訪問数 = `sum { visits }`** として扱う
  - ⚠️ この換算はCloudflareのアダプティブサンプリングの一般則に基づくもので、**本サイトでの実測はまだ無い**。
    権限追加後に**Cloudflareダッシュボードの同期間の数値と突き合わせる**こと（検証項目 V4b）。
    ずれる場合は「`count` をそのまま出し、サンプリング中である旨を注記」に切り替える
- **日付は UTC で扱う**。JSTに直すと日次グラフの境界が1日ずれて日次cronの痕跡と読み違える。
  画面のグラフ見出しに **`（UTC基準）`** と明記する（取得日時のほうはJSTで表示する）

#### パスの畳み込み規則（**上から順に評価し、最初に一致したものを採用**）

カード個別ページだけで2,240本あるため、生パスのまま並べても機能の使われ方は読めない。

| 順 | 判定 | カテゴリ表示名 |
| --- | --- | --- |
| 1 | `/` に完全一致 | トップ（カードDB） |
| 2 | `/cards/` に完全一致 | カード一覧 |
| 3 | `/cards/<何か>/` | カード個別ページ |
| 4 | `/sets/` に完全一致 | セット一覧 |
| 5 | `/sets/<何か>/` | セット別ページ |
| 6 | `/tools/deck-builder/` で始まる | デッキ構築ツール |
| 7 | `/tools/print/` で始まる | 印刷PDF生成 |
| 8 | `/tools/glossary/` で始まる | 用語解説 |
| 9 | `/tournaments/` に完全一致 | 大会一覧 |

| 11 | `/decks` または `/decks.html` | デッキ一覧 |

- ⭐ **「その他」が総PVの5%を超えたら、その行に ⚠️ バッジを出し、生パスの内訳を `<details>` で展開できるようにする。**
  畳み漏れ＝**新しいページが増えたのに規則が追いついていない**合図であり、放置すると
  そのページの利用が永久に見えなくなる（`meta.sets` の追記漏れと同じ形の失敗）
- **カード個別ページは畳んだうえで、別表で slug 別 top20 も出す**（どのカードが読まれているかは翻訳の優先順位に直結する）。
  slug → 日本語名の解決は §5.1 と同じ

### 5.3 運用ヘルス（ローカルのみ・ネットワーク不要）

CLAUDE.md に繰り返し出てくる「静かに壊れる」箇所のうち、**既存の検出経路が無いもの**を3つだけ載せる。

| 項目 | 出どころ | ⚠️ の条件 |
| --- | --- | --- |
| 日次cronの最終更新 | `data/tournaments/index.json` の `updatedAt` | **48時間**より古い |
| シーズン禁止の終了日 | `data/seasonal-banlist.json` の `seasons[].effectiveTo` | `null` が**2件以上**（1件は現行シーズンで正常） |
| 未pushコミット | `git rev-list --count origin/main..HEAD` と `git diff --stat origin/main..HEAD -- . ':(exclude)docs/*'` | 後者が**非空**（＝本番配信物が未pushで溜まっている） |

⚠️ `meta.sets` の新セット追記漏れ（#40）は**載せない**。`npm run validate` が既に exit 1 で検出しており、
二重に持つと片方の更新漏れで嘘をつく。

## 6. スナップショット

`tmp/dashboard/snapshots/YYYY-MM-DD.json`（**UTC日付**）に、その日取得した全数値をそのまま保存する。

- 同日に複数回実行したら**上書き**（1日1ファイル）
- HTML生成時に `snapshots/` を**全部読み**、累計推移グラフ（登録者数・デッキ数）を描く
- `--no-fetch` はネットワークに出ず、既存スナップショットの**最新1件**で画面を作る
- 存在意義: **RUMの6か月制限**（§3.4）と **`sessions` の30日制限**（§5.1）を超える履歴は、ここにしか残らない

⚠️ `tmp/` は `/workspaces` のバインドマウント上なので**コンテナ再構築では消えない**が、
**PC故障では消える**（`docs/dev-setup.md` のシナリオB）。長期の履歴が惜しくなったら
バックアップ対象に加えることを別途検討する（本issueでは扱わない）。

### 7.1 決定事項

1. **外部ライブラリを使わない。** グラフはCSSの棒（`div` の幅）だけで描く。
   ローカル生成HTMLなのでCSPの制約下になく、**インライン `style` を使ってよい**
   （本番の `style-src 'self'` 制約はこのファイルには掛からない。本番のコードとは混ぜないこと）
2. **単一の自己完結HTML**（外部CSS・JS・画像を参照しない）。ファイル1つコピーすれば後から単体で開ける
3. **レスポンシブ対応する。** ローカルサーバーは同一LAN内のスマホからも開けるため、
   **PC幅と375px幅の両方**を成立させる（検証項目 V9）
4. **配色はOSのライト/ダーク設定に追従**する（`prefers-color-scheme`）
5. 数値は**3桁区切り**、率は**小数第1位**まで。0件は空欄ではなく **`0`** と書く

### 7.2 前週比の出し方

`users.created_at` / `decks.created_at` から直接計算する（スナップショットが1日分しか無くても出る）。
閲覧数の前週比は RUM の「直近7日」と「その前の7日」を比較する。

- 増加は `+6（+14.6%）`、減少は `-3（-5.2%）`、比較対象が0のときは **`—`**（`+∞%` と書かない）

### 7.3 印刷ツールの計測開始日を注記する

ビーコン設置（§8）以前の期間は `/tools/print/` の閲覧数が **0 として返る**。
グラフ上は「使われていない機能」に見えてしまうため、フッタと機能カテゴリ表に
**`※ 印刷PDF生成は YYYY-MM-DD 計測開始`** を出す（日付は実装時のpush日を手で入れる）。
