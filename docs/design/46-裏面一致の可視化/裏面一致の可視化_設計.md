## 1. 問題

**両面カードの「裏面」の日本語名・効果で検索すると、タイルには「表面」の名前が出る。**
検索語を含まないカードが混ざったように見える。

本番実測（2026-08-02）:

```
名前欄「朱雀」→ 3件
   朱雀の化身 / ⚠️ 伝説の紅玉運命石 / 朱雀の号令
                  └ どこにも「朱雀」が無い
```

2件目は裏面 `suzaku-vermillion-phoenix`（**朱雀、朱き不死鳥**）に一致したが、
`fetchCard()` が表面 `fabled-ruby-fatestone`（**伝説の紅玉運命石**）を返すため、
タイルはそちらの名前・画像で描画される。

### 1.1 「1枚のカード＝1タイル」は正しい。直すのは説明だけ

#45 で **裏面を表面へ畳む**方式を採り、件数と行数を一致させた。畳むこと自体は正しい
（サイトは両面カードを1タイルで表現しており、🔄バッジで裏面を見られる）。
**本件は「畳んだ結果、一致の理由が画面から消えている」問題**であって、畳み方の問題ではない。

⚠️ **どの面で一致したかは、`localJpSlugs()` から描画まで運ばれていない。** ここが欠けている唯一の情報。

## 3. 方針

**JPモードで「裏面だけが一致した」カードは、**

1. **カード本文に `🔄 裏: 朱雀、朱き不死鳥` の行を1行足す**（案C-2）
2. **画像を最初から裏面で開く**（🔄バッジは「🔄 裏面」表示で始まり、押すと表面へ戻る）

の2つを行う。**それ以外は何も変えない** —— タイルの名前・英名・チップは表面のまま、
クリックで開く詳細も表面カード、**＋🖨️ で印刷リストに入るのも表面カード**。

## 5. 実装 — データの受け渡し

### 5.1 どこで分かるか

`shared/js/card-search.js` の JPモード経路に、すでに必要な材料が揃っている:

| 変数 | 中身 |
|---|---|
| `jpSlugs`（`localJpSlugs()` の戻り） | 日本語に一致した**全slug（表面・裏面が混在）**。`sort()` 済み |
| `idx.f` | `{裏面slug: 表面slug}`（22件・#45 で追加） |

→ この2つだけで「表面slug → 一致した裏面slug」が作れる。**取得後の情報は要らない。**

### 5.2 追加する関数（`shared/js/card-search.js`）

`foldFlip()` の直後に置く:

```js
// 「裏面だけが一致した」カードを {表面slug: 裏面slug} で返す（#46）。
// 表面も一致しているとき（リュ・ブ／方天画戟）は入れない —— 検索語はすでにタイルに見えており、
// 注記を出すとノイズにしかならない。
// ⚠ 索引に f が無い（旧形式・取得失敗）ときは空を返す＝注記が出ないだけ（fail-open）
function backOnlyHits(idx, list) {
  const f = idx && idx.f;
  const out = {};
  if (!f) return out;
  const matched = new Set(list);
  for (const slug of list) {
    const front = f[slug];
    if (!front) continue;            // 裏面slugではない
    if (matched.has(front)) continue; // 表面も一致した → 注記なし
    if (!out[front]) out[front] = slug; // 先勝ち（list は sort 済みなので決定的）
  }
  return out;
}
```

### 5.3 呼び出しと受け渡し

- 状態変数 `let jpBackHit = null;` を `jpDropped` 等と同じ場所に足し、**reset 時に `null` へ戻す**
- `jpCand === null` のブロックで、**`foldFlip` に渡す前の `jpSlugs`** から作る
  （`folded` は裏面slugを失っているので**使えない**）:

  ```js
  const folded = foldFlip(idx, jpSlugs);
  jpBackHit = backOnlyHits(idx, jpSlugs);   // ← 追加。folded ではなく jpSlugs
  ```

- `opts.onResults(cards, { … })` に **`jpBackHit: jpSlugs ? jpBackHit : null`** を足す

⚠️ **カードオブジェクトに印を付けてはいけない。** `fetchCard()` の結果は `card-cache.js` が
キャッシュしており、`card.__backHit = …` のように書くと**次の検索に前回の印が残る**。
必ず `info` 側のマップで渡すこと。

### 5.4 描画側（トップ / デッキ構築）

`info` を描画関数へ渡す（現在は `cards` だけ渡している）:

- `app.js`: `appendGrid(cards)` → `appendGrid(cards, info)`
- `tools/deck-builder/app.js`: `appendResults(cards)` → `appendResults(cards, info)`

各タイルで:

```js
const back = backFace(card);                       // 既存
const hitSlug = info && info.jpBackHit ? info.jpBackHit[card.slug] : null;
const backHit = !!(hitSlug && back);               // 裏面が一致した（表示できる裏面がある）
// 一致した裏面の絵で開く。⚠ その版に裏面画像が無いときは表面のまま（§6.3）
const startBack = !!(backHit && imgs[initialAi] && imgs[initialAi].back);
const img = imgs.length ? (startBack ? imgs[initialAi].back : imgs[initialAi].url) : null;
```

- `<img src>` に上記 `img` を使う
- 🔄バッジの初期表示: `startBack ? "🔄 裏面" : "🔄 両面"`、`aria-label` は
  `startBack ? "表面を表示" : "裏面を表示"`
- 状態の初期値: `let showingBack = startBack;`
- `syncImg()` は既存のまま使える（`showingBack && cur.back ? cur.back : cur.url`）。
  ⭐ **`aria-label` の更新を `syncImg()` に1行足す**（現在は `textContent` しか同期しておらず、
  裏面で開くと初期ラベルと状態がずれるため）
- ⚠️ **`dataset.artUrl` は今までどおり `imgs[initialAi].url`（表面）**。
  ここを裏面URLにすると**印刷リスト／デッキに裏面が入る**。変えない

### 5.5 注記のマークアップ

`backHit` のときだけ、カード本文に1行足す。

**トップ（`app.js`・`.card-body` 内、`.card-name-en` の直後）**:

```html
<p class="flip-hit"><span class="flip-hit-lbl">🔄 裏:</span><span class="flip-hit-name">朱雀、朱き不死鳥</span></p>
```

**デッキ構築（`tools/deck-builder/app.js`・`.rname` と `.addrow` の間）**: 同じ要素・同じクラス。

- 名前は **`jpName(back)`**（`backFace()` が返す裏面オブジェクトから取る）。
  ⚠️ **`info` に名前を載せて渡さない** —— 索引には訳名が無く、`I18N` を二重に引くことになるため
- **`escapeHtml()` を通す**（他の名前表示と同じ）
- ⚠️ `jpName(back)` が空文字のときは行ごと出さない（fail-open）

### 5.6 CSS の置き場所

**`shared/css/card-badges.css` に足す。** 新しいファイルは作らない。

- 理由: この行は**トップとデッキ構築の両方**に出る。デッキ構築は root の `style.css` を
  読み込まないため、共用CSSに置かないと**片側だけのコピー**が生まれる
  —— これは #35 の不具合そのものの原因である
- ⚠️ ただし**このファイルは「画像に重ねるバッジ」の置き場**として書かれている。
  **ファイル先頭のコメントを更新し、「本文側の裏面注記（.flip-hit）も含む」ことを明記する**こと。
  さもないと次に読む人が「ここにあるものは全部画像の上」と誤解する

```css
/* 裏面が一致したことを本文で示す行（#46）。
   ⚠ これは画像の上ではない。画像上のバッジは .badges-bl の縦積みに合流させること（#35） */
.flip-hit {
  margin: 4px 0 0;
  font-size: .74rem;
  color: var(--accent-2);
  display: flex; gap: 4px; align-items: baseline;
}
.flip-hit-lbl  { flex: 0 0 auto; opacity: .85; }
.flip-hit-name { font-weight: 700; min-width: 0; overflow-wrap: anywhere; }
```

- `overflow-wrap: anywhere` は**必須**。`束縛の憤怒のチーター` は 375px の2カラム（実質約165px）で
  折り返す（モック §4.1 で確認済み）
- ⚠️ デッキ構築の結果タイルは `minmax(170px, 1fr)` で**トップ（180px）より狭い**。
  実機で折り返しを確認すること（検証 V7）

#### ⚠️ 左右paddingは2画面で事情が違う（第2版で追記・レビュー指摘）

上のルールに**横paddingを入れてはいけない**が、それだけではデッキ構築で左端がずれる:

| 画面 | 本文の横paddingの出どころ | `.flip-hit` の見え方 |
|---|---|---|
| トップ | **親**の `.card-body { padding: 10px 12px 14px }` | ✅ カード名・英名・チップと**左端が揃う** |
| デッキ構築 | **`.rname` 自身**の `padding: 6px 8px 0`（`.result` に横paddingは無い） | ❌ **8px 左にはみ出し、タイルの枠に接する** |

→ **デッキ構築側にだけ、揃えるための1行を足す**（共用CSSの複製ではなく位置合わせなので #35 には反しない）:

```css
/* tools/deck-builder/style.css */
/* 共用の .flip-hit は「親に横paddingがある」前提（トップの .card-body）。
   .result は横paddingを持たず .rname が自前で持つため、ここで左端を揃える */
.result .flip-hit { padding: 0 8px; }
```

⚠️ **`.result` 自体に横paddingを付けて解決しないこと。** `.addrow` は左右いっぱいに広がる
グリッド（`grid-template-columns: 1fr 1fr`）で、枠に接しているのが正しい。

## 6. fail-open（この機能が壊れても検索は壊れない）

⭐ #45・#43 と同じ方針。**注記は「出れば助かる」ものであって、無くても検索結果は正しい。**

| 経路 | 起きること | 画面 |
|---|---|---|
| 6.1 索引が取れない・`f` が無い（旧形式） | `backOnlyHits` が `{}` を返す | 注記なし・画像は表面＝**#46 以前の挙動に戻るだけ**（#45 の畳みも同時に効かなくなるが、そちらは既存の `jpDropNote` が拾う） |
| 6.2 `backFace(card)` が `null`（APIが裏面を返さない） | `backHit` が `false` | 注記なし・表面のまま |
| 6.3 その版に裏面画像が無い | `startBack` が `false` | **注記は出す・画像は表面・バッジは「🔄 両面」**（モック §5 の右ペイン） |
| 6.4 非JPモード | `info.jpBackHit` が `null` | 何も出ない |
| 6.5 索引が腐って `f` の対応が古い | 実在しない表面slugのキーになる | そのキーは引かれないだけ。誤った注記は出ない（キーは `card.slug` と突き合わせるため） |
