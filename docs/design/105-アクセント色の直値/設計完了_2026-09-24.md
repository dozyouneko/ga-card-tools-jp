## 判断済み事項（⭐ **実装側で決め直さないでください**）

1. **`color-mix` を使う** — トークン新設は T4 の V21 で不合格・ページCSSの `:root` は `validate` が exit 1。
   ⭐ **2つの規約の隙間で成立する唯一の書き方**（T4 が同じ結論に達してコメントを残している）
2. ⭐ **等価性は実測済み** — 34箇所で使う **(色, alpha) の全24組合せ**について、
   正規化した算出色が一致し、**要素のスクリーンショットもバイト一致**（24/24）
3. ⚠️ ⭐ **`getComputedStyle()` の文字列は一致しません** — `color-mix` は
   **`color(srgb 0.85098 0.643137 0.254902 / 0.08)`** と直列化されます。
   ⭐ **0〜255 の整数に丸めてから比較してください**（小数の桁は実測で `0.658824` と `0.658823` の両方が出ました）
4. ⚠️ ⭐ **「直値を先に書いて `color-mix` を後に書く」フォールバックは効きません**（実測）。
   `var()` を含む宣言は **IACVT → `unset`** になり、**手前の宣言は生き残りません**。やらないでください
5. **`color-mix` は新しい依存になりません** — トップ・デッキ構築・大会ページ・カードページは
   **すでに全部 `color-mix` を必須にしています**（実測）。⚠️ **例外は `404.html` だけ**で、
   そこに出る要素ではないため実害なし（設計書 §4-2 に記録）
6. ⭐ **大会ページの種別バッジ4色を全部そろえる** — `tournaments.css` の `:root` に
   `--accent-3` / `--yes` を**同じ値で**追記してから参照します。
   ⚠️ **2つだけ直値のまま残すと、この issue が直そうとしている症状そのものを作る**ため
7. **hex の直書き（10箇所）は対象外** — 原因も直し方も検査の作りも違うため、
   **派生の起票案に分離**（設計書 §9-1）。⚠️ **この検査は hex を見ないので、緑を「全部トークン参照になった」と読まないこと**
8. ⭐ **検査を2本足す**（§6）——
   **(iii) トークン色の `rgb()` リテラルが1つも無いこと**（生成元2枚も走査。**生成元一覧の迷子検査つき**）と、
   **(iv) フォールバック無しの `var(--X)` が支配する `:root` に在ること**。
   ⚠️ ⭐ **(iv) は本タスク自身が開ける穴を塞ぐためのもの**です（`tournaments.css` の `var(--yes)` を誰も見張っていない）
9. ⚠️ ⭐ **生成元の `.mjs` はコメントを除去せず生テキストで走査する** — **#117 の `stripJs` の罠を踏まないため**。
   代わりに「**生成元の `.mjs` にはトークン色のリテラルをコメントにも書かない**」という規約が1つ増えます（現状0件）
