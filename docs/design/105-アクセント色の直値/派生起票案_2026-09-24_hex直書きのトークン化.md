# 派生issueの起票案 — トークンと同じ色を hex で直書きしている箇所と、腐ったフォールバック、検査(iii)の記法の穴

- 出どころ: **#105「アクセント色の直値」の設計（2026-09-24）**。全数実測の途中で見つけた、**#105 の対象外**の別型
  - ⭐ **§1-3 と §1-4 は #105 の承認時（2026-09-24）に追加**（レビュー S1-1 / S3-1 の行き先）
- ⚠️ **#105 では直さない**（理由は `アクセント色の直値_設計.md` §9-1）。⭐ **#105 の検査は hex を見ないので、
  `npm run validate` が緑でも「全部トークン参照になった」ことにはならない**

## 1. 症状

### 1-1. bare な hex 直書き（10箇所）— ⭐ 2026-09-24 に再実測（#105 実装後も同数）

トークンと**同じ色を hex で直書き**している。⚠️ **トークンを変えた日にここだけ古い色で残る**（#105 と同じ型）。

| ファイル | 箇所 | 中身 | 対応するトークン |
|---|---|---|---|
| `shared/css/card-detail.css` | 1 | `color: #fca5a5`（L63） | `--danger` |
| `style.css` | 2 | `linear-gradient(180deg, #14171d, #0f1115)`（L30）／`.card { background: #1b1f28 }`（L340） | `--bg` ／ `--panel` |
| `tools/deck-builder/style.css` | 7 | `color: #fca5a5` ×7（L51 / 228 / 235 / 530 / 608 / 609 / 716） | `--danger` |

- ⭐ **`rgba()` の直値（#105）と違って `color-mix` は要らない**——**単に `var(--danger)` と書けばよい**
- ⚠️ ⭐ **`cards/cards.css:40` の `color:#fca5a5` は数に入れていない**（実測で確認）。
  ⭐ **`cards.css` は自前の `:root` を持ち、そこに `--danger` が無い**ので、
  **「そのファイルを支配するトークンと同じ色」には当たらない**（#105 の検査の導出と同じ規則）。
  ⚠️ **`cards.css` にトークンを足すかどうかは別の判断**（§9-2「トークンの統合はしない」に触れる）

⚠️ ⭐ **`style.css:30` のグラデーションだけは判断が要る。** `#14171d` は**トークンに無い中間色**なので、
`#0f1115` だけを `var(--bg)` にすると **片側だけ追従する**という、#105 が直そうとした形そのものになる。
⭐ **中間色をどう扱うか（トークンにするのか・`color-mix` で `--bg` から作るのか・両方 hex のまま残すのか）を
先に決める**こと（→ §1-3 と**同じ判断**）。

### 1-2. ⭐ 腐ったフォールバック hex — ⚠️ **再実測で「1つ」ではなく 3トークン / 15箇所だった**

`shared/css/card-detail.css` の `var(--…)` は **43箇所すべてが `var(--x, #hex)` のフォールバック付き**
（実測 2026-09-24: `var(--` が43、うちフォールバック付き43・フォールバック無し**0**）。
⚠️ ⭐ **そのうち3トークン・計15箇所の hex が `shared/css/tokens.css` の現在値と食い違っている**:

| 参照 | フォールバックの hex | `tokens.css` の現在値 | 箇所 |
|---|---|---|---:|
| `var(--border, #2a2f3a)` | `#2a2f3a` | ⚠️ ⭐ **`rgba(255,255,255,.11)`**（**もう hex ですらない**） | **10** |
| `var(--panel-2, #1f232c)` | `#1f232c` | **`#232834`** | **4** |
| `var(--panel, #171a21)` | `#171a21` | **`#1b1f28`** | **1** |

（残り7トークン・28箇所 — `--muted` `--text` `--accent` `--accent-2` `--accent-3` `--yes` `--no` — は一致している。）

- ⭐ **実害はいまのところ無い**——これらは `card-detail.css` を読むすべてのページ
  （トップ・デッキ構築・大会ページ）で**必ず定義されている**ので、フォールバックは発火しない
- ⚠️ ⭐ **だからこそ、腐っても誰も気づかない。** 将来 `card-detail.css` を
  トークンを持たないページで読んだ瞬間に、**旧配色が出る**
- ⚠️ ⭐ **`--border` は「値が古い」のではなく「形が変わった」**（hex → `rgba()`）。
  ⭐ **フォールバックを検査する案（b）を採るなら、hex 同士の比較では足りない**
- ⭐ **選択肢は2つ**: **(a) フォールバックを全部消す**（`var(--panel-2)` にする。
  ⚠️ **`shared css tokens in sync` が「未定義参照」を見張っているので、消しても検出経路は残る**）／
  **(b) フォールバックの値が `tokens.css` と一致することを検査する**
  - ⚠️ **(b) は `card-detail.css` が「トークンを持たないページでも動く部品」であることを前提にしている**が、
    ⭐ **実測ではそんなページは無い**（読む系統すべてが `:root` を持つ）。**(a) のほうが素直**

### 1-3. ⭐ 死んでいる宣言と、対応トークンが無い「面の色」（#105 レビュー S1-1）

⚠️ ⭐ **`style.css` の `.controls` は背景宣言を2つ持ち、後ろのほうが必ず勝つ**
（同詳細度・どちらもトップレベル・`!important` なし）:

```text
style.css   .controls { … background: color-mix(in srgb, var(--bg) 92%, transparent) … }   ← #105 でトークン参照にした
style.css   .controls { background: #161a22 }                                              ← ⭐ こちらが常に勝つ
```

- ⚠️ ⭐ **結果、#105 でトークン参照にした宣言は画面に出ない。** `--bg` を変えた日に
  **前者は追従するのに画面は変わらない**——⭐ **次にここを触る人が必ず混乱する**
- ⚠️ ⭐ **`#161a22` はトークンと同じ色ではない**（`--bg` は `#0f1115` / `--panel` は `#1b1f28`）。
  **HeroUI 案Aで「面を一段明るくして階層を作る」ために足した中間色**で、**対応するトークンが存在しない**。
  ⭐ **同じ型が `.site-header { background: #191d25 }` にもある**
- ⭐ **判断の選択肢**: **(a) 勝っているほうをトークン化する**（`--surface-1` / `--surface-2` を
  `tokens.css` に新設して参照する）／**(b) 負けている宣言を消す**／**(c) 両方そのまま残す**
  - ⚠️ ⭐ **§1-1 の `#14171d`（中間色）と同じ判断**なので、**まとめて1回で決める**
  - ⚠️ **ページCSSに `:root` を足す道は無い**（`:root owners in sync` が exit 1）。
    **トークンを増やすなら `shared/css/tokens.css` の1本**

### 1-4. ⭐ #105 で足した検査 (iii) が、スペース区切り記法を見ていない（#105 レビュー S3-1）

⚠️ ⭐ **`no token-colored rgb() literals` が拾うのは「カンマ区切りの `rgb()`/`rgba()`」だけ**。
正規表現が `rgba?\( 数 , 数 , 数 [,)]` の形なので、**CSS Color 4 の記法は素通りする**:

| 書き方 | 検査 |
|---|---|
| `rgba(217,164,65,.14)` / `RGBA(217, 164, 65, .14)` | ⭕ **exit 1**（大文字・空白ありも拾う） |
| ⚠️ **`rgb(217 164 65 / 14%)`** / **`rgb(217 164 65)`** | ❌ ⭐ **素通り**（実測: 配信CSSに書き足して `npm run validate` が **exit 0**） |
| `color(srgb 0.85098 0.643137 0.254902)` | ❌ 素通り |

- ⭐ **いま漏れている実体は0件**（既存の直値はすべてカンマ記法）。⚠️ ⭐ **だが放置してよい穴ではない**——
  **スペース区切りは DevTools の色表示や新しく書くCSSで自然に出る形**で、
  ⭐ **この検査が本来いちばん止めたい「これから書かれる直値」の書き方そのもの**
- ⭐ **#105 の承認時の判断（設計担当・2026-09-24）**: **塞ぐ。ただし塞ぐのはこの派生で**
  （#105 は限界⑥として明記するにとどめ、実装は1バイトも変えない＝`アクセント色の直値_設計.md` §6-5）
- ⭐ **どこまで広げるか**: **スペース区切りの整数表記まで**（`rgb(r g b)` / `rgb(r g b / a%)`）。
  ⚠️ **`color(srgb 0.85 …)` の小数表記は広げない**——⭐ **あれは `getComputedStyle()` の出力形で、
  人が手で書く形ではない**（広げると丸めの判定が要り、検査が一段複雑になる）
