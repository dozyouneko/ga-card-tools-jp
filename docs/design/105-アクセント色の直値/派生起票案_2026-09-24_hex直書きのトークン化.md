# 派生issueの起票案 — トークンと同じ色を hex で直書きしている箇所と、腐ったフォールバック

- 出どころ: **#105「アクセント色の直値」の設計（2026-09-24）**。全数実測の途中で見つけた、**#105 の対象外**の別型
- ⚠️ **#105 では直さない**（理由は `アクセント色の直値_設計.md` §9-1）。⭐ **#105 の検査は hex を見ないので、
  `npm run validate` が緑でも「全部トークン参照になった」ことにはならない**

## 1. 症状

### 1-1. bare な hex 直書き（10箇所）

トークンと**同じ色を hex で直書き**している。⚠️ **トークンを変えた日にここだけ古い色で残る**（#105 と同じ型）。

| ファイル | 箇所 | 中身 | 対応するトークン |
|---|---|---|---|
| `shared/css/card-detail.css` | 1 | `color: #fca5a5`（L63） | `--danger` |
| `style.css` | 2 | `linear-gradient(180deg, #14171d, #0f1115)`（L30）／`.card { background: #1b1f28 }`（L340） | `--bg` ／ `--panel` |
| `tools/deck-builder/style.css` | 7 | `color: #fca5a5` ×7（L51 / 228 / 235 / 530 / 608 / 609 / 716） | `--danger` |

⭐ **`rgba()` の直値（#105）と違って `color-mix` は要らない**——**単に `var(--danger)` と書けばよい**。

⚠️ ⭐ **`style.css:30` のグラデーションだけは判断が要る。** `#14171d` は**トークンに無い中間色**なので、
`#0f1115` だけを `var(--bg)` にすると **片側だけ追従する**という、#105 が直そうとした形そのものになる。
⭐ **中間色をどう扱うか（トークンにするのか・`color-mix` で `--bg` から作るのか・両方 hex のまま残すのか）を
先に決める**こと。

### 1-2. ⭐ 腐ったフォールバック hex

`shared/css/card-detail.css` の `var(--…)` は **43箇所すべてが `var(--x, #hex)` のフォールバック付き**。
⚠️ ⭐ **そのうちいくつかの hex は `shared/css/tokens.css` の現在値と食い違っている**:

| 参照 | フォールバックの hex | `tokens.css` の現在値 |
|---|---|---|
| `var(--panel-2, #1f232c)` | `#1f232c` | **`#232834`** |

- ⭐ **実害はいまのところ無い**——`--panel-2` は `card-detail.css` を読むすべてのページ
  （トップ・デッキ構築・大会ページ426枚）で**必ず定義されている**ので、フォールバックは発火しない
- ⚠️ ⭐ **だからこそ、腐っても誰も気づかない。** 将来 `card-detail.css` を
  トークンを持たないページで読んだ瞬間に、**旧配色が出る**
- ⭐ **選択肢は2つ**: **(a) フォールバックを全部消す**（`var(--panel-2)` にする。
  ⚠️ **`shared css tokens in sync` が「未定義参照」を見張っているので、消しても検出経路は残る**）／
  **(b) フォールバックの値が `tokens.css` と一致することを検査する**
  - ⚠️ **(b) は `card-detail.css` が「トークンを持たないページでも動く部品」であることを前提にしている**が、
    ⭐ **実測ではそんなページは無い**（読む4系統すべてが `:root` を持つ）。**(a) のほうが素直**

## 2. ⚠️ 起票前に確かめること

1. ⭐ **上の10箇所と43箇所を数え直す**（この表は 2026-09-24 の値。#105 の実装で動く可能性がある）

3. ⭐ **`#fca5a5` を `var(--danger)` にしたときの算出色が同じ**であることを測る（#105 の V3 と同じ方法）
