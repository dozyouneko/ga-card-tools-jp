### D1. 共有先は **`shared/js/card-search.js`**（新規モジュールを作らない）

### D2. 戻り値は **`{ text, showLoadMore }`**

```js
GA_CARD_SEARCH.searchStatus(info, shown) // → { text: string, showLoadMore: boolean }
```

- `shown` は **DOM 由来**（トップ `el.grid.childElementCount` / デッキ構築 `el.resultGrid.childElementCount`）なので**呼び出し側が数えて渡す**。
  ⭐ **共有側を純関数に保つ**（DOM を触らない＝どちらの画面の要素も知らない）
- ⚠️ ⭐ **`showLoadMore` は今日の全経路で `!!info.hasMore` と一致する**（§2-2 の実測）。
  **観測上は no-op の変更**だが、**「もっと見るを出すか」の判断を文言と同じ場所に置く**ために2値にする
  - ❌ **文字列だけ返して呼び出し側で `!info.hasMore` を書く案は採らない**——
    ⭐ **将来「この分岐では文言は出すが『もっと見る』は隠す」を足したくなった瞬間に、いま塞いだ穴が開く**

### D3. 共通化の範囲 — ⭐ **関数まるごと**（0件の7分岐＋件数行＋`approxTotal` の2分岐＋`element-and`）

| 移すもの | |
|---|---|
| ✅ `element-and` の早期return | `ELEMENT_AND_MESSAGE` を返す1行 |
| ✅ 0件の**途中2分岐**（`hasMore === true`） | §4 の A・B |
| ✅ 0件の**終端5分岐** | §4 の 1〜5 |
| ✅ 件数行（`N 件を表示` / ` / 全 M 件` / JPモード注記） | ⭐ **注記の語はここで統一される**（D5） |
| ✅ `approxTotal` の2分岐 | ⭐ **ユーザーは判断を設計に委ねた。含める**（→ 下記） |

⭐ **`approxTotal` を含める理由**: **両画面ですでに一字一句同一**（§2-1）で、**除くと件数行が
「注記は共有・概算注記は各ファイル」と半端に割れる**＝**いま塞ごうとしている穴をそのまま残す**。

**据え置く**（＝すでに `GA_CARD_SEARCH` 側にあるので動かさない）:
`numericSortNote` / `jpSortNote` / `jpDropNote` / `fetchGapNote` / `numericSortLabel` / `ELEMENT_AND_MESSAGE`。
⭐ **共有関数からは同じモジュール内なので直接呼ぶ**（⚠️ **`?.` は付けない**——同一ファイル内では

### D4. ⚠️ 呼び出し側は `?.` ＋ **1行のフォールバック**

```js
const st = GA_CARD_SEARCH.searchStatus?.(info, shown)
  || { text: `${shown} 件を表示`, showLoadMore: !!info.hasMore };
```

- ⭐ **理由**: push直後の数十秒、**新しい `app.js` と古い `card-search.js` が組み合わさる**

- ⚠️ **この1行は `app.js` と `tools/deck-builder/app.js` の両方に入る**。
  ⭐ **§6 の自動検査は10文字未満の断片を見ないので、` 件を表示`（5文字）はこの検査に当たらない**（意図どおり）
