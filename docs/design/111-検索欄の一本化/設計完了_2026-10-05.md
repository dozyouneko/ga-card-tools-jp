## 3. 判断済み事項（⭐ 実装側で決め直さないこと）

| # | 判断 | 根拠 |
|---|---|---|
| **1** | 検索範囲は**名前＋効果だけ**。フレーバー・タイプ・サブタイプ・クラス・カード番号・用語解説は含めない | ユーザー決定 D1（2026-10-05） |
| **2** | 「名前だけ」「効果だけ」のモード切替・個別欄は**作らない** | ユーザー決定 D2。⚠️ **トレードオフを提示したうえでの決定なので蒸し返さない** |
| **3** | 空白区切りは**語ごとに AND・場所は問わない** | ユーザー決定 D3 |
| **4** | ⭐ **`"…"` で囲んだ部分は1トークン（句）として扱う** | 論点4（用語リンクが壊れないこと）を満たす唯一の最小手段。⭐ **引用符つきなら134語のうち123語は件数が完全に不変**（残り11語は +1〜+13＝名前側のヒットが加わるぶん） |
| **5** | ⭐ **一致の述語は「`card.name` ∪ 裏面の name」と「`card.effect_raw` ∪ 版ごとの `effect_raw` ∪ 裏面の `effect_raw`」の部分文字列（小文字化）** | ⭐ **これで公式APIの `name=`/`effect=` と完全に同じ結果になることを 40語 ＋ 12語の slug 集合で実測（不一致 0）**（設計書 §3-2） |
| **6** | ⭐ **ENテキストモードは「上位集合を全件取ってローカルで絞る」**（#44 の数値ソートと同じ形）。上位集合は **①最安トークンの `name=t` ∪ `effect=t`（union 路）** と **②絞り込みだけの全件（全件路）** の安い方 | 1語の答えは union と厳密に等しい／複数語の答えはどれか1語の union の部分集合（§3-2 の帰結）。⭐ **union 路は全件路の2倍を超えないので、閾値 `TEXT_UNION_MAX_PAGES = 20` の定数で切っても最適より最大2倍しか損しない** |
| **7** | ⭐ **`filterParams()` から `name=`/`effect=` を外す** | **全件路のキャッシュキーが「絞り込みだけ」になる**＝テキストを打ち換えても再取得が起きない（実測: 2回目は 40秒 → **1.85秒**） |
| **8** | ⭐ **ENテキストモードは「3文字以上のトークンが1つも無い」とき検索しない**（APIを1回も叩かない）。JPモードには適用しない | 全件路に落ちる割合の実測: **1文字 84.6% / 2文字 33.0% / 3文字 1.5% / 4文字 0.1% / 5文字 0%**。⚠️ 代価は英語2文字の名前検索ができなくなること |
| **9** | ⭐ **JPモードはトークンごとに「訳の name ∪ 訳の effect」・トークン間はAND**。`loadEffects()` は**JPモードに入ったら常に待つ** | 欄が1つなので「名前だけ探している」と知る術が無い。代価は **912,327 byte（gzip 158,241 byte）をセッション中1回**。⚠️ **#22 フェーズ2 の方針を一本化で手放すということ**（設計書 §5-7） |
| **10** | ⭐ **共有URLは `q` だけ書き、`q` と旧 `qtext` の両方を読む**。`qtext` に空白があれば `"` で囲んでから結合する | 旧URLの結果は**必ず新の上位集合**（実測 `q=lorraine&qtext=draw` は 2件→2件で同じ）。⚠️ ⭐ **デッキ構築の localStorage に保存済みのタブも `qtext` を持っている**ので同じ規則で読む（設計書 §9） |
| **11** | ⭐ **変換は `GA_CARD_SEARCH.mergeLegacyText()` に1本化**して両ページが呼ぶ | 2つの `app.js` へコピーすると、0件文言・用語ハイライト・`preferredArtIndex` に続く二重定義になる |
| **12** | ⭐ **デッキ構築の `#s-name` を `#s-q` に改名する** | 1つだけ残すなら「名前欄」という綴りは次に読む人を確実に誤らせる |
| **13** | ⭐ **`condRows()` の2行（カード名／効果）を `テキスト` の1行にする** | 「カード名」も「効果」も嘘になる（#85 のタブの条件の箱） |
| **14** | ⭐ **新しい文言は1つだけ**（「英語で検索するときは3文字以上入力してください。」）。**`SEARCH-STATUS` マーカーの内側**に置く | #101/#114。⚠️ **`search status text is single-sourced` の成功行が `5断片` → `6断片` に動く**（`SS_MIN=5` は下限なので変更不要）。⚠️ **「変わった＝壊した」と読まないこと** |
| **15** | ⚠️ **`els.q` 化に自動検査は足さない** | 直し忘れると「入力しても1件も絞られない」という誰でも気づく壊れ方になる＝無言の fail-open ではない。⭐ **無言になるのは `?qtext=` の後方互換のほう**で、そちらは派生候補 N3 に残した |
| **16** | ⚠️ **JPモードの `sortKeyOf()` と名前順・レアリティ順の比較器を一本化しない** | 入力が別物（あちらは取得前に slug を並べるのでメタ索引・こちらは取得後にカードを並べる）。⭐ **規則が同じことをコメントで相互参照する** |
