## 2. 確定している要件（⚠️ 2026-10-05 のユーザー決定。設計で蒸し返さない）

| # | 決定 |
|---|---|
| **D1** | **検索範囲は「カード名 ＋ 効果テキスト」だけ。** フレーバー・タイプ・サブタイプ・クラス・カード番号・用語解説は**含めない**。⚠️ ⭐ 理由は「APIが持っていないから」ではない（N-a のとおり `flavor=` は実在する）。**ユーザーがそう決めたから**である |
| **D2** | **「名前だけ」「効果だけ」で絞る使い方は完全に廃止する。** テキスト欄は**1つだけ**。モード切替（すべて/名前/効果）も、詳細オプションの個別欄も**作らない**。⚠️ ユーザーは「効果文に名前が出るカードが常に混ざる」というトレードオフを**提示したうえで**これを選んでいる |
| **D3** | **複数語は「語ごとに AND・場所は問わない」。** 各語について「名前か効果のどこかに含まれる」ことを要求し、語をまたいで AND を取る（`lorraine draw` は 名前に lorraine・効果に draw でも一致する） |

**カード名の第1語（1語で空白を含まないもの）243語**について「旧: 名前欄だけ」と「新: 一本化」を実測した。

## 3. ⭐ 公式APIの一致規則をローカルで完全再現できることの実測

一本化＝OR は「サーバーの1パラメータでは表現できない」（§1）。
そのため**どこかでローカル照合が必要**になる。⭐ **ローカル照合がAPIと一字一句同じ結果を出せるなら、
「APIが絞った結果」と「ローカルで絞った結果」が食い違う心配が消える**ので、まずそこを測った。

### 3-1. 確定した述語（⭐ これが「一致」の唯一の定義になる）

```text
nameTexts(card)   = [ card.name ]
                  ∪ [ e.other_orientations[].name  for e in card.editions ]

effectTexts(card) = [ card.effect_raw ]
                  ∪ [ e.effect_raw                 for e in card.editions ]
                  ∪ [ e.other_orientations[].effect_raw for e in card.editions ]

hit(card, token)  = (nameTexts ∪ effectTexts) のいずれかが
                    token を小文字化して部分文字列として含む
```

- ⚠️ **`effect` ではなく `effect_raw`**（N-b）。無いときだけ `effect` にフォールバックする
- ⚠️ **裏面（`other_orientations`）と版ごとの効果文を含める**（N-c・N-d）
- ⚠️ **大文字小文字は無視**（APIと同じ）。⚠️ **太字マーク `**` の除去は不要**（`effect_raw` には最初から無い）

### 3-2. 実測（⭐ 全2,495枚 × 40語 ＋ 12語の slug 集合まで突き合わせ）

| 測り方 | 結果 |
|---|---|
| **40語**について `name=<語>` / `effect=<語>` の `total_cards` ↔ 上の述語の件数 | ⭐ **不一致 0 / 40語** |
| **12語**について API の結果の **slug 集合**を全ページ捲って取り、述語の slug 集合と比較 | ⭐ **全語で完全一致**（APIのみ 0件・局所のみ 0件） |
| 述語から**裏面を外す**と | `fire` の `name=` が 22 → **21**（`lavaplume-fatestone` が落ちる）など |
| 述語から**版ごとの効果文を外す**と | `counter` が 579 → **578**（`regenerate` が落ちる）／`champion` が 945 → **944** |
| `effect` に `**` 除去だけを当てると | `buff counter` が 157 → **1**（太字）／`fire` が 96 → **94**（`CARDNAME`） |

測った語: `lorraine` `draw` `buff counter` `on hit` `counter` `champion` `fire` `banish` `x` `level 2` `trailblazer` `firebird`
`recover` `stealth` `distant` `aggressive` `lineage` `regalia` `materialize` `enchant` `negate` `sleep` `floating memory`
`graveyard` `reserve` `durability` `ally` `weapon` `spell` `action` `attack` `unpreventable` `spirit` `shadow` `water`
`norman` `silvie` `rai` `tristan` `prepare` `cascade` `glimpse` `end of turn` `your champion` `target unit` `put it`
`at random` `搭載` `Guo Jia` `Lv2` `—` `'s`

⭐ **帰結**（設計の土台）:

1. **1語のときの答えは `name=語` ∪ `effect=語` と厳密に等しい**。だから **union 路**（和集合を取る）は正しい
2. **複数語のときの答えは ∩（各語の和集合）** で、**どれか1語の和集合の部分集合**。だから
   **1語ぶんだけ取ってローカルで残りを当てる**のは正しい（§5-3）
3. **絞り込みだけで取った全件集合にローダルで述語を当てた結果も同じ**。だから **全件路**も正しい
4. ⭐ **union 路と全件路は必ず同じ答えを返す**（検証項目 V9 でそれを測る）

### 3-3. 止められない穴（承知のうえ）

- ⚠️ **公式APIが一致規則を変えたら、ローカル照合だけが取り残される。** 自動検査は置かない（APIを叩く検査は `validate` の
  オフライン前提に反する）。⭐ **代わりに「件数の突き合わせ」を残す**: union 路では
  **API の `total_cards` の和 ≧ ローカルの候補数**が必ず成り立つはずなので、破れたら `fetchGap`（#44）と同じ
  **fail-open の注記**を出す（§5-4）
- ⚠️ **`references` / `referenced_by` は見ていない**（API も見ていないことを確認済み。N-c の原因は裏面だった）

### 5-1. トークン化（⭐ 唯一の出所。JPモードとENモードが同じものを使う）

```js
// 公開: GA_CARD_SEARCH.textTokens(s) -> string[]
function textTokens(s) {
  const out = [];
  const src = String(s || "").replace(/　/g, " "); // 全角空白も区切りにする
  const re = /"([^"]*)"?|([^\s"]+)/g;                  // "…" は1トークン（閉じ忘れも句として拾う）
  let m;
  while ((m = re.exec(src)) !== null) {
    const t = (m[1] !== undefined ? m[1] : m[2]).trim().toLowerCase();
    if (t) out.push(t);
  }
  return out;
}
```

### 5-3. 候補集合（上位集合）の選び方 — ⭐ 2つの路

テキスト欄に**日本語が無く**、入力がある場合（＝ENテキストモード）は、
**#44 の数値ソートと同じ形**（安定キーで上位集合を全件取り、除外・並び替え・ページングはローカル）にする。

```text
① プローブ兼1ページ目（並列）
   各トークン t について  name=t  と  effect=t  の
     ?<filterParams>&name=t&sort=collector_number&order=ASC&page=1&page_size=50
   を取る（2 × トークン数 のリクエスト）。⚠ page_size=1 は使わない（N-e）

② 路を決める
   cost(t)      = ceil(nameTotal/50) + ceil(effectTotal/50)
   best         = cost が最小のトークン（同値なら先頭）
   best.cost <= TEXT_UNION_MAX_PAGES (= 20)  →  union 路
   そうでなければ                            →  全件路

③ 取得（どちらも既存の fetchAll / allCache を通す）
   union 路: fetchAll("<filterParams>&name=best")  と  fetchAll("<filterParams>&effect=best")
             → slug で重複を落として和集合 = pool
             ⭐ ①で取った1ページ目をそのまま渡して再取得を避ける
   全件路  : fetchAll("<filterParams>")  → pool
             ⭐ キーにテキストが入らないので、同じ絞り込みのまま語を変えても 0 リクエストになる

④ ローカルで仕上げる
   pool → matchesText(card, tokens) で絞る
        → 数値ソートなら isNullish の除外（#39）
        → anyAnd() なら matchesAndFilters で間引く
        → §5-5 の比較器で並べる
        → pager.page で PAGE_SIZE ずつ切る
```

- ⭐ **`filterParams()` から `name=` / `effect=` を外す**。これが鍵で、
  **全件路のキャッシュキーが「絞り込みだけ」になる**＝テキストを打ち換えても再取得が起きない
- ⭐ **`TEXT_UNION_MAX_PAGES = 20` が定数でよい理由**: `name=t` と `effect=t` はどちらも
  「絞り込みだけの集合」の部分集合なので、**union 路のページ数は全件路の 2倍を超えない**。
  つまり定数で切っても**最適な路より最大2倍しか損しない**（絞り込みを併用すると union 路はさらに安くなる）
- `ALL_CACHE_MAX` を **4 → 6** にし、**ヒット時にキーを入れ直して LRU にする**
  （union 路は1回の検索で2キー使うので、FIFO 4 のままだと全件路の集合がすぐ追い出される）
- ⚠️ `MAX_PAGES = 60` の暴走止めはそのまま

## 9. 共有URL（#20）と後方互換 — ⭐ 読み書きの規則

### 9-1. 規則

| 向き | 規則 |
|---|---|
| **書く** | ⭐ **`q` だけ**。欄の中身を**そのまま**（引用符も含めて）入れる。`qtext` は**もう書かない** |
| **読む** | ① `q` を取る ② `qtext` も取る（旧リンク・旧共有URL・旧保存タブ）。**`qtext` に空白が含まれていたら `"` で囲む**（旧 `qtext` は句の意味だったため・§4-3） ③ 両方あれば **`q` + 半角空白 + （変換後の）`qtext`** |

- ⭐ **旧URLで結果が減ることは無い**: 旧 `q=A&qtext=B` は `name=A AND effect=B`、新は `(名前∪効果 に A) AND (名前∪効果 に B)` で、
  後者は**必ず前者の上位集合**。実測（`q=lorraine&qtext=draw`）では **2件 → 2件で同じ**

### 9-2. 往復の期待値（⭐ 検証項目 V18 / V31 / V35 がこの表を測る）

| # | 入れるURL / 保存値 | 欄の中身 | 書き戻されるクエリ | 件数（2026-10-05） |
|---|---|---|---|---|
| 1 | `?q=lorraine` | `lorraine` | `q=lorraine` | 13 |
| 2 | `?qtext=lorraine` | `lorraine` | ⭐ **`q=lorraine`**（`qtext` は消える） | 13 |
| 3 | `?qtext=On%20Attack` | ⭐ **`"On Attack"`** | `q=%22On+Attack%22` | 115 |
| 4 | `?q=lorraine&qtext=draw` | ⭐ **`lorraine draw`** | `q=lorraine+draw` | 2 |
| 5 | `?q=lorraine&qtext=on%20attack` | ⭐ **`lorraine "on attack"`** | `q=lorraine+%22on+attack%22` | 0 |
| 6 | `?q=%22buff+counter%22` | `"buff counter"` | 同じ | 157 |
| 7 | `?q=lorraine&element=FIRE&sort=level&order=DESC` | `lorraine` ＋ 既存の絞り込み復元 | 同じ | （エレメント火のロレイン。既存どおり） |
| 8 | 保存タブ（localStorage）に `q=lorraine&qtext=draw` | ⭐ **`lorraine draw`** | `condFromForm()` が **`q=lorraine+draw`** に書き換える | 2 |

- ⚠️ ⭐ **トップとデッキ構築で同じ規則を使う**（`applyUrlQuery()` と `applyCondToForm()` / `condEls()`）。
  **片方だけに書くと、保存タブのテキスト条件が黙って消える**（#8 がそれを測る）
- ⭐ **変換は1か所に置く**（`GA_CARD_SEARCH.mergeLegacyText(q, qtext) -> string` を公開して両ページが呼ぶ）。
  ⚠️ **2つの `app.js` にコピーしないこと**（0件文言・用語ハイライト・`preferredArtIndex` に続く二重定義を増やさない）
