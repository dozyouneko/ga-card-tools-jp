### 3-1. ⭐ S1-a を採った理由（⚠️ **起票前に設計担当が症状を実測して再現させた**）

⚠️ ⭐ **`CLAUDE.md` の規約どおり、`gh issue create` の直前に症状を自分で再現させた**
（⚠️ **原本をスクラッチへ退避して `cp` で戻し、`git checkout` は使わず、各ケース後に `git status --short` が空・`md5sum -c` で原本一致を確認**）:

| 測ったこと | 結果（2026-10-06） |
|---|---|
| HEAD の `npm run validate` | **exit 0**・**70行** |
| ⭐ **`index.html` の `#q` の placeholder だけ**を `カードを検索` に変えて `validate` | **exit 0**／⭐ **出力がベースラインと `diff` で差分なし**（＝ **完全に無言**） |
| `scripts/validate.mjs` に `placeholder` の字面 | ⭐ **0件** |

⭐ **採った理由は3つ**:

1. ⭐ **`CLAUDE.md` が名前を付けている型そのもの**——「**片方だけ直すと画面によって文言が違う**」
   （`flavorOf()` / `RULE_TEXT` / 0件文言 と同型）。⭐ **#111 で2画面の欄が同じ意味になった**ので、
   食い違うと「**どちらが正しい説明か**」が読んだ人に分からない
2. ⭐ **両辺が別ファイルの双方向照合として成立することを、設計担当も試作して確かめた**（＝**空回りしない**）。
   試作は **片方だけ変えた写しで不一致を検出**し、**`id="q"` を消した写しでは「0個」で fail-closed** になった
3. ⭐ **#131（句検索の案内）と競合しない。** #131 の案Aは placeholder そのものなので、
   ⭐ **検査が入ると #131 は2ファイルを同時に直すことになる**＝ **検査は #131 の片側忘れを止める側に働く**

⚠️ ⭐ **ただしレビューの見立てに1件足りなかった**ので、**#133 に設計の材料として書いた**（設計書 §12-2-2）:

| # | 設計で決めること | 設計担当の実測 |
|---|---|---|
| **(1)** | ⚠️ ⭐ **「`id="q"` を配信HTMLから探す」書き方は使えない** | ⭐ **`tools/glossary/index.html` にも `id="q"` の検索欄がある**（40行目）が、**あれは用語の絞り込みで placeholder も別物**（`キーワードで絞り込み… 例: ステルス, link`）＝ **一致してはいけない**。⚠️ **もう1つ**: `tools/deck-builder/index.html` には **placeholder が2つある**（Omnidex 取り込みの `<textarea>`）。→ **照合対象は「（ファイル, id）の組の明示リスト」で持つ** |

⚠️ ⭐ **#111 の push を止める理由にはならない。** 「いま壊れている」のではなく「**将来壊れる経路が開いている**」型で、
⭐ **深刻度は見た目だけ**（機能は壊れない）。#121 / #113 と同じ待ち行列に並べる。
