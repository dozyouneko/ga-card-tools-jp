## 4. ⭐ `--posting-plan` の出力は復旧後にそのまま使えるか（自己評価）

**使えると判断しました。** 根拠:

1. **1タスク＝1 issue に対応する**。各節が `## 「呼び名」— 状態（工程記録n件）` ＋ `本文: <起票案のパス>` で始まるので、
   **`gh issue create --body-file <本文のパス>` → 返ってきた番号に対して、下の行を上から `gh issue comment <n> --body-file <パス>`** と打てば終わります
2. **順番が工程どおり**（V41・V42 で実測）。ファイル名の日付で並べると崩れる箇所（同日に複数の単位が進んだ日）も正しく並びます

4. **未コミットがあれば止まる**（V43）。⚠️ **投函の途中で順序が不定のまま進むことがありません**
5. パスは**リポジトリ相対**でそのまま `--body-file` に渡せます（`docs/design/…`）

⚠️ **足りないもの（本単位の範囲外・設計どおり）**:

- **issue のタイトル・ラベルは出ません**（起票案の見出しの直下にある「起票時」の記載＝§11 の移行で入れたもの）。**本文を開けば分かる**ので、投函の妨げにはなりません

  ⭐ 途中で中断したら、**索引 §2 の手順のほうに「どこまで投函したか」を書く**運用になります
