## 1. 症状と実測

### 1-1. 何が起きているか

公式APIのフレーバーテキストは **2箇所**に入りうる:

| 置き場 | 枚数(2,494枚中) |
|---|---:|
| トップレベル `card.flavor` が非空 | 614 |
| `card.flavor` は無い/空白だが **`editions[].flavor` が非空** | **586** |
| どこにも非空が無い | 1,294(うち**2枚は空白1文字**を持つ) |

サイト側は **`card.flavor` しか見ていない**ため、586枚は**画面のどこにも出ない**
(うち112枚は和訳が入ったので日本語だけが出ている＝§1-4)。

### 1-2. 実測(2026-08-20・スナップショット2,494枚)

⭐ 骨子(`issue反映待ち_2026-08-19.md`)の数字を**完全に再現した**。

| 状態 | 枚数 |
|---|---:|
| 表示されている(原文 614 + 和訳 112) | **726** |
| ⚠️ **原文が版側にしか無く、和訳も無いため何も出ない** | **474** |
| ⚠️ **中身が無いのに空白1文字のせいで空枠が出る** | **1**(`virgil-altered-future`) |
| フレーバー自体が無い | 1,293 |

⭐ 骨子の「726 / **473** / **2**」との差は **`zinn-volnia-abbess` をどちらに数えるか**だけで、
**同じ実測**である(このカードは `card.flavor` が空白1文字・`editions[].flavor` に原文があるため、
**空枠が出ていると同時に原文が出ていない**)。本設計書は**原文の有無**を主として上表の数え方を採る。

修正後に出力が変わるカードは **475枚**(内訳: **新たに原文が出る 474** / **空枠が消える 1**)。
**475枚すべてに `cards/<slug>/index.html` が実在する**ことを確認済み(＝差分は475ファイル)。

### 1-3. 空枠2枚の中身

| slug | `card.flavor` | `editions[].flavor` | 修正後 |
|---|---|---|---|
| `zinn-volnia-abbess` | `" "`(空白) | `“If the price of brilliance is to burn, then so be it.”` | **原文が出る** |

⚠️ **`||` だけでは直らない。** `" "` は truthy なので、空白を falsy として扱う判定が要る。

### 1-4. なぜ今まで気づかなかったか

⚠️ **和訳を入れると出るようになるため、翻訳作業では露見しない。**
#73 バッチ2で96枚のフレーバーが表示されるようになったのは**訳を入れたからで、経路が直ったわけではない**。

⭐ **同じ「未訳」でも表示が割れる**のがこの不具合の本質: フレーバーがトップレベルにあれば
英語原文が出るのに、`editions[]` 側にしか無いと**何も出ない**。

## 2. 原因

### 2-1. フレーバーの取り出し方が消費側3箇所で**バラバラ**

| # | 場所 | 現在の式 | `editions` を見るか |
|---|---|---|---|
| 1 | `scripts/build-card-pages.mjs:368`(静的カードページ) | `(t && t.flavor) \|\| card.flavor` | ❌ |
| 2 | `shared/js/card-detail.js:237`(詳細モーダル) | `(t && t.flavor) \|\| card.flavor` | ❌ |
| 3 | `shared/js/card-i18n.js:335`(`backFace()`・裏面) | `b.flavor \|\| bed.flavor \|\| null` | ⭕ **見ている** |

⭐ **3 だけが正しい形を知っていた**。つまり「版側にもフレーバーがある」ことは実装済みの箇所があり、
**1・2 に伝わらなかった**のが取りこぼしの実態。

⚠️ **ただし 3 は描画されていない。** `backFace()` は `flavor` を組み立てているが、
詳細モーダルの裏面ブロック(`card-detail.js:325〜`)も静的ページの裏面ブロック
(`build-card-pages.mjs:389〜`)も**名前・画像・効果しか出さない**。**死んだフィールド**である
(→ §8-2)。

### 2-2. 骨子の修正案では **1箇所に寄せられていない**

骨子は「両方の消費側を同じ形に」としていたが、**同じ式を2箇所にコピーする**形だった。
⚠️ それでは**3箇所目(`backFace`)との食い違いが残り**、次に増えたときまた割れる。

⭐ このリポジトリには**先例がある**: シーズン禁止の判定は
**`seasonalBanState()` 1箇所**に集約され、ブラウザ5面とビルドが共用している(CLAUDE.md)。
`shared/js/card-i18n.js` は **ブラウザとビルドの両方が評価する共有モジュール**
(ビルドは `scripts/lib/page-i18n.mjs` 経由)なので、**ここに関数を1本置けば3箇所とも同じ規則で動く**。

### 2-3. ⚠️ **「最初の非空を採る」は決定的ではない**(骨子に無い論点)

実測: **110枚は版によってフレーバーの文面が違う**(同一文面の重複は別に96枚)。

```text
acolyte-of-cultivation
  AMB(2024-10-11) → "The pursuit of transcendence by any means…"
  P25(2025-02-06) → "Heed the call of the immortal."
```

⚠️ **`editions` の配列順は公式API側で入れ替わる**(CLAUDE.md・#71 実測:
「既存カードの `editions` 配列の並び替え・画像URLの入れ替えが無関係な差分として現れる」)。
配列順で拾うと、**中身が変わっていない日に生成物の差分が出て、cronが毎日ノイズコミットを作る**
(「出力は決定的でなければならない」に反する)。

実測: **配列順ルールと初出順ルールで結果が変わるのは65枚**。⭐ **無視できない規模**。

## 3. 方針判断: 日本語サイトに英語原文を出すか

⭐ **出す**(＝473枚に英語フレーバーを表示する)。根拠:

1. **既存の挙動がすでにそうなっている。** 現在表示されている726枚のうち、**日本語訳があるのは117枚だけ**で、
   **残り609枚は英語原文がそのまま出ている**。出さない選択は**現状の726枚から英語を消す**ことになり、
   影響が逆に大きい
2. `data/translations.js` 冒頭に明記された設計思想 —
   **「訳が無いカードは英語原文のまま『翻訳募集中』バッジで表示されます」**
3. **表示の割れを直す**のがこのissueの目的で、「原文があるのに版の置き場所によって出たり出なかったりする」
   という**一貫性の欠如**こそが不具合

⚠️ **ユーザーが承認時に「出さない」と決めた場合**でも、**空枠2枚(§1-3)は直す**。
その場合の変更は `virgil-altered-future` / `zinn-volnia-abbess` の2ファイルのみになる。

## 4. 変更内容

### 4-1. `shared/js/card-i18n.js` に `flavorOf(card, t)` を新設し、公開する

```js
// フレーバーテキストの取り出し(#未採番)。
// ⚠ 置き場が2つある: トップレベル card.flavor と版ごとの editions[].flavor。
//    後者しか持たないカードが473枚あるため、両方を見ないと「原文があるのに出ない」状態になる。
// ⚠ 空白1文字(" ")を持つカードが実在する。truthy なので || では弾けず、空の枠が描画される。
// ⚠ 版によって文面が違うカードが110枚ある。editions の配列順は公式API側で入れ替わるため、
//    配列順で拾うと出力が非決定的になり、cronが毎日ノイズコミットを作る。→ 初出の版に固定する。
function flavorOf(card, t) {
  const pick = (v) => (typeof v === "string" && v.trim()) ? v.trim() : "";
  const jp = pick(t && t.flavor);
  if (jp) return jp;
  const own = pick(card && card.flavor);
  if (own) return own;
  const eds = ((card && card.editions) || []).filter((e) => pick(e.flavor));
  if (!eds.length) return "";
  // 初出(release_date の昇順)。⚠ 1970-01-01 は API 未設定を意味するので「不明」として末尾へ。
  // 同着は edition.slug の昇順で決める(slug は版ごとに一意なので必ず決着する)。
  const key = (e) => {
    const d = (e.set && e.set.release_date) || "";
    return (!d || d.startsWith("1970")) ? "9999" : d;
  };
  eds.sort((a, b) => (key(a) < key(b) ? -1 : key(a) > key(b) ? 1
    : String(a.slug) < String(b.slug) ? -1 : 1));
  return pick(eds[0].flavor);
}
```

- **戻り値の型を `""` に統一する**(現状は `null` / `undefined` / `" "` が混ざる)
- ⚠️ **`return` 文の並びに `t` を先に置く**(日本語訳が最優先。現状の優先順を変えない)
- 公開: モジュール末尾の `return { … }` に `flavorOf` を追加する

**実測で決めた規則の裏付け**:

| 論点 | 実測 | 決めたこと |
|---|---:|---|
| 版ごとに文面が違うカード | **110枚** | 配列順は使わない |
| 配列順ルールと初出順ルールで結果が違う | **65枚** | 初出順に固定 |
| `release_date` が `1970-01-01`(API未設定)の版を含む | **41枚** | 1970は「不明」として**末尾**へ |
| 最古が同着で文面が違う | **13枚** | `edition.slug` の昇順で決着 |

### 4-2. 消費側3箇所を `flavorOf()` に寄せる

| # | 場所 | 変更 |
|---|---|---|
| 1 | `scripts/build-card-pages.mjs:368` | `const flavor = CI.flavorOf(card, t);` |
| 2 | `shared/js/card-detail.js:237` | `const flavor = flavorOf(card, t);` |
| 3 | `shared/js/card-i18n.js:335`(`backFace`) | `flavor: flavorOf(b, null) \|\| pick(bed.flavor) \|\| null` ⚠️ 裏面は `b.editions` を持たないため、**版側は `bed`(その版)から拾う**形を維持する |

⚠️ **`build-card-pages.mjs` の `flavorBlock` は条件式を変えない**
(`flavor ? … : ""` のまま。`flavorOf` が `""` を返すので空枠は自動的に消える)。

### 4-3. 生成物の再生成

⚠️ **`build:cards` の前にスナップショットキャッシュを温める**(CLAUDE.md・#73の教訓)。

⚠️ **差分が475ファイル以外に出たら、それはドリフト**。混ぜずに戻す。

## 6. 保証の範囲と、残るリスク

| 守れること | 守れないこと |

| 原文フレーバーが**置き場所によらず**出る | ⚠️ **どの版のフレーバーを出すかは「初出」に固定**。ページで版を切り替えても**フレーバーは変わらない**(→ §8-1) |

| 静的ページとモーダルが**同じ文面**になる | ⚠️ **裏面のフレーバーは引き続き表示されない**(現状維持。→ §8-2) |

## 8. 未決事項

### 8-1. ページの版切り替えにフレーバーを追従させるか(**今回はやらない**)

カードページと詳細モーダルには**版(イラスト)の切り替え**がある(`cp-arts` / `#art=<set-slug>`)。
**110枚は版ごとに文面が違う**ので、本来は選択中の版のフレーバーを出すのが正しい。

⚠️ ただし**静的ページでは版ごとの文面をすべて埋め込む必要があり**、
**この不具合(何も出ない)の修正とは別の機能追加**になる。→ **別issueに切り出す**。

### 8-2. 裏面のフレーバーを表示するか(**今回はやらない**)

`backFace()` は `flavor` を組み立てているのに、**表示する側が無い**(§2-1)。
死んだフィールドを消すか、裏面ブロックに表示を足すかの判断が要る。→ **別issueに切り出す**。

### 8-3. 英語原文を出さない選択をする場合

§3 のとおり**出す**方針だが、ユーザーが覆した場合の変更は**空枠2枚のみ**になる
(`flavorOf()` の `editions` 探索を落とし、空白トリムだけを入れる)。
⭐ その場合でも **`flavorOf()` を1箇所に置く**設計は維持する(§2-2 の理由は変わらない)。
