### 1. `newestFirst()` の順序非依存化を別issueに切り出すか → ⭐ **起票する**

- ⚠️ **公開面が実際に変わっている**。今回の14件のうち**5件で `og:image` が別の版に入れ替わった**＝
  SNSカードの絵柄が変わる。**表示の劣化ではないが、意図せず変わる**のが問題
- ⚠️ **放置すると再発し続ける**。公式APIが `editions` を並べ替えるたびに、
  **中身が変わっていないカードの生成物に差分が出て、cronがノイズコミットを作る**
  （＝ CLAUDE.md「出力は決定的でなければならない」への継続的な違反）
- ⭐ **本タスクが `flavorOf()` について解いた問題と同じ型が、隣の経路に残っている**。
  片方だけ直した状態で放置するのは、次に読む人に「決定性は担保済み」と誤読させる

⚠️ **起票文に「これで全部直る」と書かない**（レビュー担当の指摘どおり）。
**`prismspire-scepter` は公式APIの `collector_number` 訂正**であり、
**第2キーを足しても消えない**（画像URL・行順とも不変であることを設計担当も差分で確認した）。

⚠️ **ただし `小タスク` ではない。** 第2キーを足すと**同着の版を持つ全カードで代表画像・
`og:image`・収録セット表の行順が変わりうる**ため、**影響枚数の実測を設計の第一段に置く**。
どの版を先頭にするか（`slug` 昇順＝`#048A` 系が先頭 / 別の規則）も**未決事項**として残す。

→ **起票内容は `docs/design/未採番-版順序の非決定性/起票案_2026-08-26.md` に用意した。**

### 2. cron停止中の陳腐化67件の扱い → ⭐ **その理解で正しい。手で取り込まない**

**復旧後の初回cronが自動追従する**という理解は正しい。根拠:

- 陳腐化の内訳（カードページの裁定+30 / `cards/index.html` / セットページ8 / `sitemap.xml` /
  新規カード `jinzhuo-bands-of-virtue`）は、**すべてcronの `git add` 対象8パスの内側**にある
  （`npm run validate` の `cron git add paths in sync — 8パス` で列挙の一致は機械検査済み）
- 放置しても**表示は壊れない**（裁定が出ないだけ＝fail-open）

⚠️ **ただし、この理解には見落とされている前提が1つある。設計担当として追加する:**

> ⭐ **push は「復旧後の初回cronより前」に行う。** cronは `origin/main` に対して走るため、
> **未pushのまま初回cronが動くと、cronが `cards/**` を旧コードで再生成してコミットする**。
> その後に `git pull --rebase origin main` すると、**`a7125896` の `cards/**` 495ファイルと
> cronのコミットが同じファイルで衝突する**（今回の14ファイルはまさにその重なりの実例）。
> ⚠️ **cronは 03:00 JST。復旧した日のうちに push の可否を判断すると衝突を避けられる。**

⚠️ **PRD発売（2026-08-21）を停止中に跨いだ**ため、初回cronの自動コミットは
**通常より大きくなる**（新カードのページ・sitemapエントリが一括で入る）。
⭐ これは CLAUDE.md「新セットが出た日は数百〜数千ファイルがレビューなしで自動publishされる」の
**ユーザー承認済みの運用どおり**で、異常ではない。⚠️ ただし **`meta.sets` の追記（#40）は自動ではない**ので、
**復旧後にPRD系の新prefixが `meta.sets` に足りているかを人が確認する**こと。
