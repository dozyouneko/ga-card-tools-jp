## 1. このタスクで何をするか

**トップページ（`app.js`）で、検索のやり直し（`reset`）中に `#grid` を空にしたときにページが縮み、
ブラウザがスクロール位置を上限（0）へクランプしてしまうのを止める。**

- ⭐ **方針は案1（ユーザー承認済み・2026-09-02）＝「再描画中だけ `#grid` の高さを維持する（`min-height` を退避する）」。**
  **位置を復元するのではなく、クランプ自体を起こさない。**
- ⭐ **対象はトップだけ**（ユーザー決定・2026-09-28）。デッキ構築（`tools/deck-builder/app.js`）は触らない（→ §9）
- ⭐ **`style.css` は触らない**（→ §4-4。触らないことで `validate` の検査②③の罠を丸ごと避ける）
- ⭐ **`shared/js/card-search.js` も触らない**（→ §5-2。0件文言の一本化を壊さない）

### 1-1. なぜ「位置を復元する」方式（案2・案3）を採らないか（2026-09-02 のユーザー承認の理由）

1. ⭐ **原因を直接断つ**ので、操作の種類（並び替えだけ／絞り込みを広げた／狭めた）で場合分けしなくてよい
2. ⭐ **取得が長い経路でも破綻しない。** 実測（§3-4）で **レベル順（数値ソート・絞り込みなし）は 24.2 秒**
   グリッドが空のままだった。「取得完了後に復元する」設計だと**その 24 秒間ずっと 0** になる
3. ⚠️ **既存の正しい挙動（何も変えずにシートを閉じたら位置が保たれる）を壊しにくい**

### 1-2. ⭐ 残る論点（ユーザーが許容したうえで案1を選んでいる）

⚠️ **案1でも「並び替えだけ変えたとき、同じ位置に別のカードが来る」状態は残る。**
⭐ **ユーザーはこれを承知のうえで案1を選んでいる**（2026-09-02）。

- ⚠️ ⭐ **いま案2（一覧の先頭へ寄せる）を足さない。**
- ⭐ **§7 の実物確認で体感を見てから、必要なら「並び替えのみ案2」を後から足す余地だけ残す**
  （そのときは**別issue**にする。この設計書の範囲は案1だけ）

## 2. 主張の再測定（⭐ 2026-09-28・設計担当が自分で測った）

### 2-1. 症状（390x844・`scrollY=1500` から絞り込みチップを1つ押す）

| 時点 | `window.scrollY` | `document.scrollingElement.scrollHeight` |
|---|---:|---:|

| # | 場所（⚠️ 行番号では書かない） | コード |

| **②** | 同 **`onError(err, { reset })`** ⚠️ **issue 本文に無い** | `if (reset) { el.grid.innerHTML = ""; el.loadMore.hidden = true; }` |

### 2-3. ⚠️ ⭐ issue と食い違った点（4つ）

| # | issue の記述 | ⭐ 実測 |
|---|---|---|
| **A** | 症状は `window.scrollY` が 0 になること | ⚠️ ⭐ **PC幅（1200px以上）では `window.scrollY` は常に 0。スクロールコンテナは `#results`**（`body.page-top { overflow: hidden }` ＋ `.page-top #results { overflow-y: auto }`）。**1440x900 で `#results.scrollTop` が 1500 → 0 にクランプした**＝**同じ欠陥が別のコンテナで起きている**（→ §6-1 の指標はこれを吸収する） |

| **D** | （検証項目の期待値が未確定） | ⚠️ ⭐ **`scrollY` を期待値にすると JPモードで偽陽性になる**——ステータス行が1行→2行に増える（33px → 56px）と**スクロールアンカリングが `scrollY` を +23px 動かす**。⭐ **これは正しい挙動**（同じカードが目の前に留まる）なので、**指標は `#grid` の矩形上端にする**（→ §6-1） |

## 4. 実装（P1〜P4）

⚠️ **変更するのは `app.js` の1ファイルだけ。** ⭐ **`style.css` / `index.html` / `shared/` は触らない。**

### 4-1. P1 — 退避（`onStart` の中）

`onStart(reset)` の `if (reset) { … }` の中で、**`el.grid.innerHTML = ""` の直前**に高さを退避する。

- 測る値: **`el.grid.getBoundingClientRect().height` を `Math.ceil` した整数 px**
  - ⭐ `* { box-sizing: border-box }` なので**矩形高さ＝`min-height` の基準（ボーダーボックス）と一致する**
  - ⭐ `Math.ceil` にするのは**縮まない側へ丸める**ため（`Math.round` だと最大1px縮みうる）
- 書き方: ⭐ **CSSOM で書く**（`el.grid.style.setProperty("min-height", h + "px")`）
  - ⚠️ ⭐ **`setAttribute("style", …)` は使わない**——CSPが `style-src 'self'` なので
    **HTMLのstyle属性は使えない**（CLAUDE.md「環境の注意」）。⭐ **CSSOM は阻まれない**
    （前例: `app.js` が `--printbar-h` を `documentElement.style.setProperty()` で書いている。
    ⭐ **実測で min-height の適用を確認済み**＝§3-2）
- ⚠️ ⭐ **すでに退避中なら上書きしない**（`el.grid.style.minHeight` が空でないときは何もしない）。
  **絞り込みを連続で変えると `onStart` が2回続く**ことがあり、そのとき2回目は
  **空のグリッド（＝高さ 0 相当）を測ってしまう**ので、**1回目の退避を守る**

### 4-2. P2 — 解放（`onResults` の末尾）

`onResults` の**末尾**（`appendGrid` / `updateSearchStatus` / `el.loadMore.disabled = false` の**後**）で
`el.grid.style.removeProperty("min-height")` する。

- ⚠️ ⭐ **`appendGrid` より前に解放しない。** 先に解放すると**一瞬縮んでからまた伸びる**ので、
  その瞬間にクランプが起きて案1が丸ごと無意味になる（同一タスク内で「埋める → 解放」の順にする）
- ⚠️ ⭐ **件数に関わらず必ず解放する。** `appendGrid()` は `if (!cards.length) return;` で
  **0件のとき何もしない**ので、**`appendGrid` の中に解放を書くと 0件で永久に残る**（→ §5-1・§4-5）
- ⭐ `reset` が false（もっと見る）のときに呼ばれても**無害**（退避されていないので何も起きない）

### 4-3. P3 — 解放（`onError` の末尾）

`onError` の**末尾**で同じく解放する（⚠️ **`el.grid.innerHTML = ""` の後**）。

- ⭐ **ここでは「クランプさせるのが正しい」。** エラー文は `#status`（グリッドより上）に出るので、
  **退避したまま位置を保つと、ユーザーには空白しか見えず失敗に気づけない**。
  **解放してページを縮め、0 へクランプさせることでエラー文が読める**（実測: 解放した瞬間 `y` 1524 → 0）
- ⚠️ ⭐ **`onError` では退避しない**（`onStart` が既に退避しているので、測り直すと**退避後の高さ**を測る）

### 4-4. P4 — コメント（⚠️ `validate` の生テキスト走査に当たらない書き方で）

P1〜P3 のそれぞれに、**なぜ必要か**と**外したときの症状**を1〜3行で書く。⭐ **必須の内容**:

- 「`#grid` を空にするとページが縮み、ブラウザがスクロール位置を上限へ丸める（#94）」
- ⭐ 「**PC幅ではページではなく `#results` が縮む**ので、両方に効くよう `#grid` に置く」
- ⚠️ 「**解放を落とすと、空のグリッドのぶん縦に長い空白が残り続ける**（0件検索の直後がいちばん起きやすい）」

⚠️ ⭐ **コメントに書いてはいけない字面**（`npm run validate` が **exit 1** になる）:

| 禁じ手 | 当たる検査 |
|---|---|
| `onRemoveOne` に続くコロン | ① `onRemoveOne wiring in sync` |
| `PANE_MIN_WIDTH` への代入 | ② `pane threshold in sync` |
| `matchMedia` / `max-width:` の字面 | ③ `mobile band marker in sync` |
| `<ファイル名>.js:<行番号>` の形 | `no line-number refs in code comments` |

⭐ **参照は関数名で書く**（例: `card-search.js の run()`）。
⭐ **`style.css` を触らないので、`MOBILE-BAND:START` マーカーの罠（`*/` と `@media` の間にコメントを置けない）には当たらない。**

### 4-5. ⚠️ ⭐ 「戻し忘れ」が起きたときどう見えるか（＝失敗の見え方）

⭐ **実測した**（0件検索で解放を止めた場合・390x844）:

| | 解放あり（正） | ⚠️ 解放なし（戻し忘れ） |
|---|---:|---:|
| `#grid` の高さ | **24px**（padding のみ） | ⚠️ **10,139px** |
| `scrollHeight` | **844px** | ⚠️ **10,714px** |
| `scrollY` | **0**（0件文言が読める） | ⚠️ **1500**（⭐ **画面は真っ白。下端まで送っても何も無い**） |

- ⚠️ ⭐ **「空白の海」になる。** 0件文言は画面外の `#status` にあるので、
  **ユーザーには「真っ白で何も出ない壊れたページ」に見える**（エラーも警告も出ない＝無言）
- ⭐ **ただし次の検索で自己回復する**（`onStart` が退避を上書きせず保持し、その検索の
  `onResults` / `onError` が解放するため）。**恒久化はしない**
- ⭐ **`onStart` の後に `onResults` / `onError` のどちらも来ない経路は、いまは無い**
  （設計担当が `shared/js/card-search.js` の `run()` を全部読んで確認した）:
  - `elementAndBlocked()` の早期 return は **`onResults([], { blocked: "element-and" })` を呼ぶ**
  - `mySeq !== seq` の早期 return（3箇所）は**新しい `run()` が既に `onStart` を呼んで退避の持ち主になっている**ので、
    その新しい `run()` の `onResults` / `onError` が解放する
  - ⚠️ ⭐ **`await loadEffects()` だけは `try` の外にある**が、`card-i18n.js` の `fetchJson()` が
    **`.catch(() => null)` を持つので reject しない**（＝いまは漏れない）。
    ⚠️ **`fetchJson()` の catch を外す変更が入ると、この経路が「空白の海」の恒久化に化ける**

## 6. 検証項目（⚠️ 期待値は「一致する相手」と許容差で書く）

### 6-1. ⭐ 位置の判定に使う指標（これを間違えると偽陽性・偽陰性が出る）

⭐ **`#grid.getBoundingClientRect().top`（＝グリッドの上端が画面のどこにあるか）を操作の前後で比べる。**

```js
const gridTop = () => Math.round(document.getElementById("grid").getBoundingClientRect().top);
```

- ⭐ **なぜ `scrollY` ではないのか（2つの理由・どちらも実測）**:
  1. ⚠️ **PC幅では `window.scrollY` は常に 0**（スクロールコンテナが `#results`）。
     `scrollY` を見ると **PC では「常に合格」になる**（＝偽陰性）
  2. ⚠️ **JPモードでは正しく動いていても `scrollY` が +23px 動く**（ステータス行が 33px → 56px に
     折り返し、**ブラウザのスクロールアンカリングが差分を足す**）。`scrollY` を見ると**偽陽性**になる。
     ⭐ **`gridTop` はどちらも吸収する**（JPモードでも `ΔgridTop = 0`）
- ⚠️ ⭐ **px の絶対値を判定基準にしない。** 判定するのは**差（`ΔgridTop`）だけ**

### 6-2. ⚠️ ⭐ `ΔgridTop = 0` にならない正しい場合（但し書き）

**新しい結果が短くて、操作前のスクロール量まで送れないとき**は、**足りないぶんだけずれるのが正しい**。

- 実測（390x844・結果 50件 → **7件**）: 解放後の `scrollHeight` は 2,320px・ビューポート 844px
  ＝**最大スクロール量 1,476px**。操作前は 1,500px だったので **`ΔgridTop = 25`**（= 1500 − 1476 + 丸め1px）
- ⭐ **期待値の書き方**: `ΔgridTop` は **0 ± 2px**。⭐ **ただし解放後の最大スクロール量
  （`scrollHeight − clientHeight`）が操作前のスクロール量を下回る場合は、
  `ΔgridTop` が「その差 ± 2px」に収まること**
