## 1. 背景

2026-08-08、コンテナが再構築され、設計セッションの開始時に次が失われていた。

- `gh` CLI **本体ごと**(コマンドが無い) → issue運用が一切できず、復旧手順を手探りで組み立てた
- `gh` の認証(`~/.config/gh/`)
- Playwright(**npmパッケージとChromium本体の両方**)
- `python3-pil` / `fonts-noto-cjk`
- Claude Code のメモリー(`~/.claude/projects/-workspaces-claude-test-vsc/memory/`)
- **`~/.cloudflare-token`**

issue #9 は当初「手順書の整備」だったが、**再構築のたびに人間とAIが同じ手作業を繰り返している**のが実態で、
手順書だけでは「読む・思い出す」コストが残る。本設計では**復旧をスクリプト化して
`postCreateCommand` に組み込み、再構築が自己修復する**ようにしたうえで、
自動化できない残りを手順書に集約する。

> 📌 スコープ判断はユーザー決定(2026-08-08): 「手順書+復旧スクリプトをpostCreateに組込」、
> 自動復旧の対象は **gh CLI / Playwright / python3-pil・fonts-noto-cjk / 復旧状態の診断表示** の4つすべて。

⚠️ **本節は 2026-08-08 に実測した結果であり、推測を含まない。** 設計・手順書の記述はすべてこの表を根拠とする。

### 2.1 マウント構成(実測)


### 2.4 ⚠️ `node_modules/` は残るのに Playwright だけ消えていた理由

`node_modules/` はバインドマウント上なので再構築では消えない。にもかかわらず Playwright が
無かったのは、**`npm install` が `--no-save` で入った extraneous パッケージを prune するため**。

- `playwright` は `package.json` に無い(実測: `devDependencies` は `wrangler` のみ)
- `postCreateCommand` は毎回 `npm install` を実行する
- → **再構築のたびに Playwright は必ず削除される**

⭐ **この性質は再構築時だけの話ではない。平常時に `npm install` を打っても同じく消える。**
手順書とCLAUDE.mdの両方に明記し、再導入コマンド(`npm run setup:env`)を案内する。

### 2.5 補足: `~/.gitconfig` は VS Code がホストから自動コピーする

`~/.gitconfig` は overlayfs 上にあるが、再構築後も存在した(mtime はコンテナ起動19分後)。
中身に `name = DESKTOP-BI16SE2\User` とあり、**VS Code Dev Containers が Windows ホストの
gitconfig をコピーしている**。実効値の出どころは:

```
$ git config --show-origin --get user.name
file:.git/config        dozyouneko          ← バインドマウント上。残る
$ git config --show-origin --get user.email
file:/home/node/.gitconfig  1020dozyouneko@gmail.com   ← ホストからのコピーに依存
```

⚠️ **コミットのメールアドレスだけがホスト環境に依存している**という隠れ依存がある。
自動復旧の対象外(壊れていない)だが、**診断表示で実効値を出して気づけるようにする**。

## 4. 方針

1. **冪等な復旧スクリプト `.devcontainer/setup.sh` を新設**し、`postCreateCommand` から呼ぶ
2. **スクリプトは絶対にコンテナ作成を失敗させない**(全ステップを失敗許容・常に exit 0)
3. **自動化できないもの(認証・シークレット・メモリー)は診断表示で明示**し、手順書へ誘導する
4. `docs/dev-setup.md` に**「コンテナ再構築」の節を新設**する(既存はPC故障前提で粒度が合っていない)
5. `CLAUDE.md` の環境記述は**手順書へ参照を寄せ**、誤記を訂正する

### 4.1 ⚠️ `package.json` の `dependencies` / `devDependencies` は変更しない

Playwright を `devDependencies` に入れれば prune 問題は消えるが、**採用しない**。

- `wrangler.toml` は `pages_build_output_dir = "."`。Cloudflare Pages のビルドが
  `npm install` を実行した場合、**`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD` が効かない本番ビルド環境で
  Chromium(約150MB)のダウンロードが走る**可能性がある
- 本番デプロイを遅くする/壊すリスクを、開発利便のために負う理由が無い
- → **`npm install --no-save --no-package-lock` でスクリプトから入れる**(4.2 の理由も参照)

`scripts` への1行追加(`setup:env`)のみ行う。これはインストール副作用が無く、Pagesに影響しない。

### 4.2 ⚠️ `package-lock.json` を汚さない

`npm install --no-save` だけでは **`package-lock.json` が更新されうる**。
必ず **`--no-package-lock` を併用**する。

> 検証項目 V6 で「setup.sh 実行前後で `git status --short` の出力が一致すること」を確認する。

## 6. `.devcontainer/setup.sh` の仕様

### 6.1 全体の作法

- `#!/usr/bin/env bash`。**`set -e` は使わない**(1ステップの失敗で全体が止まるため)
- 各ステップは関数にし、`run_step <id> <説明> <関数名>` の形で呼ぶ。
  関数が非0で戻っても記録して次へ進む
- **スクリプト全体は必ず `exit 0`**
- 出力は日本語。**シークレットの値は絶対に出力しない**(有無だけを出す)
- リポジトリルートはスクリプト位置から解決する(`cd "$(dirname "$0")/.."`)。clone先に依存しない

### 6.2 テスト用の環境変数

| 変数 | 意味 |
| --- | --- |
| `GA_SETUP_SIMULATE_FAILURE=<step-id>` | 指定ステップを強制的に失敗させる(カンマ区切りで複数)。**失敗耐性の検証用** |
| `GA_SETUP_SKIP=<step-id>` | 指定ステップをスキップ(カンマ区切り)。Playwright を省いて短時間で回す用 |

> 検証(V2)でレビュー担当がコードを書き換えずに失敗系を再現できるようにするための口。
> ⚠️ **レビュー担当はコードを直さない**規約があるため、この口が無いと失敗耐性が検証できない。

### 6.3 ステップ定義

| id | 内容 | スキップ条件(冪等性) | 目安 |
| --- | --- | --- | --- |
| `gh` | GitHub CLI | `command -v gh` が成功 | 約30秒 |
| `apt` | `python3-pil` / `fonts-noto-cjk` | 🔄 **1.2 訂正**: `dpkg -s` の**出力**が `^Status: install ok installed` に一致(両方) | 約60秒 |
| `playwright` | npmパッケージ + Chromium | `node_modules/playwright` と `~/.cache/ms-playwright/chromium-*` が**両方**存在 | 約2〜4分 |
| `diag` | 診断表示 | (常に実行) | 即時 |

#### S1: `gh`

```bash
sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
  | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt-get update -qq
sudo apt-get install -y gh
```

⚠️ **`sources.list.d/github-cli.list` は `tee` で上書きする**(`>>` で追記すると再実行で重複行になる)。
2026-08-08 にこの手順で 2.97.0 の導入を実施済み。

#### S2: aptパッケージ

```bash
sudo apt-get install -y python3-pil fonts-noto-cjk
```

##### ⚠️ 1.2 訂正: 導入判定に `dpkg -s` の**終了コード**を使ってはいけない

1.0/1.1 は「`dpkg -s` が成功」と書いていたが**誤り**。実装・レビューの双方が実測で確認した:

```text
$ sudo apt-get remove -y fonts-noto-cjk    # purge しないので設定ファイルが残る
$ dpkg -s fonts-noto-cjk | grep ^Status
Status: deinstall ok config-files          # ← 実体は消えているのに exit 0
```

⭐ **この誤りを放置すると「診断は ✅ を出すのに実際は使えない」状態を apt 側で再生産する**
(＝本設計が S3 で潰したのと同じ形)。正しくは**出力を見る**:

```bash
pkg_installed() { dpkg -s "$1" 2>/dev/null | grep -q '^Status: install ok installed'; }
```

> レビューでの裏取り: このコンテナに実在した `rc`(config-files)状態の `subversion` で
> 旧判定=「導入済み」/ 新判定=「未導入」となることを確認済み。

`apt-get update` は S1 で実行済みだが、S1 がスキップされた場合に備えて
**S2 の中でも未実行なら1回だけ実行する**(フラグ変数で二重実行を避ける)。

#### S3: Playwright

> 🔄 **1.1 で変更**(実装報告 `f283ce48` の V5 失敗を受けて確定)。

```bash
# S3-a: Chromium の共有ライブラリ(案A: 必要な14個だけを指定)
sudo apt-get install -y libasound2 libatk1.0-0 libatk-bridge2.0-0 libatspi2.0-0 libcups2 \
  libdbus-1-3 libgbm1 libnspr4 libnss3 libxcomposite1 libxdamage1 libxfixes3 libxkbcommon0 libxrandr2

```

- バージョンは **`1.61.1` に固定**(CLAUDE.md の既存記載と一致させる)
- ⚠️ **`npx playwright install-deps` は使わない**(案B: 106パッケージ・91.2MB。
  `xvfb`・mesa一式・日中泰フォントまで入る)。案Aは **54パッケージ・11.3MB で起動実測済み**
- ⚠️ **共有ライブラリは S2 でも S2b でもなく S3 に入れる。** `GA_SETUP_SKIP=playwright` を指定したとき、
  Playwright 関連が**まとめてスキップされる**必要があるため

##### ⭐ S3 のスキップ条件に「不足ライブラリ0個」を含める(自己修復)

案Aの弱点は**追随性**(Playwright を更新して必要ライブラリが増えると、手で足すまで壊れる)。
これを**スキップ条件で解消する**:

```
step_playwright_check() =
    node_modules/playwright が存在
  かつ ~/.cache/ms-playwright/chromium-* が存在
  かつ 不足共有ライブラリが 0 個        ← 1.1 で追加
```

不足数は **`ldd` の出力で `not found` を数える**(Chromiumを起動しないので高速・決定的)。対象は
`chrome-headless-shell` と `chrome` の**両方**。

これにより、将来 Playwright の更新で不足が生じた場合、S3 は**スキップされずに再実行され、
apt が自動で不足を埋める**。⚠️ この挙動が本設計における案A採用の前提条件であり、**省略不可**。

##### 不足が埋まらなかった場合の脱出口

S3-a を実行してもなお不足が残る場合(＝案Aの14個では足りなくなった場合)、
**診断表示で案Bのコマンドを案内する**(自動実行はしない):

```
[自動] Playwright         : ❌ 共有ライブラリが 3 個不足 → npx playwright install-deps chromium
```

## 7. `devcontainer.json` の変更

### 7.1 ⚠️ 呼び出し順序(最重要)

現在の `postCreateCommand` は `;` 区切りで次の順に動く:

1. `npm install`
2. `npm install -g @anthropic-ai/claude-code`
3. **Norton ルートCAをシステム信頼ストアへ登録**(`update-ca-certificates`)
4. `~/.bash_aliases` に `aliases.sh` の source 行を登録

`setup.sh` は **必ず 3 より後**に呼ぶ。理由:

- S1 は `https://cli.github.com` から keyring を `curl` で取得する
- NortonのHTTPS検査があるため、**証明書登録前に実行すると TLS エラーで失敗する**

また `npm install` より後である必要もある(2.4 の prune で Playwright が消えるため)。
→ **既存の4ステップの後ろに追加する**のが唯一正しい位置。

### 7.2 変更内容

`postCreateCommand` の末尾に次を追加する:

```
; bash .devcontainer/setup.sh || true
```

- `|| true` を付け、**万一 setup.sh 自体が起動できなくてもコンテナ作成を失敗させない**
- ⚠️ `setup.sh` に実行権限が無くても動くよう **`bash <path>` の形で呼ぶ**
  (バインドマウントの権限が Windows 側の都合で落ちることがあるため)

### 7.3 コンテナ作成時間への影響

現状の作成時間に **約3〜5分**が加算される(内訳: gh 約30秒 / apt 約60秒 / Playwright 約2〜4分)。
再構築は頻度が低く、**手作業の探索コストのほうが大きい**と判断してユーザー承認済み。
