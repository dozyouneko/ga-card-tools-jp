## 4. ⚠️⚠️ 最大の制約 — 生成物2,743ファイルに触らない

`.cp-site`（大会・カード個別・セットページのヘッダ）は **2,743個のHTMLに埋め込まれている**。

```
grep -rl 'class="cp-site"' --include=*.html .  →  2,743件
  cards/<slug>/index.html   … カード個別 2,240枚
  sets/<set>/index.html     … セット 56枚
  tournaments/**/index.html … 大会 426ページほか
```

→ ⭐ **本設計の変更は全部CSSだけで完結させる。HTMLに手を入れると全件の再生成とコミットが必要になる。**
（`.cp-brand` の文字を隠すのも `font-size:0` で行い、マークアップは変えない）

✅ **`.site-header` 側は `index.html` と `404.html` の2枚だけ**なので、ラベル短縮（論点2）のHTML変更はここに閉じる。

### 4.1 ⚠️⚠️ `.cp-*` のCSSは**2ファイルに重複していて、しかも両方とも「生成物」**

| 配信されるCSS | 読むページ | **本当の編集先（生成元）** |
|---|---|---|
| `cards/cards.css` | カード個別 2,240枚 ＋ セット 56枚 ＋ `cards/index.html` | **`scripts/build-card-pages.mjs` の `CARDS_CSS`（546行目〜）** |
| `tournaments/tournaments.css` | 大会 426ページほか | **`scripts/build-tournament-pages.mjs` の `CSS`（855行目〜）** |

両ファイルとも1行目に `生成元: scripts/build-…-pages.mjs` と書かれており、
`writeFileSync()` で丸ごと上書きされる（`build-card-pages.mjs:785` / `build-tournament-pages.mjs:1420`）。

> ⚠️⚠️ **`cards/cards.css` や `tournaments/tournaments.css` を直接編集してはいけない。**
> **日次cron（毎朝03:00 JST）が `build:cards` を実行して `cards/` をコミットするため、
> 手編集は翌朝に黙って巻き戻る。** エラーも差分も出ないので気づけない
> （CLAUDE.md「生成ロジックを変えたら生成物も再生成してコミットする」の裏返し）。

**手順は必ずこの順で:**

1. `scripts/build-card-pages.mjs` の `CARDS_CSS` を編集
2. `scripts/build-tournament-pages.mjs` の `CSS` を編集
3. `npm run build:cards` → `cards/cards.css` が更新される
4. `node scripts/build-tournament-pages.mjs --no-scan` → `tournaments/tournaments.css` が更新される
5. **生成物もコミットする**（`cards/cards.css` `tournaments/tournaments.css`）

⚠️ **手順4のあと `data/tournaments/index.json` の `updatedAt` だけが書き換わる**ので、
**`git checkout -- data/tournaments/index.json` で戻してからコミットする**（CLAUDE.md の既知の注意）。

✅ **HTMLの中身は変わらないので、2,743枚のHTMLには差分が出ないはず**（出力は決定的）。
⚠️ ただし **2026-08-21 はシーズン禁止の発効日**で対象カードのページだけ表示が変わる。
**その日に作業するなら差分の増加は想定内**（本件とは無関係）。

⚠️ **片方だけ直すと、カードページと大会ページでヘッダの高さが食い違う。必ず両方に入れる。**
⚠️ 共通CSSへの切り出しは**本件では行わない**（`<link>` の追加＝生成物2,743件のHTML再生成になるため）。

## 6. 実装の落とし穴（**モックで実際に踏んだもの**）

### 6.1 ⚠️⚠️ `min-width:0` は `.brand` だけでは足りない

flexの子は既定が `min-width:auto` で**縮まない**。`.brand` に付けても、
**その中の `<div>`（h1 と タグラインの入れ物）に付けないと縮まず、320px でヘッダが横にはみ出す**。

さらに悪いことに、`style.css` は **`html, body { overflow-x: hidden }`**（302行目）なので、
はみ出しはスクロールバーではなく**「ツール ▾」ボタンが画面外に消える**形で現れる。
→ **`.brand > div { min-width: 0 }` を必ず入れる。**

### 6.2 ⚠️ ツールボタンのタップ領域が 45px → 36px に縮む

案Bはボタンを小さくするため、`min-height:44px` を入れないと**36px**になる（モック実測）。
`min-height:44px` を入れた場合の代償は**ヘッダ +8px（65→73px）**だけ。**必ず入れる。**

> ⭐ 一方 **大会ページの nav リンクが 24px 高しかないのは本番の既存仕様**で、案Bによる劣化ではない
> （本番実測で 140×24px）。**本件では直さない**が、別途手当てする余地はある。

### 6.3 ⚠️ 大会ページは「`flex-wrap:nowrap` にするだけ」では**悪化する**

最初にそれだけ試したところ **92px → 102px** になった。375px では
「ブランド名（約200px）＋ nav（約250px）」が物理的に1行に収まらず、**ブランド名が2行に折り返す**ため。
→ **§5.3 のとおりブランドの文字を落とすところまでやって初めて効果が出る。**

### 6.4 ⚠️ 404ページにも同じCSSが当たる

`404.html` も `/style.css` を読み、`.site-header` / `.brand` / `.tagline` を持つ。
ただし**`.tools-toggle` と `.header-actions` は無く、`.brand` は `<div>` ではなく `<a class="brand brand-link">`**。
→ タグライン非表示・h1縮小・マーク縮小は**404にも効く（望ましい）**。`nowrap` は子が1つなので無害。
⚠️ **`404.html` は任意のパスで配信されるため、確認は本番でパスを変えて行う**（#23）。

### 6.5 ⚠️⚠️ **第1版の誤り** — `.header-actions` を `nowrap` にすると 641〜1024px でリンクが隠れる

第1版は `.header-actions { flex-wrap:nowrap; overflow-x:auto; }` としていたが、
**モックを1280pxでしか確認しておらず、その間の幅を見ていなかった。**

メディアクエリの境界は **640px** なので、**641px〜1279px はPCのルールが当たる**。
そこでは「ブランド ＋ ツールリンク5本」が1行に収まらず、**リンクが右へはみ出して隠れる**。

| 幅 | 変更前（本番） | 第1版の実装 | **第2版（`flex-wrap:wrap`）** |
|---|---|---|---|
| 641px | 209px・**全リンク可視** | 121px・❌ **270px 隠れる** | 144px・✅ 全リンク可視（3行） |
| 768px | 209px・全リンク可視 | 121px・❌ **195px 隠れる** | **121px**・✅ 全リンク可視（2行） |
| 900px | 209px・全リンク可視 | 94px・❌ 117px 隠れる | 102px・✅ 全リンク可視（2行） |
| 1024px | 150px・全リンク可視 | 94px・❌ 43px 隠れる | 102px・✅ 全リンク可視（2行） |
| 1280px | 150px・全リンク可視 | 74px・✅ | **74px**・✅（1行・変化なし） |

⭐ **`flex-wrap:wrap` に戻しても 1280px の効果（150→74px）はそのまま**で、
**変更前と比べれば全幅で依然として大幅に短い**（768px は 209→121px）。

⚠️ **`overflow-x:auto` も外す。** 残すと「隠れているものがある」ことに気づけない状態が再発し得る。

> ⭐ **教訓: メディアクエリの境界（640px）のすぐ上を必ず測る。**
> モックの「PC」を1280pxだけで代表させると、**641〜1024px という一番窮屈な帯が丸ごと抜ける。**
