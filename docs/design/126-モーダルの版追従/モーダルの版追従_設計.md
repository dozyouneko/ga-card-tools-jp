## 3. いまのコード（⭐ 経路の棚卸し）

### 3-1. 「どの版で開くか」を決めている場所は1つだけ

`shared/js/card-detail.js` の `render(card)`:

```js
const imgs = cardImages(card);
const initialAi = Math.min(Math.max(opts.preferredArtIndex ? opts.preferredArtIndex(imgs) : 0, 0), Math.max(imgs.length - 1, 0));
const img = imgs.length ? imgs[initialAi].url : null;   // ← 表面はここ
currentImgs = imgs; currentAi = initialAi;
```

⭐ **表面は `initialAi` に完全に従っている。** だから #126 は「`initialAi` を決めるクロージャに正しい値を届ける」話に尽きる。

### 3-2. ⚠️ 裏面だけが `initialAi` を見ていない

同ファイルの `renderBackFace(card)`:

```js
const back = backFace(card);                     // ← flipEdition(card) ＝「先頭の flip 版」の裏
const imgHtml = back.image ? `<img id="d-back-img" … src="${escapeHtml(back.image)}" …>` : …;
```

⭐ **`backFace(card)` は「カードの裏面はこれ」という版に依らない正規化**で、画像だけが先頭の版に固定されている。
⭐ サムネイルを押したときは追従する（`$("d-arts")` のハンドラが `btn.dataset.back` を使う）。
⚠️ **つまり「開いた瞬間だけ」ずれている。**

### 3-3. モーダルを開く経路の全件（⭐ 5つ）

| # | 画面 | 開き方 | 版の指定 | 版の選択UI |
|---|---|---|---|---|
| 1 | **トップの検索結果タイル** | `app.js`: `cardEl.addEventListener("click", () => GA_CARD_DETAIL.open(card))`（＋ keydown） | ⚠️ **何も渡していない**。`init()` の `preferredArtIndex: artIndexOf` が**いまの絞り込み**から導き直す | **🎨 あり**・🔄 あり |
| 2 | **トップの共有リンク** | `app.js`: `handleHash()` → `GA_CARD_DETAIL.openBySlug(slug)` | 同上（＝絞り込み） | なし |
| 3 | **デッキ構築の検索結果タイル** | `tools/deck-builder/app.js`: `openDetail(slug, activeSearchTab && { cond: activeSearchTab.artCond })` | ⚠️ **そのタブの `artCond` だけ** | **🎨 あり**・🔄 あり |
| 4 | **デッキ構築のデッキゾーン・共有画面** | `openDetail(slug, tileArtPick(tile))`（3箇所） | ⭐ **`{url}`＝タイルが表示しているURL**（#124 で実装済み） | 🎨 なし（⋯→🎨 でイラスト変更＝保存） |
| 5 | **大会デッキページ** | `tournaments/deck.js`: `GA_CARD_DETAIL.openBySlug(slug)` | 何も渡していない＝ `imgs[0]` | **なし**（タイルは常に `imgs[0]`） |

⭐ **直すのは 1・3 だけ**（#126）。2 は「絞り込みに追従」が正しい挙動で変えない。5 は版の選択という概念が無いので無関係（§4-4 で実測）。

### 3-4. ⭐ タイルは自分が表示している版のURLを既に持っている

| タイル | 属性 | 🎨 で更新されるか | 🔄 で更新されるか |
|---|---|---|---|
| トップ `.card` | `cardEl.dataset.artUrl` | ⭕ **される**（`app.js` の 🎨 ハンドラ） | ❌ されない（⭐ **表面のURLのまま＝これが正しい**） |
| デッキ構築 `.result` | `item.dataset.artUrl` | ⭕ **される** | ❌ されない（同上） |

⚠️ ⭐ **だから運ぶのは `dataset.artUrl` であって `img.src` ではない。**
`img.src` は #46（裏面一致）のとき**裏面URL**になっているので、それを渡すと `imgs[]` のどれにも当たらない
（#124 §4-4 が `img.src` 方式を却下した理由と同じ。⭐ **本件では「同じ理由がもう1画面でも成立する」ことが確定した**）。

### 3-5. 静的カードページ（`scripts/build-card-pages.mjs` 生成）

モーダルを持たず、**表面と裏面を静的に出す**:

```js
const mainImg = imgs.length ? imgs[0].url : null;                  // 表面 ＝ imgs[0]
```

```js
const select = (btn) => { main.src = btn.dataset.url; thumbs.forEach(…); };

```

⚠️ ⭐ **`.cp-thumb` は `data-back` を持っていない**ので、**裏面を更新する手段がそもそも無い**。

|---|---|

## 6. 論点と裁定

### 6-1. 論点1 — 裏面画像の決め方（#127）

| 案 | 形 | 評価 |
|---|---|---|
| **案A** | `renderBackFace()` で `imgs[initialAi].back || backFace(card).image` と書く（issue 本文の見通し） | △。⭐ 1行で済むが、⚠️ **サムネイル切替側（`btn.dataset.back`）と合わせて規則が2箇所になる**。しかも**切替側は `null` のとき前の画像が残る**という違う挙動を持っており、揃わない |
| ⭐ **案B 採用** | **`card-detail.js` に `backImageUrl(card)` を1本置き、初期描画とサムネイル切替の両方がそれを通る** | ⭐ **採用**。下記 |
| **案C** | サムネイル切替で `renderBackFace(currentCard)` を呼び直す | ❌ **却下**。⚠️ **裏面ブロックを作り直すと「英語原文を表示」の `<details>` の開閉がリセットされる**（`box.innerHTML` を丸ごと差し替えるため） |
| **案D** | `backFace(card)` 自体に版を渡す（`backFace(card, ai)`） | ❌ **却下**。⚠️ **`backFace()` の消費側は静的カードページ・モーダル・`backFace()` 経由のフレーバー等**で、版の概念を持たない呼び出し元にも引数が波及する。⚠️ **#107 の `orderedEditions()` 一本化を崩す方向** |

#### ⭐ 採用する形（案B）

```js
// 裏面画像のURL（#127）。選択中の版の裏面 → 無ければ既定版の裏面に倒す。
// ⭐ 初期描画とサムネイル切替の両方がここを通る＝規則を2箇所に書かない。
// ⭐ 倒す向きは backAction（🖨️ 裏面を印刷リストに追加）とまったく同じ（selection().back → back.image）。
function backImageUrl(card) {
  const sel = selection();
  const bf = backFace(card);
  return (sel && sel.back) || (bf && bf.image) || null;
}
```

- ⭐ **`selection()` を再利用するのが肝**。`selection()` は既に `currentImgs[currentAi].back` を返しており、
  **`backAction.onClick` がそれを使って印刷リストへ入れている**。⭐ **表示・印刷の2つが1つの出所に揃う**
- ⭐ **`backFace(card)` の集約は崩さない**（`backImageUrl()` が中で呼ぶ）。⚠️ **裏面の正規化（名前・効果等）は `backFace()` のまま**
- ⚠️ **呼び出し順**: `render(card)` は `currentAi` を設定（`card-detail.js` の `render()` 冒頭）したあと `renderBackFace(card)` を呼ぶので、
  `selection()` は常に「いま選ばれている版」を返す。⚠️ **この順序を入れ替えないこと**（入れ替えると裏面が前のカードの版で出る）
- ⚠️ **サムネイルのハンドラも `currentAi` を更新したあと**に `backImageUrl()` を呼ぶ。
  ⭐ `currentAi` は `indexOf.call($("d-arts").children, btn)` なので実在するボタンでは必ず ≥ 0

#### ⭐ `.art-thumb` の `data-back` は残す（画像の決定には使わない）

| 判断 | 理由 |
|---|---|
| ⭐ **残す** | ①**属性を消すと、外から読んでいる計測や将来の消費側を黙って壊す**（⚠️ **現に本設計の実測スクリプトが読んでいる**）②`currentImgs` が唯一の出所なので、残っていても**値が割れる余地が無い**（`data-back` も `selection().back` も `cardImages(card)` 由来） |
| ⚠️ **ただしコメントで明示する** | 「**画像の決定は `backImageUrl()` 1箇所**。この属性はサムネイル自身が持つ版の説明であって、描画の入力ではない」 |

### 6-2. 論点2 — `{url}` が解決できないときの落ち先（⚠️ ⭐ **画面ごとに違うのが正しい**）

### 6-4. 論点4 — トップページで「前に開いたタイルの版」が残らないようにする

```js
let detailArtPick = null;

```
