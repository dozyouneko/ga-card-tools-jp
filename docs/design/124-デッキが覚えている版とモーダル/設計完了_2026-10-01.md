## 3. 判断済み事項（⭐ 論点1〜4の結論）

| 論点 | 結論 |
|---|---|
| **1. 条件とURLを同じ引数に混ぜるか** | ⭐ **第2引数を「版の選び方」1オブジェクトに広げ、`{cond}` / `{url}` の排他にする**（設計書 §4-3）。⚠️ **値の形で見分ける案は却下**（`artCondOf()` がキーを増やした日に静かに壊れる）。⚠️ **引数を増やす案も却下**（位置引数3つは読めない） |
| **1b. URLの運び方** | ⭐ **タイルに `data-art-url` を持たせ、`tileArtPick(tile)` で読み戻す**。⚠️ **再導出しない**——⭐ **タイルは自分が表示しているURLを既に持っている**（`.gtile`・`#v-zones` とも描画時に `rowImageUrl()` を1回計算している）。⭐ 属性名は**検索結果タイル `.result` が既に使っている名前に合わせた** |
| **2. 一致しないときの倒し方** | ⭐ **`imgs[0]` に倒す（fail-open）**＝ `preferredArtIndex(imgs, null)` と同じ。⚠️ ⭐ **`{url}` を指定された経路は `cond` へ落ちない**——これで **#97 V4 の再発（デッキのカードが左ペインの条件で別の絵柄になる）をフォールバックの向きで構造的に塞ぐ**。⭐ 本番の該当行は **0行** |
| **2b. 既定の行（6,264行）が変わらない根拠** | ⭐ **構造**: `imageUrl(card)` も `cardImages()[0]` も同じ `orderedEditions()` の先頭。⭐ **実測**: スナップショット **2,495枚すべてで `imageUrl(card) === cardImages(card)[0].url`**（不一致 0） |
| **3. 両面（flip）／裏面URL** | ⭐ **`art_image` に裏面URLはUIからは入らない**（`openArtPicker` は表面のみ。裏面を選べる `openThumbPicker` の保存先は `decks.thumb_image`）。API直叩きなら入るが **`imgs[]` に一致せず §5 で `imgs[0]`**（実測: 一致インデックス **-1**）。⚠️ ⭐ **ただし別の発見**: 非先頭の版を選ぶと**表面は追従するが裏面は追従しない**（`card-detail.js` が初期の裏面を `backFace(card)` から取るため）。⭐ **これは #124 と無関係に今日すでに起きている**（トップの `/?q=Fabled+Azurite+Fatestone&set=P25` で実測: 表 `Wtx1yaLXi0`/裏 `fcfxhkqda6`）。⭐ **本番 0行**なので**本件では直さず派生候補にする**（→ 未決 N3） |
| **4. 検査を足すか** | ⭐ **足さないを勧める**（⚠️ **採否はユーザー**）。理由: ①**足すには `SCAN_SENTINELS` に `readers` を持たせる改修が先に要る**（#117 の規約「`readScan` が唯一の入口」＋「経路 × 全センチネル」。⭐ **1ファイルしか読まない4本目は exit 1 になる**）＝ **「塞ぐのに別の設計が要る」**＝ **#123 の射程** ②字面検査では **「渡す値がタイルとずれる」型を見られない**（破壊試験 B-3 で実演する） ③行動で測るには **`app.js` 用のDOMハーネス**が要る（#94 で既に「別の設計」と裁定済み） |

⚠️ **原本をスクラッチへ退避し `cp` で戻す**（⚠️ `git checkout --` を使わない）。**各ケース後に `git status --short` が空**であること。
