## 1. 問題（すべてコードで確認済み）

**トップページの印刷リストは、表示中・選択中のイラストを無視して常に「既定版（`editions[0]`）」を入れる。**

とくに**詳細モーダルには版を選ぶサムネイルUI（`.art-thumb`）があるのに、すぐ隣の
「🖨️ 印刷リストに追加」がその選択を捨てる**ため、「版を選んで印刷する」導線が成立していない。

### 1.1 壊れている経路は3つある

| # | 経路 | 現状のコード | 症状 |
|---|---|---|---|
| **P1** | 検索結果カードの `＋🖨️` | [`app.js:222`](../../../app.js) `addToPrint(card)` | 🎨 で版を切り替えても既定版が入る。**エキスパンション絞り込みで初期表示が変わっていても既定版**（`preferredArtIndex` の結果が届かない） |
| **P2** | 詳細モーダルの `🖨️ 印刷リストに追加` | [`app.js:603`](../../../app.js) `onClick: (card) => addToPrint(card)` | サムネイルで選んだ版が入らない |
| **P3** | 詳細モーダルの `🖨️ 裏面を印刷リストに追加` | [`app.js:608`](../../../app.js) `addToPrintItem(back.slug, jpName(back), back.image)` | ⚠️ **表示中の裏面画像は選択した版に追従しているのに**（`card-detail.js:435-436` が `d-back-img.src` を書き換える）、**追加されるのは `backFace(card)` が返す既定版の裏面** |

根本は共通で、**「いま表示している版」がどこにも保持されず `addToPrint()` に届いていない**こと。

```js
// app.js:296-300（現状）
function addToPrint(card) {
  const image = imageUrl(card);   // ← firstEdition(card) = editions[0] 固定
  if (!image) return;
  addToPrintItem(card.slug || card.uuid, jpName(card), image);
}
```

### 1.2 ⭐ もう1つ、隠れた欠陥がある — 印刷リストの同一性が「slug」

仮に P1〜P3 で正しい画像URLを渡せるようにしても、**それだけでは直らない**。

```js
// app.js:303-311（現状）
function addToPrintItem(id, name, image) {
  const existing = printList.find((x) => x.id === id);   // ← slug だけで同一判定
  if (existing) existing.qty = Math.min(existing.qty + 1, 99);   // ← image は捨てられる
  else printList.push({ id, name, image, qty: 1 });
}
```

**同じカードの別の版を追加すると、既存の行の数量が増えるだけで、画像は最初に入れた版のまま**になる。

再現（変更後に直っていることの確認にも使う）:

1. `火の精霊`（`spirit-of-fire`・全14版）の **ALC 版**を追加 → `{image: ALC, qty:1}`
2. モーダルで **DOA Alter 版**を選んで追加 → **`{image: ALC, qty:2}`**（⚠️ DOA Alter が消える）

→ **同一性キーを「カード」から「版（画像）」に変えないと、#42 は直らない。**

## 2. 目的

**「画面で見えているイラストが、そのまま印刷リストに入る」状態にする。**

| | 変更前 | 変更後 |
|---|---|---|
| 検索結果の 🎨 で切り替えた版 | ❌ 無視 | ✅ その版が入る |
| エキスパンション絞り込みで初期表示された版 | ❌ 無視 | ✅ その版が入る |
| 詳細モーダルのサムネイルで選んだ版 | ❌ 無視 | ✅ その版が入る |
| 同じカードの別の版を2つ | ❌ 1行に合算・先勝ち | ✅ **2行として別々に持てる** |
| 裏面の追加（両面カード） | ❌ 既定版の裏面 | ✅ 選択した版の裏面 |

**やらないこと**: デッキ構築ツール側の変更（#41 で対応済み）／印刷ボタンの位置（#26 で現状維持と決定済み）／
PDF生成ロジック（`shared/js/card-sheet.js`）の変更。

## 3. 設計

### 3.1 ⭐ 印刷リストの同一性キーを「画像URL」にする

**決定: `printList` の同一性を `id`（slug）から `image`（画像URL）に変える。**

理由と検討:

| 案 | 内容 | 判定 |
|---|---|---|
| **A** | **`image` を同一性キーにする** | ⭐ **採用**。画像URLは版ごとに一意で、カードをまたいでも衝突しない（`cardImages()` が `ed.image` で重複排除済み） |
| B | `id + "\|" + image` の複合キーを新しい項目として持つ | 区切り文字の扱いとDOM属性への埋め込みが増えるだけで、Aと結果が同じ |
| C | `id` のままにして、追加時に画像を上書きする | ⚠️ **後から追加した版が、先に入れた版の分まで書き換える**（3枚刷る予定のALC版が、DOA Alterを1枚足した瞬間に全部DOA Alterになる）。不可 |

⭐ **`printList` の項目の形は変えない**（`{ id, name, image, qty }` のまま）。
`image` を**キーとして使う**だけにする。これにより:

- ✅ **`localStorage`（`ga_print_list_v1`）の移行が不要**。既存の保存データはそのまま読める
- ✅ キーのバージョン（`_v1`）を上げなくてよい
- ✅ `id`（slug）は表示・デバッグ用として残る

⚠️ **`image` が空の項目は作らない**（現状どおり `if (!id || !image) return;` を維持）。キーが空になるため。

### 3.2 「表示中の版」の持ち方

#### P1: 検索結果カード — デッキ構築（#41）と同じ方式にする

[`tools/deck-builder/app.js:1190,1225`](../../../tools/deck-builder/app.js) の実装をそのまま移植する。

```js
// appendGrid() 内・cardEl を組み立てた直後
if (imgs.length) cardEl.dataset.artUrl = imgs[initialAi].url;   // ← 初期値。#41 の 1190 行と同じ

// 🎨 のクリックハンドラ内（既存の ai 更新の直後）
cardEl.dataset.artUrl = imgs[ai].url;                            // ← #41 の 1225 行と同じ

// ＋🖨️ のクリックハンドラ
addBtn.addEventListener("click", (e) => {
  e.stopPropagation();
  addToPrint(card, cardEl.dataset.artUrl || null);
});
```

⚠️ **初期値の代入（1行目）を省かないこと。** これが無いと、**エキスパンションで絞り込んで
初期表示が既定版以外になっている状態で 🎨 を一度も押さずに追加**したときに直らない
（issue #42 の「エキスパンションで絞り込んでも既定版」がこのケース）。

⚠️ **裏面（🔄）を表示中に ＋🖨️ を押しても、追加するのは表面**（現状の挙動を変えない）。
裏面の追加は詳細モーダルの専用ボタン（P3）から行う。**この点は変更しない。**

#### P2/P3: 詳細モーダル — 共有コンポーネントに選択状態を持たせる

`shared/js/card-detail.js` はモジュール内に選択状態を持っておらず、
サムネイルのクリックが `$("d-img").src` を書き換えるだけになっている（`card-detail.js:430-439`）。

**モジュール内に「選択中の版」を持ち、アクションのコールバックに第2引数で渡す。**

```js
// card-detail.js のモジュールスコープ
let currentAi = 0;      // 選択中の版の番号
let currentImgs = [];   // render() 時点の cardImages(card)

// render() の中（既存の initialAi 算出の直後）
currentImgs = imgs;
currentAi = initialAi;

// サムネイルのクリックハンドラ（既存処理に1行足す）
const idx = Array.prototype.indexOf.call($("d-arts").children, btn);
if (idx >= 0) currentAi = idx;

// アクションのコールバック
function selection() {
  const cur = currentImgs[currentAi] || null;
  return cur ? { url: cur.url, back: cur.back, index: currentAi, label: cur.label, prefix: cur.prefix } : null;
}
$("d-action").addEventListener("click", () => {
  if (currentCard && opts.action && opts.action.onClick) opts.action.onClick(currentCard, selection());
});
// 裏面ボタン（card-detail.js:353 付近）も同様に第2引数を渡す
```

**呼び出し側（`app.js:600-609`）**:

```js
action: {
  label: (card) => (imageUrl(card) ? "🖨️ 印刷リストに追加" : "画像がないため追加できません"),
  disabled: (card) => !imageUrl(card),
  onClick: (card, sel) => addToPrint(card, sel && sel.url),
},
backAction: {
  label: (back) => (back.image ? "🖨️ 裏面を印刷リストに追加" : "画像がないため追加できません"),
  disabled: (back) => !back.image,
  // ⭐ 第3版で修正（実装レビューでの指摘を採用）。既定版の裏面へ倒れたときは
  //    ラベルを付けない ＝ 画像と食い違う表示を出さない
  onClick: (back, sel) => {
    const useSel = !!(sel && sel.back);
    addToPrintItem(back.slug, jpName(back), useSel ? sel.back : back.image, useSel ? sel.label : null);
  },
},
```

⚠️ **P3 は `sel.back` を使う**（`sel.url` ではない）。`cardImages()` の各要素は
その版に対応する裏面URLを `back` に持っている（`card-i18n.js:145`）。
**`sel.back` が `null` のときは `back.image` にフォールバックする**（選んだ版に裏面画像が無い場合。
`card-detail.js:436` の表示側も同じフォールバックをしている）。

### 3.3 互換性 — 共有コンポーネントの変更が他画面を壊さないこと

`shared/js/card-detail.js` は**4か所から使われている**。
`GA_CARD_DETAIL.init` の呼び出しを**全数調査した結果**（2026-07-31 実測・設計担当）:

| 呼び出し元 | 使う画面 | `action` / `backAction` |
|---|---|---|
| `app.js:595` | トップページ | ⭐ **両方渡している**（唯一の影響先） |
| `tools/deck-builder/app.js:2289` | デッキ構築ツール | ✅ **どちらも渡していない** |
| `tournaments/deck.js:164` | 大会デッキ表示 | ✅ **どちらも渡していない** |
| `scripts/build-tournament-pages.mjs:1383` | 大会詳細ページ426件に埋め込むコード | ✅ **どちらも渡していない** |

いずれも `namesUrl` / `effectsUrl` / `seasonalUrl` / `onAfterClose`（+ デッキ構築のみ `fetchCard`）だけを渡している。

→ ⭐ **影響はトップページのみ。** さらに**第2引数の追加は後方互換**
（既存の `onClick(card)` は余分な引数を無視する）。

✅ **大会ページ426件の再生成は不要。** これらは `/shared/js/card-detail.js` を
実行時に読み込むため（`tournaments/50047/index.html` 等で確認）、ファイルを直せばそのまま反映される。
`build-tournament-pages.mjs` の埋め込みコードは `init` の呼び出し側で、**今回は変更しない**。

### 3.4 `addToPrint()` / `addToPrintItem()` の新しい形

```js
// 第2引数は「表示中の版の画像URL」。省略・null のときは従来どおり既定版
function addToPrint(card, artUrl, verLabel) {
  const image = artUrl || imageUrl(card);
  if (!image) return;
  addToPrintItem(card.slug || card.uuid, jpName(card), image, verLabel);
}

function addToPrintItem(id, name, image, ver) {
  if (!id || !image) return;
  const existing = printList.find((x) => x.image === image);   // ← キーが image に変わる
  if (existing) {
    existing.qty = Math.min(existing.qty + 1, 99);
    if (!existing.ver && ver) existing.ver = ver;   // ⭐ 第3版で追加（実装レビュー指摘）
  } else {
    printList.push({ id, name, image, qty: 1, ver: ver || null });
  }
  savePrintList(); updatePrintBar(); renderTray();
}
```

⚠️ **`ver`（版ラベル）は表示専用**。同一性の判定には使わない（同じ画像URLなら同じ版なので冗長）。

### ⭐ マージ時に `ver` を埋めること（第3版で追加・実装レビューでの指摘）

**`ver` を持たない既存行（＝この変更より前に作られた `localStorage` のデータ）に同じ版を追加したとき、
数量だけ増えてラベルが永久に出ない。**

実測（2026-07-31・設計担当）: `{image: h7q6eocoeh.jpg, qty:1}`（`ver` なし）を置いて同じ版を `＋🖨️` →
**`qty` は 1→2 になるが `ver` は `undefined` のまま・トレイの `.tray-ver` は 0個**。

⚠️ **例外も出ず、画像も数量も正しいので気づく契機が無い**（静かに劣化する形）。

⚠️ **`existing.ver` を無条件に上書きしてはいけない。** 裏面のフォールバック経路（§3.2 P3・V8）は
**意図的に `ver = null` を渡す**ため、既に入っている正しいラベルを消してしまう。
**必ず `!existing.ver && ver` の条件を付ける。**

**P1（検索結果カード）の版ラベル**: `imgs[ai].label` を `dataset` に持たせるか、
`cardEl.dataset.artUrl` から `imgs.find((im) => im.url === artUrl)` で引く。**どちらでもよい**（実装側の判断に任せる）。

### 3.5 トレイの操作（数量・削除）のキーを差し替える

`renderTray()` と委譲ハンドラが `data-id`（slug）を使っているため、**`data-key`（画像URL）に変える**。

| 箇所 | 現状 | 変更後 |
|---|---|---|
| `app.js:357` | `data-id="${escapeHtml(it.id)}"` | `data-key="${escapeHtml(it.image)}"` |
| `app.js:630` | `li.getAttribute("data-id")` | `li.getAttribute("data-key")` |
| `app.js:638` | 同上 | 同上 |
| `setQty` / `changeQty` / `removeFromPrint` | `x.id === id` | `x.image === key` |

⚠️ **`escapeHtml` を外さないこと**（画像URLをHTML属性に入れるため）。

## 5. ✅ UI追加（**2026-07-31 ユーザー承認済み**）— トレイに版ラベルを1行足す

**§3.1 の結果として、同じカードが2行並ぶことがある。**
画像は違うが名前が同じなので、**名前の下に版ラベル（`ALC #001` 等）を小さく1行**足す。

モック: **[`モック_印刷トレイ.html`](モック_印刷トレイ.html)**（現状/変更後・PC/375px・最悪ケース・旧データ混在）

| 追加するCSS | 内容 |
|---|---|
| `.tray-text` | `min-width: 0`（grid の子は既定で縮まないため、これが無いと省略記号が効かない） |
| `.tray-ver` | `font-size:.74rem` / `color: var(--muted)` / `white-space:nowrap; overflow:hidden; text-overflow:ellipsis` |

- `.tray-item` の grid 列定義（`40px 1fr auto auto`）は**変えない**
- ⚠️ **旧データ（`ver` を持たない行）はラベル行を出さない**。「不明」等で埋めない
- 追加先は `style.css`（トップページ専用）

✅ **2026-07-31 にユーザーがモックを比較したうえで「足す」を選択。実装対象。**
（却下案＝「版ラベルを出さず画像だけで見分ける」は、375px で画像が40pxしかなく判別しにくいため見送り）
