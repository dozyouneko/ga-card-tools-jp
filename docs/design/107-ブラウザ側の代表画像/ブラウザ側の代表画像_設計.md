## 2. 原因と影響箇所（起票案の①〜⑤を**いまのコードで**再確認した）

原因は `shared/js/card-i18n.js` の **`firstEdition()` が `eds[0]` をそのまま返すこと**、
より正確には **`card.editions` の配列順をそのまま信じている経路が4つあること**。

| # | 箇所 | 使い方 | 順序依存 | 実測 |
|---|---|---|:--:|---|
| ① | `card-i18n.js` `firstEdition()` → `imageUrl()` | 代表画像 | ⚠️ **する** | **487枚** |
| ② | `card-i18n.js` `cardImages()` | イラスト切替の並び | ⚠️ **する** | **578枚** |
| ③ | `card-detail.js` `renderEditions()`（`card.editions` を直読み） | モーダルの収録一覧の行順 | ⚠️ **する** | **578枚** |
| ④ | `card-i18n.js` `flipEdition()`（`eds.find(configuration==="flip")`） | 裏面画像 | ⚠️ **する** | ⭐ **1枚**（下記） |
| ⑤ | `card-search.js` `editionSetOf()` / `rarityMatchesIn()` | エキスパンション・レアリティの集合判定 | ❌ **しない** | — |
| **⑥** | ⚠️ ⭐ **`scripts/build-tournament-pages.mjs` `cardTile()`**（`CI.cardImages(card)` の `imgs[0]`） | **大会デッキページのカードタイル画像** | ⚠️ **する** | ⭐ **453 slug / 484ファイル**（下記） |

### 2-1. ④ flip版 — ⭐ **起票案の「要実測」への回答: 実在する。ただし1枚だけ**

| 指標 | 実測 |
|---|---:|
| flip 版を持つカード | **22** |
| うち **flip 版が2つ以上**あるカード | **11** |
| うち **裏面画像が実際に食い違う**カード | ⭐ **1**（`fabled-azurite-fatestone`／伝説の瑠璃運命石） |

- `fabled-azurite-fatestone`: 現状 **ReC-HVF #011** の裏面 → 変更後 **HVN 1st #027** の裏面。⭐ **画像が違う**
- 残り10枚は「採る版は変わるが裏面画像のURLが同じ」＝画面上は変わらない
- ⚠️ **1枚しか無いことを「直さなくてよい」と読まない**——`flipEdition()` を放置すると、
  **①②③を直したあとも「表は新しい版・裏は古い版」という食い違いが残る**

### 2-2. ⑤ — ⭐ **順序非依存を確定した**（コード読解で確定・実測不要）

`editionSetOf()` は `eds.filter(e => pre.includes(e.set.prefix))` で**集合**を作り、
`rarityMatchesIn()` は **∃（OR）／∀（AND）**で判定する。**どちらも順序に意味を持たない**。
→ ⭐ **触らない。並べ替えても検索結果の件数は1件も動かない**（検証項目 V9 で確認する）。

### 2-2b. ② の「重複排除で採用される版そのものが変わる」 → ⭐ **起票案の懸念は現データでは起きない**

起票案は ② に「⭐ **重複排除が先頭優先なので、採用される版そのものも変わりうる**」と書いている。
⭐ **成立条件は「同じ画像URLを2つ以上の版が共有すること」**なので、全数で数えた。

| 指標 | 実測 |
|---|---:|
| **同じ `image` を複数の版が共有するカード** | ⭐ **0枚** |

- ⭐ **したがって `cardImages()` の重複排除は「並びだけ」を変え、採る版の集合は変えない**（現データでは）
- ⚠️ ⭐ **「0だから重複排除のコードを外してよい」とは読まない**——**公式APIが同じ画像を2版に付けた日に復活する条件**で、
  外すとサムネイルが重複する。⭐ **`imgs` の要素数が版数と一致することは V3 の副産物として数える**

### 2-3. ⚠️ ⭐ ⑥ は起票案が**見落としていた**（起票案の記述は誤り）

起票案は「**生成スクリプト側には残っていない**（`build-tournament-pages.mjs` は `editions` を1度も読まない）」
と書いている。⚠️ **誤りだった。** 実際には `scripts/build-tournament-pages.mjs` の `cardTile()` が
**`CI.cardImages(card)` を呼び、`imgs[0].url` をそのまま `<img src>` に焼いている**。
しかも **`newestFirst()` 相当の並べ替えを通していない**（`build-card-pages.mjs` だけが通している）。

| 指標 | 実測 |
|---|---:|
| 大会デッキに出る slug（スナップショットにあるもの） | **2,138** |
| うち **代表画像が変わる** slug | **453** |
| ⭐ **変わる URL を含む `tournaments/<id>/decks.html`** | ⭐ **484ファイル**（＝`decks.html` の**全数 484 と一致**） |
| `tournaments/<id>/index.html` に含まれるか | **0ファイル**（順位表は属性玉の base64 なのでカード画像を持たない） |

⭐ **つまり「同じカードなのに画面によって別の絵柄」は、大会デッキページでも起きている。**
⚠️ **原因は①と同一**（`cardImages()` の順序依存）なので、**①を直せば同時に直る**。

## 4. 設計 — `orderedEditions()` に一本化する

### 4-1. 方針

`shared/js/card-i18n.js` に **版の正規順序を返す唯一の関数 `orderedEditions(card)`** を置き、
**①②③④のすべてがそれを経由する**。⭐ **`flavorOf()` / `rulesOf()` と同じ「消費側を1関数に寄せる」形**で前例がある。

```text
orderedEditions(card)  ← 版の並びを決める唯一の場所（editionOrder() の5段）
  ├─ firstEdition(card) → imageUrl(card)            … ① 代表画像
  ├─ cardImages(card)                                … ② イラスト切替の並び ／ ⑥ 大会デッキタイル
  ├─ flipEdition(card) → backFace(card)             … ④ 裏面画像
  └─ card-detail.js renderEditions(card)            … ③ 収録一覧の行順
```

### 4-2. 触る箇所（⭐ **これで全部**。§2 の棚卸しと1対1に対応する）

| # | ファイル | 変更 |
|---|---|---|
| 1 | `shared/js/card-i18n.js` | **`orderedEditions(card)` を新設**し、`firstEdition()` / `cardImages()` / `flipEdition()` を**それ経由に直す**。エクスポートに `orderedEditions` を足す |
| 2 | `shared/js/card-detail.js` | `renderEditions()` の `card.editions || card.result_editions || []` を **`orderedEditions(card)`** に差し替える（`CI` からの取り込みに `orderedEditions` を足す） |
| 3 | 比較器の置き場 | **§5 で選ぶ方式によって変わる**（方式1-A なら `card-i18n.js` へ移動＋`scripts/lib/edition-order.mjs` を撤去） |
| 4 | `scripts/build-tournament-pages.mjs` | ⭐ **変更なし**（`CI.cardImages()` 経由で自動的に直る）。⚠️ **生成物 484ファイルを再生成する** |
| 5 | `scripts/build-card-pages.mjs` | ⭐ **`newestFirst()` は残す**（→ §4-4）。方式1-A なら比較器の取得元だけ差し替える |

⚠️ **`shared/js/card-search.js` は1行も触らない**（⑤は順序非依存・`preferredArtIndex()` は `imgs` を受け取るだけ）。

### 4-3. ⚠️ `orderedEditions()` の実装上の約束（⭐ **設計として決めておく**）

| # | 約束 | 理由 |
|---|---|---|
| **P1** | **元の配列を破壊しない**（`[...eds].sort(...)` にする） | ⚠️ `card` オブジェクトは `card-cache.js` が**共有キャッシュとして持ち回る**。`sort()` を直に当てると、**同じカードを別の画面が別の並びで見ていた瞬間に静かに入れ替わる** |
| **P2** | **`card.editions \|\| card.result_editions \|\| []` のフォールバックは今の形を保つ** | ⚠️ 全件取得経路は `result_editions` を `delete` するだけで `editions` は残す（→ §6-B） |
| **P3** | **`meta.sets` が空でも落ちない**（`setOrder()` が全部 9999 を返し、キー③④⑤で決着する） | ⚠️ `card-i18n.js` を `data/translations.js` より先に読むページが将来できたときに、**例外ではなく劣化**で済む。⭐ **順序は依然として決定的** |
| **P4** | ⭐ **`WeakMap` によるメモ化は「してよいが必須ではない」** | 版数は最大16、1タイルあたり1回。⚠️ **入れるなら `card` オブジェクトをキーにする**（slug をキーにすると、訳の遅延読み込みで差し替わった `card` で古い並びを返す） |

### 4-4. ⚠️ ⭐ `build-card-pages.mjs` の `newestFirst()` は**消さない**

`newestFirst()` は `{...card, editions: eds, result_editions: eds}` という**並べ替え済みのビュー**を作り、
その後の **`const eds = card.editions; const primary = eds[0]`（代表prefix・パンくず）** と
**`for (const ed of newestFirst(card).editions)`（セットページのグルーピング）** が**配列を直読みしている**。

- ⭐ **`orderedEditions()` を足しても `newestFirst()` は要る**（直読みの2箇所が残るため）
- ⭐ **`cardImages()` が内部で並べ替えるようになると、`newestFirst()` 済みの配列を**もう一度**並べ替える**ことになるが、
  **比較器は全順序（`validate` が `同値0` を実データ 5,764ペアで確認済み）で `Array.prototype.sort` は安定**なので、
  **並べ替え済みの配列を並べ替えた結果は同一**＝ ⭐ **`cards/**` `sets/**` に差分は出ない**（V8 で数値で確認する）
