# 取り下げ — 「Starcalling でハイライトと用語解説が出ない」は**不具合ではなかった**

- 対象: `起票案_2026-08-26.md`
- 判断: **取り下げ（起票しない）**。⚠️ **GitHub復旧後もこの起票案を `gh issue create` しないこと**
- 判断者: 設計担当（2026-08-30）／ 検証時の HEAD: `d73b5c9d`

## 1. 結論

**10枚すべてで「スターコーリング」のハイライトも用語解説も正常に出ている。**
ローカル生成物・本番サイトの両方で確認した。起票案の前提そのものが成立していない。

⚠️ ただし **調査の過程で、同じ「語形ずれ」の型による実在の欠落を51枚分見つけた**。
そちらは別タスクとして起票案を用意した → `docs/design/未採番-用語ハイライトの語形ずれ/起票案_2026-08-30_用語ハイライトの語形ずれ.md`

## 2. なぜ誤りだったのか

起票案は次の3段で「出ない」と推論していた。**3の事実認識が誤っている。**

1. 英語原文にあるのはキーワード能力 `Starcalling`
2. `matchedTerms()` は `\b` + キーの前方一致なので、**キー `starcall` が `Starcalling` に当たる** ← ✅ 正しい
3. `terms["starcall"].jp` の中核語は「スターコール」で、訳文は「スターコーリング」なので見つからない ← ⚠️ **誤り**

⭐ **`terms` には `starcall` と `starcalling` の両方のキーが登録されている。**
`starcalling` キーは **2026-07-02 のコミット `38682191`** で追加済みで、
起票案が書かれた 2026-08-26 より**約2か月前**から存在していた。

`matchedTerms()` は**該当する全キーを返す**ので、`Starcalling` という語には
`starcall` と `starcalling` の**2つが同時に当たる**。`highlightTerms()` は中核語を
**文字数の降順に並べた選択和の正規表現**にするため、「スターコーリング」(8字) が
「スターコール」(6字) より先に当たり、**正しくハイライトされる**。

起票案は「`starcalling` キーも同時にマッチする」ことを見落とした。
⚠️ **起票案 §「直し方の見当」の1（`terms` に `"starcalling"` を追加する）は、すでに済んでいた作業**である。

### 発端 — `check-terminology.mjs` の報告を「不具合」と読んだこと

このツールは **キーごとに独立して**「ENにキーがある → JP訳に中核語があるか」を見る。
`starcall` キーは条件を満たしてしまうため、**`starcalling` が正しく効いていても10件を報告し続ける**。
起票案はこの報告を実画面で裏取りせずに症状として採用していた。

## 3. どう検証したか（コマンドと結果）

### 3-1. `starcalling` キーの存在と追加時期

```bash
$ grep -n '"starcalling"' data/translations.js
155:    "starcalling": { jp: "スターコーリング（Starcalling）", desc: "グリンプス中に、…" },

$ git log -S'"starcalling"' --format='%h %ad %s' --date=short -- data/translations.js
38682191 2026-07-02 Add DTRSD Japanese translations and fix expansion-filter bug
```

→ 追加は1回だけ（削除履歴なし）。**起票案より約2か月前**。

### 3-2. ローカル生成物 10枚（`cards/<slug>/index.html`）

```bash
$ for s in arisanna-astral-zenith astra-sight cometfall cosmic-bolt cosmic-focus \
           lunar-seer potion-infusion-starlight scry-the-stars stellar-bloom the-elysian-astrolabe; do
    echo "$s hl=$(grep -c 'term-hl">スターコーリング' cards/$s/index.html)" \
         "gloss=$(grep -c 'スターコーリング（Starcalling）' cards/$s/index.html)"
  done
```

**結果: 10枚すべて `hl=1 gloss=1`**（ハイライト・用語解説とも出ている）。

### 3-3. 本番サイト（キャッシュ回避クエリ付き）

```bash
$ curl -s "https://ga-card-tools-jp.pages.dev/cards/cometfall/?cb=$RANDOM"   # http=200
  → hl=1 gloss=1
$ curl -s "https://ga-card-tools-jp.pages.dev/cards/lunar-seer/?cb=$RANDOM"  # http=200
  → hl=1 gloss=1
```

### 3-4. 実装2箇所の同一性（⚠️ 片方だけ直っている可能性の排除）

`shared/js/card-detail.js:48-70`（ブラウザ）と `scripts/build-card-pages.mjs:187-205`（ビルド）を
突き合わせ、`matchedTerms()` / `highlightTerms()` が**同一規則**であることを確認した。
どちらも中核語を `sort((a,b) => b.length - a.length)` で**長い順**に並べてから選択和の正規表現を作る。

またブラウザ側の辞書の出所も確認した（同じ `data/translations.js` を読む）:

```bash
$ grep -n "data/translations" index.html tools/deck-builder/index.html
index.html:171:  <script defer src="data/translations.js"></script>
tools/deck-builder/index.html:348:<script defer src="../../data/translations.js"></script>
```

→ **静的カードページ・詳細モーダル・デッキ構築のいずれも同じ辞書**を使う。片方だけ直っている状態ではない。

### 3-5. 前方一致するキー組の全数調査

`terms`（134キー）の総当たりで、短いキーが長いキーに前方一致する組は **5組だけ**:

| 短キー | 長キー | 長の中核語が短の中核語を内包 |
|---|---|---|
| `banish`「追放」 | `banishment`「追放領域」 | はい |
| `level`「レベル」 | `level counter`「レベルカウンター」 | はい |
| `level`「レベル」 | `level locked`「レベルロック」 | はい |
| `link`「リンク」 | `link shield`「リンクシールド」 | はい |
| **`starcall`「スターコール」** | **`starcalling`「スターコーリング」** | **いいえ** |

⭐ `starcall` だけが「内包しない」ため、`check-terminology.mjs` が報告するのも**この1組だけ**。
他の4組は短い中核語が長い中核語の部分文字列なので、そもそも報告されない。

## 4. ついでに切り分けた — `check-terminology.mjs` の既存報告11件は**全部が誤検出**

起票案の出所である「用語ハイライトが効かない疑い 11件」を、スナップショット2,494枚と
`data/tl/*.js` の全訳文で再現・分類した（スクリプトはスクラッチパッドで実行、リポジトリには置いていない）。

| 内訳 | 件数 | 実体 |
|---|---|---|
| `starcall` × 10 | 10 | **全件が `starcalling` キーで正しくハイライトされている**（＝誤検出） |
| `charge` × 1 (`charge-the-soul`) | 1 | 英語の `charge` は**カード自身の名前**。訳文では日本語のカード名に置き換わる（＝誤検出） |

→ **11/11 が誤検出。このセクションの信号は現状すべてノイズ**である。
⚠️ 起票案 §「対象外（誤検出）」は `charge` の1件だけを誤検出と認めていたが、**実際は残り10件も誤検出**だった。

⭐ しかも ⚠️ **このツールは「キーが英語原文に当たった」ものしか見ないため、
「キーがそもそも当たらないので何も出ない」という本物の欠落を原理的に検出できない**。
その本物の欠落が51枚実在した（→ 別起票案）。**探す方向が逆を向いている**のがこのツールの本質的な弱点。

## 5. 残す教訓

- ⚠️ **`check-terminology.mjs` の報告は「疑い」であって症状ではない。**
  起票する前に**必ず生成物か本番で実画面を確認する**（今回は `grep -c 'term-hl">…'` 1行で済んだ）
- ⚠️ **`matchedTerms()` は該当キーを全部返す。**「このキーが当たるから、このキーの中核語で判定される」
  という単独キー前提の推論は誤り。**同じ語に複数キーが当たり、長い中核語が優先される**
- ⭐ **起票案ファイル `起票案_2026-08-26.md` は残す**（消すと、なぜ取り下げたか分からなくなり同じ調査が繰り返される）
