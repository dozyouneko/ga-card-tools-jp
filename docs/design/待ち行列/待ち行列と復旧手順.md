⭐ **復旧してまず打つのはこれ。issueの起票より先。**

**なぜ**: cronは `origin/main`（= `c5777923`・2026-08-18）に対して走る。
未pushのまま初回cronが先に走ると、**フレーバー修正・辞書追加・版順序の正規化・用語ハイライトの
是正がどれも入っていない旧コードで `cards/**` が再生成され、cronがそれをコミットする。**

⚠️ ⭐ **そうなると手で解消する根拠が無くなる。** 理由は2つ:

1. **どちらも「正しい生成物」に見える。** cronが作るページも、ローカルの67コミットが作ったページも、
   それぞれの時点のコードとしては正しい出力なので、**差分を見ても「どちらが正か」が判別できない**
2. ⚠️ **cron側に当日のAPIドリフトが混ざる。** cronは実行時点の公式API応答で再生成するため、
   タスク由来の差分と無関係なドリフトが**同じファイルの中に同居する**
   （CLAUDE.md「ドリフトの検査は変更ファイル数では不十分」＝内側に入るケース）

→ **復旧した日のうちに push の可否をユーザーに判断してもらう。**

### 手順

```bash
git status --short                                                   # 空であること
git diff --stat origin/main..HEAD -- . ':(exclude)docs/*' | tail -1  # 本番配信物の量を把握
git pull --rebase origin main                                        # ⚠️ 先に取り込む
npm run validate                                                     # rebase後に exit 0
git push origin main
```

## 4. ⭐ 「起票案が腐る」ことへの対策

⚠️ **一覧を作るだけでは同じことが起きる**（一覧のほうが古くなる）。次の3段で防ぐ。

### 4-1. 状態は**各ファイルの1行目**が正（索引はポインタに徹する）

すべての `起票案*.md` / `派生起票案*.md` は、**1行目**を次の形にする:

```text
**状態: 生きている**（最終確認 2026-08-31）— 未起票。GitHub復旧後に `gh issue create` する ／ 索引: …
```

- 取りうる状態は **`生きている` / `完了` / `取り下げ`** の3つだけ
- ⭐ **ファイル単体を開けば状態が分かる**＝索引を経由しなくてよい。索引が古くても被害が局所化する
- ⭐ **`最終確認` は「その状態がまだ正しいと人が確かめた日」**。状態を変えなくても、確かめたら更新する

### 4-2. ⚠️ **投函前の再測定**（スターコーリングで実際に必要だった手当て）

⭐ **起票案は「確定した事実」ではなく「投函前の下書き」である。**

> **`gh issue create` する直前に、その起票案が主張する症状を必ず実測して再現させる。**
> 再現しなければ投函せず、`取り下げ_<日付>.md` を書いて状態行を `取り下げ` にする。

- 根拠: スターコーリングの起票案は **2か月放置され、実測したら症状が存在しなかった**。
  ⭐ **腐りを止めたのは索引でも検査でもなく「投函前に測り直したこと」**
- ⚠️ **`最終確認` が古い起票案ほど危ない。** 索引に日付を出しているのは、この判断を一目で
  できるようにするため（**60日以上更新が無い `生きている` は、要注意として扱う**）

### 4-3. 機械検査（`npm run validate`）の要否 — ⭐ **入れる価値がある（整合のみ）**

⚠️ **「防げる型」と「防げない型」を分けて判断した。**

| 失敗の型 | 例 | 機械検査で防げるか |
|---|---|---|
| ① **索引と状態行の食い違い** | 起票案を足したのに索引に載せない／片方だけ状態を直す／リネームでパスがずれる | ⭕ **防げる。#40・#43・#70 と完全に同型**（人が書き写す運用はドリフトする） |
| ② **中身が現実と合わなくなる** | スターコーリング型（前提が崩れたのに誰も気づかない） | ❌ **防げない。** 状態行も索引も「生きている」で**整合したまま腐る** |

**判断:**

- ⭕ **①は `npm run validate` に入れて exit 1 にする。** 決定的で、同じコミットの中で直せる。
  仕様は起票案 [`起票案_起票案の状態行と索引の整合検査.md`](起票案_起票案の状態行と索引の整合検査.md) にまとめた
- ❌ **②は検査にしない。** 時計で赤くなる検査（「N日経った」で落ちる）は、
  **その日の変更と無関係に落ちるため、無視される検査に育つ**
  （`check-terminology.mjs` を exit code に載せなかったのと同じ判断）。②の手当ては **4-2 の運用規約**
- ✅ ⭐ **2026-09-02: 実装・レビュー合格・承認まで完了した。** 仕様の正は
  [`../未採番-起票案の整合検査/状態行と索引の整合検査_設計.md`](../未採番-起票案の整合検査/状態行と索引の整合検査_設計.md)、
