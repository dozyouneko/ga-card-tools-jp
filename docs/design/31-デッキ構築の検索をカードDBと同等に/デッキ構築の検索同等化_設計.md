## 目的

デッキ構築ツール(`tools/deck-builder/`)のカード検索を、トップページ(カードDB)と**同じ絞り込み機能**にする。
とくに**クラス・エレメント・タイプ・サブタイプの複数選択と AND/OR トグル**。

現状は単一選択の `<select>` で、**複数指定ができない**。

## ユーザー確定事項(2026-07-26)

| 論点 | 決定 |
|---|---|
| 絞り込み状態のURL共有・復元(#20相当) | **対象外**。デッキ構築のURLは編集中のデッキを指すため意味が混ざる。検索はモーダル内の一時操作 |
| チップUIのCSSの持ち方 | **`shared/css/` に切り出して両画面で読む**(複製しない) |
| エレメントの属性玉アイコン | **出す**(トップと完全に同等にする) |
| スマホ幅でチップが縦を使う問題 | **#31では「崩れない」ことの確認まで**。抜本対応は [#21](https://github.com/dozyouneko/ga-card-tools-jp/issues/21) に寄せる |

## 現状(2026-07-26・#22フェーズ2の反映後に実測)

### JS側の障害は無い

検索コントローラ `shared/js/card-search.js` は**両画面で共通**で、`els` の受け渡しも**10キーすべて同一**。
違うのは**絞り込みUIの構築方法だけ**:

| | トップページ | デッキ構築 |
|---|---|---|
| UI構築 | **`fillChips()`** ×4([app.js:530-533](../../../app.js#L530)) | **`fillSelect()`** ×4([deck-builder/app.js:2184-2187](../../../tools/deck-builder/app.js#L2184)) |
| 4項目(クラス/エレメント/タイプ/サブタイプ) | チップの複数選択 | **単一選択の `<select>`** |
| **AND/ORトグル** | あり | **なし** |
| 属性玉アイコン | あり(`orbs: true`) | なし |
| エレメントANDで0件確定の警告 | あり(`updateElementWarn`) | なし |
| 総件数が概算のときの注記 | あり(`info.approxTotal` を参照) | **なし** |
| 絞り込み件数のバッジ | あり(`filterToggleBadge`) | **なし** |

⚠️ **`modeOf()` は `getMode()` を持たない要素に `"OR"` を返す**([card-search.js:274](../../../shared/js/card-search.js#L274))。
`valuesOf()` も `getValues()` が無ければ `[elm.value]` を返す。
→ **現状は「1値のOR」で正常動作しており壊れていない。単に複数指定ができないだけ。**

### ⚠️ 起票時の懸念は成立しない(`defer` は安全)

issue #31 で「フェーズ2で `data/translations.js` に `defer` が付くと、`fillChips()` の
`I18N.meta` 同期読みが崩れる可能性がある」と書いたが、**成立しない**:

- `defer` は**HTMLパースをブロックしないが、記述順の実行順は保つ**
- デッキ構築の `<script>` は `translations.js` → `card-i18n.js` → `card-cache.js` → `card-search.js`
  → `card-detail.js` → `app.js` の順(全て `defer`)。**`app.js` が動く時点で `I18N.meta` は評価済み**
- 現に `fillSelect()` は `init()` 内で **`await namesReady` より前に同期的に呼ばれて動いている**
  ([deck-builder/app.js:2184](../../../tools/deck-builder/app.js#L2184))

→ **`fillChips()` に差し替えても同じ位置で動く。** 初期化順の変更は不要。

### CSSの現状(これが唯一の実作業)

| ファイル | チップUI関連セレクタ |
|---|---|
| **ルート `style.css`** | **24セレクタ**(`.fgroup` `.fgroup summary` `.flabel` `.fbadge` `.andor` `.fgroup .chips` `.fgroup .chip` …。[:125-190](../../../style.css#L125) と [:437-446](../../../style.css#L437) のスマホ幅) |
| `tools/deck-builder/style.css` | **0件** |
| `shared/css/card-detail.css` | 0件 |

デッキ構築が読むCSSは `tools/deck-builder/style.css` と `shared/css/card-detail.css` の2本で、
**ルート `style.css` は読んでいない**。`shared/css/element-orbs.css` も**読んでいない**(現在は `index.html` だけ)。

⚠️ **`.chip`(304行)と `.chip-elem`(305行)は別物** — カードの種別/レベル/エレメント表示に使う汎用チップで、
**切り出し対象ではない**。`.fgroup .chip` とセレクタが似ているので混同しないこと。

## 対処内容

### 変更1: チップUIのCSSを `shared/css/filter-chips.css` に切り出す

- **新規**: `shared/css/filter-chips.css`。ルート `style.css` の**24セレクタを移す**
  (`.fgroup` 系・`.flabel`・`.fbadge`・`.andor`・`.fgroup .chips`・`.fgroup .chip` 系 + スマホ幅の3行)
- **ルート `style.css` から該当セレクタを確実に除去する**。⚠️ 残置すると二重定義になる
  ([#11](https://github.com/dozyouneko/ga-card-tools-jp/issues/11) で残置CSSの掃除をした経緯があるため同じ轍を踏まない)
- `index.html` と `tools/deck-builder/index.html` の両方で読み込む
- ⚠️ **CSSカスタムプロパティ(`var(--accent)` `var(--panel-2)` `var(--border)` `var(--muted)` `var(--accent-2)`)に依存している。**
  デッキ構築の `style.css` で**同名の変数が定義されているか**を実装時に確認する。
  無い場合は切り出したCSS側で定義せず、**デッキ構築の `style.css` に不足分を足す**
  (共通CSSがテーマ変数を持つと、ページごとの配色を上書きできなくなる)
- ⚠️ `.chip` / `.chip-elem`(汎用チップ)は**移さない**

⚠️ **`_headers` の変更は不要**。`shared/css/` は長期キャッシュ対象ではない
(`immutable` は `/shared/vendor/*` のみ)。ファイル名を変える必要もない。

### 変更2: `<select>` を `<details class="fgroup">` に差し替える(HTML)

`tools/deck-builder/index.html` の `#s-filter-row`([:104-109](../../../tools/deck-builder/index.html#L104))を、
トップページ([index.html:59-62](../../../index.html#L59))と同じ形にする:

```html
<div class="row filter-row" id="s-filter-row">
  <details class="fgroup" id="s-g-element"></details>
  <details class="fgroup" id="s-g-class"></details>
  <details class="fgroup" id="s-g-type"></details>
  <details class="fgroup" id="s-g-subtype"></details>
  <select id="s-format"><option value="">フォーマット（全て）</option></select>
  <select id="s-set"><option value="">エキスパンション（全て）</option></select>
</div>
```

- **中身は空**にする(`fillChips()` が構築する)
- **フォーマットとエキスパンションは `<select>` のまま**(トップも `<select>`。単一選択で足りる)
- `<head>` に **`shared/css/filter-chips.css` と `shared/css/element-orbs.css` の読み込みを追加**
- ⚠️ **既存の `id` を変える**ため(`s-class` → `s-g-class` 等)、`app.js` の `el` 定義も揃えて直す。
  `<select>` のままの `id` を流用すると「selectだと思って `.value` を読む」コードが残った場合に気づけない

### 変更3: `fillSelect()` → `fillChips()` に差し替える(JS)

[deck-builder/app.js:2184-2187](../../../tools/deck-builder/app.js#L2184) を、トップと同じ引数で置き換える:

```js
GA_CARD_SEARCH.fillChips(el.sGElement, "elements", { label: "エレメント", orbs: true });
GA_CARD_SEARCH.fillChips(el.sGClass, "classes", { label: "クラス" });
GA_CARD_SEARCH.fillChips(el.sGType, "types", { label: "タイプ" });
GA_CARD_SEARCH.fillChips(el.sGSubtype, "subtypes", { label: "サブタイプ", top: GA_CARD_SEARCH.SUBTYPE_TOP });
```

- `els` に渡すキーは**変えない**(`cls` / `element` / `type` / `subtype`)。
  渡す要素が `<select>` から `details` に変わるだけで、`valuesOf()`/`modeOf()` が自動的に複数選択・AND/ORを見る
- **`shared/js/card-search.js` は変更しない**
- ⚠️ **サブタイプは146種**あるため `top: SUBTYPE_TOP` を必ず渡す(トップと同じ)。
  渡さないと全種が並んで実用にならない

### 変更4: リセットでチップ群も戻す

`resetSearchForm()`([deck-builder/app.js](../../../tools/deck-builder/app.js))に、トップの
`resetControls()`([app.js:446](../../../app.js#L446))と同じ `reset()` 呼び出しを足す:

```js
[el.sGClass, el.sGElement, el.sGType, el.sGSubtype].forEach((g) => g.reset());
```

`fillChips()` が生やす `reset()` は**選択チップ・AND/OR・開閉状態をまとめて戻す**([card-search.js:255](../../../shared/js/card-search.js#L255))。

⚠️ **訂正**: issue #31 に「リセット挙動を #16 の方針(絞り込みのみクリア・ソートは維持)に合わせる」と書いたが、
**#16の決定は大会一覧ページの話**で、カード検索には適用されない。
カード検索のリセットは**両画面ともソート・並び順も戻す**のが既存挙動で、**既に一致している**
(トップ `resetControls()`・デッキ構築 `resetSearchForm()` のどちらも `sort="name"` / `ASC` に戻す)。
→ **ソートの扱いは変更しない。** 追加するのはチップ群の `reset()` だけ。

⚠️ `resetSearchForm()` は `clearEditor()` からも呼ばれる(デッキを切り替えたときに検索条件を持ち越さないため)。
**チップのリセットもそこで効く**ことを確認する。

### 変更5: エレメントANDで0件が確定する組み合わせの警告

`elementAndBlocked()`(複属性は EXALTED+基本属性 のみ)に該当すると、`run()` は
**APIを叩かずに `blocked: "element-and"` で0件を返す**([card-search.js:466-475](../../../shared/js/card-search.js#L466))。

トップの `updateElementWarn()`([app.js:108-117](../../../app.js#L108))と同じ手当てをデッキ構築にも入れる:

- `info.blocked === "element-and"` のとき、`GA_CARD_SEARCH.ELEMENT_AND_MESSAGE` を表示する
- **エレメントのグループを開く**(`el.sGElement.open = true`)。閉じていると原因が見えない
- 警告の表示先は `fillChips()` が生やす **`details.warnEl`**([card-search.js:254](../../../shared/js/card-search.js#L254))を使う。
  トップと同じ経路にするため独自の要素を作らない

⚠️ **この警告が無いと「なぜか0件」になる。** AND を入れる以上、変更5は**必須**。

### 変更6: 総件数が概算のときの注記

デッキ構築の `onResults` は `info.approxTotal` を参照せず、常に `全 N 件` を出す
([deck-builder/app.js:1039-1041](../../../tools/deck-builder/app.js#L1039))。

**AND指定ができるようになると、非JPモードでは総件数を正確に出せない**
(APIがAND非対応で、取得済みページに客側フィルタを掛けるため)。トップと同じ注記を出す:

| 条件 | 表示 |
|---|---|
| `approxTotal` が false | `N 件を表示 / 全 M 件`(現状どおり) |
| `approxTotal` が true かつ **JPモード** | 「一部のカードは取得後に判定するため総件数は概算です」 |
| `approxTotal` が true かつ **非JPモード** | 「AND条件などは取得済みのページに適用するため、総件数は表示できません」 |

⚠️ **#22フェーズ2のレビュー(#27ではなく)で「デッキ構築の件数表示は据え置きで承認」と判断したが、
それはAND指定が無い前提だった。本issueでANDを入れる時点でその据え置きは無効になる。**

### 変更7: 絞り込み件数のバッジ(推奨・落としてもよい)

チップは既定で**閉じた状態**(開くと50個以上並ぶため)なので、閉じたままだと
**絞り込みが効いていることに気づけない**。トップは `絞り込み ▾` の隣にバッジで件数を出している
([app.js:532-536](../../../app.js#L532))。

- `#s-toggle` の隣に `<span id="s-filter-badge" class="fbadge" hidden></span>` を置く
- チップの変更時とリセット時に `getValues().length` の合計で更新する
- ⚠️ **`fillChips()` の `onChange` を使う**(トップと同じ経路)

**優先度は中**。無くても機能はするので、工数が問題なら落としてよい(そのときは設計書に記録する)。

- **スマホ幅の縦占有の抜本対応**。#21 に寄せる(#31では崩れないことの確認まで)

## 開発担当への申し送り

1. **`shared/js/card-search.js` は変更不要。** `fillChips()` は既に export 済みで、
   `valuesOf()`/`modeOf()` が段階的に劣化する作りなので、**渡す要素を差し替えるだけで機能が有効になる**
2. ⚠️ **CSS切り出しが最大のリスク。** ルート `style.css` から**確実に除去**し、
   **検証16でトップページの非回帰を必ず確認する**。`.chip` / `.chip-elem`(汎用チップ)を巻き込まないこと
3. ⚠️ **CSS変数の依存**を確認する。切り出したCSSが `var(--accent)` 等を使うので、
   デッキ構築側に同名変数が無ければ**デッキ構築の `style.css` に足す**(共通CSS側に変数を置かない)
4. **変更5・6は必須。** AND を入れると「なぜか0件」と「不正確な件数」が新たに起こるため、
   UIだけ差し替えて終わりにしないこと
5. **変更7(バッジ)は工数次第で落としてよい。** 落とす場合はissueに書いてください
6. 判断が要る点が出たら**実装側で決めずissueに書く**
