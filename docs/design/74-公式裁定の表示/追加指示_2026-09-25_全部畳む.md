### 4. ⭐ 判断1〜4 の結論（コーディネータからの問い）

| 問い | ⭐ 結論 |
|---|---|
| **1. 見出し・警告行・summary の関係（冗長にならない構成）** | ⭐ **見出しを `<summary>` の中に統合する**（`<summary><h3>公式裁定（6件・うちエラッタ2件）</h3></summary>`）。**外側は最大2行・最小1行**。⭐ **HTML仕様上 `summary` は heading content を含んでよい**ので**見出し構造（アウトライン）も保たれる**（実測で `h2` が数えられ `checkVisibility()` が `true`）。⭐ **件数の二重表示も消えた** |
| **2. 金バッジが見えなくなること vs D2** | ⭐ **役割を2つに分けて引き継ぐ**: ①**金色の警告行**（外・153枚）が「エラッタがある」ことを示す ②**summary の `うちエラッタM件`** が件数を示す。⭐ **バッジ自体は開くと先頭に見える**（並びがエラッタ先）。⚠️ **D2 の趣旨は「重みの違いを伝えること」でバッジという手段ではない**。⭐ **外に出る行が「エラッタの有無」で変わる**ので畳んだ状態でも区別が付く |
| **3. 裁定のみ 325枚で存在に気づけるか** | ⭐ **summary 1行（`▶ 公式裁定（4件）`）だけになる**。⚠️ **1.1 より1行減っているので気づきやすさは下がる**——ただし**消えたのは重複（見出しと summary の二重表示）だけで、情報量は同じ**。⚠️ ⭐ **足りなければ「裁定のみは開いたまま」に戻せる**（`hasErrata` の分岐を1つ足すだけ）。**U13 で確認する** |
| **4. V項目・U項目** | **V 32 → 34**・**U 14 → 15**（下記） |

### 5. ⚠️ 実装で踏みやすい落とし穴（1.2 で足した分）

1. ⚠️ ⭐ **ネイティブの `<details>` マーカーを残すと、見出しが右へずれる**（実測: 平文 `h2` の左端 8px に対し `summary > h2` は 12px）。
   ⭐ **`summary { list-style: none }` ＋ `summary::-webkit-details-marker { display:none }` にして、
   見出しの後ろに `::after` で `▶` / `▼` を出す**（判断13）。⭐ **`filter-chips.css` に前例がある**。
   ⭐ **モックで実測したら左端差は 0px**（静的ページ・モーダルとも）
2. ⚠️ ⭐ **警告行を `<details>` の中に入れない**（**V33** が落とします）。**中に入れたら「エラッタがあること」ごと畳まれ、本タスクの目的を失う**
3. ⚠️ ⭐ **モーダルの `<details>` は `MODAL_HTML` に固定で存在する**ので、**`render()` のたびに `removeAttribute("open")`**（**V29**）
4. ⚠️ **`.rules-block ul { display: grid }` は UA の `[hidden]` に勝つ**ので `ul[hidden]` / `.rules-warn[hidden]` を明示
5. ⚠️ ⭐ **`<summary>` に入れる `<h2>` は `効果（日本語）` ではないので、`card term highlights up to date` の検査には当たらない**（V10 で確認）
