**見落としではなく既知の状態**。ただし **エラッタ158件はカードの挙動そのものを変える**ため、
英語が読めないと「何がどう変わったのか」が分からない。

## 2. なぜ小タスクにならないか

⚠️ **現在の翻訳データは「カードの slug 単位」**（`data/tl/<セット>.js` の `cards[slug] = { name, effect, flavor }`）で、
**裁定は「カード内の配列」**。つまり **受け皿のデータ構造を新しく決める必要がある**。

- **案A**: `cards[slug].rules = ["…", "…"]`（配列の**添字**で対応づける）
  - ⚠️ ⭐ **公式APIが配列に1件差し込むと、以降の訳が全部1つずつズレる**。**ズレても誰も気づかない**（fail-open）
- **案B**: `date_added` ＋ 本文の先頭 N 文字などを**キー**にする
  - ⭐ ズレない。⚠️ **同じカード・同じ日付のエントリが実在する**（`blastshot-pump` は 2024-01-19 が4件・2026-08-16 が2件）ので、**日付だけではキーにならない**
- **案C**: 英語原文そのもの（またはそのハッシュ）をキーにする
  - ⭐ 最もズレない。⚠️ **公式が原文を微修正すると訳が外れる**（外れたことは検出できる＝**fail-closed にできる**）

⭐ **どの案でも「訳が付いていない裁定が何件あるか」を `npm run validate` で数えられるようにするのが要点**
（#22 の `data/tl-*.json` 陳腐化検査と同じ型）。
