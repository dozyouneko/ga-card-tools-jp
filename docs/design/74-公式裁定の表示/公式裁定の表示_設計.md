## 1. なぜやるか（問題の再掲）

公式APIの `rule`（公式裁定・エラッタ）は **静的カードページにだけ**出ていて、
**詳細モーダル（トップ・デッキ構築・大会詳細ページ）には出ない**。
データは取れている（モーダルが使う `/cards/<slug>` の応答にも `rule` は入っている）のに、描画していないだけ。

⚠️ **エラッタはカードの挙動そのものを変える**のに、**公式APIの `effect` はエラッタ前の印刷文のまま**。
つまり **訳文がどれだけ正確でも、モーダルしか見ない人はエラッタに気づけない**。

## 4. 設計

### 4-1. ⭐ 規則は1箇所に集約する（`rulesOf()`）— 判断と根拠

⚠️ **用語ハイライトは `shared/js/card-detail.js` と `scripts/build-card-pages.mjs` に約125行ずつ二重定義されている**（→ **#109**）。
今回は「モーダルとビルドの**両方**に裁定を出す」ので、**放っておくと同じ型を新しく作る**。

⭐ **判断: 「どの裁定を・どういう順で・エラッタかどうか」という規則を `shared/js/card-i18n.js` に `rulesOf(card)` として置き、
HTMLの字面は各ページ側に残す。**

- ⭐ **根拠1（前例）**: `flavorOf(card, t)` がまったく同じ形。**置き場が2箇所ある・空判定に落とし穴がある**という
  「規則」だけを `card-i18n.js` に集め、markup は静的ページ・モーダル・`backFace()` の3箇所が各自で持っている。
  **ブラウザとビルドの両方から呼べる**（ビルドは `scripts/lib/page-i18n.mjs` が `card-i18n.js` を vm で評価して `CI` として渡す）
- ⭐ **根拠2（markup を共通化しない理由）**: 2つのページはクラス名の体系が違う
  （モーダル = `.gacd-modal` 名前空間 / 静的ページ = `.cp-*`）。**HTMLまで共通化すると、
  どちらかのCSS規約を壊すか、両方のクラスを併記する不自然なmarkupになる。**
  ⚠️ **二重定義で困るのは「規則が2つある」ことであって「タグの字面が2つある」ことではない**
  （#109 が痛いのは、**ハイライトの当て方**が2つあるから）
- ⭐ **根拠3（検査できる）**: 規則を1箇所にすると「**`.rule` を読むファイルは1つだけ**」という
  **両辺が別ファイルの検査**が書ける（→ §6）。markup まで共通化しても、この検査は同じだけしか効かない

#### `rulesOf(card)` の仕様

```
rulesOf(card) -> [{ date, isErrata, scope, description }]
```

| 段 | 内容 |
|---|---|
| 入力 | `card.rule`（配列でなければ空配列として扱う） |
| 除外 | `description` が無い / **trim して空**のものを落とす（M7。現状0件だが fail-safe） |
| `description` | **trim した本文**（HTMLエスケープは呼び出し側で行う） |
| `date` | `date_added` を **`YYYY-MM-DD` に正規化**（`-` で分割し、月日を2桁ゼロ埋め。⭐ M8 の `2023-2-6` → `2023-02-06`）。**形が違うものは `""`** |
| `isErrata` | `title` を `,` で分割・trim したトークンに **`ERRATA`（大文字小文字を無視）が含まれるか** |
| `scope` | トークンから `ERRATA` を除いた残り。**`・` で連結**（例: `DTRSD・P25`）。空なら `""`。⚠️ **`ERRATA` を含まないタイトルが来たら、トークンがそのまま `scope` に入り `isErrata` は false**（M1 の逃げ道） |
| 並び | §4-4 |

⚠️ **`card.rule` を直接読んでよいのはこの関数だけ**（§6 の検査が見張る）。
⚠️ ⭐ **`card.rule` は1箇所でだけ読む**（`const list = (card && card.rule) || []` のように**1回**）。
検査の成功行に「参照 1件」と出るので、増やすと数字が動く。

⭐ **`rulesOf()` は「エラッタか」を返すだけで、分けるのは呼び出し側**（§4-2 の2段構えは
`rules.filter((r) => r.isErrata)` と `rules.filter((r) => !r.isErrata)` で作る）。
⚠️ **`rulesOf()` を「エラッタの配列」と「裁定の配列」を返す形に変えないこと**——
**戻り値が配列1本なので `.length` がそのまま総件数**になり、見出しの `（N件）` が単純に書ける。

### 4-2. ⭐ 2段構え（ユーザー決定・1.1）

⭐ **エラッタは常に開いたまま／単なる裁定は既定で閉じる。**

```
┌ 公式裁定（6件）                       ← 見出し。⭐ 常に出る（N = 全件）
│ ⚠️ エラッタがあります（上の効果文は…）  ← エラッタが1件以上のときだけ（153枚）
│ ※裁定は英語原文です。                  ← 常に出る
│ ┌ [エラッタ] 2026-08-16 …           ┐
│ └ [エラッタ] 2026-08-16 …           ┘ ← ⭐ 開いたまま（166件）
│ ▶ ほかの裁定を表示（4件）              ← <details>。⭐ 既定は閉じる（363枚・476件）
└
```

| カードの型 | 枚数 | 見出し | 警告行 | 開いたままのエントリ | `<details>` |
|---|---|---|---|---|---|
| **エラッタのみ** | **115枚** | `公式裁定（N件）` | ⭕ 出る | エラッタ全部 | ⭐ **出さない**（中身が0件のため。判断8） |
| **裁定のみ** | **325枚** | `公式裁定（N件）` | ❌ 出さない | なし | ⭕ `裁定を表示（N件）` |
| **両方** | **38枚** | `公式裁定（N件）` | ⭕ 出る | エラッタだけ | ⭕ `ほかの裁定を表示（N件）` |

- ⭐ **見出しは常に「公式裁定（N件）」で、N は全件**（開いている分＋閉じている分）。
  ⚠️ **見出しの文言を型で変えない**——**「裁定があること自体」は見出しで分かるようにする**のが
  **裁定のみ 325枚**で気づけるための唯一の担保（判断9）
- ⚠️ ⭐ **`<details>` は毎回閉じた状態から始める。** モーダルの `<details>` は `MODAL_HTML` に固定で存在するので、
  **前のカードで開いたら `open` 属性が残る**。**`render()` のたびに `removeAttribute("open")` する**（V29）

### 4-3. 表示する内容（D2・D4）

| 要素 | 内容 |
|---|---|
| 見出し | **`公式裁定（N件）`**（⭐ モーダルも静的ページも**同じ文言**。静的ページの現行文言に揃える） |
| 警告行 | ⭐ **エラッタを1件以上持つときだけ**: `⚠️ エラッタがあります（上の効果文は印刷時のテキストのままです）`<br>⚠️ **「裁定が優先される」とは書かない**——公式APIはそれを明言していない。**書けるのは「効果文は印刷時のまま」という実測済みの事実だけ** |
| 注記 | **`※裁定は英語原文です。`**（⭐ 静的ページの現行文言をそのまま。D4 の「揃える方向」） |
