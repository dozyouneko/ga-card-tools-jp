## 1. なぜやるか（問題の再掲）

公式APIの `rule`（公式裁定・エラッタ）は **静的カードページにだけ**出ていて、
**詳細モーダル（トップ・デッキ構築・大会詳細ページ）には出ない**。
データは取れている（モーダルが使う `/cards/<slug>` の応答にも `rule` は入っている）のに、描画していないだけ。

⚠️ **エラッタはカードの挙動そのものを変えることがある**のに、**公式APIの `effect` がエラッタ前の印刷文のままのカードが実在する**。
つまり **訳文がどれだけ正確でも、モーダルしか見ない人はエラッタに気づけない**。
⚠️ ⭐ **ただし「`effect` が常に印刷文のまま」ではない**（→ M17）。**反映済みと未反映が混在する**。

今回は「モーダルとビルドの**両方**に裁定を出す」ので、**放っておくと同じ型を新しく作る**。

⭐ **判断: 「どの裁定を・どういう順で・エラッタかどうか」という規則を `shared/js/card-i18n.js` に `rulesOf(card)` として置き、
HTMLの字面は各ページ側に残す。**

- ⭐ **根拠1（前例）**: `flavorOf(card, t)` がまったく同じ形。**ブラウザとビルドの両方から呼べる**
  （ビルドは `scripts/lib/page-i18n.mjs` が `card-i18n.js` を vm で評価して `CI` として渡す）
- ⭐ **根拠2（markup を共通化しない理由）**: 2つのページはクラス名の体系が違う（`.gacd-modal` / `.cp-*`）。
  ⚠️ **二重定義で困るのは「規則が2つある」ことであって「タグの字面が2つある」ことではない**
- ⭐ **根拠3（検査できる）**: 規則を1箇所にすると「**`.rule` を読むファイルは1つだけ**」という
  **両辺が別ファイルの検査**が書ける（→ §6）

#### `rulesOf(card)` の仕様

```
rulesOf(card) -> [{ date, isErrata, scope, description }]
```

| 段 | 内容 |
|---|---|
| 入力 | `card.rule`（配列でなければ空配列として扱う） |
| 除外 | `description` が無い / **trim して空**のものを落とす（M7。現状0件だが fail-safe） |
| `description` | **trim した本文**（HTMLエスケープは呼び出し側で行う） |
| `date` | `date_added` を **`YYYY-MM-DD` に正規化**（`-` で分割し、月日を2桁ゼロ埋め。⭐ M8 の `2023-2-6` → `2023-02-06`）。**形が違うものは `""`** |
| `isErrata` | `title` を `,` で分割・trim したトークンに **`ERRATA`（大文字小文字を無視）が含まれるか** |
| `scope` | トークンから `ERRATA` を除いた残り。**`・` で連結**（例: `DTRSD・P25`）。空なら `""` |
| 並び | §4-4 |

⚠️ **`card.rule` を直接読んでよいのはこの関数だけ**（§6 の検査が見張る）。
⚠️ ⭐ **`card.rule` は1箇所でだけ読む**（`const list = (card && card.rule) || []` のように**1回**）。

⭐ **`rulesOf()` は「エラッタか」を返すだけ。** 1.2 では**リストを2つに分けない**ので、
呼び出し側が要るのは **`rules.length`（全件）** と **`rules.filter((r) => r.isErrata).length`（エラッタ件数）** の2つだけ。

### 4-2. ⭐ 「警告行だけ残して畳む」（ユーザー決定・1.2）

⭐ **裁定はエラッタも含めて全部 `<details>` の中に畳む。外に残すのは警告行だけ。**

- ⭐ ⚠️ **見出しの語も内訳も「在るものだけ」出す**（1.4・ユーザー決定）。
  ⚠️ **「エラッタ/裁定」を全カード固定にする案と、`エラッタ0件` を出す案は、ユーザーが明示的に退けた**
