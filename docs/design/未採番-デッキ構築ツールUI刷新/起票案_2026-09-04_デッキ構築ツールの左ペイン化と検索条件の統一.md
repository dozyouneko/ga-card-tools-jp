トップの HeroUI 化は `style.css` に入っているので、**同等の見た目にするには
`tools/deck-builder/style.css` 側にも同じ値を入れる必要がある**。
⭐ **ここが本タスク最大の「二重定義」リスク**（→ §5 の Q1）。

### 4-2. ⭐ 検索条件の差分は**配線の差**であって、モジュールの差ではない

`shared/js/card-search.js` は両ページが共用している。差は**呼び出し側の引数だけ**:

| 条件 | トップ（`app.js`） | デッキ構築（`tools/deck-builder/app.js`） |
|---|---|---|
| エレメント / クラス / タイプ / サブタイプ | あり | あり |
| **レアリティ**（`g-rarity`） | ⭐ **あり** | ❌ **無し** |
| **チップ絞り込み欄**（`search: true`） | ⭐ **4群すべてに指定** | ❌ **どの群にも指定なし** |
| 選択中の条件（`#selected-filters`） | ⭐ **あり** | ❌ **無し** |
| アコーディオン | ⭐ **あり**（`app.js` に実装＝トップ専用） | ❌ **無し** |
| フォーマット / エキスパンション | あり | あり |
| 並び替え・昇降順 | 絞り込み欄の中 | ⚠️ **結果モーダルの中** |

- ⭐ **レアリティは共有モジュール側が「渡されないページ」を織り込み済み**
  （`card-search.js` の注記: `els.rarity` を持たないページでは `valuesOf(null)=[]` で常に true ＝ **no-op**）。
  **つまり足す側の作業は配線だけで、モジュールの改造は要らない見込み**
  （⚠️ **見込みであって実測ではない**。設計工程で確かめる）
- ⚠️ **アコーディオンは意図的にトップ専用**にしてある
  （`PC左ペイン_設計.md` §12-1: `shared/js/card-search.js` に書くと**デッキ構築も勝手にアコーディオンになる**＝当時のS1違反）。
  ⭐ **本タスクではそれが「望ましい挙動」に変わる**ので、**共有側へ上げるか両方に置くかを設計工程で決める**
