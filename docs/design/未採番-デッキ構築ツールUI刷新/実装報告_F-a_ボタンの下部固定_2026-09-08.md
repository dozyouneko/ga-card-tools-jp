## 4. 設計書の想定と食い違った点（＝意図内と判断した根拠）

### 4-1. ⭐ ページ縦スクロール 0 のときだけ、バーは**フォールドの下**にいる

- 実測（1440×900・`window.scrollY = 0`）: ペインは `top 178 / bottom 1021`、バーは `top 954 / bottom 1021`
  → **画面の高さ 900 を超える**ので、**その瞬間だけバーは画面外**。`window.scrollY ≧ 121`（＝サイトヘッダのぶん）
  送ると、ペインが `top 57 / bottom 900` に貼り付き、バーは `top 704 / bottom 771` で**常に画面内**になる
- ⭐ **これは F-a が持ち込んだものではない。** `#search-top` が `position: sticky; top: var(--editor-bar-h)` ＋
  `max-height: calc(100vh - var(--editor-bar-h))` である以上、**サイトヘッダを送るまでペインの下端はフォールドの外**になる。
  ⚠️ **before（3011）でもペインの矩形は 178 / 1021 で完全に同一**であることを実測済み
- ⭐ したがって **V32 は「ペインの矩形の中で位置が一定」で判定した**（設計の期待値の書き方そのまま）。
  「画面内に常にある」という強い性質は、**ページを少しでも送れば成り立つ**

### 4-2. ⭐ 1200px以上での差分は **4要素だけ**

before / after の全1024〜1347要素を比べて、動いたのは次の4つだけだった（1200 / 1440 とも同じ）:

| 要素 | before | after | なぜ |
|---|---|---|---|
| `#search-top` | 高さ 702.78 | **703.78** | バーの `border-top: 1px` のぶん |
| `.row-actions` | left 16 / 幅 287 / 高さ 42 | **left 0 / 幅 319 / 高さ 67** | `margin: 0 -16px`（端まで伸ばす）＋ `padding: 12px 16px` ＋ 枠線1px |
| `#s-reset` / `#s-search` | top 814.89 | **827.89** | バーの上 padding 12px ＋ 枠線1px |

⭐ **ほかの要素は1つも動いていない**（＝右列・ゾーン・統計に副作用が無い）。

### 4-3. `scroll-padding-bottom` は「効いてはいるが、現状は決定打ではない」

- 破壊試験で **0 にすると着地が 40px ずれる**ので宣言は生きている。
  ⚠️ ただし**チップの直後に「すべて表示」ボタン・レアリティ群・セレクト2つ・並び替え行が続く**ため、
  **サブタイプのチップは 0 でもバーの裏には入らなかった**
- ⭐ 設計 §12-7 の4 が「**実測値にしない**・ずれても『少し余分にスクロールする』だけ」と書いているとおりの位置づけなので、
  **5rem をそのまま採用した**（減らす・消す提案はしない）
