## 6. 参考（⚠️ 合否に含めない・基準に紐づかないもの）

### 6-1. ⭐ 検査(ii)の限界 —— `:root` 以外のセレクタでのトークン上書きは素通りする

**実測（レビューが能動的に確かめた）**: `tools/glossary/style.css` の末尾に **`body { --panel: #ff0000; }`** を1行足すと、

- `npm run validate` は **exit 0**（`:root owners in sync — 4ファイル` のまま緑）
- ⚠️ **`getComputedStyle(document.documentElement)` も `#1b1f28` のまま**（＝**設計 §9-2 の V4/V6 が指定した
  測り方でも気づけない**）
- ⚠️ **なのに `.notice` の実際の背景は `rgb(255,0,0)` になる**（カスタムプロパティは継承するため、
  `body` に書けば**画面上の全要素**に効く）

⭐ **`html { … }` では起きない**（`:root` は擬似クラスで詳細度が上、`html` は要素セレクタなので負ける。実測で確認）。
**素通りするのは `body` 以下に書いた場合**。

- ⚠️ **これは実装の不備ではない。** 設計 §3-5 が検査(ii)を「**`:root {` を持つCSSファイルの集合**」と
  定義しており、実装はその仕様どおり。**歴史的に起きた乖離（`2a057112`）は `:root` どうしの乖離**で、
  そちらは確実に捕まる（破壊試験#2・#3）。
- ⭐ **記録として残す価値がある**のは、この検査が「トークンの集約状態を見張る」と読まれるのに対し、
  **実際に見張っているのは `:root` の持ち主だけ**という差があるため。→ §7-4 で設計担当に判断を仰ぐ。

### 6-2. 検査(i)の保証範囲は「`tokens.css` を読むページ」に限られる

**実測**: `tournaments/*/index.html` は `/tournaments/tournaments.css` と `/shared/css/card-detail.css` を読むが
**`tokens.css` は読まない**。`tournaments.css` の `:root` には `card-detail.css` が参照する
**`--border` / `--yes` / `--no` / `--accent-3` が無い**。

- ⭐ **今日は壊れていない**——`card-detail.css` はこの4つを**すべてフォールバック付き**で書いている
  （`var(--border, #2a2f3a)` / `var(--yes, #2f9e6b)` / `var(--no, #7a6320)` / `var(--accent-3, #e07bd0)`）。
- ⚠️ **これは本コミットが作った状態ではない**（`card-detail.css` も `tournaments.css` も**今回無変更**）。
  完全な既存の状態で、**A によって悪化も改善もしていない**。
- ⚠️ ⭐ ただし **検査(i)の成功行（`未定義 0`）を「共有CSSの変数はどのページでも定義されている」と読まない**こと。
  検査が見ているのは **`tokens.css` に定義があるか**だけで、**`tokens.css` を読まないページ**
  （生成カードページ・大会ページ）は**フォールバックだけが命綱**。
  → **`shared/css/*.css` に新しい `var(--…)` を足すときは、フォールバックを書くか、
  そのページの `:root` にも足す**。⭐ `validate` は止めてくれない。

### 6-3. 4ページの `<link>` そのものを守る検査は無い

`index.html` / `404.html` / `tools/deck-builder/index.html` / `tools/glossary/index.html` から
`<link rel="stylesheet" href="/shared/css/tokens.css">` を消しても `validate` は緑のまま。
⭐ ただし**壊れ方は派手**（`var(--panel)` がフォールバック無しで無効になり面が透ける）ので、
**「静かな劣化」には当たらない**と判断した。§6-1 と合わせて設計担当の判断材料に。

### 6-4. 報告の数値に軽微な不正確が1つ

報告 §6-1 は `line-height` を外すと「**高さがトップと 6px 違うまま**」としているが、
**実測は 38px（トップは 42px）＝ 4px 差**（`padding` は新しい `10px 14px` が残るため）。
⭐ **結論（外すとトップと一致しない）は変わらない**ので合否には影響しない。

### 6-5. S1（コード品質）
