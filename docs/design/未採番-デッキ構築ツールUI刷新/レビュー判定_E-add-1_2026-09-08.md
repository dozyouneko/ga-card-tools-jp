```text
       （トップは群側が再検索するので、渡すと1回の✕で検索が2回走ります。画面は何も変わりません）
    ② 左ペインの閾値は CSS の @media と JS の PANE_MIN_WIDTH の2か所にあり、必ず同じ値でなければなりません
       （ずれると「左ペインは出るのにアコーディオンだけ効く」帯ができ、選んだ条件が画面のどこにも見えなくなります）
    ③ 絞り込み導線の帯は CSS のマーカー直後の @media と JS の matchMedia の2か所にあり、必ず同じ値でなければなりません
       （ずれても CSS 上は display が変わらないため、CSS を読むかぎり「直っている」ように見えます）
    検査を消して通さないこと。…
```

⚠️ **ファイル名と数字だけではない**＝「次に踏んだ人が検査のほうを消す」経路は塞げている。

## 5. 推奨基準の指摘（合格を妨げないもの・対応要否は設計担当の判断待ち）

### S-1（S3 fail-open）⚠️ `UI_PAGES` に無い**新しいページ**は、検査②③がまったく及ばない（**無言**）

- **再現**: 複製ツリーに `tools/newpage/app.js`（`PANE_MIN_WIDTH = 1280` ＋ `matchMedia("(max-width: 900px)")`）と
  `tools/newpage/style.css`（`min-width: 1200px` ＋ マーカー無しの `max-width: 640px`）を置く → `npm run validate` は **exit 0**。
  成功行も `2ページ` `1組` のままで**数字が動かない**（規約4の「数字で気づく」も効かない）。
- ⭐ **ただし穴は限定的**で、**2つの経路は fail-closed**:
  **①デッキ構築に JS 側の帯を足した場合**（FO-4）＝**設計 §11-9 が名指しした目的はそのまま達成されている**。
  **②新ページの著者が規約を知っていてマーカーを置いた場合**（FO-5）＝`迷子のマーカー` として落ちる。
  **残るのは「規約を何も知らない人が3ページ目を作る」経路だけ**。
- **見立て**: ⭐ **今日の規約を破る変更は止まる**ので M ではない。ただし
  **UI刷新の待ち行列には「検索結果のタブ化」など新しい画面が控えている**ので、
  ⚠️ **`UI_PAGES` に足し忘れると検査が及ばないこと**を設計書側に1行残すか、
  **Q-A1 の裁定とあわせて「ページを増やすときは `UI_PAGES` も増やす」を規約化する**のが安全。

### S-2（S3 fail-open）⚠️ 検査①はショートハンド `{ onRemoveOne }`（コロン無し）を検出しない

- **再現**: トップの `app.js` に `const onRemoveOne = () => runSearch(true);` を定義し、
  `createSelectedFilters({ …, onRemoveOne, })` と**ショートハンドで**渡す → **exit 0**（`PASS_RE` が `/\bonRemoveOne\s*:/` のため）。
- ⭐ **危ない側は塞がっている**——**デッキ構築がショートハンドに変わった場合は `passMissing` 側で exit 1**（＝**E が無言で無効化される方向は fail-closed**）。
  また**現実の追加経路はデッキ構築からのコピペ**（＝コロン形）なので、**D1-1 で止まる**。
- **見立て**: **軽微**。直すなら `/\bonRemoveOne\s*[,:}]/` 程度で足りるが、⚠️ **誤検出（受け取り側の分割代入）も増える**ので、
  **設計担当が「今の形で十分」と裁定してよい**と考える。

### S-3（S3 fail-open）⚠️ 検査③の両辺を**同時に**消すと `0組（）` で緑になる

- **再現**: `app.js` の `MOBILE_MQ` を `matchMedia` を使わない形に置き換え、かつ `style.css` のマーカーを消す → **exit 0**、
  成功行は `mobile band marker in sync — 0組（）`。
- ⭐ **これは設計 §11-9 の「対象は自動で広がる形」の裏返し**で、**JS側に帯が無いページにはマーカーを要求しない**のが仕様。
  片側だけ消した場合は**両方向とも exit 1**（D3-c / FO-2）なので、**ドリフトは止まる**。
- **見立て**: **軽微**。⭐ **`0組` という数字が成功行に出る**ので規約4の趣旨（人の目に留まる）は満たしている。
  ⚠️ ただし**「0組」を緑と読んでよいのは、帯の規約そのものを畳んだときだけ**なので、
  **`0組` のときだけ注記を出す**（`— JS 側に帯を持つページがありません` 等）ともう一段安全。

### S-4（S1 コード品質）⭐ 検査③の成功行に `MOBILE_MQ` 側の値が出ていない

- 設計 §11-9 の V56 は「**帯の値と `MOBILE_MQ` の値が出る**」と書いているが、実際の成功行は
  `mobile band marker in sync — 1組（style.css 1199px）` で、**出ているのは CSS 側の値だけ**。
- ⭐ **緑になる条件が「両者一致」なので情報としては等価**（不一致なら赤くなる）。**合否には影響しない**。
- 直すなら `1組（style.css 1199px ↔ app.js 1199px）` の形。**1行の変更**。

## 8. 次の単位（F-a）への申し送り

- ⭐ **検査②は F-a を確実に受け止める。** F-a は `@media (min-width: 1200px)` を**既存のページCSSに足す**単位で、
