## 3. ⭐ Q-F1 の判定 — **M1 の欠落ではなく S**（＝設計担当へ回す）

⚠️ dev の申告: 「**ページ縦スクロール 0 のとき、ボタン行がフォールドの下にいる**（ペイン `bottom` 1021 vs 画面 900）。
原因は B のペイン幾何で、before も矩形が完全に同一。F-a の範囲では直せない」。
⭐ **この申告を鵜呑みにせず、レビュー担当が before/after を並走させて検算した。**

### 3-1. 実測（1440幅・デッキのタイル40枚が描画された状態）

| | 画面高 | `scrollY=0` でのバー矩形 | バーは画面内か | ページのスクロール余地 | バーが完全に画面に入る最小 `scrollY` |
|---|---|---|---|---|---|
| **after** | 900 | 954 .. 1021 | ⚠️ **false** | 1419 | **121.5** |
| **after** | 1080 | 1134 .. 1201 | ⚠️ **false** | 1239 | **121.5** |
| **before** | 900 | 955 .. 997 ※ | ⚠️ **false** | 1419 | 97.5 |
| **before** | 1080 | 1135 .. 1177 ※ | ⚠️ **false** | 1239 | 97.5 |

※ before はバーがペインの流れの中にあるため、**ペインを最下端（3,749px）まで送った場合の位置**。
ペインの scrollTop が 0 のときは **top 4704**（＝画面のはるか下）。

⭐ **ペインの矩形は before/after で完全に一致した**（`scrollY=0` で **top 178 / bottom 1021**、
1025要素の全比較でも `#search-top` 以外は不動）。**dev の「before と同一」という主張は検算で裏が取れた。**

### 3-2. ⭐ 判断と根拠

| 論点 | 実測にもとづく判断 |
|---|---|
| **F-a が持ち込んだ劣化か** | ⭐ **違う。** **before も after も、`scrollY=0` ではバーが画面に一切入っていない**（`barVisibleAtScroll0: false` が4条件すべて）。before に「初期表示で押せていた」状態は**存在しない** |
| **原因はどこか** | ⭐ **B（§4-1）のペイン幾何。** `#search-top { position: sticky; top: var(--editor-bar-h); max-height: calc(100vh - var(--editor-bar-h)) }` である以上、**サイトヘッダ（121px）を送りきるまでペインの下端は必ずフォールドの外**になる。⭐ 必要な `scrollY` が **画面高 900 / 1080 のどちらでも 121.5px で同じ**なのが、これが**画面高ではなくヘッダ高で決まる構造的な性質**であることの証拠 |
| **設計の期待値を満たしているか** | ⭐ **満たしている。** §12-8 V32 の期待値は「**3点で top が一致し、かつペインの矩形の中**」で、**「常に画面内」とは書かれていない**。⚠️ しかも「常に画面内」を保証する案（画面下端の `position: fixed` バー＝§12-5 の案1）は**ユーザーが明示的に不採用にしている** |
| **到達不能ではないか** | ⭐ **到達可能。** ページ側に 1239〜1419px のスクロール余地があり、必要なのは **121.5px**。一度送れば以後は**ペインのどのスクロール位置でも常に画面内**（V32 の3点一致がそれを保証する） |
| **F-a に起因する差はゼロか** | ⚠️ **1点だけある。** 必要な `scrollY` が **97.5 → 121.5（+24px）** に増えた。⭐ これは**ペインの下padding 24px を 0 にしたぶん**で、**設計 §12-7 の3 が明示的に指示した変更**（残すと最下端でバーが浮く）。⚠️ ただし before の 97.5px は「**ペインを 3,749px 送りきった後**でようやく成り立つ数字」なので、**体感上の後退ではない** |

### 3-3. ⭐ 結論

- ⭐ **M1（設計適合）の欠落にはしない。** 設計書の期待値を満たし、before に対する後退も無く、
  是正は **B のページ縦方向の組み方**に手を入れることになる＝**F-a のスコープ外**。
- ⚠️ ⭐ **ただし「157チップを見ている最中でも常に届く」というユーザーの要望に対して、
  初期表示だけは満たしていない**のは事実なので、**S として明記し、設計担当の判断に回す**（§6 の S-1）。
- ⭐ **§12-9（ユーザーの実物確認）に1項目足すことを推奨する**（文面案は §6 の S-1）。
  ⚠️ **レビュー担当は設計を決めないので、追加の可否は設計担当が判断する。**

### 3-4. ⚠️ M1-b の観点で見直した結果

`review.md` の M1-b は「**既存の同種の条件で効いている副作用が、新しく足した条件では効かない**」型。
⭐ **F-a は絞り込み・並び替えの条件を1つも足していない**（CSS 5宣言・DOM/JS 変更ゼロ）ので、
**絵柄の追従・共有URL(#20)・バッジ集計・件数表示のいずれにも新しい条件が増えていない**。
⚠️ また M1-b 自身が「**既存の同種の条件でも効いていないものは M ではない（＝新規要望）**」と定めており、
**Q-F1 はまさにこの型**（before でも効いていない）。→ **M1-b の欠落にも当たらない。**

### Q-F2: バーの padding／枠線でボタンが 13px 下がりペインが 1px 伸びる — ⭐ **設計どおり。S にもしない**

  `#s-reset`・`#s-search` の top +13）。⭐ **右列・ゾーン・統計・タイル・バッジの矩形は1つも動いていない**（1025〜1348要素の全比較）。

## 7. ⭐ F-b への申し送り（Q-F4 の回答・**複製ツリーで実測した条件**）

⭐ **`style.css`（トップ）に `@media (min-width: 1200px)` を足すとき、次を満たせば `validate` は通る。**

### 7-1. 検査③（マーカーと帯の対）が課す条件

| # | 条件 | 破ると |
|---|---|---|
| 1 | `MOBILE-BAND:START` は**そのページのCSSにちょうど1組** | exit 1（`… マーカーが N組です`） |
| 2 | マーカーは **CSSコメント `/* … */` の中**にある | exit 1（`… コメントの中にありません`） |
| 3 | ⭐ **そのコメントの `*/` の直後は、空白・改行だけを挟んで `@media`** — 判定は `^\s*@media\b([^{]*)\{` | ⚠️ ⭐ **コメント1つ挟むだけで exit 1**（実測済み。`マーカーの直後が @media ではありません`） |
| 4 | その `@media` の prelude の `max-width` は**ちょうど1種類**で、`app.js` の `matchMedia("(max-width: …px)")` と同値 | exit 1 |

### 7-2. ⭐ したがって「書いてよい位置」は次の2つ

- ⭐ **① マーカーコメントより前**（マーカーの**前**には何を書いてもよい）
- ⭐ **② マーカー直後の `@media (max-width: 1199px) { … }` が閉じた後の任意の位置**
  （**ファイル末尾を含む**。⭐ **末尾に `@media (min-width: 1200px)` を足して exit 0 になることを実測**）
- ⚠️ ⭐ **唯一置けないのは、マーカーコメントの `*/` と `@media (max-width: 1199px) {` の間**。
  ⭐ **F-b の説明コメントをそこに書きたくなるが、書いた瞬間 exit 1 になる**（実測）。
  → **説明はマーカーコメントの「中」に書き足すか、`@media` ブロックの内側の先頭に書く**。

### 7-3. 検査②（閾値）が課す条件

| # | 条件 | 破ると |
|---|---|---|
| 5 | `style.css` の**全 `@media` の `min-width` の相異なる値がちょうど1つ**で、`app.js` の `PANE_MIN_WIDTH`(=1200) と一致 | ⚠️ `@media (min-width: 1280px)` を1つ足すと **exit 1**（実測: `min-width が [1200, 1280]`） |
| 6 | `max-width` の値は**すべて 1200 未満** | `max-width: 1200px` 以上で exit 1 |

⭐ **`@media (min-width: 1200px)` は何個足しても通る**（値が 1200 である限り。実測で確認）。
⚠️ ただし §6 の「参考」のとおり、**px の整数**で書くこと。

### 7-4. F-b で追加で見ておくべきこと（レビュー担当としての予告）

- ⚠️ **V35 は F-b でこそ本番になる**（`#reset` と `#reset-pane` の複製）。⭐ **1199 ↔ 1200 の往復で
