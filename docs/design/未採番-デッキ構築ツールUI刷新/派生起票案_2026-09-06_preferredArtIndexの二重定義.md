# 派生issueの起票案 — `preferredArtIndex()` が `app.js` と `tools/deck-builder/app.js` に二重定義されている

⭐ **由来**: [`左ペイン化_設計.md`](左ペイン化_設計.md) §7-1（設計中に見つけた。⚠️ **本タスクでは共通化しない**と決めた分）。

---

## 1. 症状（⚠️ **いま壊れている経路は無い**＝将来の穴を塞ぐ側）

**検索の絞り込みに合わせてタイルの初期イラストを選ぶ `preferredArtIndex()` が、2ファイルに別々に書かれている。**

| ファイル | 見ている条件 | 状態 |
|---|---|---|
| `app.js`（トップ） | **エキスパンション ＋ レアリティ** | ⭐ **P5 の修正が入っている**（2026-09-03） |
| `tools/deck-builder/app.js` | **エキスパンションだけ** | ⚠️ **レアリティ絞り込みが無いので、いまは症状として現れない** |

⚠️ ⭐ **デッキ構築側のコメントには「トップページの `app.js` の `preferredArtIndex()` と同じ規則。参照する `<select>` だけが違う」と書いてあるが、
2026-09-03 の P5 修正がトップ側にだけ入ったため、この記述はすでに正しくない。**

---

## 2. なぜ起票するか

⭐ **同型の失敗を、このリポジトリは繰り返している**（`card-badges.css` のバッジ座標 ／ 用語ハイライト規則の約125行×2 ／ 0件文言）。
今回も **「片方だけ直り、コメントだけが同期を主張している」**という同じ形になっている。

- ⚠️ **P5 は、ユーザーが実物を触って見つけた不具合**（レアリティで絞ってもタイルの絵柄が追従しない）。
  ⭐ **同じものがデッキ構築で再発する経路が、この二重定義によって開いている**
- ⭐ **「デッキ構築の左ペイン化」ではレアリティ群を足すので、その設計書の §7-1 で
  デッキ構築側にも同じ規則を書くことになる**（＝**二重定義が「2つとも正しい」状態に一度そろう**）。
  ⚠️ **そろった直後が最も忘れやすい**——次に規則が変わったときに、また片方だけ直る

---

## 3. 直し方の案（⚠️ 設計書はまだ無い）

`shared/js/card-i18n.js` か `shared/js/card-search.js` に **1本だけ**置き、**参照する要素を引数で受ける**:

```js
// 例
GA_CARD_I18N.preferredArtIndex(imgs, { prefixes, rarities });
```

⚠️ **ページ側に残るのは「どの `<select>` / どの群から値を取るか」だけ**にする。
