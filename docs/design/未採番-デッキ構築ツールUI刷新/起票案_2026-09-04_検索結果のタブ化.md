## 1. 要望（ユーザー・2026-09-04）

> - 検索結果はタブを生成する。過去の検索結果も残るように
> - デッキタブ、統計タブは削除できないが検索結果タブは削除できるようにする。
> - 検索結果タブの上部に何の条件で検索されたかを表示する。
> - 今まで通り検索結果からデッキへカードを投入できる

⭐ **要望の核心は「過去の検索結果も残る」**。
現状は検索するたびに**前の結果が消える**ので、
「A のカードを探して入れ、次に B を探し、やっぱり A に戻りたい」が**再検索でしか行えない**。

## 2. 現状（2026-09-04 実測）

| 項目 | 実測 |
|---|---|
| 検索結果の出し方 | ⚠️ ⭐ **モーダル `#result-modal`**（`tools/deck-builder/index.html`）。⭐ **タブではない** |
| モーダルの中身 | `#result-title`（「検索結果」固定）／並び替え `#s-sort`・昇降順 `#s-order`／件数 `#result-count`／`#result-grid`／`#result-more`（もっと見る） |
| 既存のタブ帯 | `.deck-tabs`（`role="tablist"`）に **2つ**: `#ed-tab-deck`（🃏 デッキ）・`#ed-tab-stats`（📊 統計） |
| ⚠️ 閲覧専用画面にも同じ帯がある | `#v-tab-deck` / `#v-tab-stats`（`#view-deck`）。**編集画面とは別のDOM** |
| 結果の保持 | 検索のたびに `#result-grid` を作り直す（**1つ分しか持たない**） |

⚠️ **「タブが2つある」のは編集画面と閲覧専用画面で別々**。
⭐ **本件が触るのは編集画面（`#view-editor`）側だけ**でよいはずだが、
**閲覧専用側を据え置くとタブ帯の見た目が2種類になる**ので、設計工程で扱いを決める。

## 3. 設計工程で決めること（⚠️ **未決が多い＝ここが本件の本体**）

| # | 論点 | ⚠️ 注意 |
|---|---|---|
| **Q1** | ⭐ **タブの上限をいくつにするか**（無制限にするか） | ⚠️ **「過去の検索結果も残る」を無制限に実装すると、タブ帯が横に溢れる**。上限＋古いものから捨てる、横スクロール、ドロップダウン送りなどの選択肢がある。⭐ **上限を決めないと、帯の折り返しでレイアウトが壊れる幅が必ず出る** |
| **Q2** | ⚠️ ⭐ **タブを永続化するのか** | ⭐ **要望は「過去の検索結果も残る」だが、「リロードしても残る」とは書かれていない**。⚠️ **D1に保存するなら 0005 マイグレーションが要る**（→ サイドボードプランメモと同じ論点）。`sessionStorage` で足りるなら不要。**ユーザーに確認する**（→ §6） |
| **Q3** | 結果の再取得をするか | ⚠️ **タブに「条件」だけ持たせて開くたびに再検索する**のか、**取得済みのカード配列を持ち続ける**のか。⭐ **後者は速いがメモリを食い、禁止改定・新セットで内容が古くなる**。⚠️ **前者は公式APIが約1.8秒/リクエストなので体感が変わる** |
| **Q4** | ⭐ **「何の条件で検索されたか」の文言をどう作るか** | ⚠️ **絞り込みは AND/OR モード・複数選択・日本語モードを持つ**ので、素朴に連結すると**長大になる**。⭐ **トップの「選択中の条件」ブロック（`#selected-filters`）が同じ問題を既に解いている**ので、**その表現を再利用できないか調べる**（⚠️ **できるかは未確認**） |
| **Q5** | タブの名前 | 検索語をそのまま出すのか、連番か。⚠️ **無題の検索（絞り込みだけ）で名前が空になる場合を決める** |
| **Q6** | 並び替え・昇降順の置き場 | 現状はモーダル内（`#s-sort` / `#s-order`）。⚠️ ⭐ **「デッキ構築の左ペイン化」の Q4 と同じ論点＝2件共通のモックで決める** |
| **Q7** | ⭐ **削除できるタブ／できないタブの実装** | 要望は「デッキ・統計は削除不可、検索結果は削除可」。⚠️ **サイドボードプランメモも追加・削除できるタブを要求する**ので、**ここで作る仕組みがそちらに再利用される**（→ §5） |
| **Q8** | モーダルを**廃止するのか併存させるのか** | ⚠️ **狭い幅（スマホ）ではタブよりモーダルのほうが妥当な可能性がある**。⭐ **廃止すると 375px幅の検索導線を作り直すことになる**ので、実測してから決める |

## 5. ⭐ 「サイドボードプランメモ」との関係

⚠️ **サイドボードプランメモも「統計が並んでいるところにタブを追加したり削除したりできるように」と要求している。**
⭐ **つまり2件は同じタブ帯に、同じ「動的タブ」の仕組みを要求している。**

- ⭐ **本件を先に実装し、サイドボードプランメモはその仕組みに乗せることを推奨する**
  （逆順にすると、**同じ動的タブの実装が2回別々に入る**）
- ⚠️ **ただし「動的タブ基盤」だけを3件目のissueに切り出すことは推奨しない**——
  **ユーザーに見えるものが何も出ない issue になる**ため。⭐ **本件の中で作り、サイドボードプランメモが使う**形にする

1. 続けて2回検索すると**タブが2つでき、前の結果が残っている**
