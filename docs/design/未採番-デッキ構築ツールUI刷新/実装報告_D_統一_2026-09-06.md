## 4. 設計書の想定との食い違い

### 4-1. ⚠️ `createSelectedFilters` の `selects` を実装していない（→ §6-1 で判断を仰ぐ）

設計 §7-3 のAPIスケッチには `selects: [...]  // フォーマット／エキスパンション等` があるが、**実装していない**。

- ⚠️ **渡すとトップの見た目が変わり、同じ §7-3 の「トップ側の見た目・挙動は1pxも変えない（R1・V15）」と矛盾する**。
  現状のトップの `selectedFilterItems()` は**チップ群だけ**を列挙しており、フォーマット／エキスパンションは出していない。
- ⭐ そもそも**両ページとも `#s-format`/`#s-set`（`#f-format`/`#f-set`）は左ペインに常時見えている**ので、
  「選択中の条件」に重ねて出す必要性が低い、というのが実装側の見立て。
- ⚠️ **どちらに倒すかは仕様の判断**なので実装側では決めず、**オプションごと実装していない**
  （渡す先が無いオプションを先に足すと、誰も通らないコード＝未検証の経路が増えるため）。

### 4-2. ⚠️ V14 の「4群すべて開く」は、そのままの形では成立しなくなった

- **D-1 でレアリティが増えて群は5つ**になった。
- さらに **D-4 のアコーディオンにより、1280px では原理的に1群しか開けない**（`toggle` で他が閉じる）。
  ⭐ **V13 と V14 を同じ幅で同時に満たすことはできない。**
- → **測り方を分けた**（§2 の V14 欄）: **1280px は「サブタイプ＋すべて表示（157チップ）でペイン内スクロールが破綻しないこと」**、
  **1279px は「5群すべて同時に開けること」**。⭐ **V14 が見たかった「ペインに収まりきらない量を開いても壊れない」は両方で確認できている。**
- 設計書の期待値の書き換えが要るなら §6-2。

### 4-3. D-add-1 は「上書きを足す」ではなく「既存宣言をトークンに置き換えた」

設計 §7-5 は「**ページ側で明示的に上書きする**」と書いているが、**`.result-sort select` の宣言そのものを共有トークンに書き換えた**。

- ⚠️ **理由: 詳細度を上げると 375px が壊れる。** `@media (max-width:860px)` の
  `.search-top input, .search-top select, .search-top .btn { font-size: 16px }`（iOSのフォーカス時ズーム防止）は詳細度 `(0,1,1)`。
  ここに `.search-top .result-sort select`（`(0,2,1)`）を足すと**16px指定に勝ってしまい**、
  **375px で `#s-sort` だけ 14px＝他のセレクトより低くなる**（＝**V22 を満たせない**）。
- ⭐ `.result-sort` は現在 **`#search-top` の中にしか存在しない**（C で結果ダイアログから移設済み）ので、
  宣言そのものを直しても他所への波及が無い。**結果は設計の意図どおり**（V22 合格）。
- ⚠️ **直値へ戻すと同詳細度の後勝ちでまた小さくなる**旨をCSSのコメントに残した。

### 4-4. その他（意図内と判断した差分）

| 差分 | 意図内と判断した根拠 |

## 7. レビュー担当への申し送り

- ⭐ **到達手順**: `PORT=3100 npm run dev` を上げ、Playwright で `http://localhost:3100/tools/deck-builder/` を開き、
  **`docs/design/未採番-デッキ構築ツールUI刷新/モック_左ペイン化_2026-09-05.stub.js` の中身を `page.addInitScript()` に渡す**だけで
