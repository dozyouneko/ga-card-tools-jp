## 2. 設計判断

### S-1（Q-F1）⭐ **F の目的は達成された。追加の手当てはしない**

### S-3 ⭐ **自動検査は入れない**（⚠️ E-add-1 と扱いを変える理由を残す）

⚠️ 「`.row-actions` が `#search-top` の最後の子」であることに自動検査が無い。

⭐ **裁定: 入れない。** ⚠️ **E-add-1 で2回「入れる」と裁定しているので、理由を明示する**:

| # | 根拠 |
|---|---|
| 1 | ⭐ **症状が無言ではない。** 最後の子でなくなればバーがペイン下端から浮き、**目で見て分かる**。⚠️ ⭐ **E の S1（画面は変わらずAPIリクエストだけ倍）／G-2 の S-1（帯の中で条件が見えなくなる）に検査を入れたのは、"踏んでも画面が変わらない" からだった。** 判断の分かれ目はそこにある |
| 2 | ⚠️ ⭐ **検査を書いても片手落ちになる。** HTML の静的検査で「最後の子」は見られるが、**JS が実行時に `appendChild` する経路は見られない**。⭐ **主要な経路を押さえられない検査は「緑＝安全」の誤解を作る**（⚠️ `:root` 検査(ii)の限界は**主要な経路を押さえたうえでの残り**なので事情が違う） |
| 3 | ⭐ **受け皿は既にある。** **V32**（3点で `top` が一致し、ペイン矩形の中にある）は、最後の子でなくなれば落ちる。⭐ **回帰の検出は V32 の再実行が正しい** |
| 4 | ⭐ **DOM 順への依存は §4-3 で既に減らしてある**（`:last-of-type` で書かず `.row-actions` クラスで指す） |

⚠️ ⭐ **CSS の `order` で「常に最後」を強制する案も採らない**——
`#search-top` は flex なので技術的には可能だが、**`order` は DOM 順（＝Tab の順路）を変えない**ので
**視覚順とキーボード順が食い違う**（WCAG 1.3.2）。⭐ **アクセシビリティを削って構造的防御を買うのは割に合わない。**

→ ⭐ **代わりに §12-3 に警告を1行足す**（`#search-top` に要素を足すときは `.row-actions` より前に置く）。
