## 4. 実測で確かめた「落とし穴」

### 4-1. ⚠️ `.controls` の `backdrop-filter` は包含ブロックを作るが、**このバーは当たらない**

1200px 以上でも `.controls` は `backdrop-filter: blur(6px)` を持つ（3つの対策のうち `backdrop-filter: none`
は **1199px 以下の帯にしかない**）。実測:

| 項目 | 値 |
|---|---|
| `.controls` の `backdrop-filter` | `blur(6px)`（**効いたまま**） |
| `.controls` の `position` / `overflow-y` | `static` / `auto`（＝**スクロールコンテナ**） |
| `.pane-actions` の `position` | `sticky` |
| **バー下端 − ペイン下端** | **0px**（3スクロール位置すべて） |

⭐ **`sticky` の基準は「最も近いスクロール祖先」＝ `.controls` 自身**なので、`fixed` の包含ブロックを作る
`backdrop-filter` の影響を受けない（**§12-5 で `fixed` の案1が潰れたのとは別経路**）。
⚠️ **もしバーを `fixed` に変えると、この `backdrop-filter` に当たって案1と同じ壊れ方をする**。

### 4-2. ⭐ 破壊試験：「2つ見えない」を支えている行はどれか

| 外したもの | 375 / 640 / 900 / 1199 の描画 |
|---|---|
| `@media (min-width: 1200px)` 内の F ルール **4本** | ⭐ **完全に一致（変化なし）** |
| **`.controls > .pane-actions { display: none }`（帯の外の1行）** | ⚠️ **4幅すべてで `.pane-actions` が `display: block` になり `#reset-pane` が出現**（シートを開けば `#reset` と並んで**2つ見える**状態になる） |

⭐ **この1行が V35 の片側そのもの**なので、**消すと無言で「リセットが2つ」に戻る**。設計書 §12-4 のコード例どおり
**メディアクエリの外**に置き、CSS にその旨のコメントを書いた。

### 4-3. ⭐ ハンドラ配布は**実クリック**で確認した（片方だけだと無言）

| 幅 | 押したボタン | 押す前 | 押した後 |
