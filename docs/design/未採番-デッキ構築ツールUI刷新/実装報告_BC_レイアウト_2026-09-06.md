## 4. 差分が設計書の想定と食い違った点

### 4-1. ⚠️ ⭐ 設計書のCSSのままでは V10 が落ちた（実在の不具合を1件検出）

設計 §4-1 のCSSは `#view-editor { display: grid; … }` で始まる。
⚠️ **これは UA スタイルシートの `[hidden] { display: none }` を詳細度で上回る**ため、
**1280px以上では他3ビューを表示している間も `#view-editor` が居座る**。

| 幅 | before の `#view-deck` | 設計書どおりの after |
|---|---|---|
| 1440 / 1280 | `top=121` | ⚠️ **`top=851`（+730px）** |
| 1279 / 375 | `top=121` | 一致（メディアクエリの外なので出ない） |

⭐ **`left` と `width` は一致していたので、「幅だけ見る」検査では素通りする型**。
→ **`#view-editor[hidden] { display: none; }` を1行足して解消**（実測で全12通り差分0）。
⭐ このリポジトリには**同じ対策が既にある**（`.btn[hidden] { display: none; }` に
「display指定がUAの[hidden]を上書きしないように」とコメント付きで書かれている）。

⚠️ **モックがこれを検出できなかった理由**: モックは**編集画面しか表示しない**ので、
他3ビューが同時に存在する状態を一度も作らない。**V10 が存在する理由そのものだった。**

⚠️ **いずれも実装側では決めなかった。**

### 6-1. `#view-editor[hidden]` を設計書 §4-1 のCSSに反映するか

§4-1 のコードブロックをそのまま写すと**必ず V10 が落ちる**（§4-1 に実測）。
⭐ **設計書側に1行足しておかないと、次にこのCSSを参照した人が同じ穴を掘る**。

### 6-2. ⚠️ ⭐ `#s-sort`（並び替えセレクト）だけ見た目が揃わない — 揃えるか

`.result-sort select` は**結果ダイアログ用の古い宣言**（`--panel-2` 地・角丸8px・padding 6px 10px・.85rem）を持ち、
**`.search-top select`（0,2,0）と同詳細度で、ファイル内で後にある方が勝つ**ため、左ペインの中で1つだけ小さい:

| | 角丸 | padding | font-size | 高さ |
|---|---|---|---|---|
| `#s-format` / `#s-set`（他のセレクト） | 10px | 10px 14px | 14px | **40px** |
| ⚠️ **`#s-sort`** | **8px** | **6px 10px** | **13.6px** | ⚠️ **32px** |
| （参考）トップの `#f-sort` | 10px | 10px 14px | 14px | 40px |

- ⭐ **§4-5 が名指ししたのは `.search-top .btn` と `outline-offset` の2つだけ**なので、
  **`.result-sort select` には手を入れなかった**（＝設計が名指ししていない範囲を広げない）。
- ⚠️ ただし **§5 の目的（＝検索条件をトップと揃える）と、この1つだけ違う状態は噛み合わない**。
  トップは `#f-sort` もトークンで揃っている。
- ⭐ **判断が要る**: (a) `.result-sort select` の旧宣言を消してトークンに揃える／(b) このままにする。
  ⚠️ **(a) にすると `#s-order`（すでに 42px）と高さが揃い、ペイン内で3つのセレクトが同じ見た目になる。**

### 6-3. ⚠️ ⭐ 結果モーダルが左ペインを覆うので「結果を見ながら並び替える」ができなくなった

- **変更前**: 並び替えは**結果ダイアログの中**にあった → **結果を見ながら**並び替えを変えられた。
- **変更後**: 並び替えは**左ペイン**にあり、変更すると `onStart` が `openModal()` を呼んで**モーダルが全面に開く**。
  ⭐ **実測**: モーダルを開いたまま `#s-order` の座標を `elementFromPoint` で叩くと
  **モーダル内のカード画像（`IMG`）が返る**＝**ペインの並び替えには触れない**。
  → **並び替えを変えるたびに「モーダルを閉じる → ペインで変える → またモーダルが開く」**になる。
- ⭐ 設計 §5-3・§10 は「**タブ化でモーダルが消えたら再検討**」と申し送っているが、
  **それまでの間この往復が残る**。⚠️ **これは Q4 の決定（左ペインへ移す）から直接出てくる帰結**なので、
  実装側では手を入れなかった。**許容でよいか**を確認したい。
  - 参考: 手当ての候補は「結果モーダルの中にも並び替えを**残す/複製する**」「モーダルを**右列に寄せる**」など、
    いずれも**設計の判断**が要る。

### 6-4. V16 の期待値「124件」の更新

**134件（レベル順は133件）**が現在の実測で、**変更前ツリーでも同じ**（§4-3）。
⭐ **絶対数はカードが増えるたびに動く**ので、設計書は
「**`type=CHAMPION` の総件数 − レベル順の件数 ＝ 1**（レベルを持たない `lu-bu-indomitable-titan` の分）」
という**差で書く**ほうが腐らないと思われる。⚠️ **書き換えの可否は設計担当の判断**。
