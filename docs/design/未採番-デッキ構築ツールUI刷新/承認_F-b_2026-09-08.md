## 2. 設計判断（S 3件）

### S-1 ⭐ **文言を直す**（⚠️ 反証された断定を残さない）

⚠️ 設計 §12-7 の4 は `scroll-padding-bottom: 5rem` を
**「無いと、Tabで辿ったチップがバーの下に隠れた位置で止まる」**と**断定**していたが、
レビューの実測では **80 → 0px にしてもチップは隠れず、スクロール量が 23px 変わるだけ**だった。

⭐ **裁定: 実測に合わせて書き直す。** ⚠️ ⭐ **これは vendor除外コメントで
「反証できる断定を残さない」と裁定したのとまったく同じ型**——
**断定が反証されたまま残ると、次の人が「効いていない行だ」と判断して消す**。

⭐ **宣言そのものは残す**（削らない）。理由を書き替える:

- ⚠️ **いまの構成では「隠れる/隠れない」を分けていない**（バーの高さ・チップの位置関係がたまたま噛み合っている）。
- ⭐ **残すのは保険**——**バーが2行になる**（ボタンが増える・文言が伸びる・拡大表示）と、
  **同じ構成のまま隠れる側へ倒れる**。そのとき**無言で悪くなる**のを避ける。
- ⭐ **害は「Tabで送られるスクロール量が 23px 増える」だけ**。

⚠️ **V39 の期待値も同時に直す**（「隠れないこと」は**この宣言の有無に関係なく成立する**ので、
**`scroll-padding-bottom` の効果検証としては空振りする**）。

### S-2 ⭐ **検査は入れない**（⚠️ F-a の S-3 で立てた基準に照らして確認した）

⚠️ `.controls > .pane-actions { display: none }` を消しても `validate` は exit 0。守っているのはコメントだけ。

⭐ **裁定: 入れない。F-a の S-3 と整合する。** ⚠️ **基準は「症状が無言かどうか」**で、照らすと:

| 観点 | 今回 | 検査を入れた側（E の S1・G-2 の S-1） |
|---|---|---|
| 踏んだときに画面に出るか | ⭐ **出る**——**375 / 640 / 900 / 1199 のすべてでリセットが2つ並ぶ**（レビュー実測） | ⚠️ **出ない**（APIリクエストが倍になるだけ／帯の中で条件が見えなくなるだけ） |
| 気づくのに要る条件 | ⭐ **その幅でトップを開く**だけ | ⚠️ **リクエスト数を数える／特定の帯で条件を選んで畳む** |
| 受け皿の検証項目 | ⭐ **V35**（6幅×シート閉開の12状態） | 無し（だから検査を足した） |

⭐ **したがって「入れない」で一貫している。**
⚠️ ⭐ **ただし、レビューが「この1行が V35 を支える唯一の行」と特定した事実は設計書に残す**
（→ §3）。⚠️ **設計書は「貼らない帯では器ごと消す」としか書いておらず、
重みが伝わらない書き方だった**——**次に読む人が「整形のついでに」消しうる。**

### S-3 ⭐ **足す**（§12-7 の6 と V33 に「トップは結果モーダル対象外」）

⭐ **そのとおり。** トップの検索結果は**ページ内のグリッド**で、
**結果モーダル（D-add-2）はデッキ構築にしか無い**。
⚠️ **書いていないので、F-b のレビューが「V33 をどう読むか」を毎回考え直すことになった**（実際に読み替えが必要になった）。
→ **1行足して、次の人が同じ確認事項を再発明しないようにする**（→ §3）。
