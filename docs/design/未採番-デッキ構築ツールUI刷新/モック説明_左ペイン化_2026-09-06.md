## 2. 何が本物で、何がモックか

⭐ **実物（`/tools/deck-builder/`）をそのまま iframe で動かしている。HTMLのコピーを持たないので、本体を直してもモックが陳腐化しない。**

| 要素 | 本物 / モック |
|---|---|
| HTML・CSS・JS（デッキ構築ツール本体） | ⭐ **本物**（実行時に取得している） |
| カードの絵柄・日本語名・バッジ・ゾーン描画 | ⭐ **本物**（`renderZones()` がそのまま描く。カードは公式APIから取得） |
| 絞り込みチップ（エレメント13 / クラス9 / タイプ13 / **サブタイプ157**） | ⭐ **本物**（`fillChips()` がそのまま組み立てる） |
| デッキの中身 | ⭐ **実データ**。`data/tournaments/events/60368.json`（Quicksilver Cup Auckland 2026 / player 184）のマテリアル12・メイン60・サイド9 |
| パンテオンのデッキ | ⚠️ **実在のカードで組んだ架空のシングルトン構築**（同イベントのメインから重複なし60種＋Boon 2枚＋非アクティブ確認用にサイド2枚） |
| ログイン状態・デッキの保存 | ⚠️ **モック**（`/api/me` と `/api/decks/<id>` だけ差し替え。保存系は握りつぶす） |
| 左ペイン化・3ボタンの移動・並び替えの移動 | ⚠️ **モック**（候補CSSを CSSOM で注入し、DOMを移している） |

### ⭐ 実物に到達した方法（次に同じことをする人へ）

デッキ構築ツールは **Discord ログインが前提**で、そのままでは編集画面に到達できない（CLAUDE.md「環境の注意」）。
このモックは **取得したHTMLに2つを差し込んだ `srcdoc`** として読み込んでいる:

1. `<base href="/tools/deck-builder/">` — ⚠️ srcdoc は**親のURLが基準**になるので、これが無いと相対パスが全部壊れる
2. `<script src="…stub.js">` — 本体の `<script defer>` より**先に**走り、`fetch` を差し替える

⭐ **CSP `script-src 'self'` を通る**（同一オリジンのため）。⚠️ 一方 **`<style>` の注入は `style-src 'self'` に阻まれて無言で無視される**ので、
候補CSSは既存シートへ **CSSOM の `insertRule`** で足している（検討メモ「測定でつまずいた点」と同じ罠）。

⚠️ ⭐ **`srcdoc` を差し替えたら `load` を待ってから中を触る。**
待たずに触ると**前のドキュメント**に当たり、**新しい方には何も適用されない**（このモックで実際に踏んだ）。

## 6. モックで分かった実装上の追加事項（設計書に持ち越す）

1. ⚠️ **`#search-top > .row:last-of-type` は使えない。** 3ボタンの箱をペイン末尾に足した時点で
   「最後の div」がそちらになり、**リセット/検索の行に当たらなくなる**（縦積みのままになる）。
   → ⭐ **実装ではその行にクラスを1つ足す**（モックは JS で `row-actions` を付けている）。
2. ⭐ **`.editor-bar` の高さは実測値を CSS 変数に入れる**（モックは `--mock-bar-h`）。
   sticky の `top` とペインの `max-height` の両方が同じ値に依存する。⚠️ **固定値で書かない**
   （スマホ絞り込み導線の `--printbar-h` と同じ流儀＝CLAUDE.md）。
3. ⚠️ **1279px 以下に落ちたときの3ボタンの見た目を設計書に書く**（本モックは横並びで折り返し）。
   ⭐ **DOM の位置は1つしか無いので「PCではペイン・スマホではバー」は CSS だけでは実現できない。**
4. ⭐ **案Z′ の候補CSSはモックの `layoutCss()` がそのまま雛形になる**
   （`#view-editor` を Grid・`.editor-bar` を sticky・`#s-name,#s-text` の flex-basis 打ち消し・
   `.chips` の `max-height:200px`・`:has()` での解除・`.chip { position: relative }`）。
