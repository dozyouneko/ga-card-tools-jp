## 4. ⭐ `element-and` は巻き込まない（**実測で決めた**）

⚠️ **`blocked === "element-and"` は形のうえでは「終端の0件」**なので、決定Aを字面どおり当てると
`条件に合うカードがありませんでした。` に潰れる。⭐ **潰さない。** 根拠は**推測ではなく実測**:

### 4-1. 実測（2026-09-24・`PORT=3010 npm run dev` ＋ Playwright）

エレメントANDの説明は**件数欄のほかに警告バナー（`#fwarn`）にも出る**（`updateElementWarn()`）。
**そのバナーが実際に見えるか**を測った:

| 画面 / 幅 | バナーの高さ | 見えるか |
|---|---|---|
| トップ / **1400px** | 128px | ✅ 見える（`top: 566`） |
| ⭐ **トップ / 375px** | ⭐ **0px** | ❌ **描画されない** |
| デッキ構築 / 375px | 128px | ⚠️ 描画はされる（`filters-open` が付く。スクロールは要る） |

- ⚠️ ⭐ **トップの 375px では、`updateElementWarn()` は `<details>` を開くだけでボトムシートを開かない**
  ため、**バナーが畳まれたまま**になる（デッキ構築側は `filters-open` を付けるので出る）
- ⭐ **つまりスマホのトップでは、件数欄がこの説明の唯一の伝達経路**
- ⭐ **この文言は「条件に合わなかった」ではなく「そういうカードはこの世に無い」という説明**で、
  **絞り込みを緩めても永久に出ない**＝**落とすと利用者が延々と条件を変え続ける**

### 4-2. ⚠️ 揃えたくなったときの順序

⭐ **揃えるなら「先にバナーをスマホでも出す」→「そのうえで件数欄を1文に潰す」**の順。
⚠️ **逆順にすると、スマホで説明がどこにも出ない期間ができる**。→ **別タスク**（本タスクではやらない＝R4）。
