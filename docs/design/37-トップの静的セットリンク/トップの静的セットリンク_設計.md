## 1. 背景（すべて実測）

**カード2,240ページ・大会426ページが検索結果に1件も載っていない。** GSCの観測:

| 観測 | 値 |
|---|---|
| トップページ `/` | ✅ クロール済み・**インデックス済み** |
| クロール統計「目的別」 | **更新 100% / 検出 0%**（＝新しいURLを1本も発見していない） |
| サイトマップ（2,743 URL） | **一度もダウンロードされていない** |
| サーバー・robots・レンダリング | ✅ 正常（`curl` 通常UA／Googlebot UA、GSCライブテストとも確認済み） |

Googleが新しいURLを知る経路は「サイトマップ」と「既知ページからのリンク」の2つ。
**前者は届いていない**ため、**`/` から出ているリンクだけが全2,700ページの入口**になっている。

### ⚠️ その入口が細い — 実測で確認した

`index.html` の `<a href>` を全数調査した結果、**静的HTMLにある内部リンクは5本のみ**。
カード2,240枚分のリンクは `app.js` によるJS描画で、静的HTMLには存在しない。

さらに大会ページ側も確認した（2026-07-29 実測）:

| ページ | カード関連の静的リンク |
|---|---|
| `tournaments/50047/index.html`（大会詳細・426件） | **`/cards/` の1本のみ**（デッキリストのカード名はJS描画） |
| `tournaments/index.html`（大会一覧） | **`/cards/` の1本のみ** |
| `cards/<slug>/index.html`（カード個別） | `/sets/` へ相互リンクあり。ただし自身が到達不能なので経路として機能しない |

```
/  ──→ /cards/ ──→ /sets/<56> ──→ /cards/<slug> ×2,240
   └─→ /tournaments/ ──→ /tournaments/<N> ──→ /cards/   ← 結局ここに合流
```

**カードDB全2,240ページへの経路が `/cards/` というリンク1本にぶら下がっている＝単一障害点。**

## 2. 目的

**トップページから中身への入口を広げ、`/cards/` の単一障害点を解消する。**

| | 変更前 | 変更後 |
|---|---|---|
| 入口から1ホップで届くページ | 5 | **61** |
| カード個別ページまでの深さ | 3ホップ | **2ホップ** |
| カードDBへの経路 | **`/cards/` 1本** | **56本**（各セットページへ直接） |

各セットページは `/sets/rdo/` が376枚、`/sets/doa-alter/` が280枚…という大きなハブ。
56本のうち1本でも辿られれば、数百枚のカードページが1ホップ先に現れる。

### ⚠️ 効果は保証されない（正直に記載する）

`/cards/` は**既にトップからリンクされていて、それでも辿られていない**。
Googleのクロール割り当ての決め方は観測できないため、これは**確率を上げる施策**であり確実な解決策ではない。
それでも実施する理由:

1. **単一障害点の解消はそれ自体が正しい**（効くか否かとは別に、1本の成否に2,240ページを賭ける構成は直すべき）
2. **深さ 3→2 は独立して効く**（クロール優先度は入口からの距離に影響される）
3. **コストがほぼゼロ**（gzip 1.2 KB。現在85.3 KB gzipの+約1%）

判定は #28 の **P5（GSCクロール統計の「検出%」が0から動くか）** で行う。本issue単独では判定しない。

## 4. 実装仕様

### 4.1 `index.html` — マーカー領域を置く（手作業。1回だけ）

`<footer class="site-footer">` の**直前**に、次の2行だけを追加する。

```html
  <!-- SETLINKS:START この中は scripts/build-card-pages.mjs が生成する。手で編集しない -->
  <!-- SETLINKS:END -->
```

- 中身は空でコミットしてよい（直後に `npm run build:cards` を実行して埋める）
- 印刷トレイのモーダル群より**後**、フッターより**前**。カード検索グリッドの下になる

### 4.2 生成されるHTML（マーカー間に差し込む）

```html
<details class="setlinks">
  <summary>エキスパンション別に探す（全56セット）</summary>
  <div class="sl-body">
    <div class="sl-g"><h2 class="sl-g-name">Radiant Origins</h2><ul class="sl-list"><li><a href="/sets/rdo/">Radiant Origins（RDO）</a></li>…</ul></div>
    …（グループの数だけ繰り返し）…
    <p class="sl-more"><a href="/cards/">ロゴ・収録枚数つきの一覧を見る</a></p>
  </div>
</details>
```

| 決めごと | 内容 | 理由 |
|---|---|---|
| `<summary>` の文言 | **「エキスパンション別に探す（全N セット）」** | ヘッダの「🃏 エキスパンション一覧」と**同じ文言にしない**（別物に見えないため）。N は生成時のセット数 |
| 既定の開閉 | **閉じる**（`open` 属性を付けない） | PC/スマホとも閉じた状態を既定にする。案Cの利点はここ |
| グループ名の要素 | **`<h2 class="sl-g-name">`** | ページの `<h1>`（サイト名）直下なので `h2` が正しい階層。⚠️ **モックでは `h3` で描いたが見た目は同一**（サイズはCSSで与えるため）。意図的な差分 |
| 枚数（「376枚」等） | **載せない** | 行が長くなり折り返しが増えるだけで遷移の判断材料にならない。`/cards/` には従来どおり表示がある |
| ロゴ画像 | **載せない** | `api.gatcg.com` への画像リクエストが増え、#22で削った入口のコストに逆行する |
| 末尾の `/cards/` リンク | **置く** | `/cards/`（ロゴ・枚数つきの正式な索引）への導線を残す。既存の内部リンクを減らさない |
| グループの並び・セットの並び | **`cards/index.html` と同じ `groups` 配列をそのまま使う** | 二重管理を作らない。並びの決定性も自動的に揃う（§5） |

### 4.3 CSS — `style.css` に追加

⚠️ CSPが `style-src 'self'` のため **style属性は使えない**。すべてクラスで与える。

必要な指定（モックの `.sx-*` 相当。クラス名は上記に合わせて `.setlinks` / `.sl-*` にする）:

- `.setlinks` — `border-top: 1px solid var(--border)` で上の内容と区切る、上下マージン
- `.setlinks > summary` — クリック可能に見せる（`cursor: pointer`）、フォントサイズ・太さ
- `.sl-g-name` — 小さめ・`var(--muted)` 寄りの色。**`<h2>` の既定サイズを打ち消す**
- `.sl-list` — `list-style: none; display: flex; flex-wrap: wrap; gap: 4px 12px;`
- `.setlinks a` — リンク色・`text-decoration: none`、hoverで下線

⚠️ **`style.css` は5ページから読まれる**（`index.html` / `404.html` / `tools/deck-builder/` / `tools/glossary/` / `tools/print/`）。
セレクタが増えるだけで見た目に影響は無いが、**増分は数百バイト**なので許容する。
共通CSS（`shared/css/`）には置かない（トップ専用のため）。

### 4.4 `scripts/build-card-pages.mjs`

`main()` の生成ブロック（`cards/index.html` を書く付近、現行 728行目あたり）に追加する。

1. `groups`（既に組み立て済み。`indexPage()` に渡しているものと**同じ配列**）から上記HTMLを組み立てる関数 `topSetLinks(groups)` を作る
2. `index.html` を読み、`<!-- SETLINKS:START … -->` と `<!-- SETLINKS:END -->` の間を置換して書き戻す
3. ⚠️ **マーカーが見つからなければ `throw` して落とす**（後述）

```js
const src = readFileSync(path.join(ROOT, "index.html"), "utf8");
const re = /(<!-- SETLINKS:START[^>]*-->)[\s\S]*?(<!-- SETLINKS:END -->)/;
if (!re.test(src)) throw new Error("index.html に SETLINKS マーカーがありません");
// ⚠️ 第2引数は「関数」にする。文字列にしてはいけない(下記)
writeFileSync(path.join(ROOT, "index.html"),
  src.replace(re, (_m, start, end) => `${start}\n${topSetLinks(groups)}\n  ${end}`));
```

#### ⚠️ 置換の第2引数は文字列ではなく**関数**にする（2026-07-29 レビューで追加）

`String.prototype.replace` の**置換文字列**では `$` が特殊文字として解釈される
（`$&` `` $` `` `$'` `$1`…）。差し込むHTMLはセット名・グループ名を含むため、
**将来 `$` を含む名前が来ると置換結果が壊れる**。とくに `$'`（マッチ以降の全文）が入ると
**`index.html` の後半がまるごとマーカー内に複製される**。

⚠️ **このとき `validate` は通ってしまう**。`/sets/` リンクの集合は変わらないため、
§4.5 の検査では検出できない＝**静かに劣化する**。

#### ⚠️ `esc()` を通しても安全になる形は無い（2026-07-29 実測。当初の整理を訂正）

`esc()`（`CI.escapeHtml`）は `& < > " '` を変換するが **`$` は変換しない**。
「`'` や `&` が実体参照に化けるので `$'` `$&` は無害化される」というのは**誤り**で、
**化けた先がまた `$&` になるため危険なまま**である。実測:

| 入力 | `esc()` 後 | 旧実装（置換文字列）での結果 |
|---|---|---|
| `$'` | `$&#39;` | ⚠️ `$&` と解釈され **マッチ全体**が複製される |
| `$&` | `$&amp;` | ⚠️ 同上 |
| `` $` `` | `` $` ``（変換されない） | ⚠️ **マッチより前の全文**（`<head>`〜検索UI）が入る |
| `$1`〜`$9` | そのまま | ⚠️ マーカーコメントが複製される |
| `$$` | そのまま | ⚠️ `$` 1文字に潰れる |

→ **5形すべてが壊れる。部分的なエスケープや文字種の制限で対処してはいけない。**
置換関数にすれば5形すべてが構造的に消える（それが唯一の正しい対処）。

現行データに `$` を含むセット名・グループ名は **0件**。すぐ壊れるわけではないが、
1行の変更で恒久的に消えるため対処する。

#### 逸脱1（承認済み）: マーカー検査は `main()` の冒頭で行う

書き戻し直前だけで判定すると、**カード2,240ページ・セット56ページを書き終えてから落ちる**。
cronでは無駄な上に中途半端な生成物がワークツリーに残るため、`assertSetLinksMarker()` を
`main()` の先頭に置いて**生成に入る前に落とす**（書き戻し側の `throw` も冗長化として残す）。
「恒久的な失敗を握り潰さない」という §4.4 の判断は変えていない。

⚠️ **エスケープは1回だけ。** `setLabel()` の戻り値を `esc()` に通すのは1回にすること。
モック作成時、`cards/index.html` から抜いた**エスケープ済み**の文字列をもう一度 `esc()` に通して
`Proxia&#39;s Vault` と表示される不具合を出した。生成側は生の値から `esc()` するので通常は問題ないが、
既存の生成物を参照する実装にすると同じ罠を踏む。

#### なぜ「マーカーが無ければ落とす」のか（#30 の判断との違い）

日次cronでは `build-card-pages.mjs` が落ちると**後段のコミットステップに到達せず、その日の大会データ取り込みが失われる**。
#29 の索引生成に `continue-on-error: true` を付けたのはこれが理由。**しかし本件は逆の判断をする。**

| | #29 索引生成 | 本件 マーカー欠落 |
|---|---|---|
| 失敗の性質 | **一時的**（個別APIリクエストの失敗）。翌日回復する | **恒久的**。人が直すまで直らない |
| 握り潰した場合 | 索引が1日古いだけ | **トップのリンクが消えたまま自動publishされ続ける** |
| 気づく手段 | 翌日回復するので実害が小さい | **jobは緑・差分も出ないため気づけない**（＝静かに劣化する） |

→ **恒久的な失敗を握り潰してはいけない**ため、ここは exit 1 で落とす。
ローカルの `npm run validate`（§4.5）が先に捕まえるので、cronが赤くなる状況は通常起きない。

### 4.5 `scripts/validate.mjs` — 検査を追加する（本issueの品質の要）

⚠️ マーカー方式は**失敗が差分に出ない形で壊れうる**:

- マーカーが消えている → 何も差し込まれず、`index.html` は**正常なHTMLのまま**出続ける
- 生成側の不具合でリンク0本になっても、HTMLとしては妥当なのでビルドは通る

**検査内容**（ネットワーク不要・オフラインで完結する）:

1. `index.html` に `SETLINKS:START` / `SETLINKS:END` が**両方存在する**
2. マーカー間の `href="/sets/<slug>/"` を集合として取り出す
3. **`cards/index.html`（コミット済みの生成物）の `/sets/` リンク集合と完全一致する**

3 が肝。両者は同じ `groups` から生成されるため、一致しなければ次のいずれかが起きている:

- マーカーが空（リンク0本）
- `index.html` の再生成を忘れてコミットした（**新セットが載っていない**＝#37の目的を外した状態）
- 生成ロジックの不具合

不一致なら `problems++` して **exit 1**、`node scripts/build-card-pages.mjs` の実行を促すメッセージを出す
（既存の「STALE GENERATED JSON」と同じ作法）。

### 4.6 `.github/workflows/build-tournaments.yml`

`git add` の対象に **`index.html`** を追加する（現行57行目）。

```
git add data/tournaments tournaments sitemap.xml cards sets data/card-meta-index.json data/featured-sets.json index.html
```

⚠️ これは **ルート直下のトップページがcronの自動publish対象に入る**ことを意味する。
#30 で `cards` `sets` を足したのと同じ扱いだが、**トップページは唯一のインデックス済みページ**なので影響が大きい。
§4.5 の検査と §4.4 の「落とす」判断がその担保になる。

コメントも1行足すこと（cronの `git add` に何がなぜ入っているかが追えるように）。

## 5. 決定性の要件

⚠️ **出力は決定的でなければならない。** 中身が変わらない日に差分が出ると、cronが毎日ノイズコミットを作る。

- グループの並び: `featured-sets` の応答順（＋末尾に「その他」）。`cards/index.html` と**同じ `groups` 配列**を使うので自動的に揃う
- セットの並び: 既存の `setOrder()` によるソート。同上
- **タイムスタンプ・生成日時・件数以外の可変値を入れない**
- 確認方法: `node scripts/build-card-pages.mjs` を**同日2回**実行して `git diff` が空になること（§7 V6）

### ⚠️ V5 の基準値について（2026-07-29 レビューで差し替え）

初版は #22 フェーズ2 の「**85.3 KB gzip**」を基準にしていたが、**この数字が何を合計した値かが記録に残っておらず、
再現できなかった**。設計担当が本番で測り直した結果:

| 測定 | 値 |
|---|---|
| **同一オリジンの全リクエスト**（Playwright `encodedBodySize` 合計・外部ドメインは除外） | **116,983 B = 114.2 KB / 15リクエスト** |
| 内訳の最大 | `data/tl-names.json` 41.4 KB（初期表示前に1回 `fetch`） |
| `data/card-meta-index.json`（34.3 KB） | **初期表示では取得されない**（日本語効果検索を使ったときのみ）。✅ 設計どおり |

⚠️ **#22 の「−71.5%」という削減率そのものは有効**（変更前後を同じ方法で測っているため）。
疑わしいのは**絶対値の集計範囲**だけ。今後は上の測定方法を基準にする。

`style.css` 4,922 → 5,284（+362 B）、**合計 +1,610 B = +1.57 KB = +1.38%**。設計の見積り（gzip 1.2 KB）と整合する。

## 8. リスクとロールバック

| リスク | 対処 |
|---|---|
| 生成が壊れてトップページのHTMLが不正になる | §4.4 で落とす + §4.5 で検査。**push前に必ず `npm run validate`** |
| cronがトップページを自動publishするようになる | 承認済みの運用（#30と同じ扱い）。戻すのは `git revert <自動コミット>` |
| 見た目が気に入らない | **マーカー間を空にして `index.html` をコミットするだけ**で見た目が消える（コード修正不要）。ビルドが再度埋めるので、恒久的に止めるなら §4.4 の呼び出しを外す |

⚠️ 本番配信物の変更なので、**pushはユーザーの明示的な指示を待つ**（CLAUDE.md）。
