## 1. 承認の理由

- ⭐ **設計意図（「比較器を守っているのがコメントだけ」という状態を解消する）を満たしている。**
  V1〜V15（うち**破壊試験10件**）を dev とレビューが**それぞれ独立に全件実測**し、全件が設計書 §8 の期待値と一致した
- ⭐ **検査が「両辺同源で空回り」していないことが実測で確定した。**
  合成フィクスチャは**手書きで、スナップショットから借りていない**。
  ⚠️ **5段のキーを1つずつ潰す10件が全部 exit 1**＝**1段でも削れば止まる**
- ⭐ **設計書が「0 でないこと」だけでなく符号まで見ると決めた理由が、実測で裏づけられた**（V7）。
  `numeric: true` を外すと **`F6` だけが `cmp=1`（向きが逆）で落ちる**——
  **辞書順だと `"10" < "9"` になるため 0 ではなく正を返す**ので、符号を見ない実装なら素通りしていた
- ⭐ **fail-open にしない設計が実証された**（V13）: **スナップショットが無くても案A は走って落ちる**。
  ⚠️ **スキップするのは案B だけで、そのときは成功行に「スキップ」と明記される**＝**緑の意味が空洞化しない**
- ⭐ **本番配信物が1バイトも変わらないことを両者が確認した**（V15: `GA_SNAPSHOT_MAX_AGE_MIN=0 npm run build:cards` → `git status --short` 0行）。
  ⚠️ **#71 の型（実行時ドリフトの混入）も踏んでいない**
- ⭐ **レビューが設計書の主張そのものを突く破壊試験を3本追加した点を高く評価する。**
  とくに **R-1** は、設計書が §8-1 で「交絡するので実施しない」とした fail-closed の経路を
  **`makeSetOrder([])` で交絡なしに突き直した**もので、**設計書が「実装で担保する」としか書けなかった箇所を実測で閉じた**
- **必須基準 M1〜M7 が全て ✅**。越権なし（`docs/` も `CLAUDE.md` も触っていない＝設計書 §9-2 の取り決めどおり）

### ⭐ 実装の細部2点（文面）について

実装報告 §5 が挙げた2点（V9 のメッセージに**余計だったフィールド名を同じ行に入れた**／同値ペアの例を**最大3件・1行ずつ**出す）は、
⭐ **設計書 §8 前文が明示的に認めた「文面は実装側の裁量・件数と種類は表のとおり」の範囲**であり、**逸脱ではない**。
⭐ **どちらも「直す人が2行目を読まなくても分かる」方向の改善**なので、そのまま採る。

## 2. レビューの確認事項への回答

### R-2 — 切り出しの継ぎ目に**新しいコメント依存が1本できた** → ⭐ **派生issue #113 を起票した**

- **レビューの実測**: `build-card-pages.mjs` 側で比較器を**再インライン化**すると、
  **`npm run validate` は exit 0（成功行がそのまま出る）**のに、**`build:cards` の生成物が 86ファイル変わる**
- ⭐ **設計担当が投函前に非破壊で構造確認した**（CLAUDE.md の「起票前に実測せよ」の規約）:
  **`scripts/validate.mjs` に `build-card-pages.mjs` の import を参照する経路が無い**
  （言及は「⚠ 比較器は build-card-pages.mjs から import しないこと」という**逆向きの注意**だけ）。
  ⭐ **構造上、検出は不可能**であることが確定した
- ⭐ **起票する。** 理由:
  1. ⚠️ ⭐ **#108 の出発点は「比較器を守っているのはコメントだけ」だった。**
     比較器そのものはコメント依存から救い出したが、**「lib を使い続けること」を守るのは再びコメント1行だけ**——
     **同じ型が1段上に移っただけ**で、ここを放置すると**本タスクの目的が半分しか達成されていない**
  2. ⭐ **失敗が無言**。代表画像・`og:image`・収録セット表の行順が中身と無関係に動くのが元の不具合で、
     ⚠️ **cron が動いていてもノイズコミットとして出るだけ＝API由来のドリフトと区別が付かない**
  3. ⭐ **同じ型を塞ぐ先例が2本ある**（`onRemoveOne` の配線検査・左ペインの閾値検査）。
     **「両辺が別ファイルの双方向検査」という確立した流儀に乗るだけ**で閉じられる見込み
- ⚠️ ⭐ **本issueには追加実装させない。** 実装は設計書 §4 J-4（案b）と §5 に**一字一句忠実**で逸脱がなく、
  **これは実装の不備ではなく設計側の守備範囲の線引きの問題**だから（レビューの読みに同意する）。
  ⭐ **ユーザーが承認した `a231f769` の内容を変えない**
- ⭐ **#113 には設計工程の宿題を3つ書いた**:
  ⚠️ **字句検査（import 行の有無）だけで足りるかを実測すること**（「import はしているが使っていない」形が素通りする）／
  ⚠️ **`validate` から `build-card-pages.mjs` を import してはいけない**（import しただけでビルドが走る＝#108 が lib を切り出した理由）／
  ⚠️ **破壊試験で確かめること**（入れる前に緑だった R-2 の入力が exit 1 になるまで）

### ⭐ 設計書 §7-3（緑が証明しないこと）に**この経路を1行足した**

- ⭐ **レビューの「足さないと決めるのも妥当だが、その場合も緑が何を証明しないかは明記されている方がよい」という指摘に同意する。**
  **足す方**を採った（＝塞ぐ issue も起票し、かつ**塞がれるまでの間、緑を過信しないための注記も残す**）
