## ❌ M1-1 `Esc` で入力を空に戻すと、検索を始める前の展開状態に戻らない（W6 / S-1）

- **該当**: `shared/js/card-search.js` の `cfInput` の `keydown`（Escape）ハンドラ

  ```js
  e.stopPropagation();
  clearChipFilter();   // ← ここで restBeforeSearch = null にしてしまう
  applyChipFilter();   // ← 復元条件 (restBeforeSearch !== null) が成立せず、展開したまま残る
  ```

- **再現**（1400px・左ペイン320px。`tmp/review/未採番-チップ絞り込み/t9-esc.mjs` / `log-esc.txt`）
  1. サブタイプ群を開く（**`.chips-rest` は畳んだ状態**＝「＋ すべて表示（157種）」）
  2. 絞り込み欄に `dragon` と打つ（C-A により `.chips-rest` が自動展開される）
  3. **`Esc` を押す**
- **期待**: 入力が空に戻ったので **`.chips-rest` が畳んだ状態に戻る**
  （設計書 §5 S-1「検索を始める直前の `restChips.hidden` を覚え、**入力が空に戻ったら復元する**」/ 検証項目 W6）
- **実測**: **`restChips.hidden = false` のまま**＝157種が開いたまま残る。
  同じ「入力を空にする」操作でも**経路によって結果が違う**:

  | 空にする経路 | 検索前 | 検索中 | 空に戻した後 | 判定 |
  |---|---|---|---|---|
  | **Backspace**（`input` イベント） | 畳 | 開 | **畳**（＝復元） | ✅ |
  | **ネイティブの ✕**（`input` イベント・`log-t10-clearbutton.txt`） | 畳 | 開 | **畳**（＝復元） | ✅ |
  | ⚠️ **`Esc`**（C4 の経路） | 畳 | 開 | ⚠️ **開いたまま** | ❌ |

  見た目の影響（同じ操作列での実測。`log-esc.txt`）:

  | | 検索前 | `Esc` の後 | `Backspace` の後 |
  |---|---|---|---|
  | サブタイプ群の丈 | 394px | ⚠️ **3942px** | 394px |
  | 左ペイン(`#controls`)の `scrollHeight` | 980px | ⚠️ **4528px** | 980px |

  スクリーンショット: `esc-1-before.png`（検索前）/ `esc-2-after-esc.png`（Esc後・157種が開いたまま）/
  `esc-3-after-backspace.png`（Backspace後・畳んで復元）
- **重大度**: **軽微**（落ちない・文言も `syncMore()` が整合させるので画面は破綻しない。
  ただし ⚠️ **ユーザーが畳んでいた状態を「絞り込み欄の操作」が勝手に変えて残す**——
  S-1 が防ごうとしている型そのもので、320pxのペインでは丈が**約10倍**になる）
- **根拠**: 設計書 v1.1 §5 **S-1** ／ §6 **C4**（`Esc` で入力をクリアする）／ 検証項目 **W6**
  （「入力を空に戻す → 検索を始める前の展開状態に戻る」。⚠️ **経路を限定していない**）

⭐ **参考（直し方の方向性・実装の判断で構いません）**: `restBeforeSearch` を捨てるより先に
復元を走らせれば足ります（例: Escape ハンドラで `cfInput.value = ""` にしてから `applyChipFilter()` を呼ぶ、
または `clearChipFilter()` から `restBeforeSearch = null` を外して呼び出し側に寄せる）。
⚠️ **`reset()` / `setValues()` は `clearChipFilter()` の後に自分で `restChips.hidden` を決めている**ので、
そちらの挙動を変えないこと（W8 / W9 は現状 ✅ です）。
