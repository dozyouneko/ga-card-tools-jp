## 3. 実装報告との食い違い（1件・実装の欠陥ではない）

### ⚠️ 報告-1 V31 の「1440幅」で報告されたチップの計算済みスタイルが、実際はスマホ幅の値

- **該当**: `実装報告_2026-08-28.md` §2-5 V31
- **報告値**: 「先頭チップは 1440幅で 128.63×33.75 / **フォント 12.8px** / **パディング 6px 10px 6px 8px**」
- **レビュー実測（1440幅）**: 128.625×33.75 は**一致**するが、**フォント 13.6px** / **パディング 5px 11px 5px 8px**
- **原因**: `shared/css/filter-chips.css` は **`:72`/`:76` が PC値（`.85rem` = 13.6px / `5px 11px 5px 8px`）**、
  **`:117` がスマホMQの値（`.8rem` = 12.8px / `6px 10px 6px 8px`）**。報告値は**スマホMQ側の値**であり、
  1440幅の測定として整合しない（矩形だけがPC値なのは、別条件で測った値が混在したためと考えられる）
- **合否への影響**: **無し**。V31 の期待値は「**変化なし（`git diff --stat -- shared/` が空）**」で、
  これは客観的に満たされている。⭐ そもそも `shared/` に差分がなく、deck-builder はルート `style.css` を
  読まない（V30）ため、**変化しうる経路が存在しない**
- **扱い**: **参考**。⚠️ ただし**報告の数値が別条件のものだった**という事実は残るので、
  次回以降「測定条件（ビューポート幅）とセレクタを値と一緒に書く」ことを申し送る

⭐ 逆に、実装報告 §4 ④-1（**この環境では短文でも印刷バーが79px**）は**レビューでも再現した**
（短文「印刷リスト: 1種 / 1枚（A4 1ページ）」で barH = **79**）。
設計書 F5 の「短文60px」はこの環境では再現しないが、**「固定値にするな」という結論はむしろ強化される**。

### B. スマホ幅で `.controls` の `backdrop-filter` を外した（見た目の劣化は許容範囲か）

⭐ **レビューで定量した結果、「見た目の差はほぼ無い」ではなく、実質的に差が無い。**

- **測り方**: 390x844・scrollY=0 で `.controls` の矩形（0,73,390x179）だけをクリップして撮影し、
  **CSSOM で `backdrop-filter: blur(6px)` を戻した状態**と**ピクセル比較**した（`shots/B_backdrop_none.png` / `B_backdrop_blur.png`）
- **結果**: **最大チャンネル差 1/255**、差のあるピクセルは **69,810中75個（0.11%）**、平均差 0.0005
- **理由**: `.controls` は**スマホ幅で `position: static`**（＝下にカードが潜り込まない）うえ、
  背景が `rgba(15,17,21,.92)`。**背後にあるのは平坦なページ背景だけ**なので、ぼかしても結果が変わらない
- ⭐ 補足: `overflow-x: hidden` だった**変更前も sticky は死んでいた**ので、
  **スマホでのぼかしは元々ほぼ無効だった**（今回それが明示されただけ）
- **レビューの所見**: 基準違反ではない（設計書 §8-2 で設計担当が裁量として明記し、実装はその指定どおり）。
  **ユーザーの事後承認は残るが、上の実測を添えれば判断は容易**

### C. `prefers-reduced-motion` で `transition-delay` も 0 にした（過不足の判断）

- **事実**: 実装は `transition-duration: .01ms !important` に加え `transition-delay: 0s !important` を入れている。
- **レビューの所見**: **過剰ではなく必要**。閉じるときの `visibility` は
  `transition: visibility 0s linear .26s`（**遅延**で消す）実装なので、`duration` だけを潰すと
  **遅延0.26秒が残り「閉じたのに見えている」時間ができる**。設計書 §6-6 の
  「**アニメーションを一切出さない**」を満たすには delay の無効化が要る。
  実測でも **閉じる操作の30ms後に `visibility: hidden`** になっており、意図どおり
- **設計担当の確認**: §6-6 の文言（`.01ms`）に **`transition-delay: 0s` を含む**と読む解釈でよいか

### D. ⚠️ `closeTray()` にも `no-scroll` の相互チェックを足した（スコープ超過の正当性）

- **事実**: 設計書 §4-3 ⑤ はシート側しか指定していない。実装は `closeTray()` に
  `if (!isFilterSheetOpen()) document.body.classList.remove("no-scroll");` の**1行**（実質3行）を足した
- **レビューの判定**: ⭐ **正当。M7 のスコープ違反にはあたらない**。理由:
  1. **設計書 V25 の期待値**が「**印刷トレイを開閉しても取り違えが起きないこと**」であり、
     **逆向き（トレイを閉じたときにシートの抑止が消える）を塞がないと V25 が成立しない**
  2. 実測で**両方向とも確認済み**: シート開＋トレイ開 → **トレイだけ閉じても `no-scroll` は残る**／
     **トレイ単独の開閉（×・Esc の2経路）は従来どおり `no-scroll` が外れる**＝**既存挙動は不変**
  3. 変更は `no-scroll` の除去条件だけで、**トレイの表示・非表示ロジックには触っていない**
- ⚠️ **根拠が実装報告 §5-3 に明記されている**ため、CLAUDE.md「スコープ外なら根拠をissueに書く」も満たしている

## 7. 参考（基準に紐づかない観察・合否に含めない）

1. **絞り込みを変更すると、結果の再描画でスクロール位置が先頭へ戻る。**
   - 実測: 390x844・scrollY=1500 でチップを1件変更 → 再描画の途中で `scrollHeight` が 10,764 → **844** に縮み、
     `scrollY` が **0** へクランプされる（結果描画後は 11,017 に戻るが位置は 0 のまま）
   - ⭐ **これは今回の変更による回帰ではない**。**同一条件で変更前（3101）と後（3100）を並べて測り、
     `y0=1500 → mid 0 → end 0` と完全に同一**であることを確認した
   - ⭐ **設計書の目的（§1-2「スクロール位置を失わずに絞り込みへ**戻れる**ようにする」）は満たしている**:
     開いて**何も変えずに閉じた場合**はスクロール位置 **1500 のまま**（390・375の両方で確認）
   - ⚠️ ただし利用者の体感としては「FABで絞り込みを変えて閉じたら先頭に戻っていた」となる。
     **結果集合が変わる以上妥当とも読めるので、要否は設計担当の判断**（§8 の確認事項に含めた）
2. **FAB の `bottom` はモックの 22px ではなく 16px**（`calc(16px + var(--printbar-h, 0px))`）。
   設計書 §4-1 ⑦ が `right: 16px` を指定しており、**上下左右で16pxに揃っている**ため意図的と判断した。
   印刷バーとの余白も結果的に16px（`749` と `765`）で、設計書 §4-3 ④ の「＋余白」を満たしている
3. **ベール（z:17）は FAB（z:16）も覆う**ため、シートを開いている間は FAB が押せない。
   モックと同じ挙動で、閉じ経路が3つ（×・ベール・Esc）あるため問題なしと判断した
