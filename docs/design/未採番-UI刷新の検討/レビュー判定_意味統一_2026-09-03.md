## 5. 推奨基準（S）の指摘 — ⚠️ 合格を妨げない

### S1-1 `scripts/gen-card-meta-index.mjs` のコメント内の行番号が古くなった

- **該当**: `scripts/gen-card-meta-index.mjs:51` `:55`（`card-search.js:432` / `card-search.js:403-415`）
- **実測**: 本コミットで行がずれ、`:432` は `MAX_PAGES` の行、`:403-415` は `MULTI` の途中〜空行を指す
  （⚠️ `:432` は**変更前から既にずれていた**ので、本コミットが増やしたのは実質1件）
- **重大度**: 軽微（動作に影響なし）。⭐ **行番号ではなく関数名で参照する**と再発しない

### S1-2 版レベルの絞り込みが2つ目に増えたとき、**黙って絞られなくなる**形が残っている

- **該当**: `shared/js/card-search.js` の `matchesMulti()`（`if (!field) return true;`）と、
  `matchesActiveFilters()` / `matchesAndFilters()` の `if (isIndexBlind(m)) continue;`
- **中身**: 第2段の評価は `rarityMatchesIn()` が **`vals("rarity")` / `els.rarity` を名指し**している。
  将来 `MULTI` に `field === null` の項目をもう1つ足すと、
  **一般ループでは読み飛ばされ、第2段でも評価されず、`matchesMulti()` の fail-open で `true` に倒れる**
  ＝ **絞り込みが効かないのに何も落ちない**（設計書 §4 の「一般化」が言う振り分けを、人が手で書く必要がある）
- **重大度**: 軽微（**現在 `field === null` は `rarity` の1つだけ**なので、いま壊れている経路は無い）。
  ⭐ 直すなら「`MULTI.filter(isIndexBlind)` が `rarity` 以外を含んだら落とす」1行の表明で足りる
- ⚠️ **本コミットの警告コメントは十分に書かれている**（「一般ループに戻してはいけない」「同じ版で束ねるのも誤り」）。
  自動検査が無い点だけが残課題なので、**起票の要否は設計担当の判断を仰ぐ**（§6-3）
