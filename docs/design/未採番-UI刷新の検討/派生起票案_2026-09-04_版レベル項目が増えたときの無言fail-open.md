# 派生issueの起票案 — 版レベルの絞り込みが2つ目に増えると、絞り込みが効かないのに何も落ちない（無言の fail-open）

⭐ **由来**: 意味統一のレビュー S1-2／§6-3 と、レアリティ絞り込みのレビュー §6-1。
どちらも**合否に含めない指摘**で、設計担当が1件にまとめた
（→ [`承認_意味統一_2026-09-04.md`](承認_意味統一_2026-09-04.md) §7-3 /
[`承認_レアリティ_2026-09-04.md`](承認_レアリティ_2026-09-04.md) §5）。

## 1. ⚠️ いま壊れている経路は無い

⭐ **これは「将来の落とし穴」を塞ぐ起票案である。** `shared/js/card-search.js` の `MULTI` で
**第3要素が `null` の項目（＝版レベル）は現在 `rarity` の1つだけ**なので、**現時点の挙動は正しい**。

## 2. 何が起きるか（**2つ目を足した瞬間**）

`MULTI` の版レベル項目は `isIndexBlind()`（第3要素が `null`）で判定され、
**一般ループからは読み飛ばされる**（`matchesActiveFilters()` / `matchesAndFilters()` の
`if (isIndexBlind(m)) continue;`）。⚠️ **その代わりの第2段が `rarity` を名指ししている**:

```js
function rarityMatchesIn(eds) {
  const list = vals("rarity");          // ⚠ キー名がハードコード
  ...
  return modeOf(els.rarity) === "AND"   // ⚠ 要素も名指し
```

→ ⚠️ **`MULTI` に `field === null` の項目をもう1つ足すと**:

| 段 | 何が起きるか |
|---|---|
| 一般ループ | `isIndexBlind()` で**読み飛ばされる** |
| 第2段（`rarityMatchesIn()`） | `rarity` しか見ないので**評価されない** |
| `matchesMulti()` の保険 | ⚠️ **`if (!field) return true;` の fail-open で `true` に倒れる** |

⭐ **結果は「絞り込みを選んでいるのに1件も落ちない」。** ⚠️ **エラーも警告も出ない**——
`jpDropped`（異常信号）も点灯しない（落としていないので当然）。**気づける経路が1つも無い。**

⚠️ ⭐ **同型の名指しがもう1箇所ある**: `indexBlindActive()`（D-1 の概算判定）と
`metaMatches()` の読み飛ばしは `isIndexBlind()` から導いているので**正しく一般化されている**が、
**第2段の判定だけが手書き**になっている＝**非対称が残っている**。

## 3. 再現の見込み（⚠️ **投函前に実際に足して確かめる**）

⭐ 本起票案は**コード読解に基づく予測**である。⚠️ **投函前に、`MULTI` にダミーの版レベル項目を
1つ足して「選んでも1件も落ちない」ことを実測する**（CLAUDE.md §4-2「投函前の再測定」）。

- ⭐ 版レベルの候補は実在する: **フォイル種別・版の言語・`edition.slug`** など
- ⚠️ **実測せずに投函しない**（スターコーリングの起票案が「予測のまま2か月放置され、実は症状が無かった」前例）

## 4. 直す方向（案）

| 案 | 内容 | 評価 |
|---|---|---|
| **A（レビュー提案）** | ⭐ **`MULTI.filter(isIndexBlind)` が `rarity` 以外を含んだら落とす1行の表明**を置く | ⭐ **安い。**「気づけない」を「必ず気づく」に変える。⚠️ **どこで落とすか**（読み込み時に throw ／ `console.error` ／ 検索を止める）は要判断 |
| **B** | 第2段を一般化し、**版レベル項目ごとの判定関数を表に持たせる**（`MULTI` の第4要素など） | ⭐ 正攻法。⚠️ **AND の意味が項目ごとに違う**（レアリティANDは「同じ版」では成立し得ない＝版群で判定する）ので、**表に持たせる関数の契約から設計が要る** |
| **C** | 何もしない（コメントのみ。**現状**） | ⚠️ **コメントは読まれないことがある**。⭐ ただし**現に警告コメントは十分に書かれている**（「一般ループに戻してはいけない」「同じ版で束ねるのも誤り」） |

⭐ **案A を推す**（**壊れ方が無言であること**が本件の本質なので、まず声を出させる）。

## 5. ⚠️ 検査をどこに置くかが最大の論点

⚠️ **`shared/js/card-search.js` はブラウザ側なので、`npm run validate`（node・DOM無し）からは
そのまま読めない。** ⭐ **選択肢**:

- **起動時アサート**（モジュール読み込み時に `MULTI` を検査して `console.error`）
  — ⚠️ **人が開発者コンソールを見ないと気づかない**
- **`validate` の字句検査**（`MULTI` の定義を正規表現で読み、`null` 項目が `rarity` だけかを見る）
  — ⭐ **exit 1 で人を止められる**。⚠️ **字句検査は整形で壊れる**（実績: `git add` 行の1行縛り・#70）
- **両方**

⚠️ ⭐ **「片方だけ直したときに静かにずれる」ことを止めるのが目的なので、
検査自身が無言で緑にならない形にすること**（`docs/design/未採番-ハイライト検査の無言緑/` の教訓）。
