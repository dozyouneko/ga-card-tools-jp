### 追加した検査（承認 §4 の要件1〜5に対応）

```js
const LINEREF_ROOTS   = ["scripts", "shared/js", "functions", "app.js", "tools"];
const LINEREF_EXCLUDE = ["shared/vendor"];
const REF_RE = /[A-Za-z0-9_.-]+\.(?:js|mjs):\d+(?:-\d+)?/g;
```

| 要件（承認 §4） | 実装 |
|---|---|
| **1. 対象** = `scripts/` `shared/js/` `functions/` `app.js` `tools/` の `.js`/`.mjs`、`shared/vendor/` を除外 | ✅ `LINEREF_ROOTS` を再帰的に降り、`.js`/`.mjs` だけを集める。`LINEREF_EXCLUDE` に前方一致するパスは降りない |
| **2. 検出する形** = 実装報告 T2 の grep と同じ | ✅ `[A-Za-z0-9_.-]+\.(js\|mjs):[0-9]+(-[0-9]+)?` をJSの正規表現へそのまま移した |
| **3. 失敗時** = exit 1 ＋「なぜだめか」「どう書くか」 | ✅ `problems++` → exit 1。**ファイル名と行番号を名指し**したうえで `行番号は腐ります。関数名で参照してください（例: card-i18n.js の bannedFormats()）` を出す |
| **4. 成功時** = 1行出す（無言で通さない） | ✅ `no line-number refs in code comments — 0件（45ファイル走査）` |
| **5. `docs/` が対象外である理由をコードのコメントに書く** | ✅ 「設計書・実測メモは**その時点の実測値**を記録する文書」「**2026-09-04 実測で278件ある**」「⚠️ 『docs も見たほうがよいのでは』で広げないこと」を明記 |

⭐ **要件4に「走査ファイル数」を足した**（`0件（45ファイル走査）`）。要件4の目的は
**「検査が動いていないこと」と「0件であること」の区別**なので、⭐ **ルートの改名で空回りしたときに
数字が動く**ようにした（例示の文字列 `no line-number refs in code comments — 0件` はそのまま含む）。

### ⭐ fail-open を1つも残していない

⚠️ 承認 §4 に明示は無いが、`validate.mjs` の既存検査（#40・#70）と同じ方針を採った:

| 状況 | 挙動 |
|---|---|
| ルートが読めない（改名・移動） | **exit 1**（`走査対象の指定が陳腐化しています`） |
| 走査対象の `.js`/`.mjs` が**0ファイル** | **exit 1**（同上） |
| 個別ファイルの読み込み失敗 | **exit 1** |

⚠️ **「読めなかったから0件＝合格」に倒すと、検査が壊れたことに永久に気づけない。**

## 6. 設計担当への確認事項

⚠️ **判断が要ると考えたので、実装せずに残した。**

### Q1 ⭐ `shared/pdf/card-sheet.js` が対象外になっている

承認 §4 のルートは `shared/js/` なので、**`shared/pdf/card-sheet.js`（自製のコード）が走査されない**。

| 確認 | 実測 |
|---|---|
| 現在のヒット数 | ⭐ **0件**（W4-b1 でルートを `shared` に広げた際に確認済み。46ファイル走査で緑） |
| 仕様どおりか | ✅ **承認 §4 のルート指定に忠実**（＝今回は広げていない） |

⚠️ **広げるかどうかは仕様の判断なので実装しなかった。** ⭐ 広げるなら
**`LINEREF_ROOTS` の `"shared/js"` を `"shared"` に変えるだけ**（除外リストが `shared/vendor` を守るのは W4-b1 で実証済み）。

### Q2 `tools/` の `.html` / `.css` が対象外になっている

承認 §4 要件1は対象を **`.js` / `.mjs`** と限定しているが、
元の T2 grep（`grep -r … tools/`）は**`tools/deck-builder/index.html` 等も走査していた**。

| 確認 | 実測 |
|---|---|
| 対象外になった非 `.js`/`.mjs` ファイルの現在のヒット数 | ⭐ **0件**（`scripts` `shared/js` `functions` `tools` の全非JSファイルを実測） |

⚠️ **HTML内の `<script>` にコメントを書けば同じ腐りが起きうる**が、
**仕様が `.js`/`.mjs` と明示している**ので広げなかった。**広げるべきかの判断をお願いしたい。**

### Q3 「コメント内」に限定していない（＝コード中の文字列も拾う）

承認 §4 要件2が「実装報告 T2 の grep と同じもの」なので、**コメントかどうかは判定していない**
（行単位の素の文字列一致）。⭐ **現在0件なので誤検知は発生していない**。
⚠️ 将来、コード中の文字列リテラルに `foo.js:12` の形が必要になった場合は**誤検知する**が、
**コメント判定を入れるとブロックコメントの解析が要り、かえって取りこぼしが増える**と判断した。
⭐ **必要になった時点で判断を仰ぐ**（今は先回りしない）。
