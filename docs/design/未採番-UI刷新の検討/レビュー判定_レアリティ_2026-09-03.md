## 5. ⭐ 申し送り（`isIndexBlind()` の集約）の確認

依頼のあった「本当に1か所から導かれているか」を差分で確認した。**ハードコードは残っていない。**

```
shared/js/card-search.js
  302: const isIndexBlind = (entry) => entry[2] === null;   ← 唯一の定義
  493:   indexBlindActive()            … MULTI.filter(isIndexBlind)          （D-1）
  526:   metaMatches()                 … if (isIndexBlind(m)) continue;      （P2）
  714:   matchesActiveFilters()        … if (skipBlind && isIndexBlind(m))   （D-2）
```

- ⭐ `MULTI` の第3要素が `null` なのは **`rarity` の1件だけ**で、3箇所すべてが**同じ述語**を通る
- ⭐ 「`field === null`」を直接書いている箇所は**ほかに無い**（`grep` で確認）
- ⚠️ **ただし完全に1か所ではない**（§6 の参考1）：値の取り出し `haveOf()` は
  `if (key === "rarity")` と**キー名でハードコード**している。⭐ **これは「索引に見えるか」とは別軸**なので
  設計違反ではないが、**`field: null` の項目をもう1つ足したときに `haveOf()` を足し忘れると
  その条件は常に空配列**になる（＝**0件になる**＝fail-close で画面に見えるので、静かには壊れない）

## 6. 参考（合否に含めない）

⚠️ **いずれも基準に紐づかない観察。「なんとなく気になる」を不合格の理由にしない**という規約に従い、分けて書く。

1. **`haveOf()` のキー名ハードコード**（§5）。今は正しく、コメントで注意も書かれている。
   ⭐ 将来 `field: null` の項目が2つ目になったときだけ効いてくる話。
2. ⚠️ **JPモードでレアリティを使うと「もっと見る」が細切れになる**（実測）。
   日本語「の」（候補1,599件）× CPR では **1ページ目が0件**で
   `このページには該当がありませんでした。「もっと見る」で続きを検索できます。` が出て、
   4回押しても4件。**設計書 P2 が明示的に受け入れた代償の範囲内**で、集合は正しい（表示された4件はすべて
   API の `rarity=9` に含まれることを確認済み）。⭐ ただし体感は「総件数が概算」より重い。
   → **§7 の確認事項2に回す。**
3. **レアリティで絞ってもタイルの画像はその版に切り替わらない**。
   エキスパンション絞り込みは `preferredArtIndex()`（`app.js:76`）で**選ばれた版の絵に切り替わる**が、
   レアリティにはその経路が無い（例: CPR で絞った「ロレイン、閃光の剣士」のタイルは `4・PRDSD` の絵）。
   ⭐ 設計書 §8 の「独立に効く」と矛盾はしないが、**既存の絞り込みとは非対称**。
4. **`result_editions` は絞り込み結果だけの部分集合だった**（レビューで実測: `?name=lorraine&rarity=8` の
