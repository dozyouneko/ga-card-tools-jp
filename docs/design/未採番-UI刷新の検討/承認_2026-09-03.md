## 3. ⭐ このタスクで得られた教訓（次に効くもの）

### 3-1. ⭐ 「ユーザーが実物を触る工程」が実際に不具合を捕まえた

⚠️ **レビューは1回目に合格を出していたが、その実装が二重スクロールを作っていた。**
自動検証（V1〜V19）は全部通っており、**ユーザーが「すべて表示」を押して初めて出た**。

- 原因は**「最悪ケース」の定義が「4グループ全開」だけで、群の内側の展開を含めていなかった**こと
- ⭐ **`.chips-rest` の class は `"chips chips-rest"`** なので、`.chips` を対象にしたルールは
  **必ず両方に当たる**。⚠️ **セレクタが当たる要素を数え上げていれば、操作しなくても気づけた**
- ⭐ **2026-09-02 にユーザーが要求した「承認前に実物を触る」工程は、初回で元を取った。**
  設計書 §8-4 の運用は今後も維持する

### 3-2. ⭐ 設計側の漏れを実装が見つけた（2件とも承認済み）

| 発見 | 内容 |
|---|---|
| **`body` ではなく `body.page-top`** | 素の `body` に Grid を掛けると **`404.html` の本文が左320pxの空列の右へ押し込まれる**（本文幅 820→542px）。⚠️ **`style.css` は 404 も読む**という R8 を、レイアウト側で考慮し切れていなかった |
| **`.chip { position: relative }`** | `.controls` が `sticky`→`static` になった副作用で、**絶対配置のチェックボックスの包含ブロックが外れ、チップ領域が Tab フォーカスに追従しなくなっていた**（V14） |

⭐ **どちらも「設計書どおりに書いたら壊れた」型**。実装担当が黙って直さず報告したのが正しい。

### 3-3. ⚠️ 閉じた `<details>` の中身は「スクロール可能」と数えられる

Chromium では **閉じていても `.chips` の `clientHeight` が 200px あり `getClientRects()` も空にならない**。
⭐ **`closest("details").open` で除外しないと、ユーザーに見える数と一致しない**
（開発・レビューの両方が最初に踏んだ）。**次に同種の数え上げをするときの必須知識**。

## 7. ⭐ S-2 への設計判断 — `:has()` は**条件つきで許容する**

| | |
|---|---|
| **許容する** | ⭐ `:has()` は 2023年以降の主要ブラウザすべてで実装済みで、**このサイトは静的サイト＋素のCSSなので polyfill も前処理も無い**＝使えるものは使ってよい |
| ⚠️ **条件** | ⭐ **fail-open であること**。＝ **そのルールが無視されても「壊れる」のではなく「前の見た目に戻る」だけ**であること |
| ❌ **使わない場面** | **それが無いとレイアウトが破綻する用途**（例: 2カラム化そのものを `:has()` で切り替える）。⚠️ 未対応ブラウザで**画面が使えなくなる**ため |

⭐ **今回の使い方は条件を満たす**（無視されると「すべて表示」時に200pxの枠が2つ出るだけで、
機能は全部使える）。
