### 5-1. ⭐ `#results { display: contents }`（1199px以下）は、**現時点では外しても何も壊れない**

`style.css` のコメントは「**これを外すとブロック整形文脈が1段増え、スマホ・タブレットの余白の詰まり方が変わる**」
と書いているが、**レビュー担当が実際に `display: block` を強制して測ったところ、幾何は1pxも動かなかった**:

| 幅 | `contents` → `block` に強制したときの `#status` / `#grid` / `.load-more-wrap` / `.setlinks` / `.site-footer` / 文書高 |
|---|---|
| 375 / 768 / 1024 / 1199px | ⭐ **すべて「差分なし（1pxも動かない）」** |

- ⭐ **これは不具合ではない。** `#results` は padding も border も持たないため子のマージンが素通りし、
  **今のところ**箱の有無が幾何に出ないというだけ。**ガード自体は正しく、残すべき**
  （将来 `#results` に padding や `overflow` が付いた瞬間に効き始める＝**保険として正しい形**）
- ⚠️ ⭐ **ただし実装報告 2-4 の表で R4 を「✅ 効いている」としているのは、破壊試験ではない**。
  そこで測っているのは「**計算値が contents から block に変わったこと**」だけで、
  **壊れたことは1つも示していない**（R1〜R3 は本物の破壊試験になっている）
- ⭐ **提案（設計担当の判断待ち）**: コメントの断定を「**今は幾何に出ないが、`#results` に
  padding / border / overflow が付いた日に効く保険**」に改める。⚠️ **レビュー担当はコードを直さない**

### 5-2. 「すべて解除」は**選択が2件以上のときだけ**出る

`renderSelectedFilters()` は `items.length > 1` で `.clear-all` を足すため、**1件のときは出ない**。
1件なら✕1つで済むので**動作としては妥当**だが、**設計書 §12-2 の案A は「『すべて解除』も置ける」としか
書いておらず、出現条件は未定義**。⭐ **意図した挙動なら、そのまま設計書に1行足すと次の担当が迷わない。**

### 5-3. S2（応答性）は良好

- ✕での1件解除＝`/cards/search` **1回**。⭐ **「すべて解除」も 1回**（1件ずつ `click()` していれば
  選択件数ぶん走っていた）。**コメントに理由が明記されている**のも良い
- ⚠️ 参考: チップ3件選択で `api.gatcg.com` へ **42リクエスト**飛ぶが、内訳は
  **検索3回＋カード画像39件**で、**検索の回数は増えていない**（画像取得は従来どおり）

### 5-4. S1（コード品質）に指摘なし

- CSP: `style` 属性・`<style>` 注入とも**使っていない**（追加は `style.css` の静的ルールのみ）
- カード画像バッジ（`.badges-bl` の縦積み）には**触れていない**（`card-badges.css` は差分ゼロ）
- コメントの密度・語り口は既存の `style.css` / `app.js` と揃っている。
  ⭐ とくに **`.grid` の gap を 18px にしない理由を算数つきで残した**のは、
  「また寄せたくなる値」への手当てとして適切
