## 1. 症状

**エキスパンションとレアリティを同時に絞ると、英語モードと日本語モードで結果が違う。**

| モード | 判定するのは | 「PTM ∧ CSR」の意味 |
|---|---|---|
| **英語モード** | 公式API | ⭐ **同じ版に両方**＝「**PTM版であって、その版がCSR**」 |
| **日本語モード** | 客側の `matchesActiveFilters()` | ⚠️ **項目ごとに独立**＝「PTM版を持ち、**かつ（別の版で）CSRでもある**」 |

⚠️ **同じ条件を入れても、日本語で検索したか英語で検索したかで件数が変わる。**

## 2. 実測（2026-09-03・公式API）

| クエリ | 件数 |
|---|---|
| `name=Alice` | 8 |
| `name=Alice&prefix=PTM` | 3 |
| `name=Alice&rarity=7` | 5 |
| **`name=Alice&prefix=PTM&rarity=7`** | ⭐ **0** |
| `name=Alice&prefix=PTM 1st&rarity=7` | 3 |

⭐ `アリス、歪みの女王` は **PTM/r4** と **PTM 1st/r7** を持つ。
**`PTM` かつ `CSR` の版は存在しない**ので、APIは 0 件を返す。
⚠️ 一方、日本語モードの客側フィルタは「PTM版がある」と「CSRの版がある」を**別々に**見るため、**1件返す**。

## 3. ⚠️ これは「レアリティ絞り込み」が作った不整合

⭐ **レアリティ以前は、版レベルの絞り込みがエキスパンション1つだけだったので衝突しようがなかった。**
2つ目（レアリティ）が入って初めて「同じ版で束ねるのか、独立に見るのか」が問題になった。

## 4. ⚠️ 直すときの難しさ（＝`小タスク` にしない理由）

「同じ版がすべての版レベル条件を満たすこと」に揃えるのが素直に見えるが、**そう単純ではない**:

- ⚠️ ⭐ **AND指定のレアリティ**（「**Cでも SRでも刷られている**」）は、**同じ版では原理的に成立しない**。
  ⭐ **AND は「複数の版にまたがる」ことを意味する**ので、**同じ版で束ねると必ず0件**になる
- したがって **「どの条件を同じ版で束ね、どの条件を独立に見るか」の設計から必要**になる
- ⚠️ 変更するのは `shared/js/card-search.js` の `matchesActiveFilters()`＝**デッキ構築ツールも通る経路**

## 5. どちらが「正しい」か

⭐ **英語モード（同じ版）のほうが直感に近い**。「PTMのCSR」と言われて、
「PTM版を持ち、かつ別の版がCSR」を期待する人は少ない。
⚠️ **ただし AND指定のレアリティは独立でなければ意味を成さない**ので、**単純な統一はできない**。
