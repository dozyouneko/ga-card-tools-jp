見え方を切り替える

実際に触ってから決めてください。すべて左のスマホに即反映されます。

1-e-1開き方

これが1-e案の中身そのものです。ボトムシートなら「戻る」動作自体が無くなります。

1-e-2ボタンの位置

右下は親指が届きやすい一方、カードの右列に重なります。中央下は重なりが左右に分散します。

1-e-3出るタイミング

検索条件が画面外に出てから出す方が視覚的なノイズは少なく、常時表示は迷いがありません。

1-e-4選択件数のバッジ

今そのバッジは絞り込みトグルに付いています。シートを閉じた後、何件絞っているかが分かります。

検証印刷リストバーが出ている状態

カードを1枚でも追加すると画面下部に固定バーが出ます。ここが1-e案で唯一の衝突箇所です。

この案が効く理由

  • 1-a案（バー全体を追従）は破綻します。絞り込みを開いた状態だと画面の76%、4グループを全部開くと221%が貼り付いたままになり、カードが見えません。

すでに決まっていること

判断2・3は推奨案で確定済みです。モックの挙動にも反映しています。

判断2 overflow-x: hidden → clip に置換。横はみ出し防止を保ったまま position: sticky が生き返ります。
判断3 style.css の1箇所を直し、これを読む5ページ（トップ・404・デッキ構築・キーワード解説・印刷PDF）共通で適用。他4ページは回帰確認のみ。
⚠️ 判断2は1-e案でも必要です。 1-e案はフローティングボタンなので sticky を使いませんが、 overflow-x: hidden はスマホ幅の sticky を全部壊している状態です。 今後どこかで追従UIを使うたびに同じ罠を踏むので、原因そのものは今回まとめて直します。

このモックで再現していないもの

  • カード画像は公式APIから読めないため、属性色のグラデーションで代用しています。カード名12枚は実データです。
  • 絞り込みの選択肢は代表的なものだけです。実物は属性・クラス・種別・サブタイプの4グループにチップが50個以上並びます。
  • 慣性スクロールやタッチの感触は実機と異なります。指の届きやすさは実機で確かめてください。
