## 7. ⭐ 今回の運用から得た知見（次に活かす）

| 知見 |
|---|
| ⭐ **`wrangler pages deploy` のプレビューは「push 前の実機確認」を可能にする。** ヘッドレスで原理的に測れない項目（Safari のアドレスバー伸縮・`position: fixed`）を持つ UI 変更では、**プレビュー→実機→承認**を標準手順にする価値がある。⚠️ **プレビューも公開の一種**（URLを外部に貼らない）・⚠️ **D1は本番と同じ**なので閲覧のみ |
| ⭐ **レビューの「対策を実行時に外して壊れることを確かめる」破壊試験は、この種の CSS 対策（F2・F3）に対して極めて有効。** 「動いたから合格」では、対策が効いているのか偶然動いているのか区別できない。**次の設計書でも、静かに壊れる対策には破壊試験を検証項目として書く** |
| ⚠️ **設計書の「変更内容」と「検証項目」の食い違いは、今回は D（`closeTray()`）で出た。** 検証項目 V25 が要求する範囲を、変更内容の側が書き漏らしていた。⭐ **検証項目を書いたら、その期待値を満たすために触る箇所が変更内容に全部挙がっているかを逆引きする** |
