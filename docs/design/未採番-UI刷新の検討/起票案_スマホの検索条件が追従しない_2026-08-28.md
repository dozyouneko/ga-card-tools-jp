## タイトル（案）

```text
スマホ幅で検索条件バー（.controls）の position:sticky が効かず、絞り込みに戻るのに一番上まで戻る必要がある
```

## 本文（案）

### 症状

スマホ表示でカード一覧をスクロールすると、**検索条件バーが画面外へ流れてしまい**、
絞り込みを変えるたびにページ最上部まで戻る必要がある。PC表示では追従するため、**スマホ幅でのみ発症する**。

### 原因

`.controls` には既に `position: sticky; top: 0` が付いている（`style.css:85`）。
効かない原因は `@media (max-width: 640px)` 内の次の1行:

```css
/* style.css:314 */
html, body { overflow-x: hidden; }
```

`overflow-x: hidden` は要素をスクロールコンテナ化するため、**子孫の `position: sticky` を無効化する**。
このルールがメディアクエリの中にあるので、**スマホ幅でだけ sticky が死ぬ**。

### 実測（Playwright・scrollY=1500 時点の `.controls` の `getBoundingClientRect().top`）

| 条件 | top | 追従 |
| --- | --- | --- |
| PC 1440x900（`overflow-x: visible`） | **0px** | ✅ |
| スマホ 390x844（現状 `hidden`） | **-1427px** | ❌ |
| スマホ 390x844（`visible` に変更） | **0px** | ✅ |
| スマホ 390x844（**`clip`** に変更） | **0px** | ✅ |

### 修正案

`overflow-x: hidden` を **`overflow-x: clip`** に置換する。
`clip` はスクロールコンテナを作らないため、**横はみ出し防止の目的を保ったまま sticky が復活する**。

```css
html, body { overflow-x: clip; }
```

### ⚠️ 実装時の注意

- ⚠️ **単純削除にしない。** `overflow-x: hidden` は横はみ出し対策として入った経緯がある（#21 前後）。
  実測では3条件とも `scrollWidth === clientWidth` ではみ出しは出なかったが、
  **長いカード名・チップ多数などページ状態によっては再現しうる**ため、`clip` への置換が安全
- ⚠️ **`.controls` は開いた状態だと縦179pxを占める**（390px幅で実測）。
  sticky が復活すると**画面の21%を常時占有する**ことになるので、
  **「絞り込みを閉じた状態で追従させる」等の詰めが要る**（＝見た目の設計判断が残る）。
  ⭐ **この点だけは実装前に設計担当の判断を要する**
- 検証は **`npm run dev` で足りる**（sticky は `_headers` に依存しない）。
  ⚠️ ただし Playwright の `addStyleTag` は meta CSP（`style-src 'self'`）にブロックされるので、
  スタイルを差し替えて測るときは **`element.style.setProperty()`（CSSOM）を使う**
