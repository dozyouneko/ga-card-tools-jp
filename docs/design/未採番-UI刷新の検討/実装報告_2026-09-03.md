### 2-4. 破壊試験（⭐ 対策が「効いている」ことの証明）

⚠️ **「動いたから合格」では対策が load-bearing か分からない**ので、
**CSSOM の `insertRule` で対策を実行時に外し、壊れることを測った**（ファイルは変更していない）。
⚠️ CSP `style-src 'self'` のため `<style>` 注入は使えない。既存シートへの `insertRule` で行った。

| 対策 | 外したときに期待される破綻 | **実測（375x812）** | 判定 |
|---|---|---|---|
| **R1** `html, body { overflow-x: clip }` | `hidden` に戻すと body がスクロールコンテナ化し、**子孫の `position: sticky` が死ぬ** | プローブ（`position:sticky; top:0`）を `#status` の前に置き `scrollY=1200`：**clip では top = 0（貼り付く）／ hidden では top = -950（流れる）** | ✅ **load-bearing** |
| **R2** `.controls { position: static }` | 条件バーが画面外に出ず **FABが永久に出ない** | `sticky` に戻すと `.controls` の top = **0**・FAB は **`is-hidden` のまま**。戻すと top = **-1427**・FAB **出る** | ✅ **load-bearing** |
| **R3** `.controls { backdrop-filter: none }` | シートが**画面下端に来ない** | `blur(6px)` に戻すとシートの bottom = **249**（画面高 812）。戻すと **812** | ✅ **load-bearing** |
| **R4** `#results { display: contents }`（1199px以下） | 箱ができてブロック整形文脈が1段増える | `display: block` を強制すると `#results` の計算値が **contents → block** に変わる。⚠️ ⭐ **だが幾何は動かない**——一覧開始 y は **どちらも 312px**（375px幅）。レビュー側の再測定でも 375 / 768 / 1024 / 1199px で**1pxも動かなかった** | ⚠️ **「効いている」とは言えない（＝保険）**→ §9-1 |

**破壊試験なしの現状値（375px）**: `html/body overflow-x = clip` ／ `.controls position = static` ／
`backdrop-filter = none` ／ `#results display = contents` ／ `#selected-filters display = none` ／
`#q font-size = **16px**`（iOSズーム防止が生きている）／ 横スクロール **なし**（375 = 375）／
FAB は scrollY=1500 で出現（`bottom = 796`）・シートは `bottom = 812`（画面下端）。

**スマホでアコーディオンが効かないこと**: 375px でエレメント→クラスと開くと **両方 open のまま**（設計判断 → §4-3）。

## 3. 設計書からの逸脱と根拠

⚠️ いずれも**設計書どおりに書くと壊れる**ことを実測して確認したうえでの変更。

### 3-1. `body` の Grid 化を **`body.page-top`** に限定した（⭐ 設計書の見落とし）

設計書 §3-1・§11-1 は素の `body { display: grid }` と `body > * { grid-column: 2 }` を書いている。
⚠️ ⭐ **しかし `style.css` は `404.html` も読む**（本番で `/style.css` を読むのはこの2枚だけ）。
そのまま入れると **404ページの本文が「左320pxの空列」の右へ押し込まれた**:

| 404.html（1440x900） | 設計書どおり | **`body.page-top` で限定** |
|---|---|---|
| `body` の display | **grid** | block（変更前と同じ） |
| 本文 `.notfound` の幅 | ⚠️ **542px**（変更前 820px） | ⭐ **820px（一致）** |
| 本文の x | ⚠️ **609**（変更前 310） | ⭐ **310（一致）** |
| フッタの y | ⚠️ **799**（変更前 470） | ⭐ **470（一致）** |

⭐ **対処**: `index.html` の `<body>` に `class="page-top"` を付け、Gridのルールを
`body.page-top` / `.page-top > *` / `.page-top .site-header` / `.page-top #results` に限定した。
⭐ **R8 の「404にも案Aの見た目が出る」は意図どおり残っている**（色と角丸だけが変わる＝V9）。

### 3-2. HeroUI のサイズ指定を **スマホ用メディアクエリより前**に置いた

モックは候補CSSを `style.css` の**末尾**（＝ `@media (max-width: 640px)` より後）に注入していた。
⚠️ ⭐ **そのまま実装すると `.controls input { font-size: .875rem }`(=14px) がスマホの
`font-size: 16px` を同詳細度で上書きし、iOS でフォーカスのたびに画面が拡大する**
（CLAUDE.md「iOS のフォーカス時ズーム防止」・既存コメントで明示されている対策）。

⭐ **対処**: HeroUI の節を `@media (max-width: 640px)` の**直前**に置いた。
実測で **375px の `#q` は 16px のまま**（2-4）。

### 3-3. `.controls .fgroup .chip { position: relative }` を1行足した（V14 のため）

⚠️ ⭐ **設計書に無い1行。省くと V14 が落ちる。**

- 左ペイン化で `.controls` が `position: sticky` → **`static`** になった。
- チップのチェックボックスは `position: absolute`（`shared/css/filter-chips.css`）なので、
  **包含ブロックが `.controls` から初期包含ブロックへ移った**。
- その結果 **`.chips`（`max-height: 200px` のスクロールコンテナ）が包含ブロック連鎖の外**になり、
  ⚠️ **Tab でチップにフォーカスしてもチップ領域が自動スクロールせず、フォーカスリングが枠外のまま見えなくなった**
  （実測: `chips.scrollTop` が 0 のまま・最後のチップは枠外）。
- ⭐ `.chip` を包含ブロックにすると追従する（実測: `scrollTop` 0→156→402、`.chips-rest` は 2946）。
- ⚠️ **見た目は1pxも動かない**ことを A/B で確認した（`position: static !important` を実行時に当てて
  **157チップの矩形が完全一致・差分0**）。チェックボックスに `top`/`left` を書いていないため。

### 3-4. モックの HeroUI ルールのうち **チップ寸法系は実装していない**（⭐ 元から効いていなかった）

モックの `skinCss()` には `.fgroup{border-radius:12px}` `.fgroup summary{padding:11px 14px}`
`.flabel{font-size:.875rem}` `.fgroup .chip{…}` `.fgroup .chips{…}` が含まれる。
⚠️ ⭐ **これらは `index.html` の読み込み順（`style.css` → `shared/css/filter-chips.css`）のため、
同じ詳細度では常に `filter-chips.css` が勝つ＝モックでも効いていなかった**
（実測: 実装後も `.fgroup` の `border-radius` は **10px**、`.chip` の `font-size` は **13.6px** ＝ 共有CSSの値）。

⭐ **したがって「ユーザーが承認した見た目」＝ これらが効いていない状態**。
効かせるには `shared/css/filter-chips.css` を変えることになり、**デッキ構築ツールへ波及する（R6・S1 違反）**。
⭐ **死んだルールをリポジトリに残さない**ため、実装からは外し、`style.css` に理由をコメントで残した。

### 3-5. 「選択中の条件」チップのラベル

モックは `chip.textContent` をそのまま使っており **「ノームNORM」** と繋がって出ていた。
実装では `<span>`（日本語）と `<em>`（英字キー）を分けて **「ノーム `NORM`」**（英字は muted・小さめ）にした。
⭐ チップ本体（`shared/css/filter-chips.css` の `.chip em`）と同じ見え方に揃えたもので、**情報量は同じ**。

## 4. 実行できなかった検証・残っている確認・判断が要る項目

### 4-1. ✅ V3：**1920px の1列ずれは解消した**（2026-09-03・設計担当の指示で対応済み）

⚠️ **初版の報告では 1920px が 7列**で、設計書 §3-2 の表（8列）と食い違っていた。
原因は HeroUI 案A-しっかりで `.grid { gap: 16px → 18px }` にしたことで、**境界ぴったりで落ちていた**:

| 条件 | 右列の内寸 | 8列に必要な幅 | 列数 |
|---|---|---|---|
| gap 18px（初版） | 1920−320−40 = 1560 | 180×8 + 18×7 = **1566** > 1560 | ⚠️ **7** |
| **gap 16px（修正後）** | 1920−320−40 = 1560 | 180×8 + 16×7 = **1552** ≤ 1560 | ⭐ **8** |

⭐ **設計担当の判断（2026-09-03）**: 設計書 §3-2 の表が本タスクの契約であり、
**1920px は最も一般的なPC幅で、列が1つ増える価値のほうが 2px の余白より大きい**。
→ **`.grid` の gap を 16px（既定）に戻した。⚠️ 左ペイン時の横 padding 24→20px はそのまま。**

再測定の結果は §7。**5点すべてが表と一致**した。
⚠️ ⭐ **`style.css` に「18px にしないこと」の理由をコメントで残した**（また寄せたくなる値なので）。

### 4-2. ⚠️ V6：**サブタイプだけを開いた状態は 1440x900 でペインが 23px あふれる**

| 実装（本報告 2-4） | 375px | **312px（外しても同じ）** |
| レビュー | 375 / 768 / 1024 / 1199px | ⭐ **どの幅も 1px も動かない** |

⭐ **理由**: 右列の中身が「ブロックレベルの要素が縦に積まれているだけ」なので、
箱が1段増えてもマージンの相殺のしかたが**今はたまたま**変わらない。

⚠️ ⭐ **ガードのコードは残す（消していない）。** 右列に `float` や `display: flex|grid` の要素、
margin を持つ隣接要素が増えた日に、この1段が効いてくる。
⭐ **「1199px以下は現状と1pxも変わらない」を将来にわたって保証するための保険**である、と
`style.css` のコメントを書き直した（2-4 の判定欄も「効いている」→「保険」に訂正済み）。

### 9-2. S-2: `:has()` を使う方針をコメントに残した

⭐ **設計担当の判断（承認記録 §7）をそのまま `style.css` の該当箇所に書いた**:

> `:has()` は **fail-open な用途に限って使ってよい**。
> ＝ そのルールがまるごと無視されたときに「壊れる」のではなく「1つ前の見た目に戻るだけ」であること。
> ❌ **それが無いとレイアウトが破綻する用途には使わない**（例: 2カラム化そのものの切り替え）。

⭐ **今回の `:has(.chips-rest:not([hidden]))` が条件を満たす理由**もあわせて書いた——
無視されると「すべて表示」のときに 200px の枠が2つ並ぶ（＝ユーザーが指摘した見た目に戻る）だけで、
**チップの選択・解除・AND/OR・検索はすべて従来どおり使える**。

⭐ **なお、2カラム化そのものは `:has()` ではなく `body.page-top` のクラスで書いてある**（§3-1）ので、
この方針と実装は既に一致している。

⚠️ **`CLAUDE.md` には書いていない**（設計担当の指示）。ルート直下＝本番配信物であり、
**1例だけで恒久ルールに昇格させない**方針。2例目に達したら設計担当が提案する。
