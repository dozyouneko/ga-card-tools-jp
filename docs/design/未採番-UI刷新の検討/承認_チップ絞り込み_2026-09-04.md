## 3. ⭐ 承認の理由

1. **閾値で判定する設計にした**（サブタイプ決め打ちにしない）ので、
   ⭐ **将来ほかの群が30種を超えたら自動で欄が出る**。新セットで選択肢が増える本サイトの性質に合っている
2. **レビューが「生命線」を破壊試験で確かめている。** `:has()` ルールを CSSOM で無効化すると
   入れ子スクロールが **0個 → 2個**に増える＝**ルールが効いていることの証拠**が取れている
   （「動いたから合格」で済ませていない）
3. **差し戻しの中身が「経路によって挙動が違う」型だったので、再判定を経路網羅で塞いだ。**
   `✕` / `Backspace` / `Esc` × 展開2状態の**6通り全数**を測っており、同じ穴が残らない形になっている
4. **API リクエストが増えていない**（打鍵・Enter とも 46 → 46）。⭐ **選択肢を絞るだけで検索は走らない**という
   設計の要点が実測で守られている

  本承認記録がその判断の記録になる

⚠️ なお **Q1（プレースホルダの見切れ）と Q2（外した直後のチップが残る）は設計書 v1.1 で決着済み**

### 6-2（S1-3／参考1）C6 の CSS ルールに自動検査を足すか

⭐ **足さない。起票もしない。** 理由:

- ⚠️ **「無言で緑」の型ではない。** このルールが外れると **絞り込み欄に文字を打っても何も減らない**＝
  **機能の主目的そのものが目に見えて壊れる**。⭐ 気づけないのは
  「ハイライト検査の無言緑」型（**出力を誰も見ない**もの）であって、本件は該当しない
- ⭐ **CSSに理由コメントがある**ので、整形時に消される確率も下がっている
- ⚠️ **検査を足すなら実ブラウザで「打鍵後にチップが減ること」を測る必要があり、`validate`（node・DOM無し）では書けない**。
  **費用が効果に見合わない**

⚠️ ⭐ **ただし「CSSの1行が機能の生命線」という構造は本サイトで3例目**
（スマホ絞り込み導線の `overflow-x: clip` / `.controls { position: static }` / 本件）。
**4例目が出たら、CSS破壊試験を回帰の定型手順に格上げすることを検討する**。
