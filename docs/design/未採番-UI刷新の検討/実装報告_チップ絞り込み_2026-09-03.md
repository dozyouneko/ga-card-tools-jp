### 8-2. ⚠️ ⭐ 1回目の W14 は測り方が間違っていた（教訓）

⚠️ **初回は `canvas.measureText()` で測って「193.6px ≤ 内寸196px ＝ 見切れない」と判定したが、
スクリーンショットでは `絞り込む… ドラゴン / dragc` と切れていた。**

- ⭐ **原因**: `<input type="search">` は**装飾（クリアボタン等）のぶんの余白を内側に持つ**ため、
  素のテキスト幅と `clientWidth` の比較では**過小評価**になる（実測差 **約14px**）
- ⭐ **正しい測り方**: **`input.value` にその文言を入れて `scrollWidth` と `clientWidth` を比べる**
  （はみ出していれば `scrollWidth > clientWidth`）。⚠️ この教訓は `filter-chips.css` のコメントにも書いた
- ⭐ **気づけたのは「数値が通ったあとにスクリーンショットを開いた」から**。
  ⚠️ **見た目の検証を数値だけで終わらせない**

## 11. M1-1（W6 / S-1）— `Esc` で空にしたときだけ復元しない

### 原因（レビューの特定どおり）

`Escape` ハンドラが **`clearChipFilter()` を先に呼んでいた**。同関数は
**`restBeforeSearch = null`** に戻すため、続く `applyChipFilter()` の復元条件
`restBeforeSearch !== null` が成立せず、**S-1 が効かないまま `.chips-rest` が開いて残っていた**。

### 直し方（`shared/js/card-search.js` の Escape ハンドラのみ・2行）

```
- clearChipFilter();
+ cfInput.value = "";
  applyChipFilter();
```

⭐ **Backspace / ネイティブの ✕ と同じ経路（値を空にして再判定）に揃えた**。

- ⚠️ **`clearChipFilter()` は `reset()` / `setValues()` 専用**（あちらは「復元してはいけない」）である旨を
  ⭐ **コード内のコメントに明記**した。⚠️ **同じ踏み違いが再発しないようにするための記述なので消さないこと**
- ⚠️ **`reset()` / `setValues()` は一切触っていない**（W8・W9 は合格しているため）
- ⚠️ **C4 も変更していない**（`if (!cfInput.value) return;` → `e.stopPropagation();` の並びはそのまま）

### ⭐ なぜ第2周で見落としたか

⚠️ **W6 を「`page.fill('')` で空にする」1経路でしか測っていなかった**（＝Backspace 相当）。
⭐ **「空にする経路」が3つあることを検証の観点にしていなかった**のが原因で、
