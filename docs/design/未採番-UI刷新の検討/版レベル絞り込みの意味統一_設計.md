## 1. 目的

**同じ絞り込み条件でも、日本語で検索したか英語で検索したかで結果が変わる**のを解消する。

⭐ **成否の基準**: エキスパンションとレアリティを同時に指定したとき、
**英語モードと日本語モードが同じ集合を返すこと**（§7 の M-V1）。

## 3. 現状（なぜ食い違うか）

| モード | 判定するもの | 意味 |
|---|---|---|
| **英語** | 公式API | ⭐ **∃版 e: `prefix(e)∈P` かつ `rarity(e)∈R`**（＝**同じ版に両方**） |
| **日本語** | 客側 `matchesActiveFilters()` | ⚠️ **項目ごとに独立**（「P版がある」と「Rの版がある」を**別々に**判定） |

現在のコード（`shared/js/card-search.js`）:

```js
// レアリティ: MULTI のループで matchesMulti() → 版の集合から rarity を集めて判定（版を問わない）
// エキスパンション: 下で別に eds.some(e => pre.includes(e.set.prefix)) （版を問わない）
```

⭐ **どちらも「どれか1つの版が満たせばよい」で、2つの条件が同じ版である必要が無い。**

⚠️ ⭐ **これはレアリティ絞り込みが作った不整合。** レアリティ以前は版レベルの絞り込みが
**エキスパンション1つだけ**で、**衝突しようがなかった**。

## 4. ⭐ 統一規則 — 「版の集合を先に絞り、その中で判定する」

⚠️ **単純に「全部を同じ版で束ねる」ことはできない。**
⭐ **レアリティの AND 指定（「CでもSRでも刷られている」）は、複数の版にまたがる意味**なので、
同じ版で束ねると**必ず0件**になる。

### 決定

```
① 版の候補集合 E を作る
     エキスパンション絞り込みが有効 → E = {e | prefix(e) ∈ P}
     無効                          → E = 全版
② その E の中でレアリティを判定する
     OR  指定 → ∃e∈E: rarity(e) ∈ R
     AND 指定 → ∀r∈R: ∃e∈E: rarity(e) = r
```

| 効果 | |
|---|---|
| **OR の場合** | ⭐ **`∃e: prefix(e)∈P ∧ rarity(e)∈R`** ＝ **公式APIと完全一致**（M-V1） |
| **AND の場合** | ⭐ **「そのエキスパンションの中で、CとSRの両方が刷られている」**＝意味が保たれる（M-V2） |
| **どちらか片方だけ有効** | ⭐ **現状と同じ**（E が全版、または R が空） |

⭐ **一般化**: 版レベルの条件が今後増えても、**「E を絞る条件」と「E の中で評価する条件」に
振り分けるだけ**で拡張できる。

### ⚠️ 実装の要点

- ⚠️ **レアリティを `MULTI` の一般ループから外す**（版の集合を先に絞る必要があるため、
  ほかの項目と同じ扱いにできない）。⭐ **`isIndexBlind()` の定義（`field === null`）は維持する**
  ——P2（索引で絞らない）・D-1（概算）・D-2（異常信号の分類）が全部そこから導かれているため
- ⚠️ ⭐ **`matchesActiveFilters(card, { skipIndexBlind: true })`（D-2 の分類用）は
  「レアリティを完全に無視する」意味**を保つこと。**E の絞り込み（エキスパンション）は残す**
- ⭐ **英語モードでも同じ関数を通る**（AND指定の後段フィルタ）。
  ⚠️ **新しい規則はAPIと一致するので、APIが返したカードを取りこぼすことはない**

## 5. ⚠️ 影響範囲

| 対象 | 影響 |
|---|---|
| **日本語モード** | ⭐ **結果が変わる（これが目的）**。351通りの組み合わせで英語モードに揃う |
| **英語モード（OR）** | ⭐ **変わらない**（APIが既に同じ判定をしている） |
| **英語モード（AND）** | ⚠️ **変わりうる**。後段フィルタが厳しくなる方向＝APIと整合する方向 |
| ⚠️ **`tools/deck-builder/`** | ⭐ **変わらない**。レアリティ群を持たない（`R` が常に空）ため、規則は現状に退化する。⚠️ **M-V4 で必ず確認する** |
| カード個別ページ・生成物 | **影響なし**（`matchesActiveFilters()` はブラウザ検索専用） |

## 8. 規模

⚠️ **`小タスク` を付けない。**

- 共有ファイル `shared/js/card-search.js` の**判定の中核**（`matchesActiveFilters`）を変える
- ⚠️ **`MULTI` の一般ループからレアリティを外す**ため、
  **P2・D-1・D-2・P5 の4つの既存対応と噛み合う**（どれも回帰確認が要る）
- ⚠️ **デッキ構築ツールも同じ関数を通る**（S1 の境界。**変わらないことの確認が必須**）
