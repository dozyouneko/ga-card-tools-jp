## 1. 目的

> サブタイプの検索条件がゲームシステム上これからも多くなる想定です。
> 開閉するエリア内にテキスト検索できるエリアを設けて、そこに入力した文字列で検索条件自体を絞ることはできますか？
> （ユーザー・2026-09-03）

⭐ **絞るのは「選択肢」であって「カード」ではない。**
サブタイプは現在 **157種**あり、「よく使う20種」＋`＋ すべて表示` では目当ての1つを探しにくい。

---

## 2. ⭐ 「選択肢が多い群」を閾値で判定する（サブタイプ決め打ちにしない）

⚠️ **要望の動機が「これからも多くなる想定」なので、サブタイプ限定にしない。**

```
選択肢が SEARCH_MIN（= 30）種を超える群にだけ、絞り込み欄を出す
```

⭐ **実測（試作・2026-09-03）**:

| 群 | 選択肢 | 絞り込み欄 |
|---|---|---|
| エレメント | 13 | 出ない |
| クラス | 9 | 出ない |
| タイプ | 13 | 出ない |
| **サブタイプ** | **157** | ⭐ **出る** |
| レアリティ（別タスク） | 9 | 出ない |

⭐ **将来ほかの群が閾値を超えた日に、何もしなくても欄が現れる**
（＝#40 のような「手で足す辞書」を増やさない）。

## 3. 実装方針 — `fillChips()` のオプトイン

⚠️ **`shared/js/card-search.js` の `fillChips()` に手を入れる**（S1 の境界＝報告事項）。

```js
fillChips(details, kind, { label, top, search: true })
```

- **`search: true` を渡した群だけ**が対象。⭐ **さらに `keys.length > SEARCH_MIN` のときだけ実際に出す**
- ⭐ **トップページは全群に `search: true` を渡す**（`app.js`）。どれに出すかは閾値が決める
- ⚠️ **デッキ構築ツールは渡さない**＝**完全な no-op**（S1）

### ❌ 採らない案

`app.js` で組み立て後のDOMを加工する案は**採らない**。
⚠️ **`.chip` / `.chips-rest` / `.more` の構造知識が2か所に分かれる**＝
このリポジトリが既に踏んでいる「二重定義」の型
（→ [`用語ハイライト規則の二重定義`](../未採番-用語ハイライトの語形ずれ/起票案_2026-08-30_用語ハイライト規則の二重定義.md)）。

### スタイルの置き場

⚠️ **要素は共有の `fillChips()` が作る**ので、見た目は **`shared/css/filter-chips.css`** に置く
（同ファイルの方針「チップUIそのものの見た目はここ」に従う）。

- ⭐ **オプトインなので、デッキ構築では要素自体が生成されず、ルールは死んだまま**（実害ゼロ）
- ⚠️ ⭐ **これは S1 の追加の逸脱**（PC左ペインでは `filter-chips.css` を無変更に保った）。
  **ユーザーに報告して合意を取ってから実施する**

| 入力 | 結果 |
|---|---|
| （空） | 全157種が対象に戻る。**「よく使う20種」表示と `＋ すべて表示` が復活** |
| `ドラゴン` | **1件が一致**（日本語で一致） |

## 5. ⚠️ ⭐ 「すべて表示」の状態管理との噛み合わせ（設計で新たに詰めた点）

⚠️ **ここが実装で一番壊れやすい。** `.chips-rest` の表示状態は、いま **3つの経路**が触る:

| 経路 | いつ |
|---|---|
| `moreBtn` の `click` | ユーザーが「すべて表示 / よく使う分だけ表示」を押した |
| `setValues()` | URL復元で、隠れている側の値が選ばれていた |
| `reset()` | リセットボタン |

⭐ **PC左ペインのタスクで、この3経路の文言更新は `syncMore()` に集約済み**（`b96cfedc`）。
⚠️ **チップ絞り込みは4つ目の書き手になるので、`syncMore()` と喧嘩させないこと。**

### 決めたこと

| # | 仕様 |
|---|---|
| **S-1** | ⭐ **検索を始める直前の `restChips.hidden` を覚え、入力が空に戻ったら復元する**。⚠️ 「常に畳む」にすると、**ユーザーが自分で開いた状態を検索が勝手に畳む** |
| **S-2** | ⭐ **検索中は `syncMore()` の文言を「N件が一致」に差し替えず、別の要素（`.cfhint`）に出す**。⚠️ 同じ要素を2人が書くと、どちらが最後に書いたかで表示が変わる |
| **S-3** | ⭐ **`reset()` は検索欄も空にする**（`details.reset()` の中で）。⚠️ 忘れると「リセットしたのに選択肢が絞られたまま」になる |
| **S-4** | ⭐ **`setValues()` で隠れ側の値が復元されるときは、検索欄を空にしてから既存の展開処理に任せる**。⚠️ 検索中の状態でURL復元が走ると、C-B の「選択済みは残す」と競合する |
| **S-5** | ⚠️ **「すべて表示」が押されている間に検索すると、`.chips-rest` は既に見えている。** その状態で入力を空に戻したら **S-1 により見えたまま**にする（畳まない） |

⚠️ ⭐ **PC左ペインで入れた CSS ルールとの関係**:
`style.css` は「`.chips-rest` が見えている間はチップ領域の丈の上限を外す」（`:has()`）。
⭐ **検索中は `.chips-rest` を見せるので、この間も上限が外れる＝二重スクロールにならない**。
⚠️ **意図した相互作用なので、どちらかを変えるときは両方を見ること。**

## 6. ⚠️ 気をつけること

| # | 内容 |
|---|---|
| **C1** | ⚠️ ⭐ **「カードを検索する欄」と誤解されうる。** ペイン内に `#q`（カード名）・`#qtext`（効果文）に加えて3つ目の入力欄ができる。⭐ **群の内側に置き・破線の枠にし・プレースホルダを「157種から絞り込む… 例: ドラゴン / dragon」にする**（試作の形） |
| **C2** | ⚠️ **スマホでは `font-size: 16px`。** 16px 未満は **iOS がフォーカス時にズームする**（CLAUDE.md）。⚠️ `filter-chips.css` の `@media (max-width: 640px)` は**ページ側の一括指定を「戻す」ブロック**なので、ここで小さくしないこと |
| **C3** | ⭐ **絞り込み欄は「選択肢」を絞るだけ。** 入力しても**再検索は走らない＝APIリクエストは増えない** |
| **C4** | `Esc` で入力をクリアする。⚠️ ⭐ **スマホのボトムシートの `Esc`（閉じる）と混ざらないよう `stopPropagation()` する**（⚠️ 入力が空のときは止めない——**空で Esc ならシートを閉じたい**） |
| **C5** | ⚠️ **アクセシビリティ**: 入力に `aria-label`（例: 「この項目の選択肢を絞り込む」）を付ける。⭐ **`aria-live` は足さない**（一致件数が打鍵ごとに読み上げられると邪魔） |
| **C6** | ⚠️ **`.chip[hidden]` が効くこと**を確認する。`.fgroup .chips` は `display: flex` なので、`[hidden]` に `display: none` を当てないと**隠れない**（試作では明示した） |

## 8. 規模

⭐ **`小タスク` を付けてよい。**

- ⭐ **検索結果に一切影響しない**（選択肢の表示を出し入れするだけ・APIも索引も触らない）
- ⭐ **最悪の失敗が「欄が出ない」「絞れない」**で、静かにデータを取りこぼす型ではない
- ⚠️ ただし **§5 の状態管理**は既存の3経路と噛み合うので、**W6・W8・W9 は必ず実施する**
