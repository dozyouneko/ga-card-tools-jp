## 1. 背景と目的

デッキ構築ツールの構築ルール判定に、公式ルールとの食い違いが2つある。

| # | 現状 | 公式ルール |
|---|---|---|
| **#58** | メインデッキ61枚以上を `over`（**赤**）で警告する | メインは**最低60枚・上限なし**。61枚以上は正当な構築 |
| **#59** | マテリアルのLv0チャンピオン必須を**判定していない**ため、Lv0チャンピオン不在でも統計が「✅ 使用可能」と出る | マテリアルには**Lv0チャンピオンが最低1枚**必要 |

どちらも #4（パンテオン構築対応）の設計中に発見し、スコープ外として切り出したもの
（#4 設計書 §8・§9-A / §9-B）。**両方とも2フォーマット共通の要件**で、
直す場所も `tools/deck-builder/app.js` に集中しているため**1本で対応する**。

⚠️ #58 は「実務上ほとんどのデッキがちょうど60枚だから実害は小さい」と起票時に見積もったが、
**実データで反例が見つかった**（§2-2）。優先度の見積もりは誤りだった。

## 2. 事実確認

### 2-1. 公式ルール（2026-08-11 原文で再確認）

出典: [Grand Archive Comprehensive Rules v1.1.1 — General Rules / Format Conventions](https://rules.gatcg.com/general-rules/general-rules-format-conventions)

> **Standard Constructed Rules**
> - Main decks can have **a minimum of 60 cards** and a maximum of four copies of a card with the same name.
> - Material decks can have **a maximum of 12 cards** and a maximum of one copy of a card with the same name.
> - **Material decks must contain a Level 0 champion at minimum.**
> - Sideboards contain a maximum of 15 cards. …
>
> **Pantheon Rules**
> - Main decks must consist of, **at minimum, 60 cards** of which there can be no more than one copy of each card.
> - Material decks **must consist of 12 cards** of which there is **at least one Level 0 Champion Card**.
> - Players must each present two Boons face down at the start of the game: one Lesser Boon and one Greater Boon.
> - There is no sideboard for Pantheon.

これを表にすると:

| | スタンダード | パンテオン |
|---|---|---|
| メインデッキ | **最低60枚・上限なし** | **最低60枚・上限なし** |
| マテリアルデッキ | **最大**12枚（12枚未満でも合法） | **ちょうど**12枚 |
| Lv0チャンピオン | **最低1枚**（必須） | **最低1枚**（必須） |
| サイドボード | 最大15枚・15pt | 存在しない |

- ⭐ **マテリアルの扱いは2フォーマットで違う**（スタンダードは「最大」＝下限なし、パンテオンは「ちょうど」）。
  #4 設計書 §2 の表と一致しており、原文でも裏が取れた
- ⭐ **Lv0チャンピオンは両フォーマット共通**（Draft も同様だが本ツールはDraft非対応）

### 2-2. 実データ（`data/tournaments/`）

`data/tournaments/events/59232.json`（2026-07-31 Coffer Sparks RDO Store Championship・9名）の9デッキ:

| メイン枚数 | 件数 |
|---|---|
| 60枚 | 7 |
| **62枚** | **2**（うち1つは**優勝者** BarrettCreative・rank 1） |

→ **61枚以上のスタンダードデッキは実在し、しかも入賞している。**
現状のツールは、この優勝デッキを開くと `62 / 60` を**赤で「超過」と警告する**。

### 2-3. 公式API（2026-08-11 実測）

| 調べたこと | 結果 |
|---|---|
| `type=CHAMPION` の総数 | **125枚** |
| うち `level === 0` | **31枚**（`spirit-of-wind` `spirit-of-fire` `lost-spirit` `prismatic-spirit` ほか） |
| `level` の型 | **数値**（`0` / `1` / `2` / `3` / `4`）。分布は 0:31・1:36・2:26・3:29・4:2 |
| `level` が数値でないもの | **1枚だけ**（`lu-bu-indomitable-titan`。`level: null`） |
| `lu-bu-indomitable-titan` の `types` | **`["UNIQUE","ALLY"]`** ＝ **チャンピオンではない**（`type=CHAMPION` 検索に混ざって返るだけ） |
| パンテオン禁止44枚の型 | すべて `CHAMPION`（`nameless-champion-*` 系）で **`level: 1`** ＝ **Lv0要件を満たさない** |

- ⚠️ **`level` の判定は厳密等価 `card.level === 0` で行う。**
  `Number(card.level) === 0` や `!card.level` は **`null` を 0 と誤判定する**（`lu-bu-indomitable-titan` が該当）。
  ただし当該カードは `types` にCHAMPIONを含まないため、`types` 判定を先に置けば実害は出ない。
  **それでも厳密等価で書くこと**（将来 `level: null` のチャンピオンが出た場合の安全側）
- ✅ **索引・翻訳データの再生成は不要**（`level` はカードAPIの応答から直接読む）

## 3. 決定済み要件（2026-08-11 ユーザー決定）

1. **#58 のカウンタ表記は `N / 60以上`**。60枚未満は無色、60枚以上は緑（`.ok`）。
   **`.over`（赤）はメインでは二度と付かない**
2. **#59 の「不足」はフォーマット適合を3状態にして出す**
   （⚠️ 不適合 ／ 🚧 構築中 ／ ✅ 使用可能）。加えて**マテリアルゾーンに注記**を出す
3. ⚠️ **タブ帯の警告バナー（`#deck-warn`）には「不足」を出さない**。
   構築途中は必ず未達で常時点灯するため（#4 §5-2(b) の方針を踏襲）

## 4. データモデル

**変更なし。** API・D1・マイグレーション・生成物（`cards/` `sets/` `data/*.json`）はいずれも触らない。
判定はすべてクライアント側の既存データ（`getCard()` が返すカードオブジェクトの `types` / `level`）で完結する。

### 5-1. メインデッキのカウンタ（#58）

`tools/deck-builder/app.js` の `MAIN_MAX = 60` を **`MAIN_MIN = 60` に改名**し、
`updateZoneHeader()` のメイン分岐を独立させる。

| メイン枚数 | カウンタ文言 | `.cnt` のクラス | メーターの幅 | メーターのクラス |
|---|---|---|---|---|
| 0〜59 | `55 / 60以上` | （なし） | `total / 60`（例: 91.7%） | （なし＝`--accent`） |
| 60 | `60 / 60以上` | `ok` | 100% | `ok` |
| **61以上** | **`62 / 60以上`** | **`ok`** | **100%（頭打ち）** | **`ok`** |

- ⚠️ **`.cnt.over` / メーターの `.over` はメインには付けない**（どの枚数でも）
- ⚠️ **`ok` の条件は `total === MAIN_MIN` ではなく `total >= MAIN_MIN`**
- 文言は **`${total} / ${MAIN_MIN}以上`**（半角スペースは `/` の両側のみ。`以上` の前にスペースを入れない）
- メーター幅は既存の `setBar()` が `Math.min(100, ratio*100)` で頭打ちするのでそのままでよい

#### 変更が波及するもう1箇所

検索結果からカードを追加したときのトースト（`app.js` の `summary` 組み立て、現行 `1535` 行付近）:

```
✅ 「取り戻し」をメインデッキに追加 — 62 / 60以上
```

- ⚠️ **ここも `MAIN_MIN` を使い、`${total} / ${MAIN_MIN}以上` に揃える。**
  片方だけ直すと、同じ数字がゾーンヘッダとトーストで違う表記になる

#### 変更しないもの（#58）

- **マテリアル**（`13 / 12` が赤）— 公式が「**最大**12枚」なので超過の赤は正しい
- **サイドボード**（`17 / 15 pt・13枚` が赤）— 同じく「最大」なので正しい
- **パンテオンゾーン**（`Lesser 1/1・Greater 1/1`）— #4 のまま
- **統計のゾーン別カードの見出し**（`メインデッキ 62枚`）・**合計の内訳**
- **共有閲覧画面のゾーン見出し**（`メインデッキ 62枚`）— メーターもカウンタも無いので影響なし
- **omnidex提出用コピー**・**デッキ画像出力**

### 5-2. マテリアルゾーンのLv0チャンピオン注記（#59）

`tools/deck-builder/index.html` のマテリアルゾーンに、**メーターの直後・`.zone-grid` の直前**へ1行足す:

```html
<div class="zone" data-zone="material">
  <h3><span class="zname">マテリアルデッキ</span> <span class="cnt"></span></h3>
  <div class="meter"><i></i></div>
  <p class="zone-note warn" data-lv0-note hidden>⚠️ Lv0チャンピオンが入っていません（マテリアルデッキには最低1枚必要です）</p>
  <div class="zone-grid"></div>
</div>
```

| 状態 | 注記 |
|---|---|
| マテリアルが**空**（0枚） | **出さない**（`hidden`）。新規デッキを開いた瞬間に警告しないため |
| マテリアルに1枚以上あり、Lv0チャンピオンが**0枚** | **出す** |
| マテリアルに1枚以上あり、Lv0チャンピオンが**1枚以上** | **出さない**（「入っています」とは言わない） |

- 文言は固定（HTMLに直書きし、JSは `hidden` の付け外しだけを行う）:
  **`⚠️ Lv0チャンピオンが入っていません（マテリアルデッキには最低1枚必要です）`**
- 色は既存の `.zone-note.warn`（`#fca5a5`）。**新しいCSSクラスは要らない**
- 表示の切り替えは `renderZones()` のゾーンループ内、既存の `[data-inactive-note]` の処理と同じ場所で行う
- ⚠️ **`data-active-note`（パンテオンゾーンの説明文）とセレクタを衝突させない。**
  新しい属性は `data-lv0-note` を使う
- ⚠️ **共有閲覧画面（`#view-deck`）には出さない**（ゾーン見出しだけの画面でメーターも注記も持たない）。
  共有画面の利用者には**統計タブの 🚧 構築中**（§5-3）で伝わる
- ⚠️ **フォーマットに依らず出す**（スタンダードもパンテオンも必須要件のため）

### 5-3. フォーマット適合を3状態にする（#59）

#### (a) 状態の定義

| 状態 | 条件 | 表示 |
|---|---|---|
| **不適合** | `formatIssues()` が1件以上 | `⚠️ …` を縦に並べる（現行どおり・`.fmt-ng`） |
| **構築中** | `formatShortfalls()` が1件以上 | `🚧 構築中 — <不足を「・」で連結>`（1行・`.fmt-todo`） |
| **使用可能** | どちらも0件 | `✅ 使用可能`（現行どおり・`.fmt-ok`） |

- ⭐ **不適合と構築中は同時に出す。** 違反を直した瞬間に 🚧 が新しく現れる形にしない
- ⭐ **`✅ 使用可能` は「不適合でも構築中でもない」ときだけ**出す（3つが同時に出ることはない）
- 行の構造は現行の `.fmt-issues`（`display:flex; flex-direction:column`）を**そのまま再利用**し、
  その中に `⚠️` 行群 → `🚧` 行の順で入れる。既存のシーズン禁止予告 `ℹ️`（`.fmt-notes`）は現行のまま末尾:

  ```html
  <div class="fmt-row">
    <span class="fmt-name">スタンダード</span>
    <span class="fmt-issues">
      <span class="fmt-ng">⚠️ メイン同名4枚制限の超過 1種 — Reclaim（取り戻し） ×5</span>
      <span class="fmt-todo">🚧 構築中 — Lv0チャンピオンが未設定</span>
    </span>
    <span class="fmt-notes"><span class="fmt-info">ℹ️ …</span></span>
  </div>
  ```

#### (b) 「不足」の判定（`formatShortfalls()`）

⚠️ **`formatIssues()` と対になる新関数**として、同じファイルの直後に置く。
`computeDeckStats()` が返す `format` オブジェクトに必要な数値を持たせる。

| 不足の項目 | 条件 | STANDARD | PANTHEON | 文言（画面に出る最終形） |
|---|---|---|---|---|
| 1. Lv0チャンピオン | `material` ゾーンに `types` に `CHAMPION` を含み `level === 0` のカードが**0枚** | ✅ | ✅ | `Lv0チャンピオンが未設定` |
| 2. マテリアル枚数 | `material` の合計 < 12 | ❌ **判定しない** | ✅ | `マテリアルデッキがあと{12 - N}枚` |
| 3. メイン枚数 | `main` の合計 < 60 | ✅ | ✅ | `メインデッキがあと{60 - N}枚` |
| 4. Lesser Boon | `pantheon` ゾーンの Lesser が**0枚** | ❌ | ✅ | `Lesser Boonが未設定` |
| 5. Greater Boon | `pantheon` ゾーンの Greater が**0枚** | ❌ | ✅ | `Greater Boonが未設定` |

- ⚠️ **並びは上表の1〜5で固定**（ゾーンの表示順 material → main → pantheon に合わせてある）
- ⚠️ **スタンダードのマテリアル枚数は不足に数えない。** 公式が「**最大**12枚」で下限を定めていないため、
  マテリアル8枚 + Lv0チャンピオン1枚のスタンダードデッキは**合法＝ `✅ 使用可能`** と出るのが正しい
- ⚠️ **マテリアルが0枚のとき、項目1と項目2（パンテオンのみ）は両方立つ。** 冗長に見えるが両方とも真なので**両方出す**
- ⚠️ **サイドボードに「不足」は無い**（「最大15枚」なので下限がない）
- ⚠️ **Boonの不足は「種類ごと」に1項目ずつ**（両方0枚なら2項目出る）。まとめない
- 全ゾーンが空のデッキは `statsHtml()` が先頭で `カードがありません。…` を返すため、
  **適合カード自体が描画されない**（🚧 も出ない）。ここは現行のまま

判定に使う数値の出どころ（`computeDeckStats()` 内で算出し `format` に載せる）:

```js
// 判定対象ゾーンの中だけを見る(maybe・非アクティブゾーンは対象外＝#4の方針のまま)
lv0Champion // material に入っている Lv0チャンピオンの枚数
materialCount, mainCount // byZone[...].count と同じ値
lesserCount, greaterCount // pantheon ゾーンの Lesser / Greater 枚数(rule.boons のときだけ)
```

- ⚠️ **`perSlug` は `rule.zones` に含まれる行しか持たない**（`maybe` と非アクティブゾーンは既に除外済み）。
  Lv0チャンピオンの数え上げは `perSlug` の `qty.material` を見ればよい
- Lv0チャンピオンの判定関数は `isMaterialCard()` / `isBoonCard()` の並びに新設する:

  ```js
  // マテリアルデッキに最低1枚必要な Lv0チャンピオン(#59)。
  // ⚠️ level は厳密等価で比較する(level:null のカードが実在するため。lu-bu-indomitable-titan)
  function isLevelZeroChampion(card) {
    const t = (card && card.types) || [];
    return t.includes("CHAMPION") && card.level === 0;
  }
  ```

#### (c) 警告バナー（`#deck-warn`）は変えない

⚠️ **`updateDeckWarn()` は今までどおり `formatIssues()` だけを見る。**
`formatShortfalls()` を表示条件にも理由ラベル（`warnReasons()`）にも**足さない**。

- #4 の第3版で「`formatIssues()` に判定を足したら `warnReasons()` にも足す」という規約を作ったが、
  **`formatShortfalls()` はその規約の対象外**である。⭐ 混同しないよう、
  `warnReasons()` のコメントに「**不足（`formatShortfalls`）はここに足さない**」と明記すること
- 根拠: バナーは「**このままでは大会に出せない違反**」を伝えるもので、
  構築途中に必ず立つ「不足」を入れると**カードを1枚入れた瞬間から常時点灯**する（#4 §5-2(b) と同じ理由）

#### (d) CSS（`tools/deck-builder/style.css`）

`.fmt-ok` / `.fmt-ng` の並びに1行足すだけ:

```css
/* 構築中(不足あり・違反ではない)。違反の赤とも「使用可能」の緑とも区別する(#59) */
.fmt-todo { color: var(--accent); }
```

- `--accent`（`#d9a441`）はパネル地（`--panel #171a21`）に対してコントラスト比 **7.74:1**（WCAG AAA を満たす）。
  既存の `.fmt-ng`（`#fca5a5` = 9.17:1）・`.fmt-ok`（`#7fd4a8` = 9.85:1）と同じ明度帯に収まる
- ⚠️ **`.fmt-issues` の中に入れるので、`display` や `gap` の追加指定は要らない**

## 8. やらないこと（今回のスコープ外）

- **マテリアルの「ちょうど12枚」と「最大12枚」でカウンタの色分けを変えること。**
  現行はどちらも `12` で緑・`13以上` で赤。スタンダードでは11枚も合法だが、
  「0/12 が緑」になる表記のほうが不自然なので**メーターの色分けは触らない**
  （不足の判定は §5-3(b) の 🚧 側でフォーマットごとに正しく分けてある）
- **`FORMAT_RULES` に「マテリアルがちょうど12枚か」の専用フラグを足すこと**（第2版で判断）。
  実装は `rule.boons` を流用して「パンテオンだけマテリアル不足を数える」を実現している（`formatShortfalls()`）。
  ⚠️ **`boons` の本来の意味は「このフォーマットはBoonを使うか」で、「マテリアルがちょうど12枚か」とは別の性質**。
  今は `FORMAT_RULES` が2件で両者が完全に一致するため**結果は正しい**が、
  ⭐ **3つ目のフォーマットを足すときは、まず `boons` が兼ねている意味を分離すること**
  （`materialExact` 等の専用フラグにする）。分離せずに足すと**片方だけ違う組み合わせで静かに間違える**。
  本タスクで直さない理由: 本ツールは2フォーマットのみを扱う（Draft対応は下記のとおりスコープ外）ため実害が無く、
  内部フラグの改名だけのために実装・レビューを1往復させる利点が無いため。
  この注意書きは **CLAUDE.md のデッキ構築ツールの節にも恒久ガードとして転記済み**
- **`🚧 構築中` をタブ帯の警告バナーに出すこと**（§5-3(c) の理由）
- **`🚧 構築中` をデッキ一覧のカードに出すこと**（一覧は枚数を持っておらず、全デッキのカードを取得する必要がある）
- **Draftフォーマット**（メイン最低30枚・マテリアル10枚）への対応。本ツールは2フォーマットのみ扱う
- **サイドボードのポイント計算の見直し**（#58・#59 と無関係）
- **omnidexのパンテオン出力**（#4 §9-C のまま未決）
